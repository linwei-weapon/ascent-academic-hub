# 规则试算数据新鲜度与版本一致性

## 目标

规则影响试算必须绑定确定的数据基线。成绩、学生、培养方案或当前学期发生变化后，旧候选不能继续进入审核、发布或激活。

## 数据快照

每次试算记录：

- 当前学期；
- 成绩记录数；
- 成绩分数校验和；
- 已通过成绩记录数；
- 成绩最新学期；
- 学生记录数；
- 培养方案课程数；
- 培养方案学分校验和；
- 核心课程记录数。

系统对规范化快照 JSON 计算 SHA-256，生成 `dataFingerprint`。快照、指纹、试算人和试算时间一并保存在变更单影响结果中。

## 新鲜度门禁

以下操作前会重新生成当前数据指纹：

- 提交审核；
- 审批或拒绝；
- 发布规则配置；
- 激活候选预警。

当前指纹与试算指纹不一致时返回 HTTP 409，要求重新执行影响试算。

## 页面

变更单影响信息显示：

- 候选、新增、退出人数；
- 数据有效或已过期；
- 试算所用当前学期；
- 试算时间。

## 专项验证

在数据库副本中：

1. 完成 R1 影响试算并生成数据指纹；
2. 将一条成绩调整 0.01 分；
3. 尝试提交规则变更；
4. 系统返回 409，阻止使用旧试算；
5. 回滚副本事务并清理测试数据库。

专项结果：`staleBlocked=True`，错误码 409。

## 验证

- 后端和专项测试脚本编译通过；
- 数据变化模拟验证通过；
- 前端生产构建通过；
- 服务已重启并加载最新代码；
- 生产数据未进行测试修改。
