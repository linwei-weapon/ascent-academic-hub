## 1. 文档目标、范围与阅读方式

### 1.1 文档目标

本文档完整说明“教学运行分析”中用户可以看到、筛选、比较、点击、下钻和核查的全部功能，重点回答：

1. 页面展示哪些信息、选项、指标、图表、表格和状态；
2. 每个指标如何计算，统计对象、分子、分母、去重方式、排除项和精度是什么；
3. 各页面如何共享学期和权限范围，哪些页面使用独立观察窗口；
4. 点击某个对象后进入哪个页面、抽屉或弹窗，下钻条件如何继承；
5. 哪些结论是源事实，哪些是规则推导，哪些只是原型核查阈值；
6. 数据不足、无权限、未接入或接口失败时如何诚实降级；
7. 当前实现与正式需求之间还存在哪些必须在验收时处理的差异。

### 1.2 功能范围

“教学运行分析”是一个含 6 个平级页签的业务工作台，默认页签“开课供给”同时承担模块首页职责。

| 工作区 | 主要管理问题 | 最深下钻 |
|---|---|---|
| 开课供给 | 开了多少课、多少教学班，班额与教师覆盖是否形成供给核查线索 | 完整课程清单 → 开课保障核查 → AI 开课保障研判；数据质量问题 → 处置轨迹 |
| 排课结构 | 排课片段集中在哪些星期和时段，重点课程组是否集中或晚间偏多 | 重点课程组 → 课程排课情况 |
| 教室占用 | 实际占用集中在哪些节次、楼宇和活动类型 | 楼宇实际占用核查 → AI 资源研判 |
| 教师负荷 | 排除异常后，任务在职称、教师和学院间如何分布 | 教师教学负荷核查 → AI 教师负荷研判 |
| 调听课分析（页面实际为“调停课分析”） | 当前以调课、停课、影响人次、原因、教师和月份为主；听课数据尚未接入 | 教师调课原因核查 → AI 调课研判 |
| 课程结果 | 多学期首次、补考、重修结果是否形成课程资源核查线索 | 单门课程学期结果与开课资源 |

### 1.3 不在本模块范围内的能力

- 不编制或自动执行排课；
- 不审批调课、停课，不自动创建补课安排；
- 不维护课程、教学班、教室、教师或课表主数据；
- 不依据调停课频次评价教师责任；
- 不依据课程通过率直接评价课程质量或教师教学质量；
- 不在缺少学校工作量办法时认定教师达标、未达标或超负荷；
- 不把已观测教室推断为全校可用教室全集；
- 不用演示、推导或缺失数据伪装正式结论。

### 1.4 状态标记与阅读约定

本文使用以下标记：

- **现行实现：** 当前代码和页面已实际执行的行为；
- **正式要求：** 生产开发和验收应满足的规范；
- **待修正：** 当前实现与页面文案、权限契约或统一指标之间存在差异，不能作为已确认口径；
- **原型阈值：** 只用于形成有限核查清单，不代表学校制度、质量合格线或绩效标准。

指标编号优先复用现有确认书中的 `T`（教学运行）、`R`（教室资源）、`L`（教师负荷）、`S`（调停课）和 `C`（课程结果）编号。页面功能但尚无客户指标编号的项目标记为“页面功能”。

## 2. 页面树与完整下钻链路

### 2.1 页面树

```text
教学管理分析
└─ 教学运行分析（默认进入“开课供给”）
   ├─ 开课供给
   │  ├─ 数据质量排除 → 只读问题明细（终点）
   │  ├─ 开课保障关注 TOP10 → 开课保障信息抽屉
   │  │  └─ TOP10 前 3 门 → 开课保障研判抽屉（终点）
   │  ├─ 查看全部课程 → 全部课程开课情况抽屉
   │  │  └─ 课程详情 → 开课保障信息抽屉（终点）
   │  └─ 学院教学供给规模、课程性质分布、班额分布 → 本页聚合结果（终点）
   ├─ 排课结构
   │  ├─ 重点课程组排课均衡分布情况 → 课程排课情况抽屉（终点）
   │  └─ 重点课程时段热力图（本页切换课程组，终点）
   ├─ 教室占用
   │  ├─ 生成当前资源重点 → 教室资源研判抽屉（终点）
   │  └─ 楼宇实际占用负荷 → 楼宇实际占用信息抽屉
   │     └─ 已映射且观测负荷 ≥45%、记录数 ≥100 → 教室资源研判抽屉（终点）
   ├─ 教师负荷
   │  ├─ 生成当前负荷重点 → 教师负荷研判抽屉（终点）
   │  ├─ 负荷核查队列 → 教师教学负荷信息抽屉
   │  │  └─ 队列前 3 名 → 教师负荷研判抽屉（终点）
   │  └─ 职称维度教学任务、各学院教学负荷对比 → 本页聚合结果（终点）
   ├─ 调停课分析
   │  ├─ 生成当前调课重点 → 调课治理研判抽屉（终点）
   │  ├─ 教师调停课 TOP10 → 教师调课原因信息抽屉
   │  │  └─ TOP10 前 3 名 → 调课治理研判抽屉（终点）
   │  └─ 学院排名、原因分类、月度趋势 → 本页聚合结果（终点）
   └─ 课程结果
      ├─ 公共必修课重点关注 → 学期结果信息抽屉（终点）
      └─ 需要进一步核查的课程 → 学期结果信息抽屉（终点）
```

### 2.5 下钻终点

当前实现的终点如下：

- 开课供给与教师负荷的数据质量问题明细；

- 重点课程组的“课程排课情况”；
- 未达到资源研判门槛的“楼宇实际占用信息”；
- 非队列前 3 名教师的“教学负荷信息”；
- 非 TOP10 前 3 名教师的“调课原因信息”；
- 所有 规则研判抽屉；
- 课程结果的“学期结果信息”抽屉。



## 3. 全模块公共规则

### 3.1 当前工作身份与菜单准入

| 当前工作身份 | 教学运行明细范围 |
|---|---|
| 校领导、教务处、系统管理员 | 全校授权教学运行数据 |
| 教务处运行科、二级学院院长和二级学院教学秘书 | 本学院负责或开设的课程、教师和调停课明细；他院只能在授权页面看聚合比较，不得下钻 |
| 系/专业范围身份 | 仅在明确授权并能映射到开课组织时查看相应聚合或明细 |
| 普通教师、辅导员、班主任和导师 | 无权限 |

教室属于学校共享空间。学院用户可以查看楼宇、时段和活动类型聚合，但不得获得其他学院教师、课程或学生明细。



### 3.2 通用查询条件

1. 开课供给、排课结构、教室占用、教师负荷、调停课分析  共享父页面“统计学期”；

### 3.4 精度、单位和空值

- 人数、门数、班数、记录数和人次通常显示整数；
- 平均班额、通过率、观测负荷和占比保留 2 位小数；
- 分母为 0、分层修读类型没有记录或结果不适用时显示“—”，不能显示 `0%` 冒充已计算结果；
- “百分比变化”使用百分点，不使用相对增长率替代；
- “人次”允许同一人多次计入，“人数”必须明确去重对象。

###  7.3 数据质量预警

  数据质量预警内容包括 “数据质量排除信息” 和 "查看 N 条数据质量问题明细“ 内容；

#### 7.3.1 排除规则

-  统计学期、当前用户身份和查询条件范围内，对  教学班>200、学时>1000、课程>20 的教师 进行预警；只有存在异常教师时，才显示数据质量预警内容。


```text
排除异常= 命中教学班>200、或 学时>1000、或 课程>20
```

- 页面显示：黄色警示条「`已排除` + 动态教师数 N + `名教师异常记录`」。 如 ” **已排除 9 名教师异常记录**“
- 这些教师不进入KPI指标统计、职称统计、核查队列、学院对比和 研判。

#### 7.3.2 问题明细

   显示 N 条（N 名异常教师，和数据质量预警结果保持一致）数据质量问题明细数据，只可以查看，不可以修改。

- 问题明细表格字段：

| 字段     | 说明                                                         |
| -------- | ------------------------------------------------------------ |
| 学期     | 问题对应学期                                                 |
| 教师     | 教师姓名（工号）                                             |
| 问题说明 | 问题事实与识别原因  如 : **教学班数 527 超过阈值 200；学时 16144 超过阈值 1000；课程数 58 超过阈值 20** |
| 处置建议 | 建议信息；如 ：**核对源系统教师工号映射、课程合班及教学班生成逻辑；确认数据无误前继续排除统计。** |

问题明细按教师工号升序排列。

### 7.6 职称维度教学任务

- 功能说明：按当前用户身份范围、统计学期和查询条件统计，从职称维度对 教学任务（有有效教学任务且未被排除的教师）进行统计，且未被排除的教师。

- tooltip说明：仅统计当前学期及条件内有有效教学任务的教师；不计算在岗教师上课率

- 统计表格字段包括：职称、授课教师、中位学时、P90 学时、人均课程、人均教学班

- 统计规则

  - 职称按教授、副教授、讲师、助教、其他固定顺序生成，

  - 当前条件下人数为 0 的职称行不会显示




### 7.7 负荷核查队列

- 功能说明：对教师教学负荷比较高的教师进行核查（针对当前用户身份范围、统计学期和查询条件内的、已排除异常的教师）。

- 进入列表规则：教师总课时 `≥` 当前筛选范围 P90

- 显示数量：最多显示 10 人

- 排序方式：总课时降序 → 学生人次降序 → 教学班数降序

- 表格字段：`#（排名）`、教师、总学时、教学班、管理关注、操作

  - 教师：
    - 主信息：姓名
    - 辅信息：职称 · 学院
  - 总学时 = 当前学期该教师关联的所有有效教学班“总学时”之和 【同一课程有多个教学班时，每个教学班的学时分别累加。】
  - 教学班数= 当前学期该教师关联的不同教学班数
    - 同一门课程开设3个不同教学班，计3个教学班
    - 同一个教学班即使关联多个行政班，仍计1个教学班
  - 管理关注：
    - 重点关注（红色）：当前队列排名第 1～3 名
    - 需关注（黄色）：当前队列排名第 4～10 名
  - 操作：详情，或点击教师姓名
    - 点击教师姓名或「详情」进入 **教学负荷信息抽屉，详见第 7.9 节**



### 7.8 各学院教学负荷对比

- 功能说明：对各学院总体的教师教学负荷进行统计（针对当前用户身份范围、统计学期和查询条件内的、已排除异常的教师）。

- 排序方式： P90 学时降序 → 中位学时降序

- 表格字段：学院、授课教师、中位学时、P90 学时、人均课程、管理关注、相对负荷水平。
  - 相对负荷水平： 学院相对负荷水平 = 学院 P90 学时 ÷ 当前结果中最高学院 P90 学时 × 100%
    - 红色条：学院相对负荷水平>=80% ;
    - 黄色条：学院相对负荷水平>=60%；<80% ;
    - 绿色条： 学院相对负荷水平<60%
  - 管理关注：
    - 前 3 行标记「优先关注」；红色
    - 其余相对负荷水平 `>60%` 标记「需关注」；黄色
    - 其余为「常规」；灰色

### 8.5 按学院调停课率排名

- 功能说明：对当前身份权限范围以及查询条件下各学院调停课率进行统计分析。

- 表格字段信息：学院、教学班数、调停课次数、管理关注、调停课率。
  - 调停课次数：该学院下所有开课教学任务调停课记录总数
  - 调停课率：
    - 计算公式：该学院下所有开课教学任务调停课去重记录数 ÷ 该学院下所有的教学任务数（教学任务就是教学班）× 100%
    - 呈现方式：横向柱状图。
  - 管理关注：
    - 优先关注：前 3 行标记「优先关注」
    - 需关注：其余调停课率 `≥3%`
    - 常规：其余调停课率 `<3%`

- 排序方式：按调停课率降序排序；



### 8.6 调课原因语义分类

- 功能说明：对当前身份权限范围以及查询条件下各调课原因进行统计分析。
- 统计方式：饼状图
- 调课原因语义分类：按实际调课原因进行分类统计
- 页面饼图显示内容：语义类别、事件数和占比，如：**教学计划调整：103次（25.32%）**
- 排序方式：按事件数降序



### 8.7 教师调停课 TOP10

- 功能说明：对当前身份权限范围以及查询条件下，统计每位教师的调停课事件总次数。进入列表条件为总次数 `≥3`；最多 10 人
- 统计方式：数据列表
- 表格字段：教师、学院、次数、管理关注、主要原因。
  - 管理关注
    - 重点关注：排名前三
    - 需关注：其他排名
  - 主要原因：取该教师出现次数最多的原因
- 排序方式：按次数降序
- 点击 教师 行进入 调停课原因 抽屉。**详见 8.9章节**



### 8.8 月度调停课趋势

### 9.4 公共必修课重点关注

- 功能说明：展示 当前用户身份范围和查询条件范围内的，重点关注的公共必修课信息

- 排序方式：首次通过率升序 → 修读学生人次降序

- 表格字段：课程、修读学生人次、首次通过率、补考通过率、重修通过率、关注原因、操作

  - 字段说明：修读学生人次、首次通过率、补考通过率、重修通过率 计算公式说明

  | 字段         | 计算公式                                       | 补充说明                                                     |
  | ------------ | ---------------------------------------------- | ------------------------------------------------------------ |
  | 修读学生人次 | `Σ 每个纳入学期的去重修读学生数`               | 每个“课程×学期”内按学生去重；同一学生跨多个学期修读会按多个学生人次计算 |
  | 首次通过率   | `Σ首次修读通过人次数 ÷ Σ首次修读人次数 × 100%` | 首次修读包含普通修读、缓考及其他非补考、非重修记录           |
  | 补考通过率   | `Σ补考通过人次数 ÷ Σ补考人次数 × 100%`         |                                                              |
  | 重修通过率   | `Σ重修通过人次数 ÷ Σ重修人次数 × 100%`         |                                                              |

  ​	个通过率均按汇总分子、分母进行加权计算，不是各学期通过率的简单平均；结果保留1位小数。对应分母为0时，对应内容显示 `—`。

  - 字段说明：首次通过率 显示说明

    | 情况                                                   | 显示内容                                 | 颜色               |
    | ------------------------------------------------------ | ---------------------------------------- | ------------------ |
    | 有有效首次修读记录，且低于公共必修整体首次通过率       | 例如 `77.5%`，旁边显示红色“低于均值”标签 | 红色 `#E11D48`     |
    | 有有效首次修读记录，且等于或高于公共必修整体首次通过率 | 例如 `96.0%`，不显示标签                 | 青绿色 `#0D9488`   |
    | 首次修读人次数为0                                      | `—`                                      | 当前实现仍为青绿色 |

  - 字段说明：关注原因

    | 页面显示内容          | 内部类型       | 触发条件                                                     |
    | --------------------- | -------------- | ------------------------------------------------------------ |
    | `连续N学期>15%`       | 连续高未通过   | 至少有2个纳入统计的学期，并且每个学期的首次未通过率都严格高于15% |
    | `学期间相差N个百分点` | 学期间变化较大 | 至少有2个纳入统计的学期，并且最高与最低首次未通过率之差严格高于15个百分点 |
    | `累计未通过N人次`     | 影响面较大     | 筛选范围内首次修读、补考和重修的未通过成绩记录合计达到50人次及以上 |

    其中：

    ```
    学期首次未通过率 =（首次修读人次数－首次修读通过人次数）÷首次修读人次数 × 100%
    ```

| 成绩尝试 | 学生 × 课程 × 学期 × 尝试 | 成绩尝试 ID | 学生 + 课程 + 学期 + 尝试类型 + 尝试序号；发布 / 作废状态是过滤条件，不是去重键 |
| 修读学生 | 课程结果详情的单学期学生数 | 学期 + 课程 + 学生 ID | 同学期首次、补考、重修多条记录只计 1 名学生 |
| 数据质量问题 | 学期 × 规则 × 业务对象 | `issue_id` | 页面汇总按教师稳定 ID 去重；问题状态和影响记录数单独保留 |

聚合结果必须能回溯到上述稳定键。TOP、分页、导出、AI 证据和抽屉不得另行使用姓名、显示序号或前端行号作为业务主键。

### 10.4 跨页筛选一致性

- 开课供给、排课结构、教室占用、教师负荷和调停课分析共享顶部单学期；课程结果使用独立起止学期，不跟随顶部学期。
- 共享学期写入 URL；切换页签保留查询参数和已访问组件状态。不适用于目标页签的学院、楼宇、职称等局部条件只保留在原组件内，不得作为其他页签的隐藏过滤条件。
- 排课结构当前根据 `/admin/operation/data-context` 判断可用学期；所选学期不可用时使用该身份最近可用排课学期。页面、抽屉和指标必须统一显示实际学期，不能仍标记为请求学期。
- 开课供给的学期、学院、校区、课程性质、课程类别和班额档必须共同作用于 KPI、TOP10、学院表、性质分布、班额分布、数据质量数量和完整清单。关键词只用于完整清单，不反向改变首屏 KPI。
- 开课供给课程研判当前只传课程 ID 和学期。正式验收时，研判重算结果必须与打开入口的课程切片一致；若页面按校区或班额档只选中了课程的部分教学班，AI 不得静默改为该课程全量教学班。
- 教室资源研判继承学期、楼宇和“包含晚间”；楼宇详情继承当前页面汇总行。晚间开关关闭时，事件级指标、节次级指标和参考晚间总量必须分别说明是否受开关影响。
- 教师负荷当前切片研判继承学期、学院和职称；单教师研判继承教师 ID 和学期，并按服务端当前身份复核学院范围。学院表只聚合，不允许以学院行进入他院教师明细。
- 调停课当前切片研判继承学期和学院；教师原因抽屉及单教师研判必须继承教师 ID、学期、学院与授权范围，不能只按教师和学期读取跨学院事件。
- 课程结果的摘要、主表和“公共必修课重点关注”共用一次聚合结果。课程类别筛选会同时作用于公共必修区；选择非“公共必修”类别时，该区应为空，不存在“固定公共必修不受筛选”例外。
- 课程结果详情继承起止学期，区间两端均包含；课程类别由所选课程确定，不作为详情接口的二次筛选。当前页面只渲染成绩趋势。

### 10.5 排序、舍入和显示

- 排序使用未格式化原值，不能按带 `%`、单位或千位分隔符的字符串排序。
- 百分率和课程结果通过率默认保留 1 位小数；开课供给的学院占比、班额分布占比和平均班额当前按整数展示，文档和 Tooltip 必须明确这一页面差异。
- 阈值判断使用未舍入值，最后一步才格式化。`>15%` 与 `≥15%`、`>120` 与 `≥120` 不得因显示舍入而混淆。
- 当前既定主排序为：开课 TOP10 按关注分、选课人次、教学班数；完整课程清单按教学班数、选课人次；教师队列按总学时、学生覆盖、教学班数；学院负荷按 P90、中位数；学院调停课按调停课率；课程结果按命中原因数、未通过记录、首次未通过率。
- 每个排序必须增加稳定末级键：课程 ID、教师 ID、学院 ID 或楼宇标准名升序。分页前排序，不能在分页后只排当前页。
- `0` 只表示已确认有事实范围且结果为零；`—` 表示不适用、分母为零或无可计算结果；“暂无数据”表示当前条件没有事实记录；“未接入”表示数据域不存在；403 表示无权访问。五种状态不得互换。
- 页脚合计和分页总数按全部命中记录计算，不能只统计当前页。不同统计粒度不得为了对齐视觉数字而强行相加。

### 10.6 AI 与确定性指标一致性

AI 不负责发明或临时计算正式指标。页面接口与 AI 接口可以分别取数，但必须调用同一范围解析、异常排除、去重和指标函数；输入事实至少包含实际学期、对象稳定 ID、授权范围指纹、指标 ID、原始值、单位、分母、口径版本和数据时间。

当前 AI 响应通过统一归一化补充 `traceability.ruleVersion=AI-RULE-2026.07-v1`、数据源、生成时间、范围、阈值和生成方式。无已审核离线样例时，原先标记为 `ai_sample` 的确定性结果会归一为“规则研判”；只有命中带模型、提示词、生成时间和审核状态的策展样例时，才能标记为离线大模型样例。任何结果都不得伪装为实时外部模型调用。

以下一致性规则为验收硬约束：

1. 开课保障研判必须复用开课供给的异常排除和课程切片，不得把已排除教师或筛选外教学班重新计入。
2. 教室资源研判必须复用页面的观测负荷分母和晚间开关；不能在研判中称为正式全校利用率。
3. 教师负荷研判必须复用最近秩 P50 / P90、三项异常阈值和当前学院 / 职称范围；不得输出“达标”“超负荷”或绩效结论。
4. 调停课页面和研判必须共用同一原因分类字典、优先级和版本。当前页面 `keyword-rule-v1` 与 AI 端独立分类函数仍不一致，完成统一前不得宣称分类一致。
5. 单对象研判必须重新校验课程、楼宇或教师是否仍在当前身份范围；对象从范围移除后，不得继续返回缓存结果。
6. 课程结果当前没有页面 AI 入口；不得把其他 AI 专题输出误列为本页已实现功能。

2026 年 8 月 28 日对工作区开发库只读核查得到以下快照。它用于解释原型能力边界，不构成生产固定数据量、固定学期选项或验收基准值。

由此形成四项硬边界：

1. 排课结构所选学期不在 V2 覆盖范围时，必须同时显示“请求学期”和“实际排课学期”，不能静默替换。
2. 开课供给使用 V1 教学任务；其研判若补充 V2 排课时段，必须分别标注两个数据源和实际学期。缺少同学期 V2 片段时，只能使用 V1 同源供给事实。
3. 教室占用只有一个学期，不能计算跨学期变化；缺少权威可用教室分母时不能发布正式利用率。
4. 课程结果虽然时间跨度较长，但跨成绩制度、课程代码沿革或培养方案版本比较前必须完成可比性核验；不得用演示补齐方式伪造连续学期。

### 11.3 来源、时间与版本披露

`/api/admin/operation/data-context` 已能按当前身份返回六个数据域的可用学期、来源、证据等级、范围依据和时间控件类型。页面不能只在后台请求该接口而不向用户披露关键内容。

每个页签页头或紧邻查询区的位置必须展示：

1. 当前工作身份、范围类型和范围名称；
2. 请求学期或课程结果起止学期；
3. 实际数据学期，发生降级时同时显示请求值；
4. 数据覆盖起止期和当前切片是否有记录；
5. 数据更新时间或批次时间；无法取得时明确写“暂未提供”，不能以当前页面打开时间代替；
6. 物理 / 业务来源及证据等级，区分真实事实、真实事实推导、规则分类、离线样例和演示数据；
7. 指标口径版本、课程通过率版本、原因分类版本和 AI 规则 / 模型版本；
8. 数据不足、未接入约束和不可推断事项。

详情抽屉和研判抽屉必须继承实际学期、对象、范围和版本。若入口筛选发生变化，旧抽屉应关闭或重新加载。当前部分业务接口尚未返回统一的 `asOfTime`、指标版本和批次字段，页面也未渲染完整数据上下文；这些属于第 12.3 节的验收缺口，不能用文档描述替代实现。

### 11.4 权限边界

| 模块 | 全校身份 | 二级学院身份 | 其他受限身份与明细边界 |
|---|---|---|---|
| 开课供给 | 校领导、教务处、明确授权的系统管理员查看全校 | 按课程开课 / 责任学院查看本院明细；显式请求他院返回 403 | 没有可映射学院范围时返回空范围；不因菜单可见而扩大 |
| 排课结构 | 查看全校教学任务和排课片段 | V2 按权威开课组织映射过滤 | 辅导员、班主任、导师等非学院组织范围不得回退全校；当前接口返回空业务范围或拒绝 |
| 教室占用 | 查看共享空间聚合 | 可查看全校共享楼宇、时段和活动类型聚合 | 不提供其他学院课程、教师或学生明细；楼宇名称不是学院权限维度 |
| 教师负荷 | 查看全校教师任务聚合与明细 | 只查看本院教师和课程构成；学院比较若开放他院，只能是聚合且不能下钻 | 不得把人员—班级或导师—学生关系解释为教师所属学院权限 |
| 调停课分析 | 查看全校事件聚合与授权明细 | 查看本院事件和教师原因；跨院比较只能聚合 | 教师原因、AI 和直接接口都需按事件学院复核，不能只凭教师 ID |
| 课程结果 | 查看全校责任课程结果 | 按课程责任 / 开课组织查看本院课程结果 | 当前不是“本院学生修读课程”视角；若未来新增，必须作为独立口径和接口 |

通用权限规则如下：

- 一人多角色只使用“当前工作身份”解析范围；切换身份后，数据上下文、业务缓存、表格偏好范围、抽屉和 AI 结果必须刷新。
- 服务端先验证身份已授权，再验证对象稳定 ID 和请求筛选与授权范围的交集。显式越权对象返回 403 / 404；范围映射缺失默认拒绝或空范围。
- 菜单隐藏不是安全边界。直接 URL、业务 API、详情、未来导出、AI、证据链接和数据质量接口均需重新鉴权。
- 系统管理员的全校业务范围来自明确角色授权，不是“找不到范围时默认全校”。

### 11.5 适用边界

本模块只消费、分析和挖掘教务数据，不维护课程、教师、学生、教室等业务主数据，不回写教务源库。页面标签、TOP 和研判只用于确定核查顺序，不自动执行开班、停开、拆班、排课、调课、停课、补课、教室分配、工作量认定、教师评价或学生处置。

各页签还需遵守以下边界：

- 开课供给描述已发生的教学任务和班额，不证明未来需求、计划课程开出率或资源已满足。
- 排课结构描述一个已接入课表学期的星期 / 时段分布，不掌握教师可用时间、学生全量冲突、未来教学任务和正式可用教室约束，不能生成可执行排课方案。
- 教室占用描述已观测事件。没有权威可用教室清单、停用 / 维修 / 封闭日历、座位和到场人数时，不能解释为空闲率、座位利用率或可直接释放的资源。
- 教师负荷只统计本科教学任务学时。学校工作量办法、合讲拆分、实验实践折算、岗位标准、减免和非教学任务未接入前，不能认定达标、未达标或超负荷。
- 调停课只掌握历史源事件、原始原因和影响人次。审批层级、审核耗时、补课完成、通知到达和责任归因未接入前，不输出相关结论；频次不等于教师教学质量。
- 课程结果是结果事实，不等于教学原因。课程难度、考试等值性、教师与教学班差异、专业生源、成绩政策和课程改码未完成控制前，不用于教师个人排名或课程合格认定。
- 当前没有听课 / 督导数据；模块统一名称为“调停课分析”，不得写成“调听课分析”。

## 12. 异常、空态和验收规则

### 12.1 加载、空态与错误态

| 场景 | 页面要求 | 指标与研判要求 |
|---|---|---|
| 首次加载 | 使用骨架或明确加载状态；不得先闪现 0、全校数据、上一身份数据或上一页签数据 | 在响应确认数据域可用前，不生成指标或关注标签 |
| 已有结果后重新查询 | 可以暂时保留旧结果，但必须有“正在按新条件更新”遮罩；新结果成功后一次性替换 | 旧结果必须明确属于旧条件，期间禁用详情 / AI 或把请求绑定到旧快照 |
| 查询成功但无事实记录 | 显示“当前条件下暂无数据”，保留筛选和重置 | 只有已确认数据域可用、查询成功且统计对象存在时才显示 0；不得生成风险结论 |
| 数据域未接入 | 显示“该数据域尚未接入”和最近可用信息，不显示普通空表 | 不得把未接入解释为 0 或低风险 |
| 请求学期不可用 | 显示请求学期、实际可用学期、数据源和切换说明 | 所有卡片、图表、抽屉和 AI 统一使用实际学期 |
| 接口失败 | 持久显示错误摘要和“重新加载”；筛选仍可恢复 | 不得把旧结果冒充新条件结果，也不得以 0 覆盖失败 |
| 快速连续查询 | 只接受最后一次有效请求；取消或丢弃较早响应 | 早期响应不得覆盖后选条件 |
| 权限不足 | 返回 403 或等效拒绝状态；不以“暂无数据”掩盖越权 | 不生成任何对象、聚合、导出或 AI 证据 |
| 登录失效 / 身份切换 | 清理业务缓存、打开的抽屉和 AI 结果；重新按新身份取数 | 旧范围指标和本地缓存不得继续显示 |
| 对象映射缺失 | 显示“待映射”并保留原值或来源行；进入只读质量核查 | 不参与学院 / 楼宇 / 教师评价，不触发正常资源结论 |
| 分母为零 | 显示 `—`，Tooltip 说明“无可计算分母” | 比率阈值不触发；不能显示 0% |
| AI / 规则研判失败 | 业务页面继续可用，抽屉显示失败和重试 | 保留确定性事实；不得生成空泛风险结论或伪造模型来源 |
| 抽屉对象已失效 | 关闭抽屉或显示“对象不在当前范围” | 不继续展示缓存证据；服务端重新鉴权 |

### 12.2 参数与数据质量校验

- 学期必须来自对应数据域的后端可用选项。格式非法返回 400；数据域没有该学期时，只允许按第 12.1 节显式降级或返回无覆盖状态。
- 课程结果起始学期不得晚于结束学期；两端均为包含关系。课程类别只允许“公共必修、专业必修、选修、实践、其他”。
- 分页偏移量不小于 0，页码不小于 1；每页条数应采用 DataTable 统一选项并受后端上限约束。分页前完成权限、过滤和稳定排序。
- 学院、教师、课程和楼宇筛选必须使用稳定 ID 或标准值，并与当前授权范围求交集；显式越权不能静默变为空结果。
- 人数、人次、课时、容量、节次、星期、月份、事件数、分子和分母不得为负；星期限定 `1～7`，节次超出学校字典时进入质量核查。
- 教学任务异常只使用当前确认的三项阈值：教学班数 `>200`、学时 `>1000`、课程数 `>20`。排除数量和明细数量必须在当前学期、学院、职称 / 课程切片内一致。
- 教室事件按 `occupancy_id` 去重；时序与楼宇分子分别按“教室 + 日期”和“教室 + 日期 + 节次”去重。重叠事件保留问题数量，不重复抬高利用分子。
- 调停课必须校验 `kind` 只为“调课 / 停课”，`change_id` 唯一，原因原文保留；无法分类的原因进入“其他待核验”。
- 成绩尝试类型必须经过受控映射。当前开发库有效记录只出现 `regular/makeup/retake`；后续出现未知类型时，不得因现有 SQL 的兜底条件静默计入首次修读。
- 课程性质、课程类别、重点课程组、职称、活动类型和原因分类使用版本化字典；未知值进入“其他 / 待映射 / 待核验”，同时保留原值和来源。

至少使用校领导/教务处、两个不同二级学院、两个不同辅导员或班主任、两个不同导师和系统管理员账号回归：

2. 二级学院查看本院课程、排课、教师、调停课和责任课程结果明细；获准的跨院信息只以聚合形式展示，不能下钻他院。
3. 教室占用按学校共享空间聚合展示，不暴露其他学院课程、教师或学生明细。
4. 辅导员、班主任和导师没有学院业务对象映射时，课程 / 排课接口返回空范围或拒绝；学生关系权限不能转换成全院权限。
5. 手工修改 URL 中 `semester`、`college`、课程 ID、教师 ID、楼宇、起止学期、课程类别、分页偏移量不能越权或绕过校验。
6. 直接调用开课、完整清单、排课、教室、教师、调停课、数据质量、课程结果详情和全部 AI 接口均重新鉴权。
7. 同一教师跨学院承担任务时，调停课原因抽屉和研判只返回当前授权事件范围；同一课程跨组织开课时，研判只返回当前授权教学任务。
8. 切换当前工作身份后，旧抽屉、旧 AI 结果、数据上下文、请求缓存和本地表格偏好范围不能泄露旧身份数据。
9. V2 组织映射不完整、权限关系失效或对象移出范围时返回空范围、403 或 404，不回退全校。
10. 审计日志记录用户、当前身份、接口、查询范围、对象、数据时间、响应结果、指标版本和 AI 规则 / 样例版本。

### 12.6 性能与可用性验收

- 页面容器先请求轻量数据上下文；未激活页签不发业务请求。开课供给首屏不同时加载完整课程清单；课程结果首屏只发一次摘要 / 清单聚合请求。
- 首次加载、重新查询、详情和研判均有独立响应状态；正式时延目标由部署环境性能基线确认，不能以隐藏加载状态掩盖慢查询。
- 教室占用缓存键至少包含学期、楼宇、晚间开关和导入批次签名；涉及业务权限的数据缓存还必须包含范围指纹。
- 快速切换学期、学院、楼宇、职称、课程类别、页码时，只接受最后一次响应；失败后重试使用当前条件。
- 图表 Tooltip、表格标签、键盘焦点和状态文案不能只靠颜色；热力图应能读出星期、节次 / 时段、数值和口径。
- 1366 × 768 及常用大屏下无关键操作遮挡，抽屉内容可滚动；长课程名、学院名、教师名和原因原文省略时提供完整 Tooltip。
- DataTable 的身份列和操作列不可隐藏，中间业务列遵守显示上限；列偏好按用户、当前身份和表格版本隔离。
- 导出当前未作为六页签已实现功能。后续开放时必须复用当前筛选、实际学期、稳定排序、权限和口径版本，并记录审计。

### 12.7 交付门禁

文档验收后，功能交付至少执行：前端生产构建、教学运行相关后端契约与权限测试、后端完整测试、端到端数据与权限检查、六页签浏览器回归和 `git diff --check`。

验收证据至少包含：

- 六类身份的页面和直接 API 正向结果；
- 两个学院、两个班级关系、两个导师关系的反向隔离结果；
- 六个数据域的请求学期、实际学期、数据源、版本与批次截屏 / 响应；
- KPI 与表格 / 图表复算样本，至少覆盖正常值、零值、分母为零、无记录、未接入、403、接口失败和快速切换；
- 开课、教室、教师负荷和调停课研判与页面事实一致性样本；
- 课程结果 30 条样本门槛、严格 `>15%`、`≥50`、`≥30` 和分母为零边界样本。

每个教学管理分析模块完成走查、修改和验收后，还必须在同一次模块交付中同步《本科教学分析与学业决策支持平台需求调研及指标口径确认书 V2》的指标名称、计算逻辑、管理用途、数据来源、适用边界和页面核查路径。仓库版本确认后再覆盖外部交接目录；未同步确认书或第 12.3 节仍有阻断项时，不得把教学运行分析标记为最终完成。
