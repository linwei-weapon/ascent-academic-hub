## 1. 本轮最终结论

- 数据大屏、学业预警、教学运行、培养质量、师资保障、学生学业分析、学生档案和管理决策专题均已形成可运行原型。
- 前端生产构建通过；核心页面浏览器回归无控制台错误、无错误提示、无残留加载遮罩。
- 端到端脚本覆盖鉴权、数据范围、指标公式、下钻、预警治理、V2教学与师资等契约。
- 相邻学期画像现包含“改善、稳定、恶化、变化分化、数据不足”五类；最终核对已把“变化分化”纳入分类合计和下钻验证。

## 2. 已验收的关键用户路径

1. 数据大屏：全校—学院—专业—课程—学生名单—学生详情，平均分为学分加权口径并补充 GPA。
2. 学业预警：真实学校数据—顶层卡片即时筛选—我的待办—学生详情—历史预警—跟进与状态；规则配置和规则自发现同一工作页。
3. 教学运行：课程 TOP 与完整目录、实际教室占用、晚间开关、调课原因分类与教师 TOP10、教师负荷 TOP10、重点课程排课分析。
4. 培养质量：学院—年级—专业—方案联动、毕业要求与执行证据、模块完成规则、学生进度详情抽屉。
5. 师资保障：管理指标、学院核查抽屉、课程团队年龄/职称/单点风险、教师实际排课偏好。
6. 学生学业：GPA 与挂科联合迁移、历史挂科模式、学生核查抽屉、统一成长轨迹。
7. 学生档案建议：按五类受众提供确定性建议；历史高挂科率课程明确提示学习难度并披露依据。
8. 管理决策专题：五个专题均围绕“发现问题—确定对象—查看证据—进入核查”组织页面。

## 3. 生产系统必须替换或补齐的能力

| 领域 | 原型做法 | 生产要求 |
|---|---|---|
| 培养方案 | Word 表格临时解析 | 教务 API 提供版本化方案、模块、课程组、最低学分/门数、替代和毕业要求结构 |
| 学生选课 | 以成绩、认定和方案推导当前未完成 | 接入选课轮次、退补选、应选未选、教学班容量和重修班资源 |
| 成绩口径 | 已区分真实记录并提供首次/最终通过等分析 | 学校签版补考、重修、缓考、缺考、替代、最终有效成绩规则 |
| 教室资源 | 实际占用记录用于时序与楼宇分析 | 接入全部占用行为、标准节次、可排除事件类型和教室状态；平台不维护主数据 |
| 师资档案 | 教学任务、课程团队和已有职称信息 | 接入完整出生日期、职称历史、在岗状态、所属组织历史和团队责任角色 |
| 预警处置 | 原型已有责任人、跟进和受控状态 | 是否建设完整帮扶闭环、消息推送和批量任务由产品决策后立项 |
| AI建议 | 确定性证据模板，不调用外部模型 | 明确部署方式、匿名化、留存、事实约束、人工确认和离线评估后才能启用模型 |

## 5. 明确暂缓范围

- 考风考纪、出勤：学校尚未提供可靠数据，不进入当前专题。
- 例外规则治理：当前产品阶段不建设。
- 教室可用数量维护：本平台仅消费和挖掘数据，不承担管理维护。
- 多校同步、实践教学、外部大模型、完整预警帮扶闭环：待生产范围和数据条件确认。

## 6. 交接完成定义

后续开发团队接收时，应同时取得代码基线、数据字典、API 契约、ETL 映射、指标口径、权限矩阵、容量部署方案和本验收清单。任何指标上线前必须能回答：数据从哪里来、如何计算、谁能看到、如何下钻核查、数据不足时如何降级。
