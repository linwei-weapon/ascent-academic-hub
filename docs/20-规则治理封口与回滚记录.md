# 规则治理封口与回滚记录

## 旧接口封口

旧接口 `PUT /api/admin/settings/rules/{rule_id}` 已停止直接更新生产规则，统一返回 HTTP 410，并提示调用方改用规则变更单流程。

这意味着阈值调整和规则启停不能再绕过以下步骤：

1. 创建变更草稿；
2. 执行影响试算；
3. 提交审核；
4. 非创建人审批；
5. 发布规则配置；
6. 候选预警受控激活。

## 回滚机制

已发布变更单可以根据 `previous_snapshot` 创建回滚草稿。回滚不会直接覆盖生产规则，而是生成一张新的、可审计的变更单。

回滚草稿仍需重新完成影响试算、提交、审批和发布，避免紧急回滚成为新的绕行入口。

限制条件：

- 只有 `published` 状态且具有上一版本快照的变更可以回滚；
- 同一规则存在未完成变更单时禁止创建回滚；
- 快照损坏时拒绝自动回滚；
- 回滚记录保存原发布变更单编号。

## 页面变化

已发布变更单增加“创建回滚单”操作。创建后生产规则保持不变，用户可在变更单列表中继续完成试算和审批。
