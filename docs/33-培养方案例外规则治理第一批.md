# 培养方案例外规则治理第一批

## 已完成

- 新增例外规则变更单和审计轨迹数据表。
- 建立 `draft → submitted → approved/rejected → activated` 状态机。
- 教务处处长、教研科可创建并提交变更单。
- 质量办负责审核，校领导负责最终激活。
- 激活前的规则不会写入生效表，也不会改变学生合规结论。
- 激活后按规则类型写入课程替代、学生学分认定或课程组规则表。
- 新增变更单列表、详情、创建、提交、审核和激活接口。
- 新增“例外规则治理”页面，支持新建草稿、提交、审核、激活及查看审计轨迹。
- 补齐校领导对“培养质量分析”菜单的访问权限。

## 安全与审计

- 后端逐动作校验角色，前端按钮隐藏不是权限控制的唯一依据。
- 变更原因和规则参数均在创建时固化。
- 创建、提交、审核、激活分别写入审计轨迹。
- 激活操作向用户明确提示会立即影响学生合规计算。
- 专项测试只走驳回分支，并在结束后清理临时变更单，不向生效规则表写入测试数据。

## 验证结果

- 数据库迁移成功。
- Python 编译检查通过。
- 前端生产构建通过。
- 专项测试通过：角色越权拦截、草稿提交、审核驳回、审计链完整性。
- 原有 80 项回归保持通过。
