# P2 统一权限上下文实施记录

> 实施日期：2026-07-19
> 对应设计：`docs/84-P2权限现状审计与统一模型设计.md`

## 1. 本轮完成内容

### 1.1 系统库权限关系

新增并接入：

- `sys_user_role`：账号的多个工作身份、默认身份、有效期、状态和来源。
- `sys_user_scope`：身份级学院、专业、行政班或教师范围。
- `sys_user_staff`：统一身份账号与学校人员工号映射。
- `sys_role_action`：角色的页面动作能力上限。

原有11个账号已迁移为11个默认工作身份；原有6条角色范围已复制为6条用户身份范围。迁移脚本连续执行两次，数量保持一致。

### 1.2 统一权限上下文

登录和`/api/auth/me`现在返回：

- 当前工作身份；
- 合法身份列表；
- 菜单权限；
- 动作权限；
- 明细范围；
- 聚合比较范围；
- 字段策略；
- 范围授权状态；
- `scopeFingerprint`。

受限身份缺少有效范围时标记为未授权，旧库学生、学院和专业查询返回空范围或403，不再按全校放行。

### 1.3 V2与AI

- V2学生范围优先从统一权限上下文解析。
- V2范围必须把当前用户身份的每个源范围完整映射到真实编码；部分映射不会降级为更大范围。
- AI学生研判、管理要情和决策模拟优先复用统一上下文。
- 管理要情和决策模拟缓存键已纳入`scopeFingerprint`。
- 学院教学任务范围按开课组织映射；专业、班级等当前无法稳定映射到教学任务的范围返回空供给，不使用全校数据补位。

### 1.4 当前工作身份

新增`POST /api/auth/switch-identity`：

- 只能切换到当前账号的有效身份；
- 切换后重新返回菜单、动作和数据范围；
- 记录切换前后身份和范围指纹审计；
- 前端请求通过`X-Active-Identity`传递当前身份；
- 多身份用户在顶部显示身份选择器，单身份用户保持简洁标签；
- 顶部同时显示当前数据范围。

## 3. 安全边界

- 系统管理员、校领导和教务处通过明确的`all`身份获得全校范围。
- 其他身份没有范围时默认拒绝。
- 请求头中的身份必须属于当前账号，否则返回403。
- 菜单权限不代替数据权限。
- 身份切换不签发更高权限，只重新选择账号已经拥有的有效身份。
- AI和缓存不能扩大权限。

## 4. 当前数据限制

1. 现有真实库没有辅导员—行政班关系表，当前辅导员仍使用迁移后的三个演示班级范围。
