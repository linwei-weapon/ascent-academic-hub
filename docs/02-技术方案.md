## 1. 总体架构

```
┌─────────────┐   HTTP /api/* (vite proxy)   ┌──────────────┐
│  前端 Vue3   │ ───────────────────────────► │ 后端 FastAPI  │
│  :3006       │ ◄─────────────────────────── │ :8000        │
│  Element/ECharts            {code,msg,data} └──────┬───────┘
└─────────────┘                                      │ raw sqlite3 只读
                                                     ▼
                                        ┌────────────────────────┐
                                        │ analytics.sqlite (33表) │  ← 星型分析库
                                        │ dim_/fact_/agg_/sys_    │
                                        └───────────▲────────────┘
                                                    │ ETL（一次性重建）
                                ┌───────────────────┴───────────────────┐
                                │ datasource/构造数据 9 学期源库 + 2 培养方案 docx │
                                └─────────────────────────────────────────┘
```

四层职责分离（对齐真实数据中台姿势）：

1. **贴源层**：`datasource/构造数据/*.db`（9 个按学期分文件的业务库，不可变）+ 2 份培养方案 docx。
2. **ETL 层**：抽取 → 清洗 → 派生 → 规整，产出星型库。`code/backend/etl/`。
3. **分析库层**：`analytics.sqlite`，`dim_/fact_/agg_/sys_` 命名，所有业务表带 `semester_id` 与 `source`。
4. **服务层**：FastAPI 只读查询 + 菜单级鉴权，前端按维度筛选展示。

### 接口约定

- 路径前缀 `/api/admin/...`，健康检查 `/api/health`。
- 统一响应包络：`{ "code": 0, "msg": "ok", "data": ... }`。成功 `code=0`。
- 错误：`ApiError(msg, code=, status_code=)`，其中 `code` **镜像 HTTP status**（如 401/404/400），
  前端/e2e 读 `body.code` 判错。新增 `raise` 必须同时传 `code` 与 `status_code`。
- 鉴权：登录返回 JWT；受保护接口校验 Bearer token；按角色返回可见菜单。
- 维度筛选：多数列表接口接受 `semester` 等 Optional 入参，空参不加 WHERE（返回全量/默认学期）。

## 4. 前端目录与数据流

```
code/frontend/
├── .env                   ← VITE_PORT=3006、版本号、权限模式等
├── vite.config.ts         ← dev server :3006 + proxy /api → :8000（mockPlugin 已停用）
└── src/
    ├── views/             ← 页面（admin/* + Login.vue）
    ├── store/auth.ts      ← 登录态、可见菜单
    ├── utils/             ← meta.ts(维度缓存)、export.ts(CSV/打印)、http
    ├── constants/colleges.ts ← 真实学院码 C01-C16 共享
    └── router/index.ts    ← hash 路由表
```

- 数据流：页面用 native fetch / http 封装请求 `/api/admin/...`，vite proxy 转发到后端 :8000，
  读 `d.data`。
- 维度下拉统一从 `GET /api/admin/meta/filters` 单拉 + 进程内缓存（`utils/meta.ts`）。
- 下钻跳转透传 `?semester=`，详情页据此对齐学期。

> `vite.config.ts` 内保留了一份历史 `mockPlugin`（阶段3 起已停用、注释掉），仅离线调试用。
> 正式运行经 proxy 走真实后端。

## 5. 性能要点

- 预聚合 `agg_*` 表在 ETL 阶段算好，查询直读，避免现算大表。
- 关键索引（schema.sql §4.5）：`fact_grade(lesson_id,semester_id)`、`fact_lesson(teacher_id,semester_id)`
  等。教师详情查询从 60s 优化到 0.14s 即靠这些索引。
- `fact_grade` 64 万行，所有跨表 JOIN 均走 semester_id + 实体 id 复合索引。

## 6. 安全与边界

- 只读连接，杜绝写入分析库（迁移脚本除外，仅改 sys_ 元数据）。
- CORS 演示环境放开（`allow_origins=["*"]`，`allow_credentials=False`）——生产需收紧。
- 全局异常兜底不向前端泄漏堆栈（仅打服务端日志）。
- 密码 pbkdf2_sha256（10 万次迭代 + 16 字节盐）。
