# 02 · 技术方案

## 1. 总体架构

```text
浏览器（Vue 3 / Element Plus / ECharts）
        │ HTTPS / JWT / 当前工作身份
        ▼
FastAPI 业务与统一权限层
        ├─ 教学管理分析 API
        ├─ AI 管理专家与研判 API
        ├─ 系统管理与审计 API
        └─ 统一权限上下文、范围过滤、缓存
        │
        ├─ analytics.sqlite（现有原型分析库）
        └─ analytics_v2.sqlite（真实数据接入验证库）
                ▲
        ETL / 学校数据交换平台 / 教务 API
```

生产系统建议保持“数据接入—标准模型—指标服务—权限服务—业务应用—AI研判”分层，
原型 SQLite 可替换为学校认可的关系型数据库、分析数据库和缓存服务。

## 2. 技术选型

| 层 | 原型实现 | 生产替换方向 |
|---|---|---|
| 前端 | Vue 3、TypeScript、Vite、Element Plus、ECharts | 保留；接入学校门户与统一前端规范 |
| 后端 | Python、FastAPI、Pydantic、JWT | 保留或按学校技术体系重构 |
| 数据库 | SQLite 双库 | PostgreSQL/MySQL＋分析引擎 |
| 数据接入 | ETL、Excel/Word临时解析、真实源库 | API、数据交换平台、批流同步 |
| AI | 管理专家协议、确定性指标＋模型样例 | 学校批准的云端或私有模型 |
| 部署 | 本机/私有云 | 反向代理、HTTPS、日志、备份和监控 |

## 3. 两类业务能力

教学管理分析使用预设页面稳定呈现指标、趋势、表格和证据下钻。AI管理决策复用相同事实和
权限上下文，以管理专家定义问题、数据需求、排序逻辑、可调参数和输出卡片。

大模型只负责意图理解和解释；正式指标由后端注册公式计算。自然语言调整属于临时会话参数，
保存为学校分析方案后仍需测试、发布、角色覆盖和版本治理。

## 4. 统一权限架构

登录后生成 `permissionContext`：

```text
账号
 └─ 当前工作身份（角色）
     ├─ 菜单权限
     ├─ 页面动作权限
     ├─ 详细数据范围
     ├─ 跨组织聚合比较范围
     └─ 字段与导出策略
```

范围来源包括组织授权和人员关系。学院用户可在指定页面查看他院聚合比较，但不能下钻他院
学生明细。辅导员、班主任、导师按有效人员关系取数；范围缺失默认拒绝，不回退全校。

## 5. 后端结构与接口

```text
code/backend/api/
├─ main.py                 FastAPI入口、中间件、静态资源
├─ deps.py                 登录、管理员、V2连接
├─ permission_context.py   工作身份与统一权限上下文
├─ permission_catalog.py   动作权限登记
├─ security_governance.py  密码、限流、撤销令牌和审计
└─ routers/
   ├─ dashboard/alert/operation/curriculum/faculty/students
   ├─ ai.py / ai_experts.py
   ├─ admin_rbac.py
   ├─ system_management.py
   └─ v2.py
```

- 统一包络：`{code,msg,data}`。
- 业务接口前缀：`/api/admin`；真实数据验证接口：`/api/v2`。
- JWT 携带登录主体，`X-Active-Identity` 表达当前工作身份。
- 缓存键必须包含角色、范围指纹、学期、专家版本和参数版本。
- 迁移脚本只修改平台元数据和派生结构，不回写学校源系统。

## 6. 前端结构

```text
code/frontend/src/
├─ router/                 路由与准入
├─ store/                  登录、角色、身份和范围
├─ views/admin/            三个一级分组下的业务页面
├─ components/             业务上下文、加载态、指标卡、抽屉
└─ utils/                  HTTP、AI、导出、筛选元数据
```

三类页面状态必须统一处理：加载/计算中、无数据或证据不足、无权限。详情优先使用抽屉或弹窗，
避免跳离当前业务上下文。

## 7. 性能与安全

- 大表使用学期＋业务主键复合索引；高频管理指标使用预聚合。
- 管理要情和决策研判使用范围感知缓存；数据、身份或版本变化时失效。
- 密码使用 PBKDF2-SHA256、随机盐和强密码策略；支持登录限流与令牌撤销。
- 学生名单、详情、导出、权限变更和 AI 运行进入审计。
- 生产环境收紧 CORS、启用 HTTPS、统一身份认证、最小权限数据库账号、备份和监控。
- 密钥、数据库口令和统一身份认证密钥由部署环境管理。
