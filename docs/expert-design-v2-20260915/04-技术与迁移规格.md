# 技术与迁移规格

版本V2，2026-09-15。依据独立技术审查和根代理已核实代码汇总。以下是目标技术契约，不是现有数据库、接口或测试已完成的声明。

## 1. 关键决策与现有差距

研究事项与专家解绑，一研究一主对话；同研究一个主动运行，跨研究按服务容量执行。研究切换不停止运行，身份切换则切断旧结果展示并重新鉴权。

范围、资料、规则和实际参与专家按轮次冻结。运行期间新增或移出专家只对后续生效，界面说明本轮参与关系未改变。个人意见、输入草稿、研究元信息与参与列表分别管理版本。

已核实：expert_team.py的catalog声明structured且未启用开放模型；174行起达80条消息要求另开；181—190行禁止同会话更换expert_id。前端index.vue的249、316—327行草稿与sessionStorage，337行按expertId缓存，423行按expertId/planId认定讨论，457行保存，473—475行下载前核验并导出txt。

保留受控场景、正式指标、统一权限、冲突保护和旧入口。必须补建研究容器、参与关系、可靠运行、独立版本、长历史、可追溯小结和材料快照。自然语言与获批模型是单独验收项，不以聊天界面冒充已完成。

## 2. 数据模型与字段约定

以下模型为建议设计，可按现有命名规范实现，不要求复制另一套业务事实库。

### 2.1 Research

id、owner_user_id、work_identity_key、title、status(active/archived)、current_scope_snapshot_id、latest_summary_version_id、latest_opinion_version_id、metadata_revision、created_at、updated_at、last_activity_at、legacy_session_id、migration_version。

研究默认是本人、对应合法工作身份的研究，不自动共享给其他领导。归属不代替当前授权；列表标题和摘要也可能敏感，查询前鉴权。

### 2.2 ScopeSnapshot

保存专业/学院/年级/学期、培养方案ID与版本、对象类型与安全服务器引用、数据日期及批次、有效成绩规则、比较和公共课/选修池/匹配/去重口径、范围指纹、创建人和时间。

范围快照不可变。学生集合是敏感信息，不进入普通前端日志或完整提示词日志。权限快照用于说明生成背景，不成为后续永久授权。

### 2.3 ExpertDefinition与ResearchParticipant

专家定义：expert_id、名称、职责、版本、启用状态、场景、资料条件、输出契约、规则与权限要求。参与关系：research_id、expert_id、加入版本/时间/方式、active/removed、最近贡献轮次。

参与列表使用participants_revision。加入与本轮执行分开；停用或移出保留历史贡献和方法版本。

### 2.4 ResearchTurn、AnalysisRun、ExpertContribution

轮次：turn_id、research_id、递增序号、用户问题、client_request_id、scope_snapshot_id、发起身份、指定补充事项、run_id和时间。

运行：run_id、research_id、turn_id、冻结的scope/source/metric/rule/expert版本、status、started_at、finished_at、heartbeat_at、工作租约、重试次数、取消时间、失败类型及结果适用性。

贡献：实际专家与版本、分配问题、状态、结构化结果、来源、限制及不同意见。汇总只列实际参与者，不以部分成功伪装完整共识。

### 2.5 SourceReference

来源类型/标识/版本、数据时间、页段或表行定位、规则与计算口径、权限类别、与具体判断的关联。来源分类至少分正式记录、正式资料推导、用户补充和演示。

历史模型输出和研究小结不是正式数据来源；用户补充不自动升级为学校业务事实。

### 2.6 ResearchSummaryVersion

摘要版本、覆盖至哪一轮、生成时间、已明确/未明确/分歧/比较结果、逐项来源与轮次、适用范围和资料变化提示。小结是进展索引，不替代原记录；仅根据有效完成结果更新。

### 2.7 InputDraft与OpinionVersion

输入草稿：research_id或未发送草稿标识、owner/identity、text、input_revision、updated_at。个人意见：opinion_id、research_id、opinion_revision、作者、正文、引用轮次、保存时间、来源(用户编辑/确认采纳)、上一版本及恢复关系。

研究标题、聊天、参与者更新不应导致个人意见无关冲突。自动保存过程版本可合并管理，但明确采纳、恢复和材料引用的版本必须可追溯。

### 2.8 MaterialSnapshot与ExportRun

快照保存主题、范围、数据时间、指定小结与意见版本、方案对照、待确认事项、来源清单、权限标签、模板版本、创建人/时间、内容哈希。导出记录状态、文件标识和快照引用。

材料不可变，重新整理产生新版本，不沿用旧URL偷偷替换内容。应用能控制后续下载，不能承诺撤回用户已经下载到设备的文件。

## 3. API与事件契约

建议新增独立版本路由，如/api/expert-research/v2，实际命名与项目规范统一，不覆盖旧接口行为。

| 操作 | 建议契约 |
|---|---|
| 新建/分页列研究 | POST/GET /researches |
| 读取/改名/归档 | GET/PATCH /researches/{id} |
| 历史游标分页 | GET /researches/{id}/turns?before=cursor&limit=... |
| 全部授权研究搜索 | GET /researches/search?q=...&cursor=... |
| 参与者查询/新增/移出 | /researches/{id}/participants |
| 提交问题/定向补充 | POST /researches/{id}/turns |
| 查看/停止运行 | GET /runs/{id}、POST /runs/{id}/cancel |
| 资料定位 | GET /source-references/{id} |
| 输入草稿 | GET/PATCH /researches/{id}/draft |
| 个人意见/版本/恢复 | /researches/{id}/opinion及/versions |
| 创建/预览材料 | POST /researches/{id}/materials、GET /materials/{id} |
| 导出与授权下载 | POST /materials/{id}/exports及受控下载接口 |

提交分析携带client_request_id、expected_scope_version、文本、请求类型、指定参与者和必要版本。服务端返回turn_id、run_id；前端不凭当前专家推断归属。

保存元信息、参与者、输入和意见分别携带对应expected_revision或If-Match。409冲突返回可处理的信息，不能吞掉用户内容；权限错误不泄露被拒资源细节。

状态事件至少含event_id、research_id、run_id、序号、类型、时间及安全上下文引用。支持开始、实际阶段变化、贡献完成、结果可用、失败和取消确认。事件不是唯一存储；断线按最后序号补取并从正式接口恢复，轮询可作兼容方案。

## 4. 运行、幂等、取消与并发

### 4.1 普通问题与联合回答的处理约定

统一入口依次处理：服务端身份与范围检查→识别问题类型、对象与意图→必要澄清→在允许专家和场景中确定主答及分工→调用受控计算或资料检索→校验结构化结果→形成一份围绕问题的回答→持久保存轮次与来源。正式数字由计算结果字段插入，不让模型重新口算或改写。

首次无参与者可根据明确意图匹配一位主答，开始状态明示并保存参与关系；后续普通问题仅安排已加入且相关的专家。需要未加入专家时返回补充建议，不隐式执行。定向问题带指定expert_id及用户发送确认，不允许客户端借该字段越过专家启用状态或功能授权。

建议的意图结构包括问题类型（事实说明/业务分析/比较/质疑补充/意见整理）、场景ID、对象引用、范围引用、需要澄清的条件、主答与补充职责。模型输出只能映射已注册场景及白名单工具，不执行任意SQL、脚本或资料中的命令。不支持的问题用能力说明承接，不伪装已调用工具。

联合任务共享同一事实计算引用。互不依赖的贡献可以后台并行；需要前序结果的贡献按依赖执行。这是实现选择，不暴露为领导需要配置的操作。结果校验包含范围/版本一致、指标定义一致、来源可定位、必填字段、权限及资料支持程度。

回答契约至少包含直接判断、管理含义、相关事实与metric_ref、逐项source_ref、可比较做法、重要条件、下一步操作及实际参与者。不是所有字段每次都占一张卡片。结果必须区分资料未齐、规则未齐与执行失败。出现实质分歧时列出分歧点和适用条件，不让汇总模型投票制造一致。

意见编辑和来源解释在无需重算时不重新执行全套专家分析；用户修改假设或范围后需新轮次，不能仅改一段解释却保留旧数字。该链在开放模型未获批时只允许现有明确支持的结构化入口，不承诺任意自然语言匹配。

### 4.2 状态、幂等与并发

运行状态：queued→running→completed/partial/failed；queued或running可进入cancel_requested→cancelled。结果业务状态另列，运行完成不表示规则完整或能够作正式判断。

幂等键约束为用户＋研究＋操作＋client_request_id；重复同内容返回原运行，同键不同内容返回冲突。轮次、运行与待执行事件事务创建，避免已发送却无任务。

重要运行不能只绑在一次HTTP请求或浏览器连接上。若没有任务基础设施，采用运行表、工作租约和独立后台执行器即可，不必先引入大型分布式平台。异常恢复有检查点和有限重试，不无限重复模型调用。

取消有先后裁定：若取消先被服务端接受，迟到结果不得发布为正式完成；若先完成，返回已完成，不伪造取消成功。局部有效结果可保留，但未完成内容不自动更新小结或意见。

A运行时切B，结果只写A并轻提示，不抢B焦点。范围改变后旧运行仍属于旧范围，不刷新当前范围小结。身份变化必须在数据访问及发布前重新校验，不能只靠前端epoch。

同研究一次一个主动运行；忙时可编辑草稿、切换研究、查看资料。首版不隐式排队多个新问题。跨研究按容量并发，超限真实显示等待，不编造百分比。

## 5. 长研究与上下文

取消80条强制另题的产品约束，改为稳定游标分页、授权全文检索、小结索引和必要片段读取。搜索不只覆盖前端最近50条。

当次模型上下文与完整历史存储分开。小结记录覆盖轮次与引用，正式数字取可信计算或重算，不从自然语言摘要反推。对象歧义才具体澄清，不以猜测混用上一项研究。

资料、历史回答和用户补充均作为内容，不能改变系统权限、规则和工具指令。资料变更后保留旧版本，小结不将旧判断和新资料拼成虚假的同一轮。

## 6. 个人意见与材料安全保存

自动保存使用独立opinion_revision，只有服务端成功才显示已保存。输入草稿也独立input_revision。网络失败保留内容，不默认明文持久存储敏感材料。

多窗口冲突保留双方内容，提供比较、合并、另存；不最后写入覆盖。恢复旧版本作为新版本写入。系统建议修改先预览，明确采纳后才更新意见。

材料读取指定意见与分析版本，生成不可变快照。导出前重新校验范围、新鲜度和当前授权；资料已变化时提示，不悄悄换数字。没有个人意见不制造领导观点，有未完成分析不写成完整共识。

## 7. 权限与审计

沿用现有统一专家团功能准入与实际身份范围，不复制角色白名单。教务处全校与学院本院明细分开；跨院仅用获准聚合服务。系统管理员及其他身份按既有明确授权，不因其他AI菜单自动开放。

启动、计算、读取结果、历史、小结、来源、意见、材料、事件和下载均鉴权。研究归属和生成时权限不等于永久可读。标题与通知也可能敏感，不先发给前端再隐藏。

角色或范围缺失默认拒绝。当前身份不匹配时不显示旧缓存，引导合法身份切换后重验。权限撤回时运行在关键访问和发布前检查，前端保护不能代替服务端。

下载链接即使短时有效也需受控；不能留下永久公开文件绕过权限。日志不默认存学生明细、全文提示词或敏感材料，审计记录操作人、身份、资源版本、范围标识、操作和结果。

## 8. 迁移、灰度与回退

旧会话一对一迁移为研究，原expert_id成为首位参与者，保留消息顺序、实际范围和已保存意见；不按相同专业、专家或相近标题合并。

建立唯一legacy_session_id映射，迁移可重复，未知范围和版本标缺失不编造。浏览器未提交草稿不自动当作正式意见。保留原记录，核对数量、顺序、来源、版本和权限。

新工作区、多专家参与、自然语言理解、材料导出分别设能力开关，与后端实际开放一致。先在授权测试范围用成熟专业比较走通，再扩展其他专家和角色，原有计算共用。

回退关闭新写入和入口时保留新数据及合法只读入口，不把新多专家研究强压回旧session。优先加表和兼容字段，首轮不删除旧结构。不重置唯一数据库，提供可重复迁移和回退脚本。

## 10. 技术测试矩阵

覆盖同专家多研究、专家增删和停用历史；双击和网络重试、断线、执行器中断、取消竞争和局部失败；A切B、改范围、旧响应、刷新；选修池、同代码同名称、有效成绩和资料版本；超过80条、分页检索和旧轮次来源；意见保存失败、冲突、部分采纳和恢复；材料旧版本及下载撤权；跨院聚合/明细、身份切换；文档夹带指令、缺规则索要名单、演示数混入；重复迁移、缺范围和回退。

工程检查按实际范围运行前端构建、后端相关测试、数据与权限端到端、diff检查和旧模块回归。设计文件不记录未执行的通过结果。

## 11. 高风险清单与交接条件

重点防止：按expertId缓存串研究；取消只停动画；全局revision打断意见；旧事件和下载漏权；摘要推测固化为事实；领导补充改写正式来源；专家各算一套；新标题套旧数据；浏览器暂存冒充服务端已保存；回退后新内容失联；聊天外观掩盖模型未接通；资格表达超出规则支持。

交接必须具备研究/运行归属、独立版本、来源和权限依赖、迁移映射、失败恢复及验收用例。完成标准是同一研究能开始、分析、质疑、补充、保存、离开、恢复和整理材料，不是侧栏和聊天框能显示。
