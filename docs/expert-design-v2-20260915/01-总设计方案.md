# 专家团研究工作区完整设计方案 V2

日期：2026-09-15。阶段：设计评审与研发交接准备。任务编号：UX-EXPERT-V2。

本方案由业务场景、页面交互、技术实现三个独立子任务审查后统一。本文是总设计，业务、交互、技术、验收和视觉附件共同构成完整交付，不能只实施本文的页面骨架。

## 1. 产品定位与范围

专家团是教务处领导和二级学院领导持续研究管理问题的工作区。主要服务平时独立研究，次要服务会前材料准备。用户管理经验强、信息化操作相对弱：应降低操作和寻找信息的负担，不降低业务内容的深度。

核心结构：一事一研究，一项研究一条主对话，专家按需加入，分析有清楚依据，个人意见独立保存，成果可以复看和整理。

保留原决策简报、原专家分析和专家问策入口。本次不调整其他业务页面，不回写教务源库，不自动执行审批、录取、课程认定、开课、推免或毕业决定。

不建设项目看板、督办、人员分工、截止日期或专家配置平台。多任务在界面上使用“我的研究”，而不是要求领导学习任务编排。五类专家是首批能力，不是永久固定的五个导航页。

## 3. 本方案统一的设计决定

| 编号 | 最终推荐决定 | 理由 |
|---|---|---|
| D01 | 研究事项是保存、切换、搜索、归档的主体 | 用户找回的是管理问题，不是某个专家页面 |
| D02 | 每项研究只有一条主对话 | 同问题跨专家不反复交代背景 |
| D03 | 场景是后台可靠能力单元，不是必经的25个按钮 | 用户可以直接提出管理问题 |
| D04 | 加入专家不立即分析 | 保存参与关系与启动工作是两种动作 |
| D05 | 点专家名称只查看职责 | 不形成用户未察觉的回答模式 |
| D06 | 定向补充先填入输入区，发送后执行，本轮有效 | 补充对象和问题可见、可修改、可取消 |
| D07 | 同一研究一次只执行一轮，忙时可编辑草稿与切研究 | 避免尚未完成的结论被下一轮误用 |
| D08 | 移出专家影响后续，本轮参与快照不变且明确提示 | 不静默取消工作，也不删除历史贡献 |
| D09 | 左栏默认展开，右侧默认关闭 | 首次容易理解结构，空间优先给阅读讨论 |
| D10 | 资料与个人意见共用一个辅助面板，比较放主区域 | 不叠出多个窄面板，不把宽表塞进侧栏 |
| D11 | 添加专家使用居中选择窗 | 不抢走正在编辑的个人意见 |
| D12 | 研究小结是可追溯进展索引，个人意见独立版本 | 系统总结不代替领导判断或原始资料 |
| D13 | 新资料、新范围形成新轮次，不改写旧结果和材料 | 保留判断变化的原因 |
| D14 | 权限检查覆盖标题、摘要、历史、运行事件、资料与导出 | 不能只保护当前数据页面 |
| D15 | 回退保留新数据与只读历史，不把多专家记录压回单专家会话 | 避免回退后找不到个人意见与材料 |

## 4. 研究对象与内容关系

一项研究围绕一个相对完整的管理问题。同一问题比较共同课程、专业训练和课程共建，应保持一项研究；转去研究本届毕业准备，应新建研究。

| 对象 | 内容与职责 |
|---|---|
| 研究事项 | 主题、目的、对象、当前范围、长期状态、归属 |
| 讨论轮次 | 提问、冻结范围、实际参与专家、资料和规则版本、结果与处理状态 |
| 研究小结 | 已明确、未明确、分歧、下一步，以及对应轮次和来源 |
| 我的意见 | 用户自己的判断与取舍，独立编辑和保存 |
| 相关资料 | 正式记录、原文、受控推导、用户补充或演示的明确标识 |
| 材料快照 | 某一时点的小结、意见、方案对照与来源，后续分析不回写 |

新研究不自动继承上一项的学生、专业、年度和意见。只继承当前合法身份及明确组织范围。相关问题需要另开研究时，由用户选择带入问题摘要和必要引用。

## 5. 从问题到成果的完整闭环

提出问题 → 明确必要范围 → 初步判断 ↔ 查看资料、质疑补充、比较做法、请专家补充 → 个人意见（可选）→ 讨论材料（可选）→ 以后复看。

这是工作关系，不是强制步骤条。领导可以先看依据，可以反复比较，也可以看明白后直接结束。结论先呈现是阅读顺序，不是先编结论再找理由。

| 阶段 | 页面行为 | 留下的内容 | 合理退出 |
|---|---|---|---|
| 开始 | 直接输入问题，少量业务例子辅助，不先填专家配置 | 首次发送后建立研究与建议标题 | 空白不生成大量任务；未发送草稿可恢复 |
| 明确范围 | 只补问会影响结果的专业、版本、学期等 | 明确且可见的范围 | 可取消，不改变原有效范围 |
| 初步分析 | 先说明判断、管理含义、主要依据与条件 | 一轮有范围和来源的结果 | 看明白即可离开，自动保留 |
| 深入 | 查资料、改口径、补充专家、比较做法 | 新轮次和前后差异 | 关闭面板返回原阅读位置 |
| 形成意见 | 选取或自行编辑，系统改写先预览再采纳 | 独立版本的个人意见 | 保存失败保留文字并明确提示 |
| 整理材料 | 选择内容和意见版本，预览后保存/下载 | 时点材料，不虚构决定 | 可取消，不发送给他人 |
| 复看 | 恢复原位置，提供最新进展与新资料提示 | 连续研究及变化原因 | 可归档，可恢复 |

## 6. 页面结构与阅读秩序

默认布局：原系统菜单｜我的研究与本次专家｜主阅读讨论区。右侧资料/意见按需打开。

左栏上部为新建、搜索、近期研究、归档；下部是本次参与专家和添加入口。不把任务、专家、场景、结果混成多层树。

主区域顶部显示研究标题和简短范围说明，提供查看资料和我的意见。小结以紧凑可展开入口呈现；首轮重点仍是实际回答，不再堆一张重复说明大卡片。

数字跟随相关判断，不设常驻数字信号墙。正文、图表和方案对照服务当前问题，不展示与本轮无关的综合指标。

左栏收起后仍可切研究、查看参与者和添加专家。进入资料面板直达相关原文或记录，关闭后恢复触发段落和焦点。资料与意见切换时保留编辑内容，不打开第二层侧栏。

宽表方案比较留在主区域。工作区不足以同时保证正文可读时，右侧采用覆盖面板，不擅自改变用户的左栏偏好。较窄窗口的左栏采用抽屉。

视觉延续白底、浅灰和克制紫色。正文约16px，主要阅读宽度约640—820px作为测量起点；左栏约220—240px、辅助面板约340—380px。最终以目标窗口和125%缩放验证，不把建议值当已验证结论。

输入框默认约四行，增长到约八行后内部滚动。回车换行，Ctrl+Enter可发送；中文输入法组合状态不得误发。重要操作有文字，不依赖悬停或颜色。

## 7. 专家业务体系

五类专家的25场景详见业务分册，每场景都定义领导问题、输入、处理逻辑、输出形式、下一步和资料不足处理。

| 专家 | 核心管理问题 | 主要结果 |
|---|---|---|
| 专业建设 | 共同基础是否合理，培养差异落实在哪里，如何调整 | 分层对照、特色支撑、衔接问题、方案影响 |
| 课程质量建设 | 哪些课程值得建设、问题在哪、如何改进和观察 | 建设重点、事实与原因边界、做法比较、变化说明 |
| 转专业 | 来源学习如何衔接目标要求，补修与教学保障如何安排 | 目标要求覆盖、缺口、约束、教学影响，不是录取决定 |
| 保研 | 年度规则、条件与资料准备是否清楚 | 条件说明、计算依据、待确认事项及方案影响，不冒充正式名单 |
| 毕业资格审核 | 审核准备、条件缺口和记录问题在哪里 | 准备与条件对照、共性问题、变化原因，不自动认定资格 |

专业建设的课程结构相近原则上对称；转专业的目标要求覆盖具有方向。不得共用一个相似度排行榜。候选最多2—3个，说明可比范围；资料不足不凑数。

同代码重合不能直接推导教学内容重复、专业同质化或共建必要性。共建前先确认是否已经共开，以及培养任务是否相同。培养目标写有特色不等于实际培养效果；原文没有明确支撑关系时，模型推议关系只能作为待讨论内容。

## 8. 数据、判断与领导质疑

优先整理已有培养方案原文，保留页段定位、版本及冲突。未结构化不等于没有资料；但方案规定、实际教学、学生完成情况是三个层次，不能相互替代。

正式数字沿用经确认后端口径。必修、选修课程池、有效成绩、重复修读、认定与学分分配分别处理，不把未知当0，不把未知对象从分母悄悄删除，不重复累计同一成果。

回答讲清：目前可判断什么、为什么、对管理意味着什么、还有什么条件。没有依据时不强行给积极建议，也不只用数据不足终止研究。

领导说“这门课已经共同开设”时：记录为领导补充→定位原资料→说明影响哪项判断→允许在明确假设下继续→保留待确认事项。若旧分析确有错误，标明已修正及原因，不静默删除，也不回写源库。

资料时间、范围变化、规则更新分别提示。方案测算、正式计算、用户补充和演示始终可辨识。推免、转专业、毕业与学位规则不完整时，不输出正式资格或执行结论。

## 9. 保存、运行与恢复原则

研究元信息、输入草稿、个人意见、小结与材料分别管理。新增一条聊天或改标题不应制造个人意见保存冲突。

同一研究只有一轮主动分析，输入仍可编辑；不同研究可按容量后台执行，超限显示真实等待状态。研究切换不取消运行，身份切换则切断旧身份展示并重新校验。

每轮冻结范围、专家和资料。移出专家只影响后续；已开始轮次仍保留其参与说明。范围草稿可以先编辑，但必须明确停止后新分析或待本轮完成，不能就地改写运行参数。

取消分请求停止和已停止；迟到内容不得更新为正式完成结果。部分完成清楚区分成功与失败贡献，不声称所有专家已共同确认。

长期历史分页与搜索，研究小结保留引用，正式数字从正式计算读取，不从自然语言摘要反推。恢复时不无条件跳到底部：同次切换恢复原位置，较久后打开提供继续上次位置和查看最新进展。

意见保存需服务端确认才显示已保存。冲突保留两份内容，支持比较、合并或另存。新分析和新资料只提示可能影响的段落，不覆盖领导文字。

## 10. 权限与材料

沿用既有专家团功能授权，目标用户仍为教务处领导和学院领导。系统管理员及其他身份按项目既有明确授权处理，不因其他AI菜单权限自动开放新能力，不复制新的角色白名单。

二级学院只读本院授权明细，跨院使用已批准的聚合能力。历史标题、小结、来源、运行事件、材料和下载都需当前授权；本人创建不意味着永久可读。

个人研究材料先预览再保存，不虚构领导意见、会议参加者、审批结果或执行决定；没有个人意见也能整理研究材料，但不能自动写成领导结论。

材料固定研究范围、来源时间和意见版本。新分析不改写已有材料；重新整理生成新版本。下载再次鉴权，不提供永久绕过权限的文件链接。
