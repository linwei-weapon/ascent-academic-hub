# 预警闭环第一批实现记录

> 完成日期：2026-07-11

## 已实现

- 保留 `fact_alert` 作为规则引擎计算结果；
- 新增 `alert_event`，保存独立处理状态；
- 新增 `alert_assignee`，保存主责任人和分派原因；
- 新增 `alert_followup`，保存人工联系、约谈和帮扶记录；
- 新增 `alert_status_history`，保存状态流转审计；
- 新增幂等迁移脚本，将 5,027 条现有预警初始化为事件；
- 演示环境按辅导员角色初始化 5,027 条主责任人关系；
- 新增事件详情、添加跟进和更新状态接口；
- 所有新接口复用学生数据范围，院级、班级和教师角色不能越权；
- 预警列表返回事件编号、闭环状态、主责任人和最后跟进时间；
- 预警详情抽屉支持查看责任人、添加跟进、更新状态和回读记录；
- 修复预警抽屉学业统计摘要字段映射；
- 修复挂科溯源授课教师字段映射；
- 明确跟进数据保存在平台，不回写教务源库。

## 状态集合

- 待处理 `new`
- 已分派 `assigned`
- 已通知 `notified`
- 已联系 `contacted`
- 帮扶中 `supporting`
- 待复核 `review_pending`
- 已解决 `resolved`
- 已关闭 `closed`

## API

- `GET /api/admin/alert-events/{event_id}`
- `POST /api/admin/alert-events/{event_id}/followups`
- `PUT /api/admin/alert-events/{event_id}/status`

## 当前限制

1. 演示库只有一个辅导员账号，当前初始化分派是角色级占位；下一批需要建立辅导员—班级关系后精确分派。
2. 现有摘要卡仍部分使用 `fact_alert` 的历史模拟状态，下一批应统一改为 `alert_event.workflow_status`。
3. 暂未实现批量分派、转派、通知已读和超期提醒。
4. 暂未限制状态流转路径，例如已解决事件仍可回退；下一批需要状态机校验。
5. 外部短信、邮件、企业微信不在本批范围。
