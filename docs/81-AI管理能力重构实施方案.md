# AI管理能力重构实施方案

## 1. 重构目标

本次重构不继续增加AI卡片数量，而是把AI能力从“对每个对象生成说明”调整为“帮助管理者发现少量重点、解释优先顺序、明确核查动作、比较候选方案”。

重构后的AI能力必须回答五个管理问题：

1. 发生了什么值得关注的变化；
2. 为什么该事项比其他事项更需要先看；
3. 影响哪些学生、课程、专业或学院；
4. 当前角色首先应核查什么；
5. 结论基于哪些数据，哪些部分仍存在不确定性。

原型阶段不新增预警工单和干预闭环，不自动执行开班、排课、课程认定、预警处置或教师评价。AI只输出管理研判、建议责任角色、建议时点、核查清单和候选方案。

## 2. 总体设计原则

### 2.1 异常驱动

AI不再作为所有表格行的标准操作。普通对象使用“详情”或“核查证据”；只有满足管理介入条件的对象才显示“AI重点”或进入统一AI重点清单。

### 2.2 变化优先

有历史快照时，AI首先解释新增、恶化、改善和持续未处理；没有历史快照时，明确标注“当前仅有单期证据”，不得使用“恶化、改善、持续上升”等趋势性结论。

### 2.3 角色聚焦

- 教务处：跨学院、跨专业、公共课程、资源统筹和制度性问题；
- 二级学院：本学院学生群体、专业执行、集中问题课程和学院可行动事项；
- 教学运行人员：开课、排课、教室、调课、教师负荷和课程保障；
- 学生个体：仅在授权用户下钻到学生范围后呈现，不在校级首屏平铺。

### 2.4 证据与建议分离

事实数据、规则判断、AI解释和人工核查要求分别标注。证据不足的事项只能标记为“优先核验”，不能直接输出高风险定性结论。

### 2.5 少而可行动

一个AI研判首屏最多展示：1条管理结论、3条关键变化、3条关键证据、1个首要动作和2个备选动作。管理要情首屏最多展示3项重点事项。

## 3. AI介入判定框架

### 3.1 介入状态

所有AI场景统一返回以下状态之一：

| 状态 | 含义 | 页面处理 |
|---|---|---|
| `action_required` | 证据充分且存在明确管理动作 | 显示“需优先核查”并允许打开管理研判 |
| `verification_required` | 影响可能较大，但关键证据缺失或口径待核对 | 显示“优先核验”，不得输出确定性风险结论 |
| `watch` | 尚未达到介入阈值，但值得持续观察 | 仅显示观察标签，不在普通表格提供AI按钮 |
| `no_intervention` | 当前无明显管理介入价值 | 不显示AI入口，详情中可说明“当前无需AI介入” |

### 3.2 管理优先级

管理优先级用于同一场景内排序，不跨不同业务场景直接比较原始指标：

`优先级 = 影响范围×35% + 时间紧迫度×25% + 恶化程度×20% + 可行动性×20%`

- 影响范围：去重学生数、涉及专业数、涉及学院数或受影响教学班数；
- 时间紧迫度：距选课、开课、排课、毕业审核等管理节点的时间；
- 恶化程度：相对上一快照或上一可比学期的变化；
- 可行动性：是否能明确对象、课程、责任角色和可核查证据。

证据充分度单独计算，不计入优先级。证据充分度不足时，即使影响范围较大，也只能进入“优先核验”。页面默认不展示抽象综合分，只展示排序原因。

### 3.3 首批场景介入条件

| 场景 | 进入AI重点的条件 | 不应触发的情况 |
|---|---|---|
| 学业预警 | 严重等级、较上次升级、多个风险叠加、临近关键培养节点且存在明确课程问题 | 已解决且无新增风险、单一低等级提醒、仅有静态低GPA |
| 毕业准备 | 高年级必修明确未通过、到期缺证据集中且可形成核验清单、课程供给形成瓶颈 | 只有未来学期课程、仅因数据未接入形成的泛化缺口 |
| 课程运行 | 多学期持续偏高、影响学生规模较大、波动超过阈值且有可比基线 | 单学期小样本、仅按未通过人数排名 |
| 教室资源 | 高峰持续拥挤与低谷长期闲置并存、特殊空间形成实际瓶颈 | 单个时段一般性占用差异 |
| 调课治理 | 原因聚类显示制度性或资源性集中问题、教师或课程连续异常 | 单次正常调课 |
| 教师负荷 | 明显超出同类可比范围、跨学期持续、与课程保障风险叠加 | 仅因承担一门课程或单个教学班触发 |
| 师资保障 | 高影响课程缺少备份能力、团队结构缺口与未来开课需求叠加 | “一门课一名教师”这一正常事实本身 |

## 4. 统一AI管理研判数据契约

后端AI接口逐步统一返回以下结构：

```json
{
  "intervention": {
    "status": "action_required",
    "label": "需优先核查",
    "priority": "high",
    "priorityReasons": []
  },
  "decision": {
    "headline": "一句话管理结论",
    "whyNow": [],
    "impactScope": "影响范围",
    "consequence": "暂不处理可能产生的管理影响"
  },
  "evidence": [],
  "primaryAction": {
    "role": "建议责任角色",
    "action": "首要核查动作",
    "timing": "建议时点",
    "expectedResult": "预期形成的核查结果"
  },
  "alternativeActions": [],
  "comparison": {
    "baseline": "比较基准",
    "changes": [],
    "available": true
  },
  "traceability": {},
  "limitations": []
}
```

旧接口中的`summary`、`reasons`、`suggestions`和`nextActions`在迁移期保留兼容映射，所有新页面优先使用新结构。

## 5. 页面改造方案

### 5.1 AI管理研判抽屉

首屏顺序固定为：

1. 介入状态、对象、分析范围和数据时点；
2. 一句话管理结论；
3. “为什么现在看”——最多3条变化或异常；
4. 首要核查动作——责任角色、建议时点、预期结果；
5. 关键证据——最多3项；
6. 备选动作；
7. 折叠的完整口径、来源和使用边界。

当状态为`no_intervention`时，不生成长篇内容，只显示当前未发现需要AI介入的事项以及可查看的基础证据。

### 5.2 业务列表AI入口

- 删除普通表格逐行AI列；
- 在已有“详情/核查证据”弹窗内，对满足条件的对象显示“查看AI管理研判”；
- 页面顶部只在存在AI重点时显示“AI发现X项需优先核查”；
- 点击后打开当前范围的重点清单，默认最多10项；
- 已解决、无变化或未达到阈值的对象不进入重点清单。

### 5.3 AI管理要情

“AI管理晨报 / 学期简报”更名为“AI管理要情”，提供“本次新增、本周重点、学期态势”三个视角。

建立内部分析快照和管理事件，不写回教务业务数据：

- 快照记录各专题的统计时点、范围、关键指标和重点对象摘要；
- 管理事件记录新增、升级、改善、退出和持续未处理；
- 同一根因和对象进行聚合，避免重复生成；
- 无显著变化时显示“本次更新无新增重大事项”；
- 首屏只展示Top3，每项包含变化、影响、建议动作、责任角色、建议时点和证据入口。

### 5.4 AI决策模拟

改为五步引导：

1. 选择管理问题；
2. 查看当前基线和系统推荐理由；
3. 设置该场景必要约束；
4. 对比候选方案的覆盖、剩余问题、资源成本、实施难度和不确定性；
5. 形成候选决策单并进入对应专题核查证据。

首批实现：

1. 毕业准备——先核验还是先开班；
2. 课程支持——有限资源优先投入哪些课程；
3. 师资保障——有限备份能力优先保障哪些课程。

排课资源场景在前三个场景稳定后接入。取消不可解释的综合得分，所有方案使用同一组可比结果指标。

## 7. 最终验收指标

1. 普通业务表格不再普遍出现逐行AI按钮；
2. AI重点列表默认不超过10项，管理要情首屏不超过3项；
3. 每条AI结论均有分析范围、数据时点、业务来源和使用边界；
4. 趋势性结论均有明确比较基准，无基准时不输出趋势判断；
5. 每条需介入事项均有首要动作、建议责任角色、建议时点和预期结果；
6. 证据不足的事项标记为“优先核验”，不输出确定性风险结论；
7. 相同数据重复计算时不生成新的管理变化；
8. 管理要情使用预计算或缓存后目标首屏响应不超过2秒；
9. 决策模拟参数重算目标响应不超过1秒；
10. 所有AI能力均保持辅助决策定位，不自动形成正式业务结论。
