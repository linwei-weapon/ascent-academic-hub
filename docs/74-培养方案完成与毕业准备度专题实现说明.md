# 培养方案完成与毕业准备度专题实现说明

## 1. 专题目标

帮助教务处和学院区分“已有明确未通过证据的必修课”与“当前数据尚无完成证据的课程”，提前准备课程资源与毕业审核核验，不代替学校正式毕业、学位审核。

## 2. 数据覆盖

原型使用 2022 级完整专业培养方案，当前覆盖 52 个方案、2376 名学生。培养方案中包含大量选修候选池，因此不能用方案全部课程数作为每个学生应完成的课程数。

## 3. 核心口径

- 明确需处理：培养方案必修课存在明确未通过成绩，可进入重修、跟班修读和开课资源核查。
- 待核验候选缺口：必修课尚无通过、认定或明确失败证据。由于缺少完整选课过程和部分认定数据，只能进入核验队列，不能称为漏选。
- 必修证据完整：当前接入记录中必修课均有通过或认定证据，不等同毕业审核通过。
- 必修证据完成率：已有通过或认定证据的必修课程数 / 方案必修课程数。选修候选池不进入分母。

## 4. 已实现能力

- 接口：`GET /api/v2/topics/graduation-readiness`。
- 页面：`/admin/reports/graduation-readiness`。
- 支持组织、专业、方案、准备度状态的接口筛选以及 V2 数据范围控制。
- 展示方案覆盖、明确需处理学生、待核验学生、必修证据完整学生及平均必修证据率。
- 分析专业、方案模块、必修课程的缺口集中度。
- 提供学生准备度名单、分页、学生档案下钻和原路返回。

## 5. 管理使用方式

1. 先处理“明确需处理”队列，核查高频必修未通过课程是否有后续开课或重修资源。
2. 对“待核验”队列按专业和模块批量核查选课、替代、免修及成绩认定数据。
3. 对高年级学生优先核验，但不在原型中直接生成毕业结论。
4. 学生档案中的角色化建议用于沟通提示，正式修读安排仍以教务系统为准。

## 6. 生产系统补充数据

- 完整选课过程：选中、退选、免修、缓修、重修报名与容量。
- 培养方案课程组规则：最低门数、最低学分、任选范围、互斥与替代。
- 毕业与学位审核规则版本、审核批次和人工调整记录。
- 完整课程认定、校外交流学分、转专业方案衔接。
- 新学期教学任务、重修班、跟班修读名额和报名条件。

生产系统应以规则引擎输出“证据与待核验项”，由毕业审核流程形成最终结论，并保留口径版本和审核追踪。

原型当前对约 74 万条学生方案课程状态进行实时聚合，首次专题查询约需 20 秒。生产系统必须建设按数据批次、口径版本、学生、专业和方案预聚合的专题快照或物化视图，并通过增量任务刷新；不得直接照搬原型的实时全表扫描。
