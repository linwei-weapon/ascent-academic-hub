# 63 · V2 后端查询接口说明

> 状态：原型验证接口；数据库只读；前缀`/api/v2`。

| 接口 | 用途 |
|---|---|
| `GET /api/v2/health` | V2数据库和批次健康检查 |
| `GET /api/v2/students/difficult` | 困难学生分页列表和标签筛选 |
| `GET /api/v2/students/{student_id}/growth` | 学生基本信息、成长指标、标签、时间线和毕业结果 |
| `GET /api/v2/students/{student_id}/plan-courses` | 学生方案课程状态、候选缺口和可行动缺口 |
| `GET /api/v2/courses/offerings` | 单学期课程开设统计 |
| `GET /api/v2/courses/{course_id}/team` | 单门课程团队和职称结构 |
| `GET /api/v2/teachers/{staff_id}/schedule-preference` | 教师历史实际排课时段分布 |
| `GET /api/v2/rooms/summary` | 教室资源及楼宇可用数量 |
| `GET /api/v2/curriculum/management-overview` | 当前权限范围的方案覆盖、正确绑定和执行核查总览 |
| `GET /api/v2/curriculum/management-courses` | 按明确未通过学生数提取必修课程保障优先项 |
| `GET /api/v2/curriculum/management-students` | 方案执行学生名单及服务端真实分页 |
| `GET /api/v2/curriculum/plans/{plan_id}` | 方案结构、可信模块规则、课程池和毕业要求原文 |
| `GET /api/v2/curriculum/progress/{plan_id}` | 复用统一摘要的学生模块进度 |
| `GET /api/v2/curriculum/course-supply/{course_id}` | 明确缺口课程的历史开课、教师和替代证据 |
| `GET /api/v2/topics/graduation-readiness` | 毕业准备与课程保障专题 |
| `GET /api/v2/topics/graduation-readiness/student/{student_id}` | 学生培养方案执行证据详情 |

所有接口使用现有统一响应：`{code,msg,data}`。

## 2. 数据库隔离

- 现有接口继续读取`analytics.sqlite`。
- V2接口读取`analytics_v2.sqlite`。
- V2连接使用SQLite只读模式`mode=ro`。
- V2接口不提供写操作，不修改原始数据、规则或分析结果。

## 3. 权限边界

V2已经建立现有原型范围代码到真实组织、专业和行政班的显式映射。当前6条范围配置全部映射成功：

- 校领导；
- 教务处处长；
- 教务处运行科、教研科、实践科；
- 质量办/评估中心。

- 学院院长、教学秘书：原型学院代码`C01`映射为V2组织代码`233`（人工智能学院）；
- 系主任：原型专业代码`M042`映射为V2专业代码`08002`（计算机科学与技术）；
- 辅导员：`B0360/B0363/B0364`映射为三个2021级计算机行政班名称。

这些范围已并入统一 `permissionContext`。接口同时校验当前工作身份、详细范围、对象归属和
动作权限。学院可以在指定比较接口查看他院聚合，但不能获得他院学生明细；范围缺失默认拒绝。

## 4. 关键口径

- `not_completed`必须展示为“截至当前成绩和认定记录尚无完成证据”，不能显示为“漏选”。
- `is_actionable=1`当前只表示培养方案必修且存在明确有效未通过成绩。
- 方案执行统一按`student_plan_module_status`和`student_plan_progress_summary`读取；模块规则顺序为可信最低学分、最低门数/选择组、逐门必修。
- 应绑定学生只包括其年级和专业存在已接入适用方案者；方案源未覆盖年级不进入绑定率，错配绑定不参与正式进度。
- 模块最低学分大于该叶子模块全部课程记录学分时视为不可信的临时提取结果，回退到门数或逐门必修规则。
- 当前学习学期动态推导，当前学期本身不计为逾期；到期缺结果只作数据候选。
- 课程保障优先项只来自模块尚未达到且存在明确未通过必修证据的课程；单一教师、无替代或历史无开课不单独触发风险。
- 教师排课偏好是历史实际结果分布，不是教师主动填报。
- 教室默认分母是可用、非虚拟且座位数大于0的房间。
- V2学生详情只返回展示姓名和必要学业字段，不返回证件、联系方式和地址。

## 5. 测试结果

- V2路由覆盖健康、困难列表、成长详情、方案课程、培养方案执行、毕业准备、开课、课程团队、教师排课和教室资源。
- 培养方案模块新增构建器单元测试，覆盖当前学期、错配绑定、规则优先级、选择组、替代学分、跨工作区一致性和真实分页。
- 使用真实V2数据库完成函数级烟雾测试，接口统一返回`{code,msg,data}`并执行对象和范围鉴权。
- 已纳入完整后端测试与端到端契约检查；具体数量以当前自动化运行结果为准，不再在文档中固化过时数字。

## 6. 生产切换原则

1. 继续补齐稳定人员工号、辅导员/班主任带班和导师带生权威关系。
2. 按页面逐项对账 V2 与旧接口，不做一次性无回退切换。
3. 学生、课程、教师和教室详情继续使用统一对象鉴权。
4. 旧接口只作过渡兼容，生产结构以版本化 V2 模型和学校 API 为准。
