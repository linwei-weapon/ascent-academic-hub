# 01 · 需求说明

> 产品名称：本科教学分析与学业决策支持平台
> 产品形态：面向高校本科教学管理的响应式 Web 数据消费、分析与决策支持平台。

## 1. 建设定位

平台汇聚成绩、学籍、培养方案、课程、教学任务、排课、教室、教师和人员关系等数据，
形成统一指标、证据下钻、学业风险识别和 AI 管理研判能力。

平台不替代教务系统，不维护学校业务主数据，不自动执行排课、开班、课程认定、毕业审核、
教师评价或学生工作处置。所有正式结论以学校业务审核为准。

## 2. 目标用户与权限

| 用户 | 业务范围 | 主要价值 |
|---|---|---|
| 校领导 | 全校 | 掌握教学运行、培养质量和重点风险 |
| 教务处 | 全校 | 发现问题、确定优先级、进入证据核查 |
| 二级学院 | 本学院明细；指定页面可看他院聚合 | 核查本院专业、课程、教师和学生 |
| 辅导员、班主任 | 有效带班关系内学生 | 关注学生学业风险与成长变化 |
| 导师 | 有效带生关系内学生 | 关注所带学生培养进度与课程表现 |
| 系统管理员 | 全校业务数据＋系统管理 | 管理账号、权限、口径、方案和审计 |

一人多角色时通过“当前工作身份”切换。菜单只决定入口，后端仍按工作身份、组织范围、
人员关系、对象和动作重新鉴权。

## 3. 功能架构

### 3.1 教学管理分析

| 二级菜单 | 管理问题 |
|---|---|
| 教学数据总览 | 全校/学院/专业/课程/学生多层数据概览与横向比较 |
| 学业预警监控 | 当前风险、历史预警、规则配置、规则自发现和学生证据 |
| 教学运行分析 | 开课、课程质量、实际教室占用、调课、教师负荷和排课特征 |
| 培养质量分析 | 培养方案结构、学生方案绑定、执行进度和毕业准备核查 |
| 师资保障分析 | 师资结构、课程团队连续性、负荷和历史排课偏好 |
| 学生成长与学业分析 | GPA与挂科联合迁移、成长轨迹、挂科模式和学生档案 |

### 3.2 AI 管理决策

| 二级菜单 | 管理问题 |
|---|---|
| 管理要情 | 只突出新增、升级、扩大、缓解和退出关注的管理事件 |
| 决策研判 | 以管理专家、自然语言和结构化参数形成证据卡、比较卡和候选决策单 |

AI 不逐行评价所有学生，不临时发明指标，不扩大用户数据权限。每项重要结果显示数据来源、
时间、范围、规则/专家版本、证据入口和适用边界。

### 3.3 系统管理

账号管理、角色与功能权限、菜单管理、数据权限、指标与口径管理、分析方案管理、审计日志、
系统参数共八个二级菜单。预警规则仍位于“学业预警监控”，不放入系统参数。

## 4. 核心口径

- 平均分：按有效成绩记录对应课程学分加权。
- GPA：使用学校已确认或源系统提供的绩点口径；无有效证据不补造。
- 当前挂科率：当前学期未通过成绩记录数 ÷ 有效成绩记录数。
- 历史挂科经历率：历史存在未通过记录学生数 ÷ 有成绩学生数。
- 预警：由已发布规则和统一数据范围计算，支持历史比对与证据追溯。
- 培养进度：优先按学生绑定培养方案及课程替代关系计算；模块学分为空或零时按门数要求，
  两者均无时按课程必修属性核查。
- 教室利用：基于实际占用行为；晚间是否纳入由用户筛选，不维护“可用教室数量”主数据。
- 教师排课偏好：从历史实际排课结果统计，不由教师主动填报。

## 5. 数据与证据边界

- 原型同时接入旧分析库和 V2 真实数据验证库，生产系统通过学校 API/数据交换平台获得结构化数据。
- 真实、推导、模拟数据必须保留来源和时间；缺失数据明确披露，不用模拟结果伪装正式结论。
- 学生明细、名单、导出、AI研判和证据下钻均受统一权限控制并进入审计。
- 考风考纪、出勤等学校未提供的数据不作为当前产品功能承诺。

## 6. 非功能要求

- 本科生 2～4 万人规模规划，常用页面优先使用预聚合、缓存和按需加载。
- 私有云部署，统一身份认证为主，满足网络安全等级保护二级建设要求。
- 响应式网页，不建设独立移动端，预留学校小程序、企业微信或 APP 接口。
- 学校批准后可接入云端或校内部署大模型；密钥由部署环境管理，不在页面保存或回显。
