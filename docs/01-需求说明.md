# 01 · 需求说明

> 本系统是高校教务**学业数据分析 BI 平台**的「平台管理端」（PC 端 Web 看板）。
> 定位：面向校、院两级管理者的**只读**学业洞察工具。

---

## 1. 业务背景

高校教务积累了大量成绩、学籍、培养方案、教学运行数据，但分散在业务系统中、缺乏面向
管理决策的多维分析视图。本平台把这些数据沉淀为统一分析库，提供：

- 全校/学院/专业/课程/学生多层下钻的学业监测
- 高危学生实时预警与处理跟踪
- 培养方案达成度、毕业与学位质量分析
- 师资结构、教学运行（开课/教室/调停课/教师负荷）分析
- 可导出的报表中心

**核心约束：只看不动。** 系统对教务源数据只读，不提供任何回写/审批/干预功能。

## 4. 核心业务规则

### 4.1 学业预警（5 条规则，全部阈值触发）

预警由 ETL 阶段对**当前学期在校学生快照**派生，规则与阈值：

| 规则 | 等级 | 阈值（可在系统设置调整） |
|---|---|---|
| R1 GPA持续下降 | 严重 | 近 2~3 学期 GPA 连续下降，累计降幅 > 0.3 |
| R2 挂科累积 | 严重 | 近 2 学期累计挂科（含重修）≥ 3 门 |
| R3 学分缺口过大 | 警告 | 已修学分较期望进度缺口 > 10 学分 |
| R4 核心课挂科 | 提醒 | 专业必修（核心）课近 2 学期挂科 ≥ 2 门 |
| R6 退学风险 | 严重 | 本学期 GPA < 1.8 且 近 2 学期挂科 ≥ 2 门 |

- 阈值在「系统设置」页可改，写回 `sys_alert_rule.params`；**改后需重跑 ETL 才会重算预警**
  （引擎仅在 ETL 阶段运行，UI 已明示「下次重算生效」）。
- 预警**只覆盖当前在校学生**，往届/已毕业学生天然从快照排除。

### 4.2 毕业判定（合成真表算法）

因真实成绩数据系统性不完整（未覆盖完整 4 年方案），毕业率用**专业内学分百分位**判定
（`pct >= 0.05 且 gpa >= 1.5`），而非绝对应修学分阈值——百分位自适应数据缺口。
若用绝对学分阈值，算出的毕业率会失真（仅 ~27%）。

### 4.3 真实 vs 合成数据

- **真实**（`source='real'`）：成绩、教学任务、学籍异动、校外考试、调停课、2 份培养方案。
- **合成**（`source='sim'`）：毕业去向、考纪、出勤、师资画像、培养方案学分要求（除 2 真方案外）。
  合成数据走完整 ETL（`synth_business.py`，固定种子可复现），不在 API 层硬编码，前端不暴露
  `source` 字段。

## 5. 关键数据规模（核对基线）

- 学期：9 个（2021-2022-2 ~ 2025-2026-2），当前学期 = 2025-2026-2

- 预警：5,027 条 / 3,532 人   真实挂科率：约 6%
- 学院：14（C01-C14）   专业：51   校区：2（校本部/东校区）
- 真实培养方案：2 专业（安全工程、海洋油气工程，均 2022 级）
- GPA：5 分制

> 注：`major_id` 在每次 ETL 重建时可能重排，**按专业名核对**而非 id。
