# 师资保障分析 UE 深度走查与优化方案

> 文档状态：已确认、已实施并通过验收
> 适用模块：教学管理分析 / 师资保障分析
> 依据：`docs/93-教学管理分析UE公共契约.md`
> 形成及验收日期：2026-07-24

## 1. 本轮目标与边界

本轮优化不是继续增加教师统计图表，而是把“本科教学师资保障分析”收口为一个能够回答以下管理问题的课程保障工作区：

1. 哪些课程的师资供给需要优先核查，而不是哪些教师看起来“任务多”。
2. 为什么需要核查，结论由哪些真实任务、课程属性、教师结构和历史开课证据支持。
3. 校级管理者应先找哪个学院核实，学院管理者应先核实哪门课程。
4. 当前问题属于真实保障风险、一般运行现象，还是数据不足造成的候选问题。
5. 管理者进入页面后能否在当前业务上下文中完成“发现—定位—查看证据—明确核查事项”，而不跳转到另一个模块或教师评价页面。

本模块坚持以下边界：

- 分析对象以“课程及其教学团队保障能力”为主，不建设教师绩效评价。
- 教师负荷排名、前 10% 教师任务占比等运行指标归属“教学运行分析”，不在两个模块重复维护。
- 一门课程由一位教师授课是常见事实，不能单独作为风险。
- 不根据教师平均分、通过率直接评价教师教学质量。
- 在缺少正式课程团队、年龄结构、后续开课计划等数据时，只披露证据缺口，不伪造保障结论。
- 不自动作出停课、换教师、补充教师、教师评价或人事安排。

## 2. 走查范围与方法

本轮已完成以下检查：

- 以校级身份走查师资保障首页、学院核查抽屉、课程团队证据抽屉和教师教学经历抽屉。
- 以二级学院身份走查本院首页、课程核查路径和身份范围提示。
- 直接访问历史课程团队页和教师详情页，检查兼容路由及业务焦点。
- 核对前端页面、路由、后端接口、教师维度、教学任务、课程归属和数据质量问题表。
- 对当前学期关键指标进行数据库复核。
- 测量本地主要接口响应时间。
- 按公共 UE 契约检查筛选、加载、错误、表格、抽屉、返回和数据权限行为。

## 3. 当前页面能够提供的价值

现有实现并非全部推倒重来，以下能力可以保留：

- 已建立“全校概览—学院核查—课程团队—教师教学经历”的分层证据链。
- 学院抽屉支持预取和缓存，减少重复等待。
- 课程证据与教师经历使用抽屉呈现，能够保持主页面业务焦点。
- 抽屉内“返回学院核查”的上下文返回方式基本正确。
- 校级和学院级身份已经具备基本的数据范围提示。
- 当前主要接口在本地数据量下性能良好：
  - 全校概览约 209ms；
  - 单学院概览约 75ms；
  - 单课程详情约 11ms。

这些能力应作为改造基础，不应因页面重构而丢失。

## 4. 深度走查发现

### 4.1 P0：已知异常教师任务没有在本模块中排除

当前学期教师 `2025880048` 在教学任务中出现明显异常：

- 252 个教学班；
- 108 门不同课程；
- 4,672 人次；
- 11,330 学时；
- 数据质量问题表中已经存在跨 4 个学期的未关闭异常记录；
- 异常处理建议明确要求在确认前继续排除。

“教学运行分析”的教师负荷已经排除此类异常，但“师资保障分析”仍将其纳入：

- 实际授课教师数；
- 教师任务集中度；
- 学院排名；
- 高级职称参与；
- 课程团队统计。

这会使管理者把数据异常误认为师资保障问题。改造时必须建立统一的数据质量门禁，并在页面上显示“本次分析排除了多少条异常教师任务、为什么排除、如何查看说明”。

### 4.2 P0：课程归属与教师归属混用，学院责任边界不稳定

当前后端部分口径使用教师所在部门 `teacher.dept` 作为课程学院，部分搜索又使用课程所属部门，课程详情授权还可能基于任一团队教师的部门判断。

当前学期复核发现：

- 92 门课程的课程归属与主讲教师归属不同；
- 397 名主讲教师中，仅 239 名能够直接映射到学院维表；
- 158 名教师来自未映射或非教学单位；
- 包括后勤实体、实验室、学生工作部门、团委等多种组织。

若不统一口径，会出现：

- 一门课程在不同页面归属不同学院；
- 学院看不到本院开设但由外单位教师承担的课程；
- 学院可能通过教师归属越权看到其他学院课程团队详情；
- 校级学院排名的分母和责任主体不明确。

建议统一为：

1. 课程保障责任归属使用“课程开设组织/课程责任学院”。
2. 在暂时没有正式开设组织字段时，以课程维表的课程所属部门作为临时代理口径，并明确标注。
3. 教师贡献归属使用教师人事归属，仅用于教师来源结构。
4. 本学院可以查看本院责任课程所需的完整团队证据，包括外单位承担教师。
5. 本学院教师参与外学院课程，只展示本院教师的汇总贡献，不自动开放外学院完整课程团队。
6. 跨学院比较只展示聚合结果，不开放其他学院学生或教师敏感明细。

### 4.3 P0：把“单教师授课”直接当作风险，误报规模过大

校级页面当前显示：

- 945 门课程；
- 748 门单教师覆盖课程；
- 62 门高集中课程。

单教师课程占比很高，说明“一门课一位教师”是当前排课数据中的常见组织方式，不能直接作为红色或橙色风险。历史课程团队页仍然仅凭当前一位教师就标记“优先”，与已确认的产品判断冲突。

单教师只能作为基础事实，只有同时满足以下管理条件时才进入风险队列：

- 课程具有较高保障重要性，例如必修、专业主干、公共基础、重点大课；
- 课程规模或教学班数量达到核查阈值；
- 连续多个实际开课学期均由同一教师承担，或当前任务高度集中；
- 数据质量通过门禁；
- 没有正式备份教师、课程团队或后续供给证据。

### 4.4 P1：师资保障、教师负荷和教师评价三个视角混在同一页面

当前“前 10% 主讲教师任务占比”“主讲任务集中 TOP5”等指标，本质属于教师负荷与教学运行，应归入“教学运行分析”。

教师详情历史页还展示：

- 模拟年龄、学历、学位、毕业院校、教龄；
- 平均成绩、课程通过率和成绩趋势。

这会把管理者从“课程有没有持续供给能力”带到“某位教师表现如何”，容易形成不恰当的教师评价暗示。师资保障模块中的教师抽屉应只呈现：

- 承担课程经历；
- 在课程团队中的角色；
- 教学班与规模变化；
- 跨学期连续承担情况；
- 职称及证据来源；
- 数据质量状态；
- 与当前课程保障核查直接相关的事实。

### 4.5 P1：顶层指标看起来正式，但部分数据不具备正式结论条件

当前页面展示“教授参与率 100%（25/25）”。现有教师维表并不是包含在岗状态、有效期和岗位状态的完整人事名册，因此分母不具备正式人员口径。

建议：

- 在正式人事在岗名册接入前，不将“教授参与率”作为绿色正式 KPI。
- 临时改为“已接入教授授课证据”，并在证据就绪区说明覆盖边界。
- 正式生产口径应以“有效在岗教授名册”为分母，以分析期内有效主讲或团队成员为分子。

年龄结构、临退休依赖、课程负责人覆盖和备份教师覆盖也存在相同问题：当前数据不足时，只能显示“证据未接入/暂不可正式计算”。

### 4.6 P1：课程抽屉展示了很多数据，但没有先回答“为什么核查”

以“形势与政策教育（II）”为例，现有抽屉能看到：

- 2 名实际教师；
- 26 个教学班；
- 750 人次；
- 教授 0、副教授 0；
- 历史开课记录。

但用户仍然无法快速判断：

- 该课程因哪个规则进入队列；
- 触发阈值是多少；
- 哪个事实超出阈值；
- 是当前任务集中、连续单点、职称结构，还是数据不足；
- 管理者下一步应核实什么；
- 当前证据能否支持正式结论。

抽屉需要从“平铺证据”改为“先结论和理由、再证据、最后原始明细”。

### 4.7 P1：校级与学院级页面没有按工作任务改变信息架构

学院用户当前仍能看到：

- “从全校发现……”；
- “全校共有……”；
- “学院师资保障概览”；
- 只有本学院一行的学院表格；
- “全校重点课程”。

这既浪费空间，也会让学院用户误解数据范围。建议：

- 校级用户：学院横向比较 + 全校优先课程。
- 学院用户：本院保障总览 + 本院优先课程 + 学校聚合基准位置。
- 学院用户不展示只有一行的学院表。
- 学院用户可看到本院相对学校中位数/分位数的聚合比较，但不能下钻其他学院明细。

### 4.8 P1：历史页面仍可直接访问，形成两套冲突逻辑

历史课程团队页存在以下问题：

- 默认学期为 `2023-2024-1`，与主页面当前学期不一致；
- 仅因一位教师就标记“优先”；
- 展示“替代关系 0 条（不等于师资替代）”，管理意义弱；
- 跳转到独立教师详情页，离开当前业务上下文；
- 使用另一套表格和交互样式。

建议保留旧 URL 的兼容重定向，但不再维护第二套课程团队判定逻辑：

- `/admin/faculty/team?...` 重定向到 `/admin/faculty` 并按参数打开课程证据抽屉；
- `/admin/faculty/:teacherId` 重定向到 `/admin/faculty` 并打开教师教学经历抽屉；
- 旧链接可继续访问，但所有用户进入统一工作区。

### 4.9 P2：加载、筛选和表格行为尚未完全遵守公共 UE 契约

当前问题包括：

- 切换学期时使用整页遮罩，用户无法继续阅读已加载内容。
- 学期条件未写入 URL，刷新或分享后不能恢复。
- 切换学期会直接关闭抽屉，缺少上下文变化说明。
- 加载失败缺少明确的局部重试入口。
- 主表使用公共 `DataTable`，抽屉内多张表仍使用原始 `el-table`。
- 尚未完整声明必显列、业务列上限、列配置版本及可选列。
- 历史开课表格较宽，信息密度高，但缺少跨学期摘要。

## 5. 目标管理流程

### 5.1 校级用户

```text
进入本期师资保障
  → 查看异常门禁与证据就绪情况
  → 判断本期需要优先核查的课程数量
  → 按学院比较问题规模和问题类型
  → 打开学院核查抽屉
  → 选择一门优先课程
  → 查看触发原因、阈值、团队结构和连续性证据
  → 明确应由哪个学院核实什么事项
```

校级用户的核心价值不是看到教师排行榜，而是把有限的管理注意力分配到少数真正需要学院说明的课程。

### 5.2 二级学院用户

```text
进入本院师资保障
  → 查看本院相对学校基准的位置
  → 查看本院优先核查课程队列
  → 打开课程证据抽屉
  → 核实课程重要性、团队人数、任务集中、连续承担和数据完整性
  → 查看相关教师教学经历
  → 明确需补充的数据或需在下期教学安排中确认的事项
```

学院用户的核心价值是快速得到“本院先核实哪几门课、为什么、缺什么证据”。

## 6. 目标页面结构

本模块继续采用“单页面 + 同上下文抽屉”，不增加三个顶部 Tab。

### 6.1 页面头部

- 页面标题：本科教学师资保障分析。
- 当前工作身份。
- 数据范围：全校/本学院。
- 分析学期。
- 数据更新时间。
- 口径与边界入口。

### 6.2 管理结论条

用一句可执行的结论代替套话：

> 本期共识别 12 门需优先核查课程，其中 5 门为连续单点承担、4 门为重要课程任务高集中、3 门为职称结构待核实；另有 7 门仅因证据不足进入数据候选。分析已排除 4 条异常教师任务。

结论中的每个数字均可点击，点击只更新下方课程队列，不整页刷新。

### 6.3 顶层卡片

建议保留 5 个课程导向指标：

1. **可评估课程**
   - 含义：通过数据质量门禁，具有课程责任组织、实际授课教师和有效教学任务的课程。
   - 管理价值：说明本次分析覆盖了多少课程，避免把数据不足误当作无风险。
2. **优先核查课程**
   - 含义：满足重要性、规模、团队持续性或任务集中等复合规则的课程。
   - 管理价值：形成校院两级本期核查工作量。
3. **连续单点承担课程**
   - 含义：最近若干次实际开课均仅由同一位教师承担，且课程具有保障重要性。
   - 管理价值：识别请假、离岗或任务调整时可能缺少替代供给的课程。
4. **结构待核实课程**
   - 含义：在职称证据达到门槛后，重要课程团队未体现预设的高级职称或梯队结构。
   - 管理价值：提示核实课程团队建设和梯队安排，不评价单个教师水平。
5. **数据候选课程**
   - 含义：因组织映射、教师信息、团队关系或异常任务等问题，暂不能作正式判断的课程。
   - 管理价值：把数据核实与业务核查分开。

每张卡片必须提供统一风格 Tooltip，说明定义、分子分母、排除项、数据时间和管理用途。

### 6.4 证据就绪条

使用紧凑的灰色证据状态区，不把未接入数据伪装成风险：

- 课程责任组织：已接入/覆盖率；
- 教师职称：已接入/覆盖率；
- 正式课程团队：未接入；
- 年龄段及临退休：未接入；
- 后续开课计划：未接入；
- 课程负责人/备份教师：未接入。

点击可打开口径说明抽屉，不进入系统设置。

### 6.5 校级主体区

左侧“学院师资保障概览”：

- 学院；
- 可评估课程；
- 优先核查课程；
- 连续单点课程；
- 结构待核实课程；
- 数据候选课程；
- 核查率；
- 操作“核查学院”。

右侧“全校优先课程”：

- 仅展示优先级最高的 8—10 门；
- 每门课程显示课程名、责任学院、触发类型、关键证据和“查看证据”；
- 提供“查看全部课程”入口，在抽屉中使用服务端分页。

### 6.6 学院主体区

学院用户不展示单行学院表，改为：

- 本院指标摘要；
- 与全校中位数/分位数的聚合比较；
- 本院优先核查课程；
- 本院数据候选课程；
- “查看全部课程”抽屉。

不展示其他学院教师和课程团队明细。

## 7. 指标体系调整

### 7.1 现有指标处置

| 现有指标 | 处置 | 原因 |
|---|---|---|
| 实际授课教师 | 降级为范围说明 | 需先通过异常门禁和有效组织映射，不能直接代表师资充足 |
| 实际开设课程 | 改为可评估课程 | 需要明确哪些课程进入正式分析分母 |
| 单教师覆盖课程 | 保留为抽屉事实，不作为顶层风险 | 单教师授课本身是常见现象 |
| 高集中课程 | 重定义 | 必须公开集中度算法、可比组和阈值 |
| 教授参与率 | 暂离开正式 KPI | 缺少有效在岗教授名册，现有分母不正式 |
| 前 10% 主讲教师任务占比 | 移至教学运行分析 | 属于教师负荷与任务分配 |
| 主讲任务集中 TOP5 | 移至教学运行分析 | 属于教师负荷，不是课程团队韧性 |
| 高影响单点课程 | 保留并重定义 | 必须由课程重要性、规模和单点事实共同触发 |
| 年龄结构风险 | 证据未接入前只显示状态 | 不能用模拟年龄形成管理结论 |
| 高级职称覆盖 | 保留为结构证据 | 必须以职称证据覆盖率为前提，且不评价教师个人 |

### 7.2 可评估课程

设分析学期为 \(t\)，课程为 \(c\)：

```text
可评估(c,t) =
  存在有效开课任务
  AND 存在课程责任组织
  AND 存在至少一名可识别的实际授课教师
  AND 未命中需排除的数据质量异常
```

```text
可评估课程数 = COUNT(DISTINCT course_id WHERE 可评估 = true)
```

排除数量和排除原因必须能够查看。

### 7.3 当期任务高集中课程

不使用不透明综合分。先在可比课程组内计算：

```text
教师教学班占比 = 某教师承担该课程教学班数 / 该课程教学班总数
教师学生人次占比 = 某教师承担该课程学生人次 / 该课程学生人次总数
```

可比课程组建议由以下维度组成：

- 课程类别；
- 必修/选修属性；
- 课程规模区间；
- 公共课/专业课属性。

触发规则：

```text
当期任务高集中 =
  可评估
  AND 教学班数或学生人次达到最小规模
  AND 最大教师教学班占比 >= 可比组P90
  AND 最大教师学生人次占比 >= 可比组P90
```

若可比组样本不足，不作正式判断，进入“数据候选”或仅展示事实。

### 7.4 高影响单点课程

```text
高影响单点 =
  可评估
  AND 实际授课教师数 = 1
  AND 课程属于重点保障范围
  AND（学生人次 >= 阈值 OR 教学班数 >= 阈值）
```

重点保障范围由学校配置，可包括：

- 必修课程；
- 专业主干课程；
- 公共基础课程；
- 思政、体育、数学、英语等重点公共课程；
- 学校明确的关键课程。

页面必须同时显示触发的课程属性和规模证据，不能只写“仅一名教师”。

### 7.5 连续单点承担课程

以“实际开课次数”而不是自然学期数计算：

```text
连续单点承担 =
  最近N次实际开课均仅有1名实际授课教师
  AND 其中至少N-1次为同一教师
  AND 当前课程属于重点保障范围
  AND 当前及历史数据均通过质量门禁
```

原型建议 \(N=3\)，但规则应可配置并记录版本。

不连续开课课程按最近实际开课记录计算，不能因中间学期未开课而直接中断。

### 7.6 结构待核实课程

```text
职称证据率 = 已有有效职称教师数 / 课程团队可识别教师数
```

只有当职称证据率达到学校设定阈值时，才允许计算结构类指标。

示例规则：

```text
结构待核实 =
  课程属于重点保障范围
  AND 职称证据率 >= 90%
  AND 团队中未体现学校配置的高级职称/梯队结构
```

该指标只提示“课程团队结构需要核实”，不能得出课程质量低或教师能力不足的结论。

### 7.7 优先级分类

建议采用可解释的分类规则，不展示黑箱分数：

| 分类 | 进入条件 | 管理动作 |
|---|---|---|
| 优先核查 | 重点课程 + 高影响单点或连续单点，或重点大课当期高度集中 | 核实下期供给、团队安排和替代准备 |
| 结构核查 | 重点课程 + 职称证据充分 + 团队结构未达到学校设定规则 | 核实团队梯队与课程负责人安排 |
| 数据候选 | 组织、教师、职称、任务或团队证据不完整/异常 | 先核实数据，不形成保障结论 |
| 一般观察 | 存在单教师等事实，但未达到管理阈值 | 保留观察，不列入本期重点 |

## 8. 课程证据抽屉

### 8.1 首屏必须先回答四个问题

1. **为什么进入队列**
   - 示例：连续 3 次开课均由同一教师承担；本期覆盖 12 个班、420 人次；该课属于专业必修。
2. **触发了什么规则**
   - 规则名称、规则版本、可比组和阈值。
3. **证据是否完整**
   - 课程归属、实际教师、职称、正式团队、年龄、后续计划分别标明。
4. **建议核实什么**
   - 示例：核实下期是否仍开课、是否已有共同授课或备份安排、正式课程团队是否尚未入库。

### 8.2 抽屉内容顺序

1. 核查结论与边界。
2. 关键证据卡片。
3. 当前教学团队。
4. 最近 3 次实际开课连续性摘要。
5. 原始历史开课记录，可折叠。
6. 数据来源、更新时间和规则版本。

### 8.3 团队明细默认列

默认业务列不超过 7 列：

- 教师；
- 团队角色；
- 人事归属；
- 职称；
- 教学班数；
- 学生人次；
- 任务占比。

必显列：

- 教师；
- 团队角色；
- 教学班数；
- 学生人次。

可选列：

- 教师编号；
- 人事归属；
- 职称；
- 学时；
- 首次/最近承担学期；
- 数据状态。

用户可调整显示列和顺序，但业务列最多显示 8 列；选择超过上限时给出明确提示。

## 9. 教师教学经历抽屉

教师抽屉只为当前课程保障核查提供证据。

### 9.1 保留内容

- 当前教师的有效身份和人事归属；
- 职称及来源时间；
- 最近若干学期承担课程；
- 在目标课程中的持续承担次数；
- 教学班、学生人次和学时；
- 主讲/共同授课/课程负责人等角色；
- 数据质量状态。

### 9.2 移除内容

- 平均成绩；
- 课程通过率；
- 以成绩结果形成的教师排名；
- 模拟年龄、学历、学位、毕业学校和教龄；
- 与当前课程保障无关的个人画像。

如果未来需要教师教学质量评价，应另行定义正式数据、规则、权限和申诉边界，不在本模块顺带实现。

## 10. 加载、筛选与状态交互

### 10.1 学期筛选

- 学期写入 URL 查询参数。
- 首次进入使用学校当前分析学期。
- 切换学期后只刷新受影响区域，保留页面骨架和上次有效数据。
- 若抽屉已打开，先显示“正在切换至××学期”，再更新同一课程证据；该学期无数据时给出空态，不直接关闭抽屉。

### 10.2 卡片筛选

- 卡片点击后在页面显示明确的筛选条件条。
- 再次点击同一卡片或点击条件条上的关闭按钮可清除。
- 提供“恢复全部课程”，不能让用户只能通过“重置”猜测清除逻辑。
- 卡片、学院表和课程队列共享同一筛选状态。
- 不整页刷新，不回到页面顶部。

### 10.3 加载与错误

- 页面首载：显示结构化骨架和“正在汇总本期课程团队与历史开课证据”。
- 局部刷新：对应区域显示内嵌加载，不遮挡整个页面。
- 抽屉加载：抽屉骨架保留标题和返回路径。
- 空数据：区分“本期无课程”“没有命中核查规则”“证据不足暂不可判断”。
- 请求失败：显示失败范围、重试按钮和上次成功数据时间。
- 预取失败不得影响主页面使用。

## 11. 权限模型

### 11.1 校领导、教务处和系统管理员

- 查看全校课程保障汇总；
- 查看所有学院聚合和课程团队证据；
- 查看与课程保障有关的教师教学经历；
- 系统管理员仍需按明确全校业务授权访问，不以菜单权限代替数据权限。

### 11.2 二级学院

- 查看本学院责任课程的完整保障证据；
- 查看本学院责任课程中外单位承担教师的必要教学证据；
- 查看本院教师参与外学院课程的聚合贡献；
- 查看学校和其他学院的聚合比较；
- 不查看其他学院完整课程团队和教师个人明细。

### 11.3 辅导员、班主任和导师

本模块默认不向上述身份开放完整师资保障工作区。若业务上允许进入，仅提供与其所带学生课程相关的必要课程公开保障信息，不开放学院级团队核查数据。

### 11.4 服务端要求

- 首页、学院抽屉、课程抽屉、教师抽屉、导出和直接 API 均重新鉴权。
- 课程责任组织和教师人事组织使用不同字段，不得混为一个 scope。
- 权限范围缺失时返回空范围或拒绝，不能回退到全校。

## 12. 后端与数据结构建议

### 12.1 接口拆分

建议形成以下接口职责：

1. `GET /api/admin/faculty/management-overview`
   - 只返回顶层摘要、学院聚合、证据状态和少量优先课程。
2. `GET /api/admin/faculty/management-courses`
   - 服务端分页；
   - 支持学院、学期、优先类型、课程属性、关键词和数据状态筛选。
3. `GET /api/admin/faculty/management-course/{course_id}`
   - 返回触发原因、规则版本、阈值、当前团队、历史连续性和证据完整性。
4. `GET /api/admin/faculty/management-teacher/{teacher_id}`
   - 只返回与课程保障有关的教学经历。

不得由前端临时重算优先级。

### 12.2 统一异常门禁

师资保障和教学运行应复用同一异常排除函数或统一有效任务视图：

```text
valid_teaching_task =
  teaching_task
  - open_data_quality_issue
  - invalid_teacher_mapping
  - invalid_course_mapping
  - impossible_workload_record
```

每次分析返回：

- 排除记录数；
- 受影响教师数；
- 受影响课程数；
- 异常类型；
- 数据批次。

### 12.3 生产系统需补充的数据

| 数据 | 最小字段 | 用途 |
|---|---|---|
| 有效在岗教师名册 | 教师编号、组织、岗位/职称、在岗状态、生效失效日期 | 正式教师分母和职称结构 |
| 职称历史 | 教师编号、职称、生效日期、来源 | 按分析期还原职称 |
| 课程开设责任组织 | 课程/开课编号、责任组织、生效日期 | 统一课程保障责任 |
| 正式课程团队 | 课程、教师、团队角色、负责人、有效期 | 团队规模、负责人和备份证据 |
| 教师可授课程/资格 | 教师、课程或课程组、资格状态、有效期 | 替代供给能力 |
| 教学任务教师角色 | 开课、教学班、教师、主讲/共同授课、任务份额 | 真实团队贡献 |
| 年龄段/退休距离 | 教师、合规年龄段或距退休年限、有效期 | 年龄梯队和临退休依赖 |
| 后续开课及教学计划 | 课程、学期、预计规模、教师/团队计划 | 从历史风险升级为未来保障决策 |
| 规则配置 | 规则、阈值、适用课程、版本、生效日期 | 学校个性化口径 |

年龄数据优先接收合规年龄段或距退休年限，不要求在分析库暴露不必要的出生日期明细。

## 15. 验收标准

### 15.1 管理价值

- 校级用户能够在 3 次操作内从全校结论进入某门课程的核查证据。
- 学院用户进入页面后直接看到本院任务，不再看到无意义的单行学院表。
- 每门优先课程均明确显示触发原因、事实数值、阈值、规则版本、数据时间和核查事项。
- 一门普通单教师课程不会仅因“1 名教师”进入优先核查。
- 数据异常和业务风险分开呈现。

### 15.2 数据与口径

- 已登记异常教师任务不进入正式指标。
- 相同课程在首页、学院抽屉和课程抽屉中的责任学院一致。
- 跨学期连续性按最近实际开课次数计算。
- 职称、年龄、团队和后续计划证据不足时不输出正式结论。
- 所有卡片的分子、分母和排除项可查看。

### 15.3 权限

- 教务处/校领导可查看全校。
- 二级学院只能查看本院责任课程明细。
- 二级学院可查看跨院聚合比较，不能下钻其他学院完整团队。
- 外单位教师参与本院课程时，本院只能看到课程保障所需字段。
- 直接 API、旧 URL、导出和抽屉接口均执行相同服务端校验。

### 15.4 体验与性能

- 页面加载期间有明确进度提示，已有内容不被整页清空。
- 卡片筛选和清除不引起整页刷新。
- 学期、课程和教师上下文可通过 URL 恢复。
- 课程列表使用服务端分页。
- 单学期首页目标响应不高于 1 秒，课程抽屉目标响应不高于 500ms；超过目标时显示局部加载和可重试状态。
- 桌面端默认表格不因可选列过多破坏布局。
