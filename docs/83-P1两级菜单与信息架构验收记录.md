# P1 两级菜单与信息架构验收记录

> 验收日期：2026-07-19
> 分支：`产品终稿`
> 范围：菜单真值源、登录菜单契约、侧栏树、路由准入、菜单管理、角色菜单授权、角色默认入口

## 1. 验收结论

P1 已通过阶段门禁，可以进入 P2“统一数据权限底座”。

本阶段将原有 11 个扁平菜单迁移为 3 个一级分组、14 个二级叶子菜单。数据库只保存角色的叶子菜单权限；登录接口根据获授权叶子节点补齐必要父节点，父菜单不构成业务权限。

## 2. 迁移快照

### 2.1 迁移前

- `sys_menu` 共 11 项，主要为一级扁平菜单。
- 教学运行曾将课程、教室、调课、教师负荷、排课等操作页作为菜单节点。
- 管理专题和系统设置与业务分析菜单混排。
- 登录菜单契约未返回 `parent_id`。

### 2.2 迁移后

| 一级菜单 | 二级菜单 |
|---|---|
| 教学管理分析 | 教学数据总览、学业预警监控、教学运行分析、培养质量分析、师资保障分析、学生成长与学业分析 |
| AI管理决策 | 管理要情、决策研判 |
| 系统管理 | 账号管理、角色与功能权限、菜单管理、指标与口径管理、审计日志、系统参数 |

迁移结果：

- 一级菜单：3 项。
- 二级叶子菜单：14 项。
- 系统管理员 `dean` 角色：14 项叶子权限。
- 父菜单权限记录：0 项。
- 孤儿节点、三级节点、重复路径：0 项。

## 3. 关键实现

### 3.1 菜单与授权

- `code/scripts/migrate_menu.py` 提供幂等迁移，可重复执行。
- `code/backend/etl/seed.py` 与正式迁移使用同一菜单结构。
- 历史教学运行子菜单权限迁移到“教学运行分析”。
- 历史学生清单权限迁移到“学生成长与学业分析”。
- 历史管理专题权限迁移到“管理要情”和“决策研判”。
- 非系统管理员的系统管理遗留授权被清理。

### 3.2 登录与路由

- 登录和 `/api/auth/me` 返回 `menu_id`、`parent_id`、标题、路径、图标和排序。
- 侧栏仅展示至少拥有一个授权叶子的父分组。
- 当前路由只展开一个所属一级菜单。
- 学院、专业、课程、学生和历史专题路由映射到正确叶子菜单。
- 无权 URL 进入 403 说明页，不再静默跳到其他业务模块。

### 3.3 管理页面

- 菜单管理采用两级树形表格。
- 新建、编辑菜单可选择一级父菜单。
- 后端禁止自身为父、挂到二级节点以及形成三级菜单。
- 角色授权采用树形勾选；父节点只表达分组和半选状态。
- 提交到数据库前再次过滤为叶子权限。

## 6. P2 接续边界
