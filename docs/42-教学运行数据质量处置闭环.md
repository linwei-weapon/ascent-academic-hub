# 教学运行数据质量处置闭环

## 本批目标

将教学运行模块中已识别的教师课时异常，从只读提示升级为有权限、有状态约束、有处置意见、有审计轨迹的问题闭环。

## 实现内容

### 1. 处置状态

- `open`：待处理
- `reviewing`：复核中
- `closed`：已关闭

允许的状态流转：

- 待处理 → 复核中
- 复核中 → 待处理
- 复核中 → 已关闭
- 已关闭 → 待处理

接口拒绝未定义的跨级流转；每次流转必须填写处置说明。

### 2. 权限边界

当前仅教务管理角色 `dean` 和院系教学运行角色 `dept_operation` 可以改变问题状态。质量办等其他角色可以查看问题，但不能代替业务责任部门处置。

后端执行最终鉴权，前端按钮仅作为交互提示，不作为安全边界。

### 3. 审计留痕

新增 `data_quality_issue_audit` 表，逐次记录：

- 问题编号
- 原状态和新状态
- 操作角色与操作人
- 处置说明
- 操作时间

新增问题审计查询接口，便于后续在详情抽屉中展示完整处理轨迹。

课程总览问题清单已增加“处置轨迹”入口，以时间线展示状态变化、操作人、处置说明和操作时间；无记录时明确显示暂无处置记录。状态代码统一转换为“待处理、复核中、已关闭”中文标签。

### 4. 统计口径联动

处于“待处理”或“复核中”的异常记录继续从教学运行可信统计中排除；问题关闭后，对应记录恢复进入统计。重新打开后再次排除。

这使问题处置状态与课程统计口径保持一致，避免界面显示已关闭、统计仍永久剔除的口径冲突。

## 验证结果

- 数据迁移成功，现有 32 条课时异常已纳入问题台账。
- 前端生产构建通过。
- 专项自动化验证通过：越权拒绝、合法状态流转、审计顺序均符合预期。
- 全量端到端检查：94 项通过，0 项失败。
- 浏览器角色回归通过：教务处处长与运行科显示处置入口及中文状态；质量办无教学运行菜单，且后端写接口拒绝越权操作。

## 后续工作

教学运行模块本轮需求差距已完成收口。后续若接入真实教室座位、设备约束、教师禁排时段和学生课表冲突数据，可将当前“时段场景分析/人工核验候选”升级为受约束排课求解；在这些源数据接入前，系统继续明确保持辅助决策边界，不宣称自动排课。
