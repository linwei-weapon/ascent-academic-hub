# V2 教学运行与师资前端迁移验收记录

## 本批范围

- 单门课程开课情况：接入 `GET /api/v2/courses/offerings`，展示真实教学任务聚合。
- 课程类别时段分布：新增 `GET /api/v2/courses/schedule-distribution`，支持体育、思政专项。
- 教室资源基数：接入 `GET /api/v2/rooms/summary`，按可用、非虚拟、座位数大于 0 统计利用率分母候选。
- 课程团队：接入 `GET /api/v2/courses/{course_id}/team`，展示实际授课教师及职称缺失情况。
- 教师排课偏好：接入 `GET /api/v2/teachers/{staff_id}/schedule-preference`，定义为历史实际排课结果分布，不是教师主动填报。

## 证据边界

1. 体育、思政专项在原型阶段按课程类别、性质和课程名称关键词识别；生产系统应改为课程标签主数据。
2. 教师职称缺失不参与人才梯队风险结论，年龄、学历、教龄等未提供字段不得伪装成真实数据。
3. 教室低利用率必须以上游主数据提供的可用教室数量为分母；本系统只消费、核验和分析，不提供数据维护入口。
4. V2 教学运行学期由“已接入真实教学任务的学期”元数据动态确定，避免与旧原型模拟趋势混用。

## 验收结果

- 后端 V2 单元测试：23 项通过。
- 前端生产构建：通过，2444 个模块完成转换。
- 浏览器交互验收：
  - 开课情况页：V2 证据提示和课程明细正常。
  - 教室资源页：可用基数和分楼宇统计正常。
  - 排课分析页：体育、思政实际排课时段热力图正常。
  - 课程团队页：按课程代码查询、选择课程、展示真实团队正常。
  - 教师详情页：历史排课时间分布及“非主动填报”边界正常。
- 浏览器控制台：未发现错误。

## 后续收口项

- 将 V2 数据学期改为元数据驱动，并为无真实排课数据的学期提供清晰空态。
- 与上游系统约定教室可用状态、可用数量及同步质量规则，本系统不承担维护职责。
- 课程标签主数据到位后替换体育、思政关键词识别。
- 将课程团队的真实职称分布与人员档案缺口清单纳入开发交接文档。
