# 账号管理 UE 深度走查与优化方案

> 模块：系统管理 / 账号管理
> 日期：2026-07-25
> 状态：方案已确认，实现与回归已完成

## 1. 模块定位

账号管理不是学校人员主数据维护页面，而是平台访问资格、统一认证映射和权限准备度的治理入口。

- 学校人员、组织和在职状态以权威系统为准；
- 平台维护“学校认证主体—平台账号”的映射，以及本地应急/实施账号；
- 工作身份、组织范围、带班和带生关系进入“数据权限”工作台配置；
- 账号停用或归档保留身份、范围和审计证据，不物理删除历史。

## 2. 原页面主要问题

1. 账号列表一次性加载，账号规模扩大后缺少稳定的服务端分页契约。
2. 账号角色字段与实际默认工作身份可能不一致，容易形成两个权限真值。
3. 多认证来源关联后可能重复账号行，无法把“一个账号、多个认证入口”作为同一事实核查。
4. 缺少统一认证接入准备度、孤儿映射、权限关系缺失等实施检查。
5. 新增、停用、删除、密码重置等操作边界不清，容易把学校同步账号当成本地账号处理。
6. 查看数据权限会离开账号上下文，返回时无法恢复原查询条件。
7. 登录审计与账号治理审计混在账号详情中，噪声较大。

## 3. 管理问题与页面答案

| 管理问题 | 页面答案 | 后续动作 |
|---|---|---|
| 当前多少账号可以访问平台 | 有效账号 | 查看启用账号及其最近登录 |
| 多少账号已接入学校统一认证 | 已完成认证映射 | 核查认证来源和稳定主体标识 |
| 哪些账号仍需接入或核验 | 待完成认证映射 | 筛选名单，补充或确认认证映射 |
| 哪些账号身份、人员或范围不完整 | 权限准备异常 | 定向进入数据权限配置 |
| 哪些账号已停止访问但需保留历史 | 已停用或归档 | 核查停用原因和变更记录 |

顶部卡片始终反映全量账号治理状态；下方查询条件只影响账号名单，避免把局部筛选误读为总体状态。

## 4. 统一操作路径

1. 管理员进入账号管理，先看五项治理状态；
2. 点击卡片直接形成对应名单筛选，筛选条件写入 URL；
3. 使用账号、姓名、教职工号、来源、工作身份、认证状态、权限状态和账号状态组合查询；
4. 在当前页面打开“账号核查”抽屉，查看认证映射、工作身份、人员关联、最近登录和账号治理记录；
5. 需要调整范围时定向进入该账号的数据权限配置；
6. 从数据权限返回后恢复原账号查询条件；
7. 停用、恢复和归档必须填写原因，历史身份与审计证据保留。

## 5. 功能与数据契约

### 5.1 账号列表

`GET /api/admin/rbac/users`

- 参数：`page`、`page_size`、`keyword`、`status`、`role_id`、`auth_status`、`permission_status`、`account_source`；
- 返回：`items`、`total`、`page`、`pageSize`、`summary`；
- `page_size` 服务端限制为 10—100；
- 多认证来源使用关联子查询，不复制账号行；
- 默认工作身份从当前有效且标记为默认的工作身份读取，不再以历史兼容角色字段作为页面真值。

### 5.2 账号核查

`GET /api/admin/rbac/users/{user_id}`

返回账号基本信息、全部认证来源、工作身份、人员关联、权限准备问题、最近登录和最近账号治理动作。详情中的“最近账号变更”只显示 `rbac.user.*` 类治理事件，不混入普通登录记录。

### 5.3 认证接入检查

`GET /api/admin/rbac/users/readiness`

返回有效账号、已映射、待映射、权限异常、孤儿映射、多认证来源账号、当前认证来源，以及学校实施时需确认的稳定认证主体、教职工号、生命周期和密钥边界。

### 5.4 生命周期

- 本地账号：可由平台创建、重置本地密码、停用和归档；
- 学校同步账号：以权威人员数据和统一认证为主，不把本地密码维护作为常规入口；
- 服务账号：必须明确用途、责任人和停用规则；
- 归档：停用账号并停用认证映射，保留工作身份、数据范围和审计证据；
- 已归档账号不得重新增加有效认证映射，恢复前必须先完成账号状态核验。

## 6. UI 与表格约束

- 使用公共 `DataTable` 契约，支持前端列显隐、列顺序、行密度和每页行数；
- 用户识别列、状态列和操作列为必选列；
- 默认只展示七列，避免横向滚动和操作按钮挤压；
- 行内操作只保留“查看”和“更多”，低频操作收入口袋菜单；
- 加载时显示账号、认证映射和权限准备度核验提示，不以正式零值代替未加载；
- 无结果时区分“没有账号”和“当前条件无结果”，提供清除条件入口。

## 7. 快速交付实施清单

学校实施阶段只调整字段映射和认证适配，不复制账号页面。需确认：

1. 统一认证协议与稳定 `subject/uid` 字段；
2. 教职工号及有效在职状态字段；
3. 姓名和所属组织字段；
4. 角色、带班和导师关系的数据来源；
5. 新增、调岗、离职、停用和恢复规则；
6. 同步频率、失败重试和人工核验责任人；
7. 认证客户端密钥、票据和回调密钥只由部署环境管理。

## 8. 性能设计与验收边界

- 账号列表采用数据库总数统计加 `LIMIT/OFFSET` 服务端分页；
- 为账号状态/来源、有效工作身份、认证主体和审计查询建立索引；
- 默认每页 20 条，服务端最大 100 条；
- 自动化测试使用少量可解释账号验证分页边界、多认证来源去重、筛选与权限异常；
- 原型阶段不生成 4 万条模拟账号。生产验收再根据学校真实账号规模、数据库和部署资源制定容量测试目标。

## 9. 验收结果

- 账号治理、系统管理和权限上下文相关自动化测试通过；
- 真实库幂等迁移后共 187 个有效账号，服务端分页为 20 条/页；
- 浏览器已验证卡片筛选、组合查询、URL 状态、第二页、账号详情、认证接入检查、数据权限定向进入及带条件返回；
- 菜单迁移已把“决策配置”纳入统一菜单真值，避免后续系统管理迁移误删；
- 非管理员系统管理准入继续由前端路由和后端接口双重限制。

## 10. 生产交接边界

原型已完成账号治理模型和操作路径，尚不代替学校真实统一身份认证回调。生产系统需按学校协议实现登录回调、认证签名验证、人员生命周期同步和异常告警，并在学校实际部署规模下完成容量与故障恢复测试。
