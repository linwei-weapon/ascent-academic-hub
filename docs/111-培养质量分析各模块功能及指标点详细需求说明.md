## 1. 文档目标、范围与阅读方式

### 1.1 文档目标

本文档完整说明“培养质量分析”中用户能够看到、选择、查询、比较、点击、下钻、导出和研判的功能，重点回答以下问题：

1. 培养质量分析首页及其下钻页面分别展示哪些指标、字段、状态、按钮、Tooltip 和提示信息；
2. 每个指标的统计对象、分子、分母、去重方式、计算顺序、排序方式、精度和适用边界是什么；
3. 年级、学院、专业、培养方案和证据状态的选项从哪里产生，如何联动，何时真正应用；
4. 从首页到学生名单、学生证据、课程保障证据和 AI 研判的条件如何继承，哪个页面是下钻终点；
5. 哪些信息是源数据，哪些是版本化规则推导，哪些只是原型核查阈值；
6. 当前实现与正式业务要求之间有哪些差异，验收时应如何判断；
7. 数据不足、无权限、接口失败、无记录或能力未接入时应显示什么，而不是用假数据补齐。

### 1.2 功能范围

“培养质量分析”是“教学管理分析”下的二级业务模块。当前页面包含 3 个平级工作区：

| 工作区 | 主要管理问题 | 最深下钻 |
|---|---|---|
| 方案执行总览 | 当前范围有哪些方案，学生是否正确绑定，哪些学院、专业、课程和学生需要先核查 | 方案执行学生名单 → 培养方案执行详情（终点） |
| 学生进度核查 | 某一培养方案覆盖的学生，其模块与课程完成证据如何 | 学生模块进度核查 → 培养方案进度核查（终点） |
| 毕业准备与课程保障 | 哪些学生已有明确必修问题，哪些课程需要核查历史供给和下一周期保障 | 学生核查名单 → 毕业准备核查证据 → 毕业准备研判（终点）；课程保障清单 → 课程保障证据 → 学生核查证据 / 研判 |

“方案结构与要求”当前隐藏，不是用户可见页签；其方案、模块、课程池和规则数据仍作为 3 个可见工作区的计算底座。旧“课程目标”“毕业要求”地址兼容返回培养质量分析首页，不再展示旧达成度页面。

### 1.3 不在本模块范围内的能力

- 不维护学校培养方案、课程、学籍、成绩、选课、认定或教学任务主数据；
- 不回写教务源库，不自动修改学生培养方案绑定；
- 不自动认定漏选、缺修、免修、替代、跨模块抵扣或课程归属；
- 不输出“可以毕业”“不能毕业”“可以授予学位”等正式审核结论；
- 不用课程平均分、通过率或大模型文本替代毕业要求指标点达成度；
- 不根据历史开课直接承诺下一周期一定开课，也不自动开设重修班；
- 不自动执行补考、重修、课程替代、毕业审核或课程保障处置；
- 不把“过期漏修”候选队列当作已确认的学生责任或正式缺口；
- 不允许 AI 扩大当前工作身份的数据权限，也不允许自然语言绕过服务端鉴权。

### 1.4 状态标记与阅读约定

本文使用以下标记：

- **现行实现：** 当前代码和页面已经实际执行的行为；
- **正式要求：** 生产开发和验收必须满足的规范；
- **待修正：** 当前实现与统一指标、证据边界、分页或页面文案存在差异，不能固化为正式需求；
- **原型阈值：** 只用于形成有限核查顺序，不代表学校制度、质量合格线或毕业标准；
- **未接入：** 当前数据域不存在，页面必须诚实显示“未接入”“待确认”或“—”。

指标编号优先复用指标口径确认书中的 `P-01～P-26`。尚无稳定编号的页面派生项标记为“页面功能”或“原型派生口径，稳定 ID 待登记”。

## 2. 页面树与完整下钻链路

### 2.1 页面树

```text
教学管理分析
└─ 培养质量分析（默认进入“方案执行总览”）
   ├─ 方案执行总览
   │  ├─ 学院方案执行关注
   │  │  ├─ 必修未通过数字 → 方案执行学生名单
   │  │  ├─ 过期漏修数字 → 方案执行学生名单
   │  │  ├─ 绑定待核验数字 → 方案执行学生名单（未匹配学生到此为终点）
   │  │  └─ 核查名单 → 方案执行学生名单
   │  │     └─ 已正确绑定学生“执行详情” → 培养方案执行详情（终点）
   │  ├─ 专业执行关注
   │  │  └─ 核查名单 → 方案执行学生名单 → 培养方案执行详情（终点）
   │  └─ 必修课程瓶颈
   │     └─ 学生 → 方案执行学生名单 → 培养方案执行详情（终点）
   ├─ 学生进度核查
   │  └─ 学生模块进度核查“详情” → 培养方案进度核查
   │     ├─ 模块完成核查（终点）
   │     ├─ 必修未通过课程（终点）
   │     ├─ 过期漏修课程（终点）
   │     └─ 全部课程证据（终点）
   └─ 毕业准备与课程保障
      ├─ 三张可下钻 KPI 卡 → 学生核查名单
      ├─ 各专业毕业准备概览“核查学生” → 学生核查名单
      ├─ 学生核查名单“核查证据” → 毕业准备核查证据
      │  └─ 仅存在必修未通过时“归纳核查重点” → 毕业准备研判（终点）
      └─ 课程保障待确认清单“保障证据” → 课程保障证据
         └─ 受影响学生“核查学生” → 毕业准备核查证据
            └─ 仅存在必修未通过时“归纳核查重点” → 毕业准备研判（终点）
```

| 起点 | 触发动作 | 目标 | 继承规则 |

### 2.5 下钻终点

当前下钻终点包括：

- 绑定待核验、方案源未覆盖等不能打开“执行详情”的方案执行学生名单行；

## 3. 全模块公共规则

### 3.1 当前工作身份、菜单准入和数据范围

当前菜单配置允许校领导、教务处、教学研究、质量管理、二级学院院长、学院教学秘书和专业负责人进入培养质量分析；系统管理员按已确认产品决策拥有全校业务数据与系统管理权限。普通教师、辅导员、班主任和导师当前不显示本模块菜单。

| 当前工作身份 | 明细范围 |
|---|---|
| 校领导、教务处、系统管理员及明确全校授权角色 | 全校授权范围内方案、学生和课程证据 |
| 二级学院及学院教学管理角色 | 本学院授权学生、方案和相关课程问题明细 |
| 专业范围身份 | 仅限显式映射到专业范围的学生与方案 |
| 班级、导师等关系范围身份 | 即使其他模块可按关系访问，本模块仍需同时具备菜单功能权限；不得因直接 URL 自动放开 |

公共安全规则如下：

1. 菜单隐藏不是安全边界；方案、学生、课程、导出、证据和 AI 接口都必须在服务端重新鉴权；
2. 权限上下文无效时返回 403；对象不存在或对象不在当前明细范围时返回 404，避免泄露对象存在性；
3. 查询条件只能收窄授权范围，不能把学院、专业、学生或课程范围扩大到当前工作身份之外；
4. 当前培养质量聚合先应用学生明细权限，再形成学院、专业和课程聚合；学院身份当前不提供他院聚合比较；
5. 缺少范围映射时默认拒绝，不得回退为全校；全校角色必须来自明确授权；
6. 缓存键必须包含权限范围指纹，切换工作身份后不得复用上一身份的结果。

### 3.2 统一学生方案评价链

3 个工作区必须共用以下唯一计算链，不得各自维护另一套课程缺口算法：

```text
有效成绩结果与正式课程替代
        +
学生—培养方案绑定与方案课程要求
        ↓
student_plan_course_status（学生—方案课程状态）
        ↓
student_plan_module_status（学生—方案模块状态）
        ↓
student_plan_progress_summary（学生—方案进度摘要）
        ↓
方案执行总览 / 学生进度核查 / 毕业准备与课程保障
```

统一规则版本当前为 `growth-v1`；有效课程结果版本为 `grade-effective-v1`。

### 3.3 有效课程结果和课程完成证据

#### 3.3.1 有效成绩选择

同一学生、同一课程只生成 1 条有效课程结果：

1. 只纳入“已发布且未作废”的成绩尝试；
2. 存在通过记录时，优先选择通过记录，并取通过记录中的最高分；
3. 没有通过记录时，选择最新学期、最新来源行的未通过记录；
4. 通过时计入该成绩记录学分，未通过时计 0 学分；
5. 历史未通过但后来已经通过的课程，不再作为当前“必修未通过”。

#### 3.3.2 课程状态固定选项

| 内部值 | 页面显示 | 判定规则 | 管理含义 |
|---|---|---|---|
| `recognized` | 替代/认定 | 存在审批结果“通过”且流程状态“流程已结束”的课程替代 | 按原方案课程学分计入一次，不与替代课程重复累计 |
| `passed` | 成绩通过 | 有效课程结果 `is_pass=1` | 课程完成证据明确 |
| `failed` | 明确未通过 | 有效课程结果 `is_pass=0` | 必修课可进入明确处理核查 |
| `unknown` | 证据未知 | 存在成绩尝试引用，但通过标记未知 | 不能直接认定完成或未完成 |
| `not_completed` | 尚无完成证据 | 未找到有效成绩结果或正式替代 | 不等同漏选、缺修或未参加考试 |

#### 3.3.3 当前学习学期和到期规则

当前学习学期按入学年级与当前日期动态推导：

```text
若当前月份为 9～12 月：学年起始年 = 当前年，学年内学期 = 1
若当前月份为 1～2 月：学年起始年 = 当前年 - 1，学年内学期 = 1
若当前月份为 3～8 月：学年起始年 = 当前年 - 1，学年内学期 = 2

当前学习学期 = (学年起始年 - 入学年级) × 2 + 学年内学期
结果限制在 1～20
```

课程“到期”条件为：课程尚未通过或认定，建议学期是 `1～20` 的有效整数，学生当前学习学期可计算，且 `建议学期 < 当前学习学期`。当前学期本身不算逾期。

### 3.4 模块规则优先级与可信性校验

每名学生的每个方案模块按以下顺序选择唯一评价规则：

1. **可信最低学分：** 模块最低学分大于 0，课程池记录学分大于 0，且最低学分不大于该叶子模块课程池记录学分合计；
2. **最低门数 / 选择组：** 无可信学分规则，但存在最低门数，或模块名称、性质文本可识别“二选一”等选择组；
3. **逐门必修：** 前两类规则均不可用，但模块内存在必修课程；
4. **暂不可评价：** 学分、门数和逐门必修规则均缺失。

选择组当前只识别“X 选 Y”文本，其中中文数字支持一至十。模块规则优先精确匹配标准化模块名；找不到精确项时，再按模块名包含关系或原始层级文本匹配。

| 规则类型 | 目标值 | 达成值 | 完成条件 |
|---|---|---|---|
| `minimum_credits` | 可信最低学分 | 模块内通过或正式认定课程的认可学分合计 | 达成值 ≥ 目标值 |
| `minimum_courses` | 最低门数或选择组需完成门数 | 模块内通过或正式认定课程门数 | 达成值 ≥ 目标值 |
| `required_courses` | 模块内必修课程数 | 模块内通过或正式认定的必修课程数 | 达成值 ≥ 目标值 |
| `not_assessable` | 空 | 空 | 不自动形成完成结论 |

若从 Word 合并单元格提取出的最低学分大于叶子模块全部课程记录学分合计，则该学分规则视为不可信，回退到门数或逐门必修规则。原始来源仍需保留用于人工核验。

### 3.5 模块状态、学生状态与优先级

#### 3.5.1 模块状态

| 内部值 | 页面显示 | 条件 |
|---|---|---|
| `complete` | 已达到 | 模块可核查且达成值 ≥ 目标值；即使课程池存在其他历史未通过或未选备选课，也不再形成模块问题 |
| `explicit_gap` | 必修未通过 | 模块未达到，且至少存在 1 门必修课当前有效结果为 `failed` |
| `candidate` | 过期漏修 | 模块未达到，没有明确必修未通过，但至少存在 1 门已过建议学期且状态为 `not_completed` 或 `unknown` 的必修课 |
| `not_due` | 尚未到期 | 模块未达到，但未发现上述明确问题或到期候选 |
| `not_assessable` | 暂不可评价 | 缺少可信学分、门数和逐门必修规则 |

当模块已经达到时，该模块的“必修未通过课程数”和“过期漏修课程数”在模块摘要中归零，防止把课程池内已被模块规则覆盖的普通备选项继续推入管理队列。

#### 3.5.2 学生摘要状态

学生状态按模块问题优先级汇总：

```text
存在任一 explicit_gap 模块 → explicit_gap
否则存在任一 candidate 模块 → candidate
否则 → no_due_issue
```

页面映射为：

| 接口 / 内部值 | 页面显示 | 颜色 |
|---|---|---|
| `explicit_gap` / “明确需处理” | 必修未通过 | 红色 / danger |
| `candidate` / “数据候选” | 过期漏修 | 琥珀色 / warning |
| `no_due_issue` / “当前未发现到期问题” | 当前未发现到期问题 | 绿色 / success |
| 绑定异常 | 方案绑定待核验 | 琥珀色 / warning |
| 无适用方案源 | 暂不在方案源覆盖范围 | 信息色 |

同一学生可以同时有必修未通过课程数和过期漏修课程数。学生总状态按“必修未通过”优先，但总览两类人数与课程人数分别按各自证据独立统计，不能因为总状态是必修未通过就把其过期漏修事实清零。

### 3.6 方案适用、正确绑定和覆盖边界

1. 方案适用范围按“入学年级 + 专业”确定；专业代码双方都有值时优先按代码匹配，否则按专业名称匹配；
2. 同一“年级 + 专业”存在多个方案时，当前接口以最小方案 ID 作为预期方案；正式系统应由版本化绑定规则消除该歧义；
3. 正确绑定要求学生绑定方案与年级、专业一致，且 `growth-v1` 进度摘要使用同一方案并标记为 `matched`；
4. 年级错配、专业错配、关键字段缺失、摘要方案错配，或存在适用方案但没有正确摘要，进入“绑定待核验”；
5. 学生年级与专业不存在任何已接入方案时，标记“方案源未覆盖”，只披露数据覆盖边界，不计为绑定异常；
6. 绑定待核验和方案源未覆盖学生不得进入正式模块进度、必修未通过或毕业准备计算。

### 3.7 公共表格、列设置、分页与排序

本模块全部正式表格使用公共 `DataTable`。每张表默认提供：

- 行密度：`紧凑`、`默认`、`宽松`；
- 列设置：显示 / 隐藏非必选业务列、拖拽或上下移动业务列、恢复默认；
- 必选识别列和操作列不可隐藏，且始终位于左右固定区域；
- 每页行数：配置分页的表显示 `10、20、50、100 条/页`；
- 用户偏好按“用户名 + 当前工作身份 + 表格标识 + 配置版本”保存到浏览器本地；切换身份不会复用另一身份偏好；
- 文本溢出 Tooltip 仅对列定义中明确设置 `tooltip=true` 的字段生效。

当前培养质量各表列定义均未启用表头排序，因此用户不能点击表头改变顺序；顺序由后端或页面固定。正式排序必须在分页前使用未格式化原值，并补充稳定末级键。

### 3.8 精度、单位、空值和提示语义

| 内容 | 显示规则 |
|---|---|
| 人数 | 去重学生数，单位“人”，整数 |
| 方案数、模块数 | 单位“个”，整数 |
| 课程数 | 单位“门”，整数 |
| 学分 | 默认保留 1 位小数；汇总底层可保留 2 位 |
| 比率 | 方案绑定率保留 2 位小数；模块规则可核查率保留 1 位小数 |
| `0` | 已有明确统计范围，结果确实为零 |
| `—` | 分母为零、不适用或无可计算结果 |
| 暂不可评价 | 规则证据不足，不能自动计算 |
| 暂不在方案源覆盖范围 | 没有对应年级与专业的方案源数据 |
| 待确认 / 尚未接入 | 未来计划、重修资源等数据域不存在 |
| 暂无数据 | 当前授权和筛选范围内没有记录 |

“过期漏修”是页面队列名称；Tooltip、状态原因和边界说明必须持续强调其仍需核对选课、缓修、免修、课程替代、课程认定和数据同步状态。

### 3.9 加载、缓存和请求并发

- 培养方案选项加载时显示整页遮罩“正在读取可用培养方案…”；
- 总览 KPI 显示“正在汇总方案覆盖与执行状态…”；必修课程瓶颈独立显示“正在按需提取课程证据…”；

- 总览与通用查询缓存有效期当前为 900 秒，并在数据库文件修改时间变化时失效；
- 毕业准备主题缓存有效期当前为 900 秒，缓存键包含权限范围、学院、专业、方案、年级和证据状态；
- 毕业准备页使用请求序号防止慢响应覆盖新条件结果；学生证据和课程证据抽屉也只接收最后一次请求结果；
- 页签按需加载：总览在进入时加载，学生进度组件只在对应页签渲染，毕业准备组件只在对应页签渲染。

    | `来源文件名|来源表名`     | 当前模块匹配到了培养方案模块规则记录，并且同时记录了来源文件和来源表 |
    | `结构化培养方案|来源表名` | 匹配到模块规则，但来源文件为空                               |
    | `来源文件名|—`            | 匹配到模块规则，但来源表名为空                               |
    | `结构化培养方案|—`        | 匹配到模块规则，但来源文件和来源表名都为空                   |
    | 空白                      | 没有匹配到培养方案模块规则记录，例如仅根据模块名称中的“二选一”推导门数规则，或者仅根据模块内必修课程生成逐门核查规则 |

  - **判断：**判断严格按以下优先级执行

    | 显示内容     | 触发条件                                                     |
    | ------------ | ------------------------------------------------------------ |
    | `暂不可评价` | 模块缺少最低学分、最低门数、选择组和逐门必修规则，无法形成目标值 |
    | `已达到`     | 模块可核查，并且实际完成值大于或等于目标值。例如认可学分达到最低学分，或完成门数达到最低门数 |
    | `必修未通过` | 模块尚未达到目标，并且模块内至少存在一门当前有效结果为“未通过”的必修课程 |
    | `过期漏修`   | 模块尚未达到目标、没有明确未通过必修课程，但存在建议修读学期已过且结果为“尚无完成证据”或“证据未知”的必修课程 |
    | `尚未到期`   | 模块可核查但尚未达到目标，同时没有明确未通过必修课程，也没有已过建议学期但缺少结果的必修课程 |

    优先级会影响最终显示：

    1. 达到目标后直接显示“已达到”，即使课程明细中曾存在其他未完成记录。
    2. 模块未达到时，“必修未通过”优先于“过期漏修”。
    3. “尚未到期”实际表示当前没有明确未通过或到期缺结果证据，不代表该模块已经完成。

- **排序方式：**按判断优先级排序（必修未通过 → 过期漏修 → 尚未到期 → 已达到 → 暂不可评价），同状态按模块名称排序。

- **分页：** 无分页，全部展现。

固定边界为：当前数据未提供教学班类型中的重修班标识和未来开课计划；教学任务只证明已接入学期曾经开设，不能据此承诺下一次开课。

#### 6.8.2 汇总字段

| 字段 | 计算 / 显示 |

| 必修未通过 | 继承全局学生范围后，该课程明确未通过的去重学生数 |
| 过期漏修 | 继承全局学生范围后，该课程到期缺结果候选的去重学生数 |

**待修正：** 当前请求固定 `limit=100`，无分页和总数提示，超过 100 人时静默截断。正式实现必须返回真实总数并提供服务端分页。

### 6.9 最深下钻页面：毕业准备研判

> 页面路径：教学管理分析 → 培养质量分析 → 毕业准备与课程保障 → 毕业准备核查证据 → 归纳核查重点 → 毕业准备研判<br>
> 载体：AI 研判抽屉，宽度 600 px<br>
> 下钻状态：终点

#### 6.9.1 触发前提与权限

- 页面入口前提：学生证据摘要中必修未通过课程数 > 0；
- 接口按学生 ID 再次校验当前工作身份的学生明细范围；
- 研判只解释结构化事实并给出管理核查建议，不改变学生状态，不自动创建任务；
- AI 规则版本为 `AI-RULE-2026.07-v1`；无已审核模型样例时统一标记为“规则研判”，不得伪装实时模型调用。

#### 6.9.2 当前证据计算

接口读取该学生全部必修方案课程，并形成：

- 明确未通过：`completion_status='failed'`；
- 到期缺结果候选：`completion_status in ('not_completed','unknown') and is_overdue=1`；
- 无开课证据：上述课程在教学任务中教学班数为 0；
- 风险级别：有明确未通过为 `critical`，否则有候选为 `warning`，否则为 `low`；
- 证据充分度：有任一问题课程为“高”，否则为“中”。

**待修正：** 当前 AI 查询没有关联 `student_plan_module_status`，会纳入已经达到模块中的历史未通过或课程池候选；而页面证据抽屉只纳入未达到模块。正式要求是 AI 与页面复用同一模块状态和证据集合，二者人数、课程与原因必须一致。

#### 6.9.3 可见信息元素

当前毕业准备研判使用精简视图，显示：

1. 学生姓名；
2. 学院 / 专业 / 班级元信息和数据时点；
3. 标题区“研判依据”悬浮入口；
4. 管理结论；
5. “为什么现在看”原因，最多 3 条；
6. 影响范围；
7. 当前角色建议先做的动作、责任角色、动作详情与建议时点；
8. 全部关键证据卡；
9. 最多 2 项首要核查后的备选动作。

精简视图明确隐藏：处理状态标签、规则 / AI 来源标签、证据充分度、比较基准、无可比基准标签、暂不核查影响、预期形成、关键证据逐卡来源、底部完整追溯折叠区。

#### 6.9.4 “研判依据”Tooltip

标题区保留以下 4 项：

| 字段 | 当前内容 |
|---|---|
| 分析范围 | 当前学生姓名或接口返回范围 |
| 事实来源 | 学生培养方案课程状态、培养方案课程、学生、课程等业务数据的中文来源说明 |
| 规则版本 | `AI-RULE-2026.07-v1` |
| 适用边界 | 仅用于毕业准备提前核查，不替代学校正式毕业资格审核 |

#### 6.9.5 管理结论与建议动作

存在必修未通过时：

- 结论摘要列出最多前 3 门问题课程、明确未通过门数和到期候选门数；
- 当前主要动作默认是“确认必修未通过课程处理路径”；
- 动作详情要求逐门确认补考、重修、课程替代及下一教学周期资源；
- 建议时点为“下一轮选课或开课计划确定前”。

动作会按当前角色匹配：学院角色优先采用二级学院动作；教务处、校领导和系统管理员优先从建议列表匹配教务处动作；未匹配角色时使用后端主动作。备选动作来自学院、教务处、辅导员 / 班主任建议，排除与主动作重复项后最多显示 2 项。

#### 6.9.6 关键证据卡

当前平铺展示接口返回的全部 4 项：

| 证据 | 值 | 说明 |
|---|---|---|
| 明确未通过 | `N 门` | 已发布成绩中存在必修课未通过记录 |
| 缺结果候选 | `N 门` | 到建议学期仍缺完成证据，需先核验选课与认定 |
| 无开课证据 | `N 门` | 历史教学任务中暂未发现该课程教学班 |
| 培养方案 | 方案名称或“未绑定” | 详情显示方案版本或“当前学生绑定方案” |

## 7. 跨页面指标词典与一致性要求

### 7.1 核心指标词典

| 编号 | 统一名称 | 统一公式 / 定义 | 当前展示位置 |
|---|---|---|---|
| P-01 | 适用学生绑定率 | 正确绑定学生 ÷ 其年级与专业存在适用方案的应绑定学生 × 100% | 方案执行总览 KPI |
| P-03 | 已认可总学分 | 通过或正式认定、可计入方案的课程学分合计；重复修读与替代不得双算 | 学生进度、毕业准备学生表与详情 |
| P-08 | 到期缺结果候选课程数 | 建议学期 < 当前学习学期，且没有通过、认定或明确未通过结果的课程数 | 页面展示名“过期漏修”或“到期缺修读结果” |
| P-09 | 未通过必修课程数 | 未达到模块中，当前有效结果仍为未通过的必修课程数 | 页面展示名“必修未通过” |
| P-13 | 数据候选 | 模块未达到且存在到期缺结果等不完整证据 | 接口内部“数据候选”，页面“过期漏修” |
| P-14 | 必修未通过学生 | 至少有 1 门 P-09 课程的去重学生数 | 3 个工作区 |
| P-15 | 过期漏修学生 | 至少有 1 门到期缺结果候选必修课的去重学生数 | 3 个工作区 |
| P-18 | 关键缺口课程涉及学生数 | 某必修课程存在明确未通过且所属模块未达到的去重学生数 | 必修课程瓶颈、课程保障清单 |
| P-23 | 可进行规则核查方案数 | 同时有课程表和可信模块规则的方案数 | 方案执行总览 KPI |
| P-24 | 模块规则可核查率 | 可核查学生—模块记录数 ÷ 全部学生—模块记录数 × 100% | 学生进度与毕业准备 |
| P-25 | 培养方案总数 | 当前授权与查询范围内存在对应学生的去重方案数 | 方案执行总览 KPI |
| P-26 | 学院 / 专业正确绑定率 | 正确绑定学生 ÷ 当前查询范围在籍学生总数 × 100% | 学院、专业执行关注 |

P-02、P-04～P-07、P-10～P-12、P-16～P-17、P-19～P-22 已在指标确认书定义，但当前 3 个可见工作区没有完整展示或因数据未接入不能计算，不得写成页面已实现指标。

### 7.2 同名与近似指标不得混用

| 易混项 | 正确区分 |
|---|---|
| P-01 适用学生绑定率 vs P-26 正确绑定率 | P-01 分母排除方案源未覆盖；P-26 学院 / 专业表分母为查询范围全部在籍学生 |
| 必修未通过学生 vs 必修未通过课程数 | 前者按学生 ID 去重，后者是单名学生或单门课程下的课程 / 学生计数 |
| 过期漏修 vs 明确缺修 | 过期漏修是数据候选；未核验选课和认定前不能称明确缺修 |
| 已达到模块 vs 当前未发现到期问题 | 前者是模块级完成；后者是学生级没有明确或候选到期问题，可能仍有尚未到期或暂不可评价模块 |
| 模块规则可核查率 vs 模块完成率 | 前者衡量规则覆盖，后者衡量学生达到情况；规则不可核查不能当作未完成 |
| 历史开课证据 vs 下一周期供给 | 历史开过只证明已有事实，不代表下期会开，也不代表容量或资格可用 |
| 课程替代记录 vs 已认可替代 | 前者表示记录存在；只有审批通过且流程结束才可作为 `recognized` 计入学分 |
| 课程池课程数 vs 学生应修课程数 | 课程池可能包含选修备选范围，不能作为完成率分母 |

### 7.3 去重键和统计粒度

| 对象 | 稳定键 | 统计粒度 |
|---|---|---|
| 学生 | `student_id` | 当前工作身份授权范围内去重学生 |
| 培养方案 | `plan_id` | 年级 + 专业适用的版本化方案 |
| 方案课程 | `plan_course_id` | 方案 + 课程 + 模块 + 建议学期 |
| 学生课程状态 | `student_id + plan_course_id + rule_version` | 学生在具体方案课程上的最新完成证据 |
| 学生模块状态 | `student_id + plan_id + module_name + rule_version` | 一名学生一个方案模块 |
| 学生方案摘要 | `student_id + plan_id + rule_version` | 一名学生一个方案版本 |
| 教学班 | `lesson_id` | 一门课程一个学期的教学任务实例 |
| 替代关系 | `substitution_id` | 学生的一条课程替代流程记录 |

同一课程若在多个方案模块重复出现，当前学生课程状态按 `plan_course_id` 分开生成。**正式要求：** 学校必须提供跨模块重复计入和抵扣规则，否则已认可总学分只能标注当前方案行汇总边界。

### 7.4 跨页面一致性硬约束

1. 3 个工作区必须读取同一 `growth-v1` 模块状态和学生摘要；
2. 方案执行总览与毕业准备页的全局筛选不同，但在相同学生、方案与权限范围下，P-14、P-15 和 P-24 必须一致；
3. 页面“必修未通过”必须同时满足“模块未达到 + 必修 + 当前有效未通过”，不能只按历史成绩未通过；
4. 页面“过期漏修”必须同时满足“模块未达到 + 必修 + 建议学期已过 + 无明确结果”，不能把所有未选课程池行纳入；
5. 学生证据、课程保障受影响学生和 AI 研判必须继承同一权限与方案范围；
6. 页面列表、导出、课程聚合和 AI 不得使用不同的方案绑定或课程替代规则；
7. 阈值判断使用未舍入原值，最后一步才格式化；
8. 排序在分页前完成，并使用稳定 ID 作为末级键；
9. 任何缓存结果都必须绑定权限范围指纹、业务筛选、规则版本和数据库版本；
10. AI 只负责解释和动作归纳，不得临时发明正式指标、改变人数或补造未来供给事实。

### 7.5 当前已识别的一致性缺口

| 编号 | 缺口 | 影响 | 正式处理要求 |
|---|---|---|---|
| CUR-01 | 学生进度页只加载前 1,000 人，搜索、筛选和导出均基于截断集合 | 大方案名单与导出不完整 | 服务端分页、服务端导出并显示真实总数 |
| CUR-02 | 课程保障清单 SQL 只取 `failed`，导致“过期漏修学生”恒为 0 | 表格列与业务定义不一致 | 同源聚合两类证据或删除该列 |
| CUR-03 | 课程保障受影响学生固定取前 100 人且无提示 | 大课程影响名单不完整 | 服务端分页、真实总数、分页前排序 |
| CUR-04 | 学生 AI 研判未关联模块状态 | 可能重新纳入已达到模块中的历史问题 | 复用证据抽屉查询或统一证据服务 |
| CUR-05 | 方案执行详情“无历史开课证据”Tooltip 称全部必修课程，后端只统计问题证据课程 | 用户误解统计范围 | 修正文案或扩大后端统计范围并登记新口径 |

| CUR-07 | 学院、专业 TOP 截断没有提示，部分排序无稳定末级键 | 记录可能遗漏或翻页不稳定 | 分页或明确 TOP 范围，并加稳定键 |

## 8. 数据来源、版本和适用边界

### 8.1 数据域与用途

| AI 研判追溯 | AI 场景配置与上述结构化事实 | 原因、动作、时点和关键证据解释 | `AI-RULE-2026.07-v1`；默认确定性规则研判 |

### 8.2 当前原型源文件与接入事实

当前学生方案装载器使用白名单字段读取：

- `学籍信息.xlsx`：学号、姓名、年级、学院、专业、行政班、学籍状态、培养方案、入学日期等；
- `专业方案全部计划课程 (1).xlsx`：方案、年级、专业、课程模块、课程代码、课程性质、开课学期、学分、开课部门等；
- `2021级学生成绩.xlsx`：学期、学号、课程、成绩、尝试类型、通过状态、发布状态、学分等；
- `课程替代.xlsx`：学生、原课程、替代课程、审核结果、流程状态和完成时间；
- 方案原文与模块要求解析结果；
- 已接入的真实教学任务和教师关联。

仓库交接文档记录的原型覆盖为 53 个 2022 级培养方案，其中 39 个方案取得总学分、毕业要求原文和模块要求。该数量是当前数据批次事实，不是产品固定上限；页面必须随数据批次动态变化。

### 8.3 来源、批次和时间要求

1. 每个源文件记录文件路径、哈希、导入时间、源行数、接收行数与质量状态；
2. 每次推导保存规则版本、计算时间和 `source='derived'`；
3. 页面重要结论至少可追溯到学生、方案、模块、课程、规则来源和数据批次；
4. 生产系统应由成绩发布、课程认定、方案调整和绑定变更事件触发增量重算，而不是长期依赖全量重建；
5. 页面目前除 AI 抽屉外没有统一显示数据时点；**正式要求：** KPI、名单、导出和证据应携带数据截至时间与规则版本。

### 8.4 当前可用与不可用边界

#### 当前可用于管理核查

- 已接入方案的年级、专业、课程池和模块规则；
- 学生当前方案绑定及其与年级、专业的一致性；
- 已发布、未作废的有效课程结果；
- 审批通过且流程结束的课程替代；
- 基于可信最低学分、最低门数或逐门必修的模块状态；
- 明确未通过与到期缺结果候选的分层名单；
- 已接入历史教学任务中的开课、教师、容量和排课文本。

#### 当前不足或未接入

- 2021 级及以前的完整培养方案源；
- 个人完整选课、退选、缓修、免修和数据同步状态；
- 转专业、留级、休复学后的正式方案适用与有效期规则；
- 完整课程组、跨模块重复计入和抵扣规则；
- 下一周期正式教学任务、重修班标识、容量、校区、时间冲突和修读资格；
- 正式“毕业要求 / 指标点—支撑课程—评价环节—实际结果”矩阵；
- 学校正式毕业资格和学位资格审核结果。

因此当前不能计算或输出：按期完成高风险学生、课程供给覆盖率、重修资源覆盖率、正式毕业要求达成度、能否毕业或能否获得学位。

### 8.5 AI 适用边界

- AI 输入必须是当前身份有权访问的结构化证据；
- AI 不得把缺结果候选改写为事实缺修；
- AI 不得把历史开课改写为未来承诺；
- AI 不得根据课程问题推断学生主观原因、态度或心理状态；
- AI 结论必须保留分析范围、事实来源、规则版本、数据时点和适用边界；
- 只有命中带模型名称、提示词版本、生成时间和审核状态的离线策展样例时，才可标为离线大模型样例；否则显示规则研判；
- 研判结果只支持人工核查，不自动执行补考、重修、替代、开班或毕业审核。

## 9. 异常、空态和验收规则

### 9.1 参数、权限和对象异常

| 场景 | 期望行为 |
|---|---|
| 总览未选择年级 | 前端提示“年级为必选项，请至少选择一个年级”，不请求接口 |
| 年级参数不能解析为整数 | 总览接口返回 422；毕业准备 / 课程保障接口返回 400 |
| 毕业准备状态不在固定枚举 | 返回 400“不支持的准备度状态” |
| 当前身份未授权 V2 | 返回 403，不显示任何跨范围数据 |
| 当前身份范围映射为空 | 返回 403，不回退全校 |
| 方案不在当前范围 | 返回 404“培养方案不存在或无权访问” |
| 学生不在当前范围 | 返回 404“学生不存在或无权访问” |
| 课程不在当前明细范围 | 返回 404“课程不存在或不在当前明细范围” |
| 切换当前工作身份 | 重新加载菜单、选项和页面数据；不得沿用上一身份缓存和表格偏好 |

### 9.2 页面空态与失败反馈

| 页面 / 区域 | 当前空态或失败行为 | 正式要求 |
|---|---|---|
| 培养方案选项 | 加载遮罩“正在读取可用培养方案…” | 失败时提供明确错误和重试，不只静默回落 |
| 方案执行总览 | 表格无记录时使用公共表格默认空态 | 区分“当前筛选无数据”“无权限”“方案源未覆盖”和接口失败 |
| 学生进度未选方案 | “请先选择培养方案” | 保持 |
| 学生进度详情失败 | “详情加载失败” + “重新加载” | 保持并记录错误日志 |
| 必修未通过 / 过期漏修课程 | 使用各自明确空态文案 | 不用空表伪装接口成功 |
| 毕业准备查询选项失败 | “查询条件加载失败，请重试” + “重试” | 保持；主题空结果不得清空备用选项 |
| 毕业准备主数据失败 | 当前主要依赖全局 HTTP 错误处理 | 增加页面级失败卡和重试，保留上次成功结果并标注未刷新 |
| 学生 / 课程证据抽屉失败 | 当前主要依赖全局错误处理 | 抽屉内显示失败、无权限、无数据与重试，不留下上一对象数据 |
| AI 加载 | “正在形成管理研判” + 骨架 | 保持 |
| AI 无内容 | “暂无AI管理研判内容” | 保持，并可显示规则未命中的原因 |
| 下一周期计划 | “尚未接入” | 不得显示 0 或“无风险” |
