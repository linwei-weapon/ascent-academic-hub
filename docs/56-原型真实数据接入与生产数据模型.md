# 56 · 原型真实数据接入与生产数据模型

> 目标：用 2026-07-12 补充数据使原型基本达到业务目标，同时让原型数据层能够平滑迁移到未来生产系统。

## 1. 实施结论

本批数据在原型阶段按“基本完整”处理，不再等待所有生产级条件满足。数据分三类使用：

1. **真实数据**：学生、学籍、培养方案、课程、成绩、教学任务、组织、班主任、导师、学期、楼宇、房间、异动、课程替代、毕业学位、校外考试和调课。
2. **真实数据派生**：学生课程完成状态、培养方案缺课、学分进度、挂科轨迹、早期困难学生、教师排课时间分布、课程团队结构、教室利用率。
3. **有限模拟**：出勤、尚未提供的选课过程、可报名重修资源和实践教学事实。模拟记录必须保留 `source='sim'`，不能作为学校真实结论。

原型使用批量 Excel/CSV 接入；生产系统使用源系统接口或受控文件交换。两者共享业务键、指标口径和目标表含义，不要求共享同一物理数据库。

## 2. 原型数据使用映射

| 数据域 | 原型用途 | 接入目标 | 处理原则 |
|---|---|---|---|
| 学年学期 | 筛选、趋势、课程日历基准 | `dim_semester` | 使用学校学期代码，不再仅由成绩推导 |
| 组织机构 | 学院/专业归属、权限范围 | `dim_organization`，兼容生成 `dim_college` | 保留组织代码和父子层级 |
| 2022 学籍 | 当前学生底表、班级/专业/方案 | `dim_student`、`fact_student_plan` | 只提取脱敏后的必要字段 |
| 2021 及以前学籍 | 历史队列、毕业学位、成长结果 | `dim_student_history`、`fact_graduation` | 按培养层次过滤，状态不再模拟 |
| 专业培养方案 | 应修课程、缺课、学分进度 | `fact_plan_meta/course/module_rule` | 53 个方案全部接入；组规则不足时采用保守口径 |
| 课程信息 | 分类、学分学时、考核方式 | `dim_course` | 课程代码为主键；历史失配进入映射表 |
| 成绩 | 挂科、重修、趋势、课程完成 | `fact_grade_attempt`，兼容生成 `fact_grade` | 保留原始记录；有效成绩由版本化规则派生 |
| 教学任务 | 开课、课程团队、排课分布 | `fact_lesson`、`fact_course_meeting` | 保留源教学班代码；解析周/星期/节次 |
| 班主任/导师 | 学生详情权限和成长关系 | `bridge_staff_student_scope` | 使用工号；缺有效期时按当前批次有效 |
| 课程替代 | 学生个人课程认定 | `fact_student_course_substitution` | 只用审核通过记录，不作通用等价规则 |
| 学籍异动 | 休复学、转专业、退学轨迹 | `fact_student_status_change` | 无流水号时使用文件＋行号＋行哈希 |
| 楼宇/房间 | 可用教室分母、楼宇利用率 | `dim_building/room`、`fact_room_availability` | 默认可用、非虚拟、座位数大于 0；允许管理员覆盖 |
| 调课 | 调停课分析、日历修正 | `fact_schedule_change` | 解析前后安排，按审批状态生效 |
| 校外考试 | 四六级分析 | `fact_external_exam_attempt` | 只覆盖实际提供学期 |

## 3. 原型优先形成的真实能力

### 3.1 成绩与挂科治理

- 一条源成绩对应一条 `fact_grade_attempt`，不互相覆盖。
- 补考、缓考、重修、替代分别保留类型。
- `fact_student_course_result` 统一输出有效成绩、是否通过、获得学分、依据记录和规则版本。
- 所有页面的挂科人数、挂科率、累计挂科和重修情况读取同一结果层。
- 正式规则未完全确认前，原型采用版本化临时口径：优先已发布且有效的最高通过结果；均未通过时取最近有效结果；替代审批通过后才抵扣。

### 3.2 学生成长轨迹

按学生和时间合并：学籍状态、专业/班级/方案变化、每学期修读与通过、挂科与重修、累计学分、课程替代、校外考试、毕业学位、班主任和导师关系。

首批重点标签：大一首次挂科、连续两学期挂科、同类课程重复失败、培养方案应修未完成、毕业/学位学分风险。预警后续处置闭环继续暂缓。

### 3.3 培养方案差异与建议

- `方案应修课程 - 已通过或已认定课程` 得到课程缺口。
- 建议学期已经过去且未完成，标记逾期未修。
- 已挂科且仍属毕业要求，标记重修候选。
- 选修模块只有在课程组规则充分时才做精确毕业审核。

当前缺少完整选课过程，因此页面应表述为“截至当前成绩/认定记录尚未完成”，不能宣称学生在某轮选课中主动漏选。

### 3.4 开课、排课、师资和空间资源

- 按课程、类别、年级、学院和学期统计开课及教学班。
- 解析教学任务时间，生成体育课、思政课等类别的星期×节次热力图。
- 教师偏好仅由历史实际排课结果统计，不提供主动填报入口。
- 同一课程按教师工号组成课程团队；只展示真实可用的职称结构，不补造学历和年龄。
- 房间利用率分母读取可用房间快照和管理员覆盖值。

## 4. 原型接入架构

```text
受控脱敏文件
    ↓ 批次登记、文件哈希、字段白名单
stg_* 原始暂存表
    ↓ 编码标准化、质量检查、对账
dim_* / bridge_* / fact_* 标准明细层
    ↓ 统一口径计算
fact_student_course_result / agg_* 应用层
    ↓
现有 FastAPI 与前端页面
```

建立新的 `analytics_v2.sqlite` 完成接入和对账，通过后切换 API 配置。不要在现有演示库上边导入边修正。

每次构建输出：数据批次、表行数、主键重复、必填缺失、孤儿键、编码失配、真实/派生/模拟行数和关键指标差异。

## 5. 生产系统数据分层

| 层级 | 职责 | 关键要求 |
|---|---|---|
| ODS/暂存层 | 原样接收教务、学工、人事和资源数据 | 来源、批次、行号、哈希、采集时间；追加不覆盖 |
| 主数据层 | 学生、人员、组织、课程、专业、方案、空间统一编码 | 代理键＋源业务键、历史拉链、编码映射 |
| 业务事实层 | 成绩尝试、选课、教学班、课程日历、异动、认定、毕业 | 事件粒度、原始状态、生效时间 |
| 规则结果层 | 最终课程结果、方案差异、成长标签、建议、预警 | 规则版本、计算批次、证据链、可重算 |
| 服务层 | API、权限、审计、导出 | 行列级权限、脱敏、访问审计、幂等接口 |

| 表 | 粒度 | 核心字段 |

## 8. 原型 V2 验收标准

1. 2022 学籍、方案绑定和方案课程覆盖达到可解释水平，未匹配项形成清单。
2. 2021 及以前学籍能够生成真实毕业、学位和异动统计。
3. 成绩页面统一使用同一份有效课程结果。
4. 成长轨迹至少展示学籍、修读、挂科、重修、认定、校外考试和毕业结果。
5. 课程开设、类别时序、教师排课分布和教室资源使用真实任务/资源数据。
6. 班主任和导师的数据可见范围可验证。
7. 页面口径能区分真实、派生和模拟；模拟不参与正式结论。
8. 构建可重复执行，不依赖手工修改数据库。

## 9. 实施顺序

1. 建立字段白名单和文件配置，不复制原始文件进仓库。
2. 扩展暂存表、学生方案、成绩尝试、有效结果、组织、房间、师生关系和异动 Schema。
3. 编写新增数据提取器；旧 `.xls` 优先转换为 `.xlsx`/CSV。
4. 完成课程、方案、学生和教师标识映射。
5. 接入真实学籍、方案、课程、教学任务、成绩和关系数据。
6. 重建成长轨迹、培养方案差异、课程开设、教师偏好和教室利用指标。
7. 前端逐模块切换并验收真实/派生/模拟来源。
8. 本模块全部完成后统一提交 Git。
