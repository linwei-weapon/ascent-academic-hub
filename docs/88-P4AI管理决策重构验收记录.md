# P4 AI管理决策重构验收记录

> 验收日期：2026-07-19
> 验收分支：`产品终稿`
> 范围：管理专家协议、首批三个专家、管理要情、决策研判、AI权限与追溯
> 结论：P4阶段门禁通过；低年级受挫和排课资源优化专家按计划留作后续扩展，不影响首批三个专家验收

## 1. 管理价值收口

P4不再给每一条业务数据平铺一段通用AI话术，而是把AI能力收口为“少量重要变化—管理问题—事实证据—临时测算—候选动作”。

| 能力 | 管理者看到什么 | 可以做什么 | 明确边界 |
|---|---|---|---|
| 管理要情 | 相对上次快照的新增、升级、扩大、缓解和退出事件，首屏最多3项 | 查看事实证据，或带着事件继续研判 | 数据不变时不重复制造任务 |
| 毕业准备核查专家 | 明确未通过、待核验证据、涉及学生和课程保障缺口 | 比较先核验、先分流或增开班的候选路径 | 不替代毕业审核，不把缺证据直接判定为未完成 |
| 高影响课程保障专家 | 跨学期未通过率、显著波动、影响学生和重修资源 | 调整本轮支持课程数、波动阈值和教师资源 | 不评价教师个人，不把相关性解释为因果 |
| 课程团队连续性专家 | 高覆盖或多班课程中的单点保障、学生覆盖和备份资源 | 模拟优先保障课程及备份教师需求 | 普通“一班一教师”不作为风险，不输出人才危机结论 |
| 决策研判 | 推荐问题、当前范围、临时条件、比较方案、证据和候选决策单 | 用自然语言或结构化控件调整本次条件 | 临时条件不改变正式口径，不能扩大授权范围 |

## 2. 专家协议与治理

管理专家协议标识为 `management-expert/1.0`。每个专家均登记：

- 专家名称、版本、适用角色、管理问题和管理价值；
- 所需数据、必需/可选条件和完整性检查；
- 指标公式、管理含义、规则、触发与抑制条件；
- 输出卡片、证据路由、追问意图、可调参数；
- 推荐动作、建议责任角色、办理时点和模拟器能力；
- 不确定性、适用边界和协议测试案例。

学校级覆盖只允许修改白名单阈值、参数默认值和推荐问题；不允许覆盖公式、数据来源和证据路由。专家版本支持草稿、发布和基于既有版本生成回滚版本。学校分析方案支持草稿和单独发布，保存草稿不会自动生效。

## 3. 数据证据与计算隔离

三个专家未复用同一组候选数据伪装成不同场景：

| 专家 | 主要事实表 | 关键证据 |
|---|---|---|
| 毕业准备核查 | `student_plan_course_status` | 学生—培养方案—课程完成状态、明确未通过、待核验证据 |
| 高影响课程保障 | `grade_attempt` | 课程跨学期成绩、未通过记录、重修尝试和波动 |
| 课程团队连续性 | `agg_course_team`、`agg_course_offering`、`teaching_lesson` | 教师数、教学班数、学生覆盖、团队结构证据 |

正式指标由确定性SQL和规则计算；自然语言只解释白名单临时参数，不直接计算正式指标，也不生成无证据趋势。

## 4. 权限与会话边界

- 专家目录、运行时和模拟接口使用当前工作身份的统一权限上下文。
- 学院身份只能看到本学院范围；辅导员等非适用角色不能读取管理专家。
- 自然语言出现“全校、其他学院、全部学院”等扩展请求时，在非全校身份下明确拦截。
- 解释接口校验范围指纹；切换身份或关系失效后，旧会话以409失效。
- 缓存键包含范围指纹、角色、专家版本、参数版本、学期和临时参数。
- 证据链接进入既有业务接口后再次执行后端鉴权。
- 只有具备 `system.manage` 的身份可以保存学校分析方案草稿；发布使用独立授权接口。

院级实测结果：

```json
{"role":"college_dean","scopeType":"college","scopeIds":["C01"],"requestedExpansion":true,"blocked":true,"availableTeachers":5,"recalculate":true,"temporaryOnly":true,"officialDefinitionChanged":false}
```

该结果证明系统可以理解“可协调教师改为5名”，但仍拒绝把范围扩大到全校；临时重算没有改写正式专家定义。

## 5. 管理要情验收

- 相同根因和对象使用稳定根键聚合。
- 事件状态支持新增、升级、变化、缓解和退出。
- 首屏变化事件最多3项；没有变化时显示“无新增重大事项”，持续事项保留但不重复标记为新增。
- 每项包含当前影响、为何现在看、首要动作、建议责任角色、时点和事实证据。
- 已绑定专家的事件显示“继续研判”；学生学业风险在低年级受挫专家完成前保留为事实证据入口，不伪造专家能力。
- “继续研判”已验证自动带入专家、事件、问题和学期。

## 6. 决策研判交互验收

浏览器按真实用户路径完成：

1. 进入“AI管理决策—决策研判”；
2. 在三个专家间切换，指标、约束、公式和来源随专家变化；
3. 对高影响课程保障专家输入“优先支持3门课程，把显著波动改为10个百分点”；
4. 页面复述为“优先支持课程：3门；显著波动阈值：10个百分点”，并更新临时条件；
5. 从管理要情的“毕业准备核查”点击“继续研判”，正确打开毕业准备核查专家并带入管理问题；
6. 浏览器控制台未发现运行错误。

页面不以空白聊天框开始，而是提供推荐管理问题；同时显示当前专家版本、角色、数据范围、学期、数据就绪状态和临时条件。恢复正式口径、保存学校方案草稿和证据查看均有独立入口。
