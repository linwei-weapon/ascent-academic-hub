# 52 · 学校基础数据需求与缺口清单

> 用途：供学校业务部门、信息化部门和源系统厂商分派数据补充任务。  
> 定位：生产系统建设前的数据合同草案，不要求第一批即提供未脱敏全量数据。  
> 基线日期：2026-07-12。

## 1. 当前原型数据基线

| 数据域 | 当前情况 | 主要限制 | 结论 |
|---|---|---|---|
| 学生 | 12,670 名当前快照学生 | 入学日期、学籍历史、导师/辅导员关系不足 | 可做当前聚合，不能完整还原成长过程 |
| 成绩 | 640,239 条真实记录 | 补考、重修、缓考、作废和成绩更正关系未标准化 | P0 补充并治理 |
| 教学班 | 50,115 条真实记录 | 星期、节次、周次、实际上课日期未形成标准课程日历 | 不能据此生成真实时段热力图 |
| 选课 | 有一份 2022 届脱敏样例源 | 缺全学期选退补选过程、失败原因和实时容量 | 不能准确判断应选未选 |
| 课程 | 有课程维表，源课程信息存在残缺 | 课程类别、历史变更、替代和先修关系不完整 | 需要正式课程主数据 |
| 培养方案 | 仅 2 个专业、2 个版本 | 无法覆盖全校学生 | P0 补充全校版本化方案 |
| 教室利用 | 当前时段利用聚合为 `source='sim'` | 缺可用教室台账和真实时段占用 | 不得用于生产结论 |
| 教师画像 | 437 条画像为 `source='sim'` | 年龄、学历、学缘、教龄非真实人事数据 | 仅可演示，不可迁移 |
| 毕业学位 | 2,286 条记录为 `source='sim'` | 缺真实毕业审核和未授位原因 | 不可验证毕业影响模型 |
| 出勤/异动/处分/调停课 | 当前部分为模拟业务事实 | 缺正式源系统数据 | 未取数前保持明确限制 |

## 2. 学校需补充的数据集

### P2：范围确认后再获取

- 出勤、请假和课堂行为数据。
- 奖惩、考试违纪和处分数据。
- 实验、实习、论文、创新学分等实践教学数据。
- 学生帮扶记录和外部通知回执；预警闭环是否纳入产品尚未决定。
- 多校组织、租户和跨校同步数据。

## 3. 关键数据集字段要求

### 3.1 成绩尝试 D06

至少需要以下业务键和状态：

- `student_id`、`course_id`、`lesson_id`、`semester_id`。
- 修读序号或考试批次号。
- 考试性质：正常、补考、重修、缓考等正式代码。
- 原始成绩、等级成绩、绩点、通过状态、获得学分。
- 成绩状态：有效、作废、更正中、已更正。
- 关联原成绩或原修读记录的标识。
- 录入、发布时间和最后修改时间。

没有“关联原记录”的情况下，必须由学校确认可接受的归并规则，不能只按最高分推断。

### 3.2 培养方案 D03/D04

- `plan_version_id`、专业、年级、培养层次、生效/失效时间。
- 课程模块、课程性质、最低学分、最低门数、建议学期。
- 课程组、任选/限选规则、替代课程和等价课程。
- 先修、并修、后续关系。
- 毕业总学分、必修学分、实践学分及学位条件。
- 转专业、留级等学生个别适用方案。

### 3.3 选课过程 D05

- 选课记录主键、学生、教学班、课程、学期。
- 操作类型和时间：选课、退课、补选、管理员调整。
- 选课轮次、结果、失败原因和限制原因。
- 操作时教学班容量、已选人数和剩余名额。
- 最终有效选课状态。

### 3.4 课程日历 D08

- 教学班、课程、教师及教师角色。
- 面向专业、年级、行政班或选课学生。
- 星期、起止节次、起止周、单双周、实际日期。
- 校区、教学楼、教室。
- 正常班、重修班、补修班等班型。
- 原始排课和调停课后的实际排课均需保留。

### 3.5 权限关系 D09

- 用户统一身份标识与业务人员标识映射。
- 辅导员负责班级的有效期。
- 导师/班主任负责学生的有效期。
- 任课教师与教学班、学生的当前关系。
- 学院、系部、专业管理岗位和授权范围。

## 4. 每个数据集必须随附的元数据

学校提供数据时，应同时填写：

| 项目 | 要求 |
|---|---|
| 来源 | 系统名称、库/接口、业务负责人、技术负责人 |
| 标识 | 主键、业务唯一键、跨表关联键 |
| 范围 | 历史起点、当前数据量、是否包含已毕业学生 |
| 更新 | 全量/增量方式、频率、延迟、删除表达方式 |
| 代码 | 枚举值、状态流转、历史代码变更 |
| 质量 | 已知缺失、重复、错误和人工修正规则 |
| 安全 | 敏感级别、脱敏方式、授权和保留期限 |
| 样例 | 20～100 条脱敏代表性记录，覆盖正常和异常状态 |

## 5. 首批取数交付方式

第一批不要求立即交付生产全量库，建议按以下顺序：

1. 字段字典和代码表。
2. 脱敏样例数据。
3. 表关系、主键和历史范围说明。
4. 数据量与增量更新说明。
5. 通过样例验收后再提供授权环境中的全量或接口。

文件或接口均须携带批次号、生成时间、来源系统和口径版本。禁止通过姓名、课程名称等文本字段作为唯一关联键。

## 6. 数据验收标准

- 主键唯一，跨表业务键可以稳定关联。
- 代码值均有解释，未知值有处理策略。
- 能用选课、成绩和方案数据复现至少一个学生的完整课程状态。
- 能用课程日历复现至少一门课程一个学期的全部上课安排。
- 能区分原始考试尝试与当前有效成绩。
- 能区分真实源数据、业务派生数据和人工配置。
- 样例数据不得包含无关个人敏感信息。
- 缺失数据必须返回明确空值，不使用模拟值填补生产字段。

## 8. 当前待学校确认的业务问题

1. 补考、重修通过后，学校正式的“当前未通过”口径是什么。
2. 学位审核使用最高成绩、最终成绩还是指定有效成绩。
3. 转专业学生适用原方案、现方案还是个别方案。
4. 应选未选的提醒时间点及选课例外如何认定。
5. 重修资源是否允许跨专业、跨年级或跟班修读。
6. 任课教师可查看学生成长记录的最小必要范围。
7. 预警后的业务处置是否进入本产品范围。

## 10. V2 验证后的口径修订

V2 接入验证已完成，上一节的“待建设”表述以 `57`～`67` 号报告为最新状态：

- 已建立独立 V2 验证库，原分析库未被覆盖。
- 教学任务、课程日历解析、课程团队、教师历史排课分布、楼宇和房间主数据已进入原型验证。
- 教室可用状态与数量属于上游主数据，本系统只消费、核验和分析，不建设维护入口。
- 体育、思政课程当前采用临时关键词识别；生产仍缺正式课程标签代码表。
- 教师职称存在缺失，年龄段、课程资格、课程负责人和有效期仍需生产数据补充。
- 目前教学运行真实数据只形成一个可用学期样本，长期排课偏好和团队稳定性分析仍需多学期课程日历。
- 全量选课过程、重修资源和正式成绩归并规则仍是影响培养方案干预建议的主要缺口。
