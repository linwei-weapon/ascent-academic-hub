# 分析方案管理 UE 深度走查与优化方案

日期：2026-07-25
任务：P5-06
状态：已实施并通过自动化、真实数据副本和生产构建验证

## 1. 产品定位

分析方案管理是“学校管理分析方法的配置、验证、发布与版本治理中心”。

学校可以调整：

- 已登记的管理关注阈值；
- 管理事项优先级参数；
- 专题默认分析条件；
- 适用管理角色；
- 学校方案名称和变更原因。

学校方案不能调整：

- 正式指标分子、分母和计算公式；
- 数据来源及证据路由；
- 用户的组织、学院、班级或学生范围；
- 学生、教师、成绩等业务事实；
- 模型密钥和统一身份认证密钥。

## 2. 走查发现

### 2.1 原分析方案没有形成运行闭环

原页面读取`sys_ai_analysis_scheme`，只提供测试、发布、停用和角色调整，没有创建、
复制、编辑和查看参数入口。正式库保存方案为0，用户进入页面只能看到空表。

更重要的是，AI决策简报、专题工作区和专家问策实际读取的是
`sys_ai_skill_config`；旧分析方案即使发布，也不会改变业务运行结果。

### 2.2 存在两套重复治理能力

- “分析方案管理”维护旧管理专家和旧方案表；
- “决策配置”维护当前四个实际运行Skill的阈值与版本。

两套页面均描述草稿、发布和回滚，导致管理员不知道在哪一处调整，实施人员也需要
维护两套相互漂移的数据模型。

### 2.3 原测试只有形式校验

旧测试只判断专家、版本、参数和角色，权限边界固定为通过；没有检查学校数据是否
就绪，没有使用当前数据试运行，也不比较新旧方案会改变哪些管理信号。

### 2.4 UE不满足完整任务路径

- 首屏空态不能回答“当前实际采用什么方案”；
- 管理参数没有中文意义、默认值、当前值、单位和可调范围；
- 没有未保存提示、数据就绪提示和发布影响预览；
- 表格未使用公共`DataTable`；
- 发布、停用和角色调整会造成版本语义不完整。

## 3. 统一运行模型

### 3.1 唯一真值源

当前四个真实运行的管理分析能力统一作为产品模板：

1. 毕业缺口核查；
2. 课程质量趋势；
3. 预警优先级；
4. 师资结构核查。

运行配置只从`sys_ai_skill_config`解析。旧`sys_ai_analysis_scheme`和
`sys_ai_expert_version`保留一个兼容周期，不再作为页面和运行主链。

### 3.2 产品默认与学校覆盖

- 没有学校版本时，任何适用角色均使用产品默认；
- 每个专题最多存在一个已发布学校版本；
- 学校版本可以覆盖多个管理角色；
- 未被学校版本覆盖的角色继续使用产品默认；
- 组织和学生范围不进入方案，始终按当前工作身份实时计算。

### 3.3 版本与缓存

- 草稿修改后，原测试结果立即失效；
- 只有测试状态为`passed`的草稿可以发布；
- 新版本发布后，同专题上一学校版本退役；
- 回滚以历史版本为蓝本生成新的已发布版本，不覆盖历史；
- 决策简报缓存指纹包含每个专题的配置版本，发布后不会复用旧方案快照。

## 4. 发布前检查

发布前检查包含五项：

| 检查 | 含义 |
|---|---|
| 参数边界 | 所有调整只使用Skill登记的白名单参数，并在上下限内 |
| 数据就绪 | 必需表存在，非必需表缺失时披露降级边界 |
| 角色边界 | 适用角色属于AI管理决策授权角色且不能为空 |
| 协议版本 | 草稿基于当前`decision-skill/1.0`协议 |
| 当前数据试运行 | 使用系统管理员全校业务数据权限执行一次只读试运行 |

试运行比较当前生效方案与草稿：

- 全部管理信号数；
- 高优先级信号数；
- 新增信号标识；
- 退出信号标识。

变化只用于核查发布影响，不形成开课、预警处置或教师评价结论。

## 5. 页面结构

### 5.1 四项管理状态

- 产品标准方案；
- 学校生效方案；
- 待发布草稿；
- 需要处理事项。

卡片可切换页面关注范围，不只展示数字。

### 5.2 正在使用

正式库即使没有学校方案，也常驻显示四个产品标准模板。每个模板显示：

- 管理问题；
- 产品默认或学校版本；
- 数据就绪状态；
- 适用角色；
- 查看、配置、调整和停用入口。

### 5.3 草稿与发布

草稿表使用公共`DataTable`，支持列显隐、列顺序、显示上限、密度和分页偏好。

编辑抽屉展示：

- 学校方案名称；
- 中文参数名称和管理含义；
- 产品默认值、草稿值和允许范围；
- 适用角色；
- 变更原因；
- 未保存关闭确认。

### 5.4 版本与变更

版本表展示状态、适用角色、变更原因、形成方式、创建/发布信息，并提供方案包导出
和基于历史版本回滚。

### 5.5 发布影响

检查弹窗使用人可理解的五项检查结果和新旧信号数量对比。失败时直接显示缺失数据、
无效参数或试运行错误，不只显示“未通过”。

## 6. 快速实施能力

- 四个产品模板从注册表自动发现，新学校不需要初始化方案数据；
- 可一键基于当前生效值生成学校草稿；
- 方案包支持JSON导入、导出；
- 方案包不包含业务数据、组织范围或模型密钥；
- 导入只生成未测试草稿，不能绕过检查直接发布；
- 旧“决策配置”菜单退出，旧地址兼容跳转至分析方案管理；
- LLM接入方式和允许范围由系统参数治理，方案页只显示就绪状态；
- 幂等迁移兼容旧`sys_ai_skill_config`表并自动补齐角色映射。

## 7. 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/admin/ai/decision/config/skills` | 产品模板、学校方案、数据就绪和版本 |
| POST | `/api/admin/ai/decision/config/skills/{skill_id}/draft` | 创建学校草稿 |
| PUT | `/api/admin/ai/decision/config/skills/{skill_id}/draft/{config_id}` | 修改草稿并使旧测试失效 |
| POST | `/api/admin/ai/decision/config/skills/{skill_id}/test/{config_id}` | 发布前检查和影响预览 |
| POST | `/api/admin/ai/decision/config/skills/{skill_id}/publish` | 发布通过检查的草稿 |
| POST | `/api/admin/ai/decision/config/skills/{skill_id}/retire` | 停用并回退产品默认 |
| POST | `/api/admin/ai/decision/config/skills/{skill_id}/rollback` | 生成新的回滚发布版本 |
| GET | `/api/admin/ai/decision/config/skills/{skill_id}/export/{config_id}` | 导出无业务数据的方案包 |
| POST | `/api/admin/ai/decision/config/schemes/import` | 导入为未测试草稿 |

全部接口要求系统管理员权限。创建、修改、测试、发布、停用、回滚、导入和导出均写
安全审计。

## 8. 数据结构

`sys_ai_skill_config`新增：

- `scheme_name`
- `base_protocol_version`
- `test_status / test_result_json`
- `tested_by / tested_at`
- `action / source_config_id`

新增`sys_ai_skill_config_role`保存版本—角色关系。方案不保存组织或学生范围。

## 10. 生产边界

1. 学校新增分析能力应先注册确定性取数、数据要求、配置边界和证据路由，再进入方案管理。
2. 方案只承载学校管理方法，不承载指标公式和数据权限。
3. 模型密钥仍由学校批准的部署环境或密钥管理系统提供。
4. 生产多实例部署时，方案发布和版本号生成需要使用数据库事务或配置中心锁。
