# 指标与口径管理UE深度走查与优化方案

> 日期：2026-07-25
> 分支：`产品终稿`
> 范围：系统管理 / 指标与口径管理
> 结论：已按确认方案完成实施与回归

## 1. 模块定位

“指标与口径管理”不再作为八项仪表盘卡片的展示开关，而是平台正式指标目录、
学校口径确认和页面实现一致性核查工作台。

本模块服务三类工作：

1. 教务业务人员确认指标名称、计算逻辑、边界和管理价值；
2. 实施人员判断学校还需确认什么、数据是否具备以及哪些指标已进入页面；
3. 开发人员核查正式定义、技术标识、计算版本和页面引用是否一致。

本模块不允许执行自然语言公式或任意SQL；关注阈值、优先级和适用角色归属
“分析方案管理”，不再与正式指标分子、分母混在一起。

## 2. 走查发现

### 2.1 覆盖不完整

- 客户确认材料中有214行指标表记录，去重后为207个稳定指标编号；
- 原正式库只登记12项，前台固定查询`module=dashboard`，实际只展示8项；
- V2 `metric_definition`为空，形成“文档、V1配置、V2目标表”三处断裂；
- 四项课程质量指标虽已登记，但原页面不可见。

### 2.2 定义与实现不一致

- 原`current_fail_rate`登记为未通过成绩记录数÷有效成绩记录数，现行总览实际是
  去重挂科学生数÷有有效成绩学生数；
- 原`history_fail_rate`登记和现行总览使用了不同分母；
- 应届毕业率、学位授予率已有历史登记，但现行总览因只有合成结果而不再使用；
- 原页面的显隐、排序和阈值对现行总览结构已基本不生效。

### 2.3 交互问题

- 面包屑错误地把指标配置归在账号管理下；
- 主表横向字段过多，所有指标均提供没有管理意义的阈值输入；
- 没有业务域、定义状态、实现状态和页面引用筛选；
- 详情无法说明管理价值、错误解读边界和实际实现证据；
- 保存提示与真实生效页面不一致。

## 3. 已完成的数据治理

### 3.1 统一目录

新增：

- `sys_metric_definition`：正式定义、候选定义、范围背景和历史兼容目录；
- `sys_metric_page_binding`：指标定义版本与页面实现版本的显式绑定；
- `code/backend/metric_catalog.py`：从版本化确认文档读取结构化指标表，并叠加由代码
  维护的实现证据。

正式库迁移结果：

| 类型 | 数量 |
|---|---:|
| 客户确认指标稳定编号 | 207 |
| 范围背景/历史兼容记录 | 3 |
| 统一目录合计 | 210 |
| 已实现并验证 | 10 |
| 待学校确认 | 198 |
| 已停用或迁移 | 2 |
| 已绑定页面 | 5 |

“待学校确认”表示建议口径尚待学校确认或尚未建立实现绑定证据，不等同于功能缺失。

### 3.2 首批口径纠偏

- `current_fail_rate`正式名称改为“当前挂科学生率”；
- 分子改为当前学期至少一门明确未通过的去重学生数；
- 分母改为当前学期至少一条有效成绩的去重学生数；
- “历史挂科经历率”统一使用有历史有效成绩的学生作为分母；
- Dashboard的实际聚合与登记口径同步修改；
- 应届毕业率和学位授予率从现行页面配置中停用，保留历史兼容记录；
- 首次、补考、重修、公共必修首次通过率进入统一可见目录。

### 3.3 性能处理

目录只在幂等迁移时完整生成，普通列表、摘要和详情请求不再重复解析207项定义并写库。
本机直接调用摘要、20行列表和单项详情组合20次：

- 平均耗时：1.65ms；
- P95：1.44ms；
- 最大值：11.22ms。

服务启动原有师资全量预热会阻塞健康检查和登录。现改为环境变量
`BI_WARM_FACULTY_CACHE=1`时才可选启用，默认不在启动阶段争用CPU。

## 4. 已完成页面设计

### 4.1 管理概览

顶部五项可点击卡片：

1. 统一指标目录；
2. 已实现并验证；
3. 待学校确认；
4. 实现不一致；
5. 已停用或迁移。

卡片点击后直接筛选对应指标清单，不刷新整页。

### 4.2 指标目录

- 支持业务域、定义状态、实现状态和关键词组合查询；
- 使用服务端分页；
- 主表接入公共`DataTable`；
- 支持显示列、列顺序、行密度和每页行数；
- 识别列、操作列固定，业务列同时显示上限为7列；
- 候选指标和已发布指标使用不同状态，避免把“已讨论”误读为“已上线”。

### 4.3 页面引用与一致性

按页面汇总：

- 已绑定指标数；
- 定义与实现版本一致数；
- 待核查数；
- 最近核验时间；
- 当前一致性状态。

### 4.4 指标核查抽屉

抽屉包括：

- 管理解释；
- 不应如何解读及学校待确认边界；
- 完整计算逻辑；
- 数据来源、粒度、周期和技术标识；
- 页面引用、展示名称和实现版本；
- 展示配置变更记录。

### 4.5 版本与治理规则

页面明确区分：

- 正式指标定义；
- 页面展示配置；
- 分析阈值与学校管理方案。

提供带当前筛选条件的CSV指标确认清单导出。

## 5. 接口

| 接口 | 用途 |
|---|---|
| `GET /api/admin/settings/metric-catalog/summary` | 目录治理摘要 |
| `GET /api/admin/settings/metric-catalog` | 服务端分页、筛选和搜索 |
| `GET /api/admin/settings/metric-catalog/{metric_id}` | 定义、实现和页面证据 |
| `GET /api/admin/settings/metric-catalog/pages` | 页面引用一致性 |
| `GET /api/admin/settings/metric-catalog/export` | 导出电子确认清单 |

原`kpi-config`接口保留一个兼容周期，只用于旧展示配置，不再作为正式指标目录。

## 7. 生产交接

1. 学校确认后，将候选指标按版本转为已确认或已发布；
2. 页面新增正式指标时必须同时增加定义、计算、权限、页面绑定和测试；
3. 学校特有阈值进入分析方案，不修改指标定义；
4. 生产系统可把当前目录映射到统一指标平台或数据中台接口；
5. 正式口径变更须升级版本，不直接覆盖历史定义。
