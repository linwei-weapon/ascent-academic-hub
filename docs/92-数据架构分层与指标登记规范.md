# 数据架构分层与指标登记规范

> 日期：2026-07-22 ｜ 分支：产品终稿 ｜ 任务：M4（ETL 采集监控 + 数据分层收口）
> 关联：`docs/91-管理分析增强实施计划.md` M4 节、`code/backend/etl/schema_v2.sql`、`code/scripts/migrate_etl_run.py`

## 1. 四层架构总览

平台只消费、分析和挖掘教务数据，不维护学校业务主数据。数据按职责分四层，
上层只能读下层，禁止跨层回写。

```
贴源层（raw）        源文件与采集批次台账
  └─ data_batch、各数据源 Excel/交换平台文件
事实层（fact）       最小粒度业务事实，保留 source 标识
  └─ grade_attempt、fact_grade、fact_lesson、staff_student_scope …
聚合层（agg）        面向分析主题的预聚合，builder 幂等重跑
  └─ agg_course_pass_stat、agg_course_offering、agg_course_team …
指标层（metric）     管理口径登记与展示配置
  └─ sys_kpi_config（现役）、metric_definition（目标登记处，0 行待合流）
```

### 1.1 贴源层

- 每个源文件一次接入登记一条 `data_batch`：`batch_id / source_code /
  source_file / file_hash / collected_at / ingested_at / row_count /
  accepted_count / rejected_count / quality_status`。
- `UNIQUE(source_code, file_hash)`：同一文件重复接入不产生重复批次。
- 批次只追加不修改；源文件修复后重新采集形成新批次，旧批次保留可追溯。

### 1.2 事实层

- 表命名 `fact_*`（V1 库）或 V2 核心事实表（`grade_attempt`、
  `student_course_result`、`student_status_event`、`staff_student_scope` 等）。
- 每行必须带 `source` 标识（`real` / `real_partial` / `derived` / `sim`），
  真实数据、推导数据和演示数据不得混写。
- 事实行可溯源到贴源批次（如 `grade_attempt.batch_id + source_row_no`）。

### 1.3 聚合层

- 表命名 `agg_*`；每张 agg 表必须有对应 builder，且 **幂等可重跑**
  （先删后插或按版本整体替换，如 `agg_course_pass_stat` 的
  `build_course_pass_stat`）。
- 聚合行的 `source` 恒为 `derived`；口径版本写入 `rule_version`，
  口径变化必须升版本而不是原地改数。
- builder 执行结果落 `etl_run`（成败、行数、校验 JSON、耗时），
  在「系统管理 → 数据采集监控」可查证。

### 1.4 指标层

- 现役登记处：`sys_kpi_config`（指标与口径管理页），字段含
  `formula / data_source / grain / update_cycle / management_value`。
- 目标登记处：V2 `metric_definition(metric_id, version, grain, formula,
  source_policy, valid_from, valid_to)`，表已建（0 行）。
  **本阶段只做文档约定，正式合流列入遗留**（见 §4）。

## 2. 指标登记约定（强制）

1. **新指标必须先登记口径再上线**：先写 `sys_kpi_config`（formula 为
   自然语言口径 + data_source + grain），再改后端计算与前端展示；
   后端计算、前端展示、指标登记三处口径必须一致（AGENTS.md 修改纪律）。
2. 指标口径写清：分子/分母、有效记录过滤条件、空值与分母为 0 的处理、
   数据来源表、粒度、更新周期。
3. 口径变更升版本（`version` 字段或 `rule_version`），旧口径证据保留可查。
4. AI 与页面不得发明未登记指标；未登记数字只能以"临时测算"名义出现并标注。

### 范例：M1 课程通过率三分层（已按约定执行）

| 指标 kpi_id | 口径要点 | 数据源 | 粒度 |
|---|---|---|---|
| course_first_pass_rate | 首次修读链路（regular+缓考等）通过÷有效人次；有效=已发布且未作废且 is_pass 非空；分母 0 存 NULL | agg_course_pass_stat | 课程×学期 |
| course_makeup_pass_rate | 补考通过÷补考有效人次 | agg_course_pass_stat | 课程×学期 |
| course_retake_pass_rate | 重修通过÷重修有效人次 | agg_course_pass_stat | 课程×学期 |
| public_required_first_pass_rate | 公共必修课程组的首次通过率；类别=培养方案模块+V1 category 合并推导 | agg_course_pass_stat | 全校/学院×学期 |

登记脚本：`code/scripts/migrate_course_pass_stat.py`（INSERT OR IGNORE，幂等）；
聚合 builder：`code/backend/etl/v2_course_pass_builder.py`（幂等全量重建，
运行历史落 `etl_run`）。

## 3. ETL 运行治理

- `etl_run`（V2 库）：`run_id / task / batch_id / started_at / finished_at /
  duration_ms / status(running|success|failed) / rows_read / rows_written /
  checks_json / error / triggered_by / source`。
- 公共 helper：`code/backend/etl/run_log.py` 的 `run_logged` 上下文；
  各 loader/builder 只在公共入口包一层，失败也落记录。
- 并发保护：`uq_etl_run_running_task` 唯一部分索引保证同任务至多一条
  running；手动触发接口遇 running 返回 409。
- 手动触发仅白名单任务（`TRIGGER_TASKS`），需 `etl.trigger` 动作权限，
  每次触发写 `sys_security_audit`。
- 原型期不内置调度器；采集频率以 `sys_system_parameter` 的
  `data.refresh_mode / data.refresh_cron` 展示，定时由学校数据交换平台触发。

## 4. 遗留

- `metric_definition` 与 `sys_kpi_config` 正式合流（指标层双登记处归一）。
- 其余 V2 loader/builder（history/master/scope/growth 等）入口补 `run_logged`。
- 内建定时调度器（待学校数据交换平台对接方案明确）。
- `data_quality_issue` 的采集域（domain='collection'）问题自动登记；
  当前监控页只读引用教学运行域的 open 计数。
