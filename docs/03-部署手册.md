# 03 · 部署手册

> 从零把系统跑起来。包含环境要求、初始化、启动、验证、常见报错。

---

## 1. 环境要求

| 软件 | 版本 | 说明 |
|---|---|---|
| Python | 3.11+（推荐 3.13） | 后端 + ETL |
| Node.js | 18+（推荐 20+） | 前端构建 |
| pnpm | 8+ | 前端包管理（`npm i -g pnpm`） |
| 操作系统 | Windows / macOS / Linux | 脚本提供 .bat 与 .sh 两版 |

磁盘：GitHub 脱敏演示初始化约需 500MB；接入完整源数据时建议预留 ≥ 1.5GB。

> **Windows 终端编码**：中文环境默认 GBK，跑 Python 务必带 `PYTHONIOENCODING=utf-8 python -X utf8`，
> 否则日志中文乱码。提供的 .bat 脚本已内置 `chcp 65001` + 环境变量，直接双击即可。

---

## 2. 部署步骤

### 步骤 1：安装后端依赖

```bash
cd code/backend
pip install -r requirements.txt
cd ..
```

（建议用虚拟环境：`python -m venv .venv` 后激活再装。）

### 步骤 2：初始化分析库（跑 ETL）

分析库文件不直接提交到 Git。初始化脚本会优先读取 9 学期教务源库执行正式 ETL；GitHub 源码检出未携带教务源库时，会自动生成脱敏、可重复的轻量演示库、V2 库及四级累计学期源库，确保基础报表菜单和九张报表均有可查询、可导出的演示结果。

- **Windows**：双击 `code/scripts/init.bat`
- **macOS / Linux / Git-Bash**：
  ```bash
  cd code
  bash scripts/init.sh
  ```

脚本会：① 有教务源库时运行 `backend.etl.run_etl`，无源库且无现有分析库时运行 `scripts/bootstrap_demo_data.py`；② 依次执行菜单、预警规则、统一权限、人员关系、系统管理、学生成长索引和基础报表幂等迁移。新部署不会遗漏工作身份、数据权限、四级一级菜单、九个基础报表菜单、指标口径和系统参数。正式 ETL 约 1-3 分钟，演示初始化通常在 1 分钟内完成。

产物：`code/backend/db/analytics.sqlite`。

> 手动等价命令（在 `code/` 目录下）：正式数据执行 `PYTHONIOENCODING=utf-8 python -X utf8 -m backend.etl.run_etl`；无源库演示执行 `PYTHONIOENCODING=utf-8 python -X utf8 scripts/bootstrap_demo_data.py`，随后执行 `scripts/migrate_basic_reports.py`；脚本发现现有分析库时默认拒绝覆盖，只有人工确认重建后才能给演示生成命令增加 `--force`。

### 步骤 3：安装前端依赖

```bash
cd code/frontend
pnpm install
cd ..
```

### 步骤 4：启动前后端

- **Windows**：双击 `code/scripts/start.bat`（两个独立窗口）
- **macOS / Linux**：
  ```bash
  cd code
  bash scripts/start.sh   # Ctrl-C 同时停止前后端
  ```

启动后：
- 后端：http://localhost:8000/api/health → 应返回健康包络
- 前端：http://localhost:3006/ → 登录页

进入“系统管理 → 分析方案管理”，首次部署即应看到4项产品标准方案。没有学校
个性化版本时显示“产品默认”，不需要手工初始化方案记录。旧“决策配置”地址会
自动跳转到分析方案管理。

### 步骤 5：登录验证

用 **dean / Demo@2026** 登录，应看到“教学管理分析 → AI管理决策 → 基础报表 → 系统管理”四个一级分组、全部业务模块和九个系统管理入口。
兼容账号 `admin` 使用同一强密码；历史密码 `admin123` 已由幂等迁移停用。

进入“基础报表”，应看到 9 个统计报表菜单。选择 `2025-2026-2` 学期和 `2022` 级查询，各报表应返回结果；导出 Excel 应包含与页面一致的首行标题。GitHub 脱敏演示数据的人员姓名、学号、组织和成绩均为构造内容，`source=demo`，不得作为学校正式结论。

进入“系统管理 → 数据采集监控”，应看到18项数据源目录。接入状态与校验状态分别
显示；实际教室占用应出现在“教室占用”域。初始化脚本会幂等执行
`scripts/migrate_etl_run.py`，建立数据源目录、运行—批次关联和查询索引。

## 3. 数据一致性自检（可选）

后端起着时，跑端到端核对脚本（无第三方依赖，逐接口与库现算基线比对）：

```bash
cd code
PYTHONIOENCODING=utf-8 python -X utf8 scripts/e2e_check.py
# 或指定地址： ... scripts/e2e_check.py --base http://localhost:8000
```

退出码 0 = 全部通过。

## 4. 手动分步启动（不止脚本）

后端（在 `code/` 目录）：
```bash
PYTHONIOENCODING=utf-8 python -X utf8 -m uvicorn backend.api.main:app --port 8000
```

前端（在 `code/frontend/` 目录）：
```bash
pnpm dev
```

前端生产构建：
```bash
cd code/frontend && npm.cmd run build
```

> 生产部署时前端 `dist/` 需把 `/api` 反代到后端，或改 `.env` 的 `VITE_BASE_URL` 与代理目标。

## 5. 常见报错

| 现象 | 原因 | 处理 |
|---|---|---|
| ETL 报找不到源库 | datasource 路径不对 | 确认 `datasource/构造数据/` 下有 9 个 `*.db`；或设环境变量 `TS_DIR` 指向源库目录 |
| ETL 报缺培养方案 | 缺 docx | 确认 `datasource/培养方案docx/` 下有 2 个 `.docx`；或设 `DATA_DIR` |
| 日志中文乱码 | 终端 GBK | 加 `PYTHONIOENCODING=utf-8 python -X utf8`，或用 .bat 脚本 |
| start 提示未找到分析库 | 没跑 init | 先跑 `init.bat`/`init.sh` |
| 前端 404/接口空 | 后端没起 / 端口占用 | 确认 :8000 在跑；改端口见下 |
| 改了后端代码不生效 | uvicorn 未开 reload | 重启 uvicorn（脚本特意未开 `--reload`） |
| `pnpm: command not found` | 未装 pnpm | `npm i -g pnpm` |
| 旧管理员弱密码仍可登录 | 未执行最新系统管理迁移 | 在 `code/` 下运行 `python -X utf8 scripts/migrate_system_management.py` |

### 改端口
- 后端：启动命令 `--port 8001`，同时改前端 `vite.config.ts` proxy target。
- 前端：改 `code/frontend/.env` 的 `VITE_PORT`。

---

## 6. 重新初始化 / 换数据源

- **重建分析库**：直接重跑 `init` 脚本（ETL 幂等，先 DROP 再 CREATE）。
- **换一批源数据**：把新的 9 学期库放到 `datasource/构造数据/`（或设 `TS_DIR` 环境变量），重跑 init。
  注意源库 schema 需与现有一致（19 张业务表，见 `datasource/构造数据/README.md`）。

## 7. 私有云生产部署补充

- 使用学校域名、HTTPS 和反向代理，前端静态资源与 `/api` 分离部署。
- 使用学校统一身份认证，认证密钥通过环境变量或密钥管理服务提供。
- 数据库、模型、统一身份认证和日志服务使用最小权限账号。
- 按等保二级要求配置访问控制、操作审计、备份恢复、主机与应用日志留存。
- 若学校批准使用云端大模型，仍须在当前工作身份授权范围内调用，并保留来源与审计。
- 生产环境不保留公开演示账号；初始管理员密码通过部署流程单独交付并首次登录修改。
