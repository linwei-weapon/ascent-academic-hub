## 文档说明

### 0. 快速反馈入口

如需先组织教务处与二级学院进行第一轮电子反馈，请先填写
`docs/104-学校电子反馈导航与重点确认清单.md`。该清单归并了12项跨模块基础口径、六个业务模块的重点讨论问题、生产数据接口、数据权限和四类学校分析方案；本文件继续作为全部指标名称、计算逻辑、数据来源和边界的完整确认依据。

### 1. 文档目的

本文件用于以电子文档方式，与学校教务处及二级学院共同确认本科教学数据分析需求。文件不依赖系统原型，重点确认以下问题：

1. 学校实际需要回答哪些管理问题；
2. 哪些指标具有管理决策价值；
3. 每个指标的统计对象、计算公式和业务边界是否符合学校制度；
4. 管理者看到异常后，需要核查哪些对象、采取哪些行动；
5. 学校是否具备相应数据，以及数据由哪个部门或系统提供；
6. 哪些需求应纳入生产系统，以及各项需求的建设优先级。

本文件不是系统验收文件，也不预设学校必须采用其中全部指标。文中公式分为“建议正式口径”和“原型阶段暂行口径”。所有影响成绩、挂科、预警、毕业和学位判断的规则，须经学校确认后才能作为生产系统正式口径。

平台包含“教学管理分析”与“AI管理决策”两类能力。本确认书只确认教学管理分析的指标口径，AI管理决策的需求本期不展开，另行确认。

### 4. 通用统计约定（待确认）

除单个指标另有说明外，建议统一采用以下基础约定：

- **学生范围**：统计时点处于学校确认的有效在籍状态，按学校授权范围查看；
- **人数**：同一名学生无论出现多少条成绩、选课、占用或预警记录，只算一个人。正文指标表中的“学生数”“教师数”均按此理解，不再逐条重复说明；人次、门次、记录数会单独标明；
- **成绩范围**：已发布、未作废且业务状态明确的成绩记录；
- **课程范围**：同一门课程可能存在改码、同名不同码或替代关系，按学校稳定课程编号归并，不只按课程名称识别；
- **组织归属**：同时保留学生所属学院、课程开课学院和教学任务承担学院，不混用；
- **时间口径**：明确“当前学期”“学年”“培养周期”“历史观察期”，页面显示数据截止时间；
- **百分比**：同时显示分子和分母；“个百分点”表示两个百分比直接相减；
- **分母为零**：任何比率的分母为0时，页面显示“—”，不显示0%，避免把“没有人修读”误读为“全部未通过”；
- **无数据与零值**：无数据、数据未接入和真实为0必须区分；
- **阈值性质**：原型阈值只用于筛选和排序，不直接等同于学校制度或质量合格线；
- **结果核查**：重要指标应能下钻到学院、专业、课程或学生证据，不只展示汇总数字。
- **分析上下文**：每个页面应明确当前工作身份、明细数据范围、统计学期、数据截止时间和指标口径版本，筛选条件不得静默扩大分析范围；
- **横向与纵向比较**：跨学院比较必须采用相同统计对象、分母和学期；与上期比较还必须保证规则版本和数据覆盖可比，不具备条件时显示“暂不可计算”；
- **事实与过程分离**：学生是否仍命中风险规则与管理人员是否已经核查分别记录，不能用“已核查”推断“风险消失”，也不能用“仍命中”推断“无人关注”；
- **页面筛选关系**：影响指标、图表和名单的条件称为“分析范围”；只影响当前名单的姓名、核查状态等条件称为“名单筛选”，页面应明确二者差异；
- **可配置表格**：业务表格允许用户选择显示列和调整顺序，但保留必选身份列、核心业务列和操作列，并限制最大显示列数，避免横向滚动失控。

# 第一部分 管理需求与指标口径

## 专题一 学校与学院学业运行概览

### 1.1 管理问题

本专题帮助教务处和学院快速判断：学生总体学业表现如何，学院、专业和年级之间是否存在显著差异，问题主要集中在哪些课程和学生群体，是否需要进一步进入专题核查。

### 1.2 指标口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| O-01 | 在籍学生数 | 统计时点处于有效在籍状态的学生数 | 休学、保留学籍、交流生、延期毕业生是否计入 | 确定分析总体和各学院学生规模 |  |
| O-02 | 有效成绩学生数 | 观察期内至少有1条有效成绩记录的在籍学生数 | 无成绩的新生不计入任何成绩类指标的分母 | 说明成绩指标实际覆盖的学生范围 |  |
| O-03 | 学分加权平均分 | 在当前学期和授权范围内，将每条有效百分制成绩乘以课程学分后求和，再除以这些有效记录的学分总和。公式：Σ（成绩×学分）÷Σ学分 | 只纳入成绩有效、成绩可转为数值且学分大于0的记录；等级制折算、重修取值规则待确认 | 作为学院横向比较的总体成绩水平指标；学分较高课程权重更大 |  |
| O-05 | 学生平均GPA | 先按学校GPA规则计算每名学生当前学期GPA，再对范围内有有效GPA的学生求算术平均 | 每名学生在组织平均中只贡献一次，避免修课门数多的学生被重复加权；GPA转换表和重修覆盖规则待确认 | 观察学院、专业总体绩点水平并支持同口径比较 |  |
| O-06 | 学生总GPA | 对每名学生的每门课程取最新一条真实、有效且结果明确的修读结果，再按课程学分加权。公式：Σ（最终有效课程绩点×课程学分）÷Σ计入GPA课程学分 | 缺少绩点、学分不大于0的课程不纳入并披露排除数；五级制、免修、补考覆盖规则仍待学校确认 | 在课程学生画像、学生证据和完整档案中使用同一累计GPA口径 |  |
| O-07 | GPA中位数 | 全部有效学生的GPA从低到高排序后取中间值；人数为偶数时取中间两人的平均 | 需同时展示参与排序的学生数 | 避免个别极高或极低GPA影响平均数 |  |
| O-08 | 未通过学生数 | 观察期内至少有1门课未通过的学生数 | “当期未通过”与“历史遗留、至今未解决”分开统计 | 判断问题涉及多少学生 |  |
| O-09 | 未通过人次 | 观察期内结果为未通过的有效成绩记录条数；一名学生多门未通过、同一门课多次未通过，每条都计入 | 人次反映事件规模，不等于人数 | 判断教学与考试结果事件规模 |  |
| O-10 | 当前挂科学生率 | 当前学期至少有1条明确未通过成绩的去重学生数÷当前学期至少有1条有效成绩的去重学生数×100% | 分母只用当前学期有有效成绩的学生，不用全部在籍学生；不等于未通过成绩人次率 | 比较不同学院、专业当期受影响学生比例 |  |
| O-11 | 课程人次未通过率 | 未通过成绩记录条数÷全部有效成绩记录条数×100% | 缓考、缺考、取消资格是否计入分子分母待确认 | 比较课程结果的总体压力 |  |
| O-12 | 人均未通过门次 | 未通过的课程门次÷未通过学生数 | 同一门课多次未通过，按“门”计还是按“次”计需标明 | 判断问题集中在少数课程还是分散在多门课程 |  |
| O-13 | 当前有效预警学生数 | 当前至少命中1条已启用预警规则的去重学生数；命中多条规则仍只算一人 | 不同规则命中同一学生不重复计数；当前命中与人工核查状态分别统计 | 判断当前需要关注的学生规模 |  |
| O-14 | 当前有效预警学生率 | 当前有效预警去重学生数÷当前权限范围内有效在籍学生数×100% | 同时披露规则版本、数据截止时间和权限范围；不等于待核查率 | 比较学院、专业、年级的当前风险覆盖 |  |
| O-15 | 培养方案覆盖率 | 已绑定有效培养方案的学生数÷应绑定学生数×100% | 未绑定方案的学生不能被默认为“已完成”或“有风险” | 判断毕业准备分析的可信覆盖范围 |  |
| O-16 | 学分完成率 | 已认可学分÷培养方案要求总学分×100%；超过100%时按100%显示 | 只对绑定了有效方案的学生计算 | 宏观观察培养进度 |  |
| O-17 | 学院横向偏离 | 某学院指标值减去全校同学期、同对象、同分母的指标值；比率差使用百分点（pp），平均分和GPA使用原单位差值 | 可同时显示排名，但样本规模、专业结构和课程结构不同，不据此对学院作简单优劣结论 | 快速识别需要进一步核查的学院及偏离方向 |  |
| O-18 | 可比学期变化 | 本期指标值减去上一可比学期的同口径指标值 | 统计范围、数据覆盖或规则版本变化时不得直接比较；无可靠基线显示“暂不可计算” | 判断情况在改善、恶化还是发生结构变化 |  |
| O-19 | 有效成绩覆盖率 | 所选学期至少有1条有效成绩的去重学生数÷该学期当前权限范围内有效在籍学生数×100% | 各学期分别使用本学期有效成绩人数和本学期在籍人数；覆盖不足时，挂科率、平均分和GPA不能被解释为整个学生群体情况 | 先判断当前页面的成绩结论是否具有代表性 |  |
| O-20 | 重点课程受影响学生数 | 当前学期某课程至少有1条明确未通过成绩的去重学生数 | 与未通过记录条数分开；同一学生同一课程多次记录只计1人 | 按实际影响规模安排课程核查优先级 |  |
| O-21 | 重点课程入选依据 | 综合受影响学生数、课程未通过人次率、较上期变化、课程属性和当前分析范围，形成可读的入选原因 | 原型默认优先受影响学生规模，不形成学校正式课程质量评价；排序规则需版本化 | 说明课程为什么进入TOP10，避免只给排名不给理由 |  |
| O-22 | 课程最终有效未通过率 | 在所选课程、学期和授权范围内，对每名学生取该课程最后一条真实有效且结果明确的成绩；最终结果未通过学生数÷最终有效结果学生数×100% | 与O-11“成绩记录人次未通过率”分开；分母为0时显示“—”；补考、重修覆盖以现有最后有效记录为原型规则，待学校签版 | 课程详情判断当前仍受影响的学生比例 |  |
| O-23 | 课程平均GPA | 在所选课程、学期和授权范围内，对每名学生取该课程最后一条真实有效且有绩点的结果，对这些课程绩点求算术平均 | 不按课程学分二次加权；缺少绩点的结果不纳入并披露样本边界 | 与课程平均分配套观察该课程结果水平 |  |

注：O-04简单平均分已移入专题十二，作为管理意义存疑指标单独确认。

**示例：**某学院有2,000名在籍学生，其中1,850人具有有效成绩，400人当期至少一门未通过。未通过学生率为400÷1,850=21.62%，不是400÷2,000。

### 1.3 总览首屏与学院比较的呈现顺序

总览首页默认先回答四个管理问题：

1. **数据是否可解释**：有效成绩覆盖率（O-19）；
2. **当期影响多少学生**：当前挂科学生率（O-10）；
3. **总体学习结果如何**：学生平均GPA（O-05）；
4. **当前规则覆盖多少学生**：当前有效预警学生率（O-14）。

在籍学生数、开课门数和教师数作为当前分析范围背景，不与风险指标同等突出。学院横向比较至少同时提供学分加权平均分、学生平均GPA、当前挂科学生率、有效成绩覆盖率和当前预警学生率，并允许按管理问题排序。排名必须同时展示与全校同口径均值的明确差值。

首页“优先核查事项”按类别分别保留全局TOP1：学院偏离TOP1取当前挂科学生率高于范围均值的学院中估算影响规模最大者，点击进入学院详情；重点课程TOP1取重点核查课程排序第一，点击进入课程详情。两类候选不得合并后只截取一项；某一类没有满足条件的真实候选时，仅该类不展示，不以其他类别补位。

“本学期重点核查课程TOP10”以受影响学生数为主要排序依据，同时披露课程未通过人次率、较上期变化和入选原因；点击课程后继续沿用来源学院、专业、年级和学期范围。GPA分布、首次/补考/重修通过率作为结构与解释信息，不与首要核查事项争夺首屏焦点。

学院详情在“本学院所有专业偏离与核查”之后、“各年级本学期修读结果/优先核查课程TOP6”之前复用首页“学院偏离与变化”。该表按全校学院聚合返回在籍学生、当前挂科学生率、较全校均值、较上期变化、学生平均GPA及排名、当前有效预警学生率和有效成绩覆盖率，并支持与首页一致的五种前端排序。该区域仅用于学院横向参照：学院名称和整行均不可点击，不设置详情列，不提供“查看全校学生名单”入口；他院不返回学生标识、名单、档案或明细路由。数据来源分别为学生与组织主数据、真实有效成绩和当前有效预警，学期变化只在上一可比学期存在同口径结果时输出。校级身份与首页一样展示全部学院；学院身份查看他院聚合时，小于最小群体规模的学院不展示。

学院详情的“各年级本学期修读结果”和“优先核查课程TOP6”在桌面端按约1:2分配横向空间，优先保障字段较多的课程核查表可读性；较窄屏幕下改为上下整行排列。该布局调整不改变任何指标、排序、权限或下钻口径。

### 1.4 建议下钻和管理动作

全校概览应支持从学校到学院、专业、年级或课程，再到学生名单和学生证据的逐级核查。进入下一层时必须保留来源范围、所选学期、筛选条件和返回路径；学生详情优先在当前清单打开抽屉，进入完整档案后应先返回原名单。横向比较用于确定核查优先级，不用于脱离学生基础、课程结构和培养方案差异对学院作简单评价。

### 1.5 数据来源与刷新边界

本专题的学生规模来自有效学籍与组织归属，成绩指标来自已发布且未作废的成绩记录及课程学分，GPA来自学校确认的绩点转换规则，预警指标来自当前启用规则的最近一次可靠计算结果，学院、专业和课程名称来自组织机构与课程主数据。页面必须同时显示统计学期、数据截止时间和权限范围。

总览页面采用“一次设置分析范围、各区域共享结果”的交互：学院、专业、年级和学期属于分析范围，会同时影响顶部指标、图表、学院比较和重点课程；姓名、学号等只属于下钻名单筛选，不得反向改变总览指标。首次加载、切换分析范围或重新计算期间，应保留页面结构并显示当前加载阶段，不用空白页或反复整页刷新代替状态提示。

### 1.6 历史变化、下钻与核查路径（2026-07-27同步）

- O-19、O-10、O-05、O-14以及首次/补考/重修/公共必修首次通过率，统一通过“历年学期变化”弹窗核查；学校、学院、专业只改变授权学生集合和组织范围，不改变指标公式。
- 历史在籍分母只读各学期教务源库 `students` 既有字段，并与当前身份授权学生集合求交集；趋势中的当前统计学期使用总览卡片同一 `dim_student` 授权名单，确保当前卡片与趋势最后一点分子、分母一致。每个学期有效成绩覆盖率均按“该学期有效成绩人数÷该学期在籍人数”计算；“较上学期”严格等于当前行覆盖率减去紧邻上一学期行覆盖率。首页卡片与学校、学院、专业历史明细共用同一结果，不使用隐藏的当前名单回溯比较基线。上一学期无可用覆盖率时显示“-”。两类来源均在弹窗逐期披露，不新增数据库表或字段，不将源数据写回分析库。

## 专题二 成绩、挂科、补考与重修口径

### 2.1 管理问题

这是全平台优先级最高的基础口径。需要先区分“某次考试未通过”“首次修读未通过”“历史有过挂科”“目前仍有课程未解决”和“最终已通过”，再据此计算课程质量、学生风险和毕业准备指标。

### 2.2 建议结果归并逻辑

对每名学生、每门课程，按成绩记录形成以下过程：

1. 找出已发布、未作废的有效成绩记录；
2. 区分首次修读、补考、重修、缓考、缺考、免修和其他特殊类型；
3. 应用课程替代、成绩更正和免修认定；
4. 形成“首次结果”“最近一次有效结果”“是否曾通过”“当前是否仍未解决”等不同字段；
5. 不用一个“是否挂科”字段代替全部业务概念。

### 2.3 通过率的三分层口径

平台现已能区分三种修读类型：首次修读、补考、重修。课程通过率不再用一个总数代表，拆成三个独立指标：首次通过率回答“第一次学，结果如何”，补考通过率回答“补考救回了多少”，重修通过率回答“重修解决了多少”。三个指标分别统计，互不混算。任何一个比率的分母为0时，页面显示“—”，不显示0%。

原“最终通过率”保留为参考口径，只用于观察学生最终解决程度，不作为课程质量比较的主要依据（见G-17、C-06）。

**示例：**某课程某学期有300名学生首次修读，240人通过，首次通过率为240÷300=80.00%。未通过的学生中有50人参加补考，35人通过，补考通过率为35÷50=70.00%。之后有20人报名重修，16人通过，重修通过率为16÷20=80.00%。如果某学期没有任何学生参加补考，该学期补考通过率显示“—”，不显示0%。

### 2.4 指标口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| G-01 | 有效成绩记录 | 已发布、未作废、结果能判定通过与否的成绩记录 | 更正前的旧记录、暂存未发布的成绩不算 | 所有成绩类指标的基础记录 |  |
| G-02 | 课程通过 | 成绩达到学校通过标准，或结果状态明确为通过 | 百分制、五级制、二级制和特殊课程的通过标准待确认 | 判断学分取得和课程完成 |  |
| G-03 | 课程未通过 | 有效成绩低于通过标准，或结果状态明确为未通过 | 缺考、作弊、取消资格是否都算未通过待确认 | 判断某次修读的结果 |  |
| G-04 | 首次修读人数 | 对每名学生的每门课，取最早一次有效修读作为首次修读；统计有首次修读记录的学生数 | 转入前已修课程、先修后认定的课程如何算首次待确认 | 首次通过率等指标的分母 |  |
| G-05 | 首次通过率 | 修读类型为首次修读且结果明确的学生中，一次通过的人数÷首次修读且结果明确的人数×100%；分母为0时显示“—” | 首次结果为缓考的学生是否计入分母待确认 | 衡量首次教学和学习结果 |  |
| G-06 | 首次未通过率 | 首次修读且结果明确的学生中，未通过人数÷首次修读且结果明确的人数×100%；分母为0时显示“—” | 与“当前仍有课程未解决”是两个概念 | 识别首次受挫的规模 |  |
| G-07 | 历史挂科经历学生数 | 历史上曾出现至少1次未通过成绩的学生数；后来已通过的仍算“有过挂科经历” | 只描述历史经历，不代表现时有风险 | 描述群体历史受挫情况 |  |
| G-08 | 历史挂科经历率 | 历史挂科经历学生数÷有历史有效成绩的学生数×100% | 必须标注观察期 | 分析年级和群体的历史受挫 |  |
| G-09 | 当前未解决课程数 | 学生曾经未通过、且截至统计时点从未取得通过成绩的课程门数；同一门课多次未通过只算一门 | 课程替代、免修、成绩覆盖后如何认定“已解决”待确认 | 判断学生当前真实的课程欠账 |  |
| G-10 | 当前未解决学生数 | 当前未解决课程数大于等于1的学生数 | 不等同于历史挂科人数 | 识别当前真正需要帮助的学生 |  |
| G-11 | 重复未通过课程数 | 同一学生同一门课未通过达到2次及以上的课程门数 | 补考未通过与重修未通过分开看 | 识别持续学习困难 |  |
| G-12 | 补考人数 | 发生过学校定义的补考记录的学生数 | 若源数据把补考和重修混在一起，不得据此出正式结论 | 评估补考资源与结果 |  |
| G-13 | 补考通过率 | 修读类型为补考且结果明确的成绩记录中，通过人次÷结果明确的补考人次×100%；分母为0时显示“—” | 一名学生多次补考按人次计入；按人数统计的口径可另行提供 | 分析补考的补救效果 |  |
| G-14 | 重修人数 | 发生过重修修读记录的学生数 | 重修班、跟班重修、免听重修需统一编码 | 判断重修学生规模 |  |
| G-15 | 重修人次 | 已发布、未作废、修读类型为重修的成绩记录，按记录计数；同一学生同一课程多次重修，每次都计入 | 人次用于估算教学资源，不等于重修人数 | 估算重修教学资源需求 |  |
| G-16 | 重修通过率 | 修读类型为重修且结果明确的成绩记录中，通过人次÷结果明确的重修人次×100%；分母为0时显示“—” | 按每次重修结果统计还是只按最终结果统计待确认 | 评价重修资源效果 |  |
| G-17 | 最终通过率（参考口径） | 观察期内修读过该课程的学生中，截至统计时点至少有1次通过成绩的学生数÷修读学生数×100% | 参考口径：只用于观察学生最终解决程度，不作为课程质量比较的主要依据；正式比较使用首次、补考、重修三分层通过率；需规定最长观察窗口 | 比较首次结果与最终解决程度 |  |

## 专题三 学业风险、预警与低年级受挫

### 3.1 管理问题

本专题用于从学校真实数据中识别当前需要关注的学生、安排有限核查注意力，并从大一首次出现未通过记录开始观察后续变化。当前规则快照、人工核查过程和低年级历史观察是三种不同的统计对象，页面必须分别说明。规则定义和规则自发现属于同一预警模块。

### 3.2 指标与规则口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| A-01 | 当前预警学生数 | 当前命中有效预警规则的学生数；命中多条规则的学生只算一人 | 不同规则命中同一学生不重复计数 | 确定当前关注队列规模 |  |
| A-02 | 预警事件数 | 当前有效的预警记录条数；同一名学生可对应多条 | 事件数反映工作量，不等于人数 | 衡量规则和事件工作量 |  |
| A-03 | 最高风险等级人数 | 按每名学生当前命中规则中的最高等级归入严重、警告或提醒；一名学生只进入一个等级 | 预警记录明细可分别展示全部命中等级，但顶部学生指标不能重复计数 | 安排学生核查优先级 |  |

### 3.3 风险事实、人工核查与后续处置边界

本期首先解决“哪些学生当前命中什么规则、为什么应优先核查、核查时能看到哪些证据”的问题，不把平台扩展为学生工作管理系统，也不预设完整的帮扶、干预和结案闭环。学校后续确认哪些处置环节纳入平台后，再单独固化流程、职责和状态。

预警页面同时保留两套不能互相替代的状态：

1. **风险事实状态**：当前命中、新增或升级、持续命中、当前不再命中。只有存在可靠计算批次、可比规则版本和一致分析范围时，才能判断相邻批次变化；证据不足时显示“暂不可计算”。
2. **人工核查状态**：待核查、核查中、已记录核查结论、已关闭核查事项。该状态只说明管理人员的核查进度，不表示学生风险已经消失，也不等同于已经完成帮扶。

平台可以按权限显示主责人员，并在学校启用后保存核查事实、备注和证据链接；是否进一步包含谈话、帮扶方案、任务流转、提醒催办和结案认定，由学校另行确认。任何状态变更必须由有权限的人员操作并留痕，AI不得自动改变状态、分派任务或认定风险已解决。

### 3.4 页面操作路径与数据来源

学业预警监控采用三个平级工作区：

1. **预警监控**：先看当前风险学生规模、严重程度、叠加规则和优先核查队列，再打开学生预警核查抽屉，通过“预警核查摘要”页签查看命中规则和当前证据，并结合学业证据、历史预警和核查记录继续核查；
2. **预警规则**：在同一页面内切换“规则配置”和“规则自发现”，不增加系统菜单或二级子菜单；
3. **低年级受挫观察**：只分析大一首次出现未通过记录后的历史走向，不把群体统计当作个体预测。

本专题的学生和组织范围来自有效学籍、组织机构、人员—行政班关系和导师—学生关系；规则命中来自预警事实、规则版本与计算批次；课程表现与低年级观察来自有效成绩、课程和学期数据；人工核查状态来自独立核查记录。页面必须披露数据截止时间、规则版本、分析范围和当前工作身份。

### 3.5 规则治理要求

规则自发现只输出候选规则及证据，不直接启用。候选规则应依次经过业务解释、影响范围评估、历史回放、人工审核、版本发布和启用，且可停用、回滚并追溯。规则配置与规则自发现使用同一指标词典和成绩口径，避免同名指标在两个入口出现不同算法。

## 专题四 培养方案执行与毕业准备核查

### 4.1 管理问题

帮助教务处和学院回答：学生是否绑定正确培养方案，各课程模块是否按要求完成，哪些学生存在必修课、模块学分或门数缺口，未来课程供给能否支持其按期完成学业。

毕业要求和指标点可用于分析课程支撑与执行证据，但其主观评价结果不直接作为学生毕业评审条件。

### 4.2 培养方案模块判定顺序

1. 模块存在大于0的学分要求时，优先按认可学分判断；
2. 学分要求为空或为0、但存在门数要求时，按完成门数判断；
3. 学分和门数要求均不存在时，依据方案课程清单中的必修属性逐门核查；
4. 学生完成的课程替代、免修和校外课程认定，只有在正式审批有效后才抵扣；
5. 不同模块间课程能否重复计入，按培养方案组规则执行；
6. 原型阶段从Word表格临时提取方案；生产系统从教务系统API取得结构化、版本化数据。

原型临时提取还必须进行规则可信性校验：若从合并单元格取得的模块最低学分大于该叶子模块全部课程记录学分之和，则不能把父级要求直接套用到该模块，应回退到门数规则或逐门必修规则，并把原始要求留作数据核验。课程池记录学分只用于校验和解释可选范围，不作为学生应修分母。

当前页面采用四个平级工作区：“方案执行总览、方案结构与要求、学生进度核查、毕业准备与课程保障”。总览按当前工作身份的完整授权范围计算；学院、年级、专业、方案条件只作用于“方案结构与要求”和“学生进度核查”；毕业准备页使用自身的名单条件，页面必须明确条件作用范围。

| P-17 | 按期完成高风险学生 | 在剩余学期内，按未来开课、容量、校区、时间和修读资格难以完成明确缺口的学生数 | 需未来教学任务和重修资源；当前原型不计算、不用历史开课替代未来承诺 | 提前安排课程与重修资源 |  |
| P-18 | 关键缺口课程涉及学生数 | 某门必修课程存在明确未通过证据、且所属模块尚未达到要求的去重学生数 | 数据候选单独呈现；课程已经被模块内其他完成证据覆盖时不再形成课程保障优先项 | 确定课程保障优先级 |  |
| P-19 | 课程供给覆盖率 | 下一周期有可用开课资源的明确缺口课程数÷需保障的明确缺口课程数×100% | 需未来教学任务和适用学生范围数据；未接入时显示“待确认”，不输出供给不足 | 评估课程保障能力 |  |
| P-20 | 重修资源覆盖率 | 有可参加重修班或跟班资源的当前未解决学生数÷需重修学生数×100% | 时间冲突、容量、校区和修读资格都要满足才算“可参加”；当前原型未接入正式重修资源 | 判断帮扶资源是否可获得 |  |
| P-21 | 毕业要求证据覆盖率 | 已建立“毕业要求/指标点—支撑课程—评价环节—实际结果”结构化映射的指标点数÷应建立指标点数×100% | 只反映证据完备性，不代表达成；当前仅有方案原文时不计算 | 支持专业建设核查 |  |
| P-22 | 课程支撑执行率 | 实际开设且有结果证据的支撑课程数÷方案规定支撑课程数×100% | 必须先有正式支撑矩阵；当前不用课程平均分或通过率替代毕业要求达成度 | 发现方案执行与开课脱节 |  |
| P-23 | 可进行规则核查方案数 | 同时具备课程表、至少1条可信模块规则和毕业最低总学分的有效方案数 | 只说明可进行模块级执行核查，不代表方案合规 | 判断当前分析可用范围 |  |
| P-24 | 模块规则覆盖率 | 可自动评价的学生—模块记录数÷全部学生—模块记录数×100% | 没有可信学分、门数或逐门必修规则的模块不进入达标结论 | 识别需要补充结构化规则的模块 |  |

**示例：**某模块要求20学分，学生已通过该模块课程18学分，则模块学分完成率为18÷20=90%，模块学分缺口为2学分。如果模块学分要求为空，但明确要求完成4门课程，则应改按完成门数判断。

### 4.4 学校需重点确认

- 学生与培养方案的正式绑定键及转专业后的适用规则；
- 各类课程替代、免修、校外成绩和跨模块课程的抵扣顺序；
- “建议修读学期”是否具有管理约束意义；
- 学位条件是否进入本平台，若进入，应提供结构化、可计算的正式规则；
- 哪些缺口必须下钻到学生，哪些只用于课程供给保障。

## 专题五 课程质量与教学结果分析

### 5.1 管理问题

帮助管理者识别未通过结果持续偏高、学期间波动显著、影响学生较多或重修压力较大的课程，并进入课程、学期、教学班、学生结果的证据核查。指标用于发现问题线索，不能脱离课程类型、学生基础、考核方式和教学过程直接评价教师个人。

### 5.2 课程类别分组

每门课程归入公共必修、专业必修、选修、实践、其他五类之一（C-17）。归类以培养方案模块归属为主要依据推导；方案缺失或归属不明时标注“待核验”，不作猜测。

公共必修课学生覆盖面广，其首次通过率单独作为重点关注指标（C-18）：某门公共必修课的首次通过率低于全校公共必修课平均值时，在课程清单中自动置顶，提醒管理者优先核查。置顶只代表需要核查，不代表课程不合格。

### 5.3 指标口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| C-01 | 可比课程学期单元数 | 一门课在一个学期内、有效成绩样本量达到最低要求的“课程×学期”个数 | 原型最低样本量30，正式阈值待确认 | 说明趋势分析基于多少有效样本 |  |
| C-02 | 课程平均分 | 该课程全部有效成绩相加÷成绩记录条数 | 建议同时展示中位数和样本量 | 观察课程结果水平 |  |
| C-03 | 课程学分加权平均分 | 每门课成绩乘以学分相加后除以学分总和。公式：Σ（成绩×学分）÷Σ学分 | 同一课程学分通常一致；跨课程汇总时使用 | 支持课程群总体比较 |  |
| C-04 | 课程未通过率 | 该课程未通过成绩记录条数÷全部有效成绩记录条数×100% | 首次、补考、重修分别统计，不混算 | 识别课程结果压力 |  |
| C-05 | 首次通过率 | 该课程修读类型为首次修读且结果明确的学生中，通过人数÷首次修读且结果明确人数×100%；分母为0时显示“—” | 与补考、重修分开，避免后续补救掩盖首次结果 | 观察首次教学学习结果 |  |
| C-06 | 最终通过率（参考口径） | 截至观察时点曾取得通过成绩的学生数÷修读学生数×100% | 参考口径，需披露观察窗口；正式比较使用首次、补考、重修三分层通过率 | 观察学生后续解决程度 |  |
| C-07 | 持续偏高课程 | 至少N个可比学期，未通过率都达到阈值的课程 | 原型N=2、阈值15%，只用于筛选排序 | 识别持续性问题线索 |  |
| C-08 | 显著波动课程 | 至少N个可比学期中，最高未通过率与最低未通过率之差达到阈值的课程 | 原型阈值15个百分点，注意不是“上升15%” | 识别学期间结果不稳定 |  |
| C-09 | 未通过率变化 | 本期未通过率减去基准期未通过率 | 结果表述为“上升/下降X个百分点” | 判断近期变化方向 |  |
| C-10 | 影响面较广课程 | 观察期内累计未通过人次达到阈值的课程 | 原型阈值50人次，正式应按课程类型调整 | 确定优先核查课程 |  |
| C-11 | 累计重修人次 | 观察期内该课程修读类型为重修的有效成绩记录条数；同一学生多次重修每次都计入 | 数据必须能区分补考与重修 | 估算教学资源压力 |  |
| C-12 | 重修压力课程 | 累计重修人次达到阈值的课程 | 原型阈值30人次，仅用于排序 | 提前安排重修资源 |  |
| C-14 | 教学班差异 | 同一课程同一学期，各教学班同一指标的最大值减最小值 | 需最小班级样本量；不直接归因教师个人 | 发现需要核查的班级差异 |  |
| C-15 | 同类课程基准差 | 课程指标值减去同类别、同层次课程的基准值 | 同类课程分类规则需学校提供 | 避免不同性质课程直接比较 |  |
| C-16 | 课程趋势完整度 | 有足够历史可比学期的课程数÷纳入分析的课程数×100% | 课程改码需沿革映射 | 解释趋势结论的覆盖范围 |  |
| C-17 | 课程类别归属 | 每门课程归入公共必修、专业必修、选修、实践、其他五类之一，以培养方案模块归属为主要依据推导 | 同一门课在不同专业方案中类别不同时，按开课面向的方案口径处理，规则待确认；归属不明标注“待核验” | 保证同类课程比较和公共必修课重点监控有统一分组 |  |
| C-18 | 公共必修课首次通过率 | 公共必修类课程中，修读类型为首次修读且结果明确的学生里，通过人数÷首次修读且结果明确人数×100%；分母为0时显示“—” | 低于全校公共必修课平均值的课程自动置顶；置顶只代表需要核查，不代表课程不合格 | 聚焦学生面广、影响大的公共必修课首次教学结果 |  |

注：C-13成绩标准差已移入专题十二，作为管理意义存疑指标单独确认。

### 5.4 单门课程核查应呈现

课程趋势不应默认只展示某一门示例课程。管理者从重点课程清单点击后，再加载该课程历学期样本量、平均分、未通过率、首次/补考/重修三分层通过率、教学班差异、重修压力、开课资源和课程团队证据。

### 5.5 当前原型呈现与确认方式

- “达到统计样本要求的课程”指至少一个学期具有不少于30条有效、已发布、未作废且通过状态明确的成绩记录的去重课程，不是课程总数；
- “持续高首次未通过”按至少2个可比学期、且每学期首次未通过率均不低于15%识别；
- “学期间变化较大”指最高学期与最低学期首次未通过率相差不低于15个百分点，不是同比上升15%；
- 公共必修课关注区与课程结果主表共用同一观察窗口和一次聚合结果，按公共必修首次通过率由低到高形成有限清单；
- 点击课程后在当前页抽屉加载学期结果和已接入开课资源，关闭抽屉返回原名单，不跳转至其他模块；
- 上述规则只形成课程与资源核查顺序，不形成课程质量等级，不评价教师个人。

## 专题六 教学运行、开课供给与重点课程排课

### 6.1 管理问题

帮助教务处和学院回答：课程是否按培养需要开出，教学班和容量是否匹配，体育、思政、数学、英语等重点课程在年级、星期和时段上的分布是否均衡，单门课程的开课明细如何进一步查询。

### 6.2 指标口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| T-01 | 开课课程数 | 学期内有有效教学任务的课程数；同一门课开多个班只算一门 | 不等同于教学班数 | 判断课程供给广度 |  |
| T-02 | 教学班数 | 学期内有效教学任务数；一个任务对应一个教学班 | 已取消的任务不计入 | 判断实际开班规模 |  |
| T-03 | 选课人次 | 各有效教学班的已选人数相加 | 合班上课的学生避免重复计数；统计来源需明确 | 判断教学服务规模 |  |
| T-04 | 平均班额 | 选课人次÷教学班数 | 建议同时展示中位数 | 判断总体班额压力 |  |
| T-05 | 容量使用率 | 教学班已选人数÷教学班容量×100% | 容量为空或临时调整的教学班单独标记 | 识别容量过松或过满 |  |
| T-06 | 满班/超容量教学班数 | 已选人数等于或超过容量的教学班数 | 满班和超容量分别统计 | 发现选课资源瓶颈 |  |

| T-11 | 时段占比 | 某星期某时段的排课片段数÷全部排课片段数×100% | 片段、课次、学时须选定统一单位 | 观察排课集中程度 |  |
| T-12 | 高峰时段集中度 | 排课最多的K个时段的片段数÷全部排课片段数×100% | K值和是否含晚间待确认 | 判断是否过度集中 |  |
| T-13 | 年级时段分布 | 某年级学生在各星期、各时段的排课片段数及占比 | 跨年级课程如何分摊待确认 | 识别学生课表拥挤 |  |
| T-14 | 单门课程开课规模 | 某课程的教学班数、授课教师数、选课人次和平均班额 | 首页展示TOP10或重点课程，全部课程进入分页明细 | 支持课程供给核查 |  |

注：T-15课程时段均衡度已移入专题十二，作为管理意义存疑指标单独确认。

**呈现建议：**首页只展示重点课程、异常课程或TOP10，提供“查看全部课程”分页页面，避免仅因页面最多显示100门而使用户误以为其他课程没有数据。

### 6.3 当前原型已采用的运行口径

| 管理对象 | 当前原型计算逻辑 | 数据来源与时间范围 | 管理用途与边界 |
|---|---|---|---|
| 开课供给规模 | 开课课程数=有效教学任务中的去重课程数；教学班数=有效教学任务数；选课人次=各教学班有效人数之和；平均班额=选课人次÷教学班数 | 教学任务事实；页面明确显示实际覆盖学期，V1运行统计与V2结构化教学任务分别披露数据期 | 说明当前教学供给规模，不等同于培养方案课程已按计划全部开出 |

| 峰值时段占比 | 排课片段最多的“星期＋上午/下午/晚上”单元格片段数÷当前范围全部排课片段数×100% | 当前身份可见课程的课程日历 | 发现排课集中位置；仅表示集中程度，不自动判定冲突或不合理 |
| 晚间排课占比 | 晚上时段排课片段数÷当前范围全部排课片段数×100% | 同上 | 支持学校结合本校作息核查晚间安排，不预设晚间排课一定不合理 |
| 重点课程组 | 原型按课程名称关键词临时识别体育、思政、数学和英语课程，分别统计课程门数、教学班、排课片段、学生人次、峰值和晚间占比 | 课程主数据、教学任务、课程日历 | 观察大面积公共课程时序分布；生产系统应使用学校正式课程标签替代关键词 |

## 专题七 教室实际占用与空间资源分析

### 7.1 管理问题

分析所有实际占用教室的活动，包括课程、考试、自习、招生复试和其他教学活动。管理者可选择是否纳入晚间时段，观察星期—节次热力、楼宇占用强度和重叠占用线索。

本平台不维护可用教室数量。生产系统应从权威房产、教务或资源系统读取教室主数据和有效期。

### 7.2 指标口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| R-01 | 已观测教室数 | 占用数据中实际出现过占用的教室数 | 不等同于全校可用教室数 | 说明当前数据覆盖的范围 |  |
| R-02 | 可用教室数 | 统计时点上游系统标记为可用、非虚拟、纳入分析的教室数 | 必须来自权威主数据，平台不自行维护 | 构成正式利用率的分母 |  |
| R-03 | 占用事件数 | 有效、未取消的教室占用事件数 | 同一事件跨多个节次仍算一个事件 | 描述业务活动规模 |  |
| R-04 | 占用教室时段数 | 按“教室+日期+节次”合并后的占用格子数；同一格内有多个活动只算一格 | 同格多事件不能重复计入利用率分子 | 计算时段利用率 |  |
| R-05 | 可用教室时段总数 | 各可用教室在纳入日期和节次内的时段数相加 | 扣除停用、节假日、封闭和不纳入时段 | 形成正式利用率的分母 |  |
| R-06 | 教室时段利用率 | 占用教室时段数÷可用教室时段总数×100% | 只有已观测数据时应称“已观测占用率” | 判断空间时段使用程度 |  |
| R-07 | 座位利用率 | 实际到用人数之和÷占用时段对应可用座位数之和×100% | 没有到场人数时只能用选课人数近似，并标明 | 判断容量适配 |  |
| R-08 | 高峰时段占用率 | 高峰节次被占用的教室数÷该节次可用教室数×100% | 按单日还是平均日计算待确认 | 识别资源紧张时段 |  |
| R-09 | 晚间占用率 | 晚间纳入节次的占用教室时段数÷晚间可用教室时段数×100% | 用户可切换包含或排除晚间，默认值待确认 | 观察晚间资源使用 |  |
| R-10 | 楼宇占用强度 | 楼宇内占用教室时段数÷楼宇可用教室时段总数×100% | 楼宇映射和可用范围须可靠 | 比较空间分布 |  |
| R-11 | 低使用楼宇/教室 | 利用率低于学校设定阈值的楼宇或教室 | 阈值需区分校区、用途和可用期 | 形成进一步核查清单 |  |
| R-12 | 活动类型占比 | 某类活动占用时段数÷全部占用时段数×100% | 同一格内有多类活动时分类冲突需处理 | 解释教室被何种活动使用 |  |
| R-13 | 重叠占用格数 | 同一教室、同一日期、同一节次存在多个未取消活动的格子数 | 是核查线索，不自动认定冲突 | 发现重复预约或数据问题 |  |
| R-14 | 教室映射成功率 | 能对应到稳定教室编号的占用记录数÷有效占用记录数×100% | 名称别名仅作过渡，生产使用正式编号 | 说明空间分析的可信度 |  |

**当前原型边界：**已接入实际教室使用记录，可分析已观测教室集合的占用强度和时序，但仅凭发生过占用的记录不能推断全校正式空闲率或可用教室总数。

### 7.3 当前原型的“观测负荷”口径

当前原型尚未取得全校可用教室数量、停用期、节假日和正式可用时段，因此页面不输出正式教室利用率，统一使用以下过渡口径：

- **时序单元格观测负荷**=某星期某节次的占用教室日数÷（本批数据已观测教室数×该星期实际采集日期数）×100%；
- **楼宇观测负荷**=该楼宇占用教室日节次数÷（该楼宇已观测教室数×实际采集日期数×当前纳入节次数）×100%；
- **实际占用记录**按源占用事件计数，同一事件跨多个节次只计1条；“占用教室日节次”按教室、日期和节次去重；
- 热力图采用固定分段：低于15%、15%—30%、30%—45%、不低于45%；颜色用于定位尖峰，不随用户拖动改变阈值；
- “包含晚间”由用户选择，关闭后仅从当前计算和图表中排除晚间节次，不删除源记录；
- 学院用户看到的是学校共享空间聚合，不获得其他学院教师、课程或学生明细。

### 8.1 调课分析

**当前原型采用的调停课事实指标：**

- 调课记录数、停课记录数、停课记录占比、受影响学生人次、涉及教师数和原因文本覆盖率均由当前筛选范围内的源事件计算；
- 停课记录占比=停课事件数÷调停课事件总数×100%，用于观察变更结构，不是停课率；
- 原因文本覆盖率=原因原文非空事件数÷全部调停课事件数×100%，语义分类为可解释规则推导，必须保留原因原文；
- 月度趋势按源事件实际发生月份动态生成；
- 当前不从事件时长推导“自动审核”“教务审核”或固定审核天数，未接入真实审批链、审核耗时、通知和补课完成证据时不输出这些结论。

### 8.2 教师负荷与任务集中

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |

| L-01 | 本科教学活跃教师数 | 学期内至少承担1个有效本科教学班的教师数 | 联合授课教师合并计算 | 判断实际参与教学的人数 |  |
| L-02 | 教师授课学时 | 教师承担的有效课程日历学时相加 | 联合授课需工作量分配比例，否则只展示关联学时 | 观察实际教学任务量 |  |
| L-03 | 教师教学班数 | 教师承担的有效教学班数 | 主讲和联合授课教师需区分 | 描述任务数量 |  |
| L-04 | 教师课程门数 | 教师承担的不同课程门数；同一门课多个班只算一门 | 按课程不按教学班计数 | 描述课程准备广度 |  |
| L-05 | 教师覆盖学生人次 | 教师关联教学班的选课人次相加 | 联合授课没有分配比例时，不得直接当作个人工作量 | 观察教学影响范围 |  |
| L-06 | 教师负荷TOP10 | 按学校认可的工作量或授课学时从高到低取前10名 | 未接入正式工作量标准时只展示原始数据，不称“超负荷” | 识别任务集中和保障压力 |  |
| L-07 | 任务集中度 | 排课前10%的主讲教师覆盖学生人次÷全部主讲教师覆盖学生人次×100% | 只描述集中程度，不直接判断是否合理 | 判断任务是否过度集中 |  |
| L-08 | 超负荷教师数 | 核定工作量超过学校岗位标准上限的教师数 | 取得岗位和工作量标准后才能计算 | 支持教学任务协调 |  |

**当前原型采用的教师负荷核查口径：**

- 有效授课教师数=当前学期、当前责任范围内，排除已登记或命中异常规则后仍承担有效教学任务的去重教师数；
- 教师学时中位数=P50，即按教师关联教学学时从小到大排序后的中间位置，用于降低极端值对判断的影响；
- 教师学时P90=90%的有效授课教师不超过的统计位置值，只用于形成任务集中上沿，不是学校工作量标准；
- P90核查队列=当前范围中教学学时达到或超过P90的有限教师集合，并结合课程数、教学班数、学生覆盖和课程构成进行证据核查；
- 已排除异常教师数必须随当前学院和职称范围计算并披露，异常记录不得进入均值、中位数、P90、学院比较、TOP和AI研判；
- 在学校正式工作量办法、岗位标准、联合授课分配、减免规则和完整在岗教师名册未接入前，不输出“达标、未达标、超负荷”认定，也不计算教授上课率。

### 8.3 历史实际排课分布

教师“排课偏好”应从多个学期实际排课结果中分析，不要求教师主动填报。系统应优先称“历史实际排课分布”或“历史行为倾向”，避免把资源约束造成的结果误认为个人主观偏好。

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| H-01 | 历史样本学期数 | 教师或课程有有效课程日历的学期数 | 建议至少3个有效学期后再判断稳定倾向 | 说明结论可靠程度 |  |
| H-02 | 教师时段占比 | 教师在某星期某时段的排课片段数÷该教师全部排课片段数×100% | 反映实际排课结果，不代表教师主动申报 | 描述历史分布 |  |
| H-03 | 教师行为集中度 | 教师排课最多的那个“星期+时段”的片段数÷该教师全部片段数×100% | 样本不足时只展示事实，不分级 | 识别稳定或集中的安排 |  |
| H-05 | 课程时段分布 | 某课程在各星期、各时段的排课片段数及占比 | 应区分课程类型和年级 | 为新年度课程安排提供依据 |  |
| H-06 | 历史倾向匹配率 | 新方案中满足已确认软倾向的排课片段数÷适用片段数×100% | 硬约束优先；倾向不得自动决定方案 | 比较新方案对历史习惯的影响 |  |

注：H-04偏好稳定性已移入专题十二，作为管理意义存疑指标单独确认。

## 专题九 师资保障与课程团队风险

### 9.1 管理问题

从课程保障而不是教师个人评价角度回答：本期哪些课程已经具备分析证据，哪些重点课程需要优先核查供给连续性，哪些课程只需核实团队结构，哪些对象必须先补正数据。单一教师承担是一项事实，不自动等于师资风险；年龄、临退休、正式课程团队和未来开课计划未接入前，不形成相应正式结论。

### 9.2 指标口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| F-01 | 实际授课教师数 | 有效教学任务关联的主讲及联合教师去重人数；已登记为待处理的高等级教师任务异常不进入正式统计 | 仅表示参与本科教学的实际规模，不评价教师个人；同时披露被排除记录数 | 判断本期真实师资参与规模及数据可信度 |  |

| F-03 | 单一教师承担课程数 | 本期实际授课教师去重后等于1人的课程数 | 仅为当期承担事实，不单独进入优先核查队列，也不等于课程团队只有1人 | 观察单点承担面，供组合规则使用 |  |

| F-15 | 课程负责人覆盖率 | 已明确课程负责人的课程数÷学校规定应设置负责人的课程数×100% | 当前原型未接入正式课程负责人主数据，只显示“未接入”，不参与正式风险判断 | 判断课程团队治理基础 |  |
| F-16 | 备份教师覆盖率 | 至少有2名经资格、历史授课或学校正式认定可承担教师的重点课程数÷重点课程数×100% | 当前原型只有历史实际授课证据，不能等同于未来可承担资格，因此不输出正式值 | 衡量未来课程供给韧性 |  |

注：F-06课程影响指数、F-08教授本科教学参与率已移入专题十二，作为管理意义存疑指标单独确认。

### 9.3 管理原则

课程团队指标用于课程资源配置、人才培养和接续准备，不以学生平均成绩、通过率或学生评价对教师排名，不使用模拟年龄、学历或职称形成结论。课程责任组织在原型阶段使用课程主数据中的开课/责任院系，教师人事归属只作为成员证据，不用教师所属学院替代课程责任学院。

全校视角先看学院聚合比较和优先课程；学院视角直接进入本院工作区。点击课程后在当前页面抽屉中依次查看“为什么进入、建议核查、规则版本、最近实际开课、当期团队、教师教学经历、数据来源和适用边界”，不跳转到其他模块。二级学院只能查看本院责任课程明细；如外院教师承担本院课程，仅允许查看与本院课程保障有关的必要教学证据。

当前数据来源为真实教学任务、课程主数据、教师职称与人事归属、学院组织和已登记数据质量问题。正式生产系统还需接入版本化课程责任组织、正式课程团队及负责人、教师资格与岗位状态、合规年龄段、退休政策和未来开课计划；未接入项在页面显示证据状态，不作为零值或风险结论。

## 专题十 学生成长轨迹、学业建议与管理关注

### 10.1 管理问题

面向学生、辅导员、班主任、导师、学院和教务处，在同一事实证据基础上提供不同角色可理解、可行动的学业信息。信息应说明原因和数据边界，不替代学校正式认定，也不对学生贴标签。

### 10.2 指标口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| D-01 | 学期GPA | 本学期有效课程的“课程绩点×课程学分”之和÷计入GPA的有效课程学分之和；列表、核查抽屉和完整档案共用同一聚合结果 | 课程有效性、绩点换算和是否计入GPA使用学校统一规则；分母为0时显示“—” | 形成可跨页面核对的学期成长轨迹 |  |
| D-02 | GPA变化 | 选定目标学期GPA减去选定起始学期GPA | 两个学期都存在有效GPA才计算；不是简单取自然相邻学期 | 判断所选观察区间的成绩方向和变化幅度 |  |
| D-03 | 学期未通过课程数 | 选定学期内有效成绩结果为未通过的不同课程数，同一学生同一课程在该学期重复记录只算一门 | 与未通过成绩记录条数、未通过人次区分 | 观察当期困难涉及多少门不同课程 |  |
| D-04 | 未通过课程数变化 | 目标学期未通过课程数减去起始学期未通过课程数 | 两个学期须可比较；需结合修读量和课程难度解释 | 判断困难范围是在扩大、收缩还是保持 |  |
| D-05 | 学期未通过学分 | 本学期未通过课程的学分相加 | 零学分课程另列 | 观察失败结果的影响 |  |
| D-06 | 学业画像迁移 | 同时比较GPA和未通过课程数：GPA上升不少于0.3且未通过课程数未增加，或未通过课程数减少且GPA未下降0.3以上，判为“明确改善”；反向条件判为“明确恶化”；两个方向冲突判为“表现分化”；其余判为“基本稳定” | 只对两个学期均有有效成绩证据的学生分类；0.3为当前原型阈值，需学校确认 | 不依赖单一GPA，帮助管理者区分改善、恶化和指标冲突 |  |
| D-07 | 明确改善学生 | 学业画像迁移结果为“明确改善”的不同学生数 | 与“表现分化”“基本稳定”等分组可能受观察学期选择影响 | 识别已出现积极变化、可核验帮扶效果的学生 |  |
| D-08 | 明确恶化学生 | 学业画像迁移结果为“明确恶化”的不同学生数 | 不是预警等级，也不自动触发处置 | 提前识别成绩与未通过情况同时恶化的学生 |  |
| D-09 | 首次挂科学期 | 学生历史上第一次出现未通过成绩的学期 | 补录历史成绩可能改变结果 | 定位首次受挫节点 |  |
| D-10 | 重复未解决课程 | 同一学生同一课程历史未通过达到2次及以上，且该课程最新一次有效结果仍为未通过 | 最新有效结果已通过的课程转入“历史已解决课程”；补考、重修类型保留在证据中 | 识别反复受挫且当前仍需解决的课程 |  |
| D-11 | 历史预警记录 | 学生历次预警的时间、规则、等级和命中证据 | 规则版本必须保留 | 比较风险变化 |  |
| D-12 | 培养方案完成进度 | 总体和各模块完成率、明确缺口、候选缺口 | 只对绑定有效方案的学生显示正式结论 | 指导选课与毕业准备 |  |
| D-13 | 历史高难度课程 | 历史有效修读样本达到阈值、且未通过率达到提醒阈值的课程 | 建议按近3至5年、分课程层次和类别统计；阈值待确认 | 提醒学生提前投入学习 |  |
| D-14 | 高难度课程选修提醒 | 学生已选课程命中历史高难度课程条件时给出提醒 | 不评价教师；提醒中说明样本量、观察期和历史未通过率 | 提供学习准备提示 |  |
| D-15 | 选课缺失提醒 | 当前应选或建议选、但没有选课记录的课程清单 | 需正式选课数据、培养方案和开课资源 | 提醒学生及时选课 |  |
| D-16 | 重修资源可获得性 | 学生未解决课程是否存在时间、资格、容量、校区都匹配的重修资源 | 需实时或准实时开课与选课数据 | 提供可执行的重修路径 |  |
| D-18 | 我的班级（辅导员、班主任） | 对当前登录人所带行政班汇总：班级人数、班级加权平均GPA、本学期未通过学生率（本学期至少一门课程未通过的学生数÷本学期有有效成绩的学生数×100%）、学分完成率中位数、当前有效预警数 | 只统计与登录人存在有效“人员—行政班”关系的班级；看不到其他班级数据 | 辅导员、班主任先看班级整体，再下钻到学生 |  |
| D-19 | 我的学生（导师） | 对当前登录人所带学生逐人展示：按D-01计算的本学期GPA、本学期未通过课程数、学分完成率、当前有效预警数 | 只统计与登录人存在有效“导师—学生”关系的学生 | 导师按学生逐一掌握学业状态，安排谈话和帮扶顺序 |  |
| D-20 | 可比较学生及覆盖率 | 起始学期和目标学期都存在有效真实成绩证据的学生数；覆盖率=可比较学生数÷当前权限范围内学生数×100% | 无法比较的学生不进入画像迁移分母；覆盖率不足时不得外推全体学生 | 先判断分析覆盖度，再解释改善或恶化人数 |  |
| D-21 | 连续受挫学生 | 起始学期和目标学期均至少有一门未通过课程的不同学生数 | 仅表示两个观察学期均受挫，不等于连续所有学期受挫 | 识别需要持续关注而非一次性提醒的学生 |  |
| D-22 | 低年级首次受挫学生 | 当前低年级范围内，目标学期至少有一门未通过课程，且已接入的更早学期未观察到未通过记录的不同学生数 | “首次”仅指当前已接入历史范围内的首次；历史数据不完整时必须标注边界 | 在受挫早期及时发现并安排学习支持 |  |
| D-23 | 当前未解决课程 | 学生历史上出现未通过，且同一课程最新一次有效结果仍为未通过的不同课程清单 | 每门课程只保留最新有效状态，不能把历史失败全部当作当前风险 | 直接回答学生当前还需要解决哪些课程 |  |
| D-24 | 历史已解决课程 | 学生历史上出现未通过，但同一课程最新一次有效结果已通过的不同课程清单 | 作为成长证据展示，不计入当前未解决课程或当前风险 | 核验重修、补考或后续学习已经取得的结果 |  |
| D-25 | 当前有效预警 | 预警事件工作流状态尚未进入已解除或已关闭的预警；人数按不同学生计数 | 保留规则版本、命中证据和状态时间；不把历史已解除预警计入当前值 | 将当前成绩变化与学校正式预警事件对照核查 |  |
| D-26 | 透明优先核查名单 | 按“连续受挫且有重复未解决课程、低年级首次受挫、明确恶化且未通过课程增加、GPA明显下降、其他可比较学生”的公开顺序组织名单 | 不使用无法解释的综合风险分；各关注分组允许重叠，人数不得直接相加 | 让管理者知道先看谁、为什么进入名单以及下一步核查什么 |  |

注：V0.1中的D-17已删除，该指标服务于自动建议可信度，不属于教学管理分析范围。

“明确改善”“明确恶化”“连续受挫”“低年级首次受挫”和“重复未解决”等分组用于回答不同管理问题，允许同一学生同时进入多个分组，因此各组人数不能相加作为总人数。页面不得使用不公开权重的综合风险分替代上述可解释证据。

### 10.3 页面与核查路径

- 学生成长与学业分析保持一个菜单入口，根据当前工作身份呈现不同工作台：校领导和教务处看全校学院比较，学院看本院专业比较，辅导员和班主任看所带行政班，导师看所带学生。
- 顶部管理指标、组织比较、关注分组、名单和学生证据抽屉使用同一分析范围、同一聚合结果和同一筛选上下文；卡片数字必须能够下钻到对应名单。
- 学生核查优先在当前页面打开共用证据抽屉，集中呈现“为什么现在看”、两个观察学期变化、当前未解决课程、重复未解决课程、历史已解决课程、当前有效预警和培养方案证据边界。
- 只有需要查看完整跨学期档案时才进入完整档案；返回后应恢复原组织、关注分组、页码和滚动位置，不跳往其他业务模块。
- 数据来源至少标明成绩事实、课程最新有效结果、预警事件、培养方案绑定及学分完成证据，并显示聚合刷新时间；数据不足时显示“待核验”而不是推断正式结论。

### 10.4 分角色使用边界

- **学生本人**：说明当前进度、近期优先事项、学习难度提醒和可用资源；
- **辅导员**：关注持续风险、低年级首次受挫、历史预警和联系重点；
- **班主任**：关注专业课程学习、班级同类困难和课程学习支持；
- **导师**：关注所带学生的成绩变化、挂科门数、学分进度和未解除预警；
- **学院**：关注专业培养进度、集中缺口课程、课程供给和团队保障；
- **教务处**：关注跨学院结构问题、制度口径、资源协调和课程保障。

## 专题十一 新学年排课策略与方案优化

### 11.1 管理问题

面向教务处和学院排课人员，根据多年历史实际排课、新年度教学任务、教室和师资约束，辅助发现冲突、瓶颈和不均衡，比较候选排课方案。系统提供分析和参考，不自动发布正式课表。

### 11.2 指标口径

| 编号 | 指标名称 | 计算逻辑 | 边界与待确认 | 管理用途 | 意见 |
|---|---|---|---|---|---|
| Q-01 | 硬约束冲突数 | 候选方案违反不可违反规则（教师、学生、教室、校区、容量等）的事件数 | 硬约束清单须学校确认 | 判断方案是否可执行 |  |
| Q-02 | 教师时间冲突数 | 同一教师同一时段被安排多个教学任务的冲突数 | 联合授课角色须准确 | 排除不可执行安排 |  |
| Q-03 | 学生课表冲突数 | 同一培养群体、行政班或选课学生在同一时段被排了多门课的冲突数 | 按行政班还是按实际选课判断待确认 | 保护学生修读可行性 |  |

| Q-10 | 重点课程均衡度 | 体育、思政、数学、英语等课程在星期和时段上的分布离散程度 | 重点课程标签和合理分布标准待确认 | 优化关键课程安排 |  |

注：Q-12方案综合评分已移入专题十二，作为管理意义存疑指标单独确认。

## 13. 技术口径说明：数据分层与指标登记

本节向业务老师说明数据在平台内部的处理顺序，帮助理解“为什么同一个数字在不同页面必须一致”。技术实现细节供开发对照。

平台数据分四层，逐层加工。任何页面上的数字都能从下往上回溯到数据来源：

| 层 | 内容 | 说明 |
|---|---|---|
| 贴源层 | 从学校各系统采集的原始数据和采集批次台账 | 每批数据记录来源文件、行数、采集时间和质检状态；任何指标都能回溯到具体批次 |
| 事实层 | 清洗后的业务事实 | 成绩修读记录、预警记录、教学任务、课程日历、教室占用等；修读类型（首次/补考/重修）、成绩状态在这一层判定完成 |

| 指标层 | 指标口径登记表 | 每个正式指标先登记口径（统计对象、分子分母、排除项、数据来源、版本）再上线；页面展示与登记表一致 |

数据采集目前为手动或触发式：由管理员在系统管理端发起，采集监控页展示每批数据的采集时间、行数、质检状态和失败原因。平台尚不是实时同步，页面上的“数据截止时间”以最近成功批次为准。

### 14.2 分析方案治理与学校个性化确认

分析方案用于把学校确认的关注阈值、优先级参数和适用管理角色配置到既有分析能力中。它不新建指标、不修改正式指标公式、不改变数据来源，也不扩大当前工作身份的数据权限。系统始终保留产品默认方案；学校未发布自定义方案，或当前角色未被学校方案覆盖时，继续采用产品默认方案。

原型内置以下四类产品方案，学校可分别确认是否需要形成校本版本：

| 产品方案 | 回答的管理问题 | 学校可调整内容 | 不允许通过方案改变的内容 | 建议覆盖角色 | 学校意见 |
|---|---|---|---|---|---|
| 学业预警优先核查 | 有限核查时间应先关注哪些风险事实 | 风险等级分值、持续时长分、叠加规则上限等白名单参数 | 预警事实、学生范围、规则命中证据和正式指标公式 | 教务处、学院教学管理者等 |  |
| 毕业准备核查 | 哪些毕业准备缺口应优先核验 | 必修缺口、候选缺口、影响学生规模等关注阈值 | 培养方案、成绩、课程替代事实和毕业审核结论 | 教务处、学院教学管理者等 |  |
| 课程质量核查 | 哪些课程结果变化值得优先复核 | 最小样本、未通过率、持续偏高和波动阈值 | 成绩口径、课程归并、统计分母和教师评价结论 | 教务处、学院教学管理者等 |  |
| 师资保障核查 | 哪些课程供给连续性需要优先核验 | 教学班数、覆盖人次、单点承担和结构关注阈值 | 教师身份、教学任务、课程团队事实和人事评价结论 | 教务处、学院负责人等 |  |

学校方案从草稿到正式采用必须经过发布前检验，至少核对以下五项：

1. **参数边界**：只允许修改产品登记的参数，且数值在允许范围内；
2. **数据准备度**：方案所需事实表、字段和有效数据已经具备，缺失项明确披露；
3. **角色边界**：至少选择一个允许的管理角色，不用组织或学生名单替代正式数据权限；
4. **基础协议版本**：草稿基于当前产品协议，避免产品升级后继续使用失效配置；
5. **真实样本回放**：在当前授权数据上比较默认方案与草稿的信号数、高优先级数以及新增、移除对象，帮助业务人员判断调整影响。

发布、停用、回滚、导入和导出均须保留操作人、时间、理由、版本及结果。导入包只能形成“未检验草稿”，不得直接成为正式方案；回滚产生一个新的已发布版本，不覆盖历史版本。产品部署环境统一管理大模型服务地址和密钥，分析方案页面只引用其运行状态，不保存明文密钥。

# 附录A 指标确认的统一检查问题

对每个关键指标，请确认以下八个问题：

1. 指标名称是否符合学校日常用语；
2. 统计对象是人数、人次、课程数、门次、教学班数还是课次；
3. 分子包括哪些记录，排除哪些记录；
4. 分母代表谁，是否存在无数据学生被错误计入；
5. 时间范围是当前学期、学年、培养周期还是历史累计；
6. 结果能否下钻到可复核证据；
7. 指标异常后，管理者准备采取什么行动；
8. 数据是否具备，正式责任部门和更新频率是什么。

# 附录B 关键术语

- **人数**：同一名学生无论出现多少条记录，只算一个人；教师数同理；
- **人次**：一个人在不同课程、不同教学班或不同事件中可重复累计；
- **课程数**：按学校稳定课程编号计数；课程改码、同名不同码归并后算一门；
- **课程学期单元**：一门课程在一个学期内形成的统计单元；
- **修读类型**：每条成绩记录属于首次修读、补考或重修中的一种；通过率按三类分别统计，互不混算；
- **未通过记录**：某一次有效成绩记录结果未通过；
- **历史挂科经历**：历史上曾出现未通过记录，后续可能已解决；
- **当前未解决课程**：曾未通过且截至统计时点未形成认可通过结果；
- **明确缺口**：依据完整方案、成绩和替代证据能够确认的缺口；
- **候选缺口**：因方案绑定、课程归属、替代或结果证据不足而需要人工核验的疑似缺口；
- **历史实际排课分布**：根据真实课表统计出的行为结果，不等同于教师主动申报偏好；
- **高影响单点课程**：重点保障课程中，本期由1名教师实际承担且达到4个教学班或100人次规模的课程；单教师事实本身不自动进入风险队列；
- **数据覆盖率**：具备计算所需证据的对象数占应分析对象数的比例；覆盖率不足时不得把未知解释为正常或异常。

- 发布前必须通过参数边界、数据准备度、角色边界、基础协议版本和真实样本回放五项检验；检验失败不能发布，草稿再次编辑后原检验结果失效。
- 发布、停用、回滚、导入和导出均保留审计证据；导入只生成未检验草稿，回滚通过新版本恢复历史配置。

## 3. 同步快速实施与权限边界

- 学校可导出方案包用于测试与生产环境交接，也可导入合法方案包减少重复录入；环境中的大模型地址和密钥仍由部署配置统一管理。
- 方案适用角色不等于组织和学生数据范围，所有运行、详情和证据下钻继续按当前工作身份在服务端鉴权。
- 详细走查、实现和验收依据见 `docs/103-分析方案管理UE深度走查与优化方案.md`。
