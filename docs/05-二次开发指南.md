# 05 · 二次开发指南

## 1. 开发前最小上下文

先阅读仓库根目录 `AGENTS.md`，再按任务读取对应文件。不得先复制角色白名单或页面指标，
应复用统一权限上下文、指标注册和管理专家协议。

## 2. 本地运行与验证

```powershell
cd code
PYTHONIOENCODING=utf-8 python -X utf8 -m uvicorn backend.api.main:app --port 8000

cd frontend
npm.cmd run dev
```

长期演示服务使用 `code/scripts/start.bat`，不要依赖可见 PowerShell 窗口。

提交前至少执行：

```powershell
python -X utf8 -m unittest discover -s code/backend/tests -p "test_*.py"
python -X utf8 code/scripts/e2e_check.py
cd code/frontend
npm.cmd run build
git diff --check
```

## 3. 新增后端接口

1. 选择 `code/backend/api/routers/` 下的业务 router。
2. 使用统一包络 `ok()` 和 `ApiError`，业务错误码镜像 HTTP 状态码。
3. 通过依赖注入获得当前用户、旧库或 V2 连接。
4. 使用 `permission_context` 解析详细范围、聚合比较范围和动作权限。
5. 对学院、专业、课程、学生和教师对象再次鉴权，不能只信前端参数。
6. 敏感读取、导出和写操作接入审计。
7. 增加正向、跨范围反向、无映射和无权限测试。

范围缺失默认拒绝或返回空授权结果，禁止回退全校。

## 4. 新增页面或菜单

1. 页面放入 `frontend/src/views/admin/` 对应业务模块。
2. 在 `router/index.ts` 注册路由和管理员准入。
3. 菜单同时更新 `backend/etl/seed.py` 与幂等迁移脚本。
4. 菜单只保存二级叶子授权，父分组由后端按叶子补齐。
5. 页面必须显示工作身份、范围、学期、来源和更新时间。
6. 统一处理加载、无数据、证据不足、无权限和错误状态。
7. 详情优先使用抽屉并保留筛选、分页与返回路径。

## 5. 指标和口径

正式指标必须先完成：

- 后端公式和数据源。
- 统计粒度、更新周期、适用范围和版本。
- 权限过滤与测试。
- 管理意义和页面引用。
- 再登记到 `sys_kpi_config`。

指标管理页只调整显隐、排序和展示阈值，不能录入任意公式。修改公式时同步后端实现、测试、
口径文档和所有页面引用。

## 6. 数据模型与迁移

- 旧分析库权威结构：`backend/etl/schema.sql`。
- V2真实数据模型：`backend/etl/schema_v2.sql`。
- 结构变化必须提供可重复执行的迁移脚本。
- 先在真实库副本连续执行两次，再迁移正式库。
- 学校业务主数据只读，不通过本系统维护或回写。
- 临时 Word/Excel 解析仅服务原型；生产使用教务 API 或数据交换平台。

## 7. AI管理专家扩展

新增专家必须定义名称、版本、适用角色、管理问题、数据要求、指标、排序逻辑、事件条件、
输出卡片、证据路由、可调参数、边界和测试案例。

大模型可解释用户意图，不可：

- 修改正式指标公式。
- 扩大当前权限范围。
- 输出没有事实来源的趋势。
- 自动执行管理动作。

学校个性化通过白名单参数和分析方案版本实现，不复制整套页面。

## 8. 系统管理边界

- 账号与学校统一身份只保存主体映射，不保存认证密码或密钥。
- 角色页管理菜单和动作，数据范围页管理组织和人员关系。
- 预警规则在学业预警监控中治理。
- 系统参数不保存模型密钥、数据库口令或统一身份密钥。
- 所有配置变更必须带原因、版本和审计记录。

## 9. Git纪律

- 保护用户已有和未跟踪文件。
- 一个完整模块通过验收后再提交。
- 提交前检查 staged 文件清单和 `git diff --cached --check`。
- 数据库、日志、缓存、临时文件和真实敏感数据不得提交。
