# 05 · 二次开发指南

> 给接手开发的人：项目结构、如何加页面/接口/维度/数据、鉴权机制、注意事项。

---

## 1. 开发环境

按 `03-部署手册.md` 装好后端依赖、前端依赖、跑通 init。开发时建议：

- 后端：用 `--reload` 起 uvicorn 便于热更（脚本默认不开，是为演示稳定）：
  ```bash
  cd code
  PYTHONIOENCODING=utf-8 python -X utf8 -m uvicorn backend.api.main:app --reload --port 8000
  ```
- 前端：`pnpm dev` 本身热更。
- 改 Python 代码后若用脚本启动（无 reload），需重启 uvicorn；必要时清 `__pycache__`。

---

## 2. 后端：加一个接口

1. 在 `code/backend/api/routers/` 选合适的 router（或新建 `xxx.py`）。
2. 用 `code/backend/api/db.py` 的只读连接查 `analytics.sqlite`，返回时用 `envelope.ok(data)`。
3. 抛业务错误用 `ApiError(msg, code=, status_code=)`——**code 必须镜像 HTTP status**
   （如 404 传 `code=404, status_code=404`），否则前端/e2e 断言失败。
4. 新建 router 要在 `api/main.py` 的 `from .routers import (...)` 与注册处加上。
5. 维度入参遵循「Optional + 空参不加 WHERE」约定，保证空参时行为与全量一致（e2e 基线依赖此）。

示例（伪代码）：
```python
@router.get("/api/admin/xxx")
def xxx(semester: str | None = None, conn=Depends(get_ro_conn)):
    sem = semester or CURRENT_SEMESTER
    rows = conn.execute("SELECT ... WHERE semester_id=?", (sem,)).fetchall()
    return ok([dict(r) for r in rows])
```

---

## 3. 前端：加一个页面

1. 在 `code/frontend/src/views/admin/` 加 `.vue` 页面。
2. 在 `src/router/index.ts` 注册路由（hash 路由 `#/admin/...`）。
3. 数据请求走 native fetch / http 封装，读 `d.data`。
4. 若需出现在侧边栏，要在 `sys_menu` + `sys_role_menu` 里加菜单项（见下「改菜单」）。
5. 维度下拉统一用 `src/utils/meta.ts` 的 `getFilterMeta()`（进程内缓存，单拉）。
6. 学院码用 `src/constants/colleges.ts` 的真实 C01-C16，勿硬编码虚构码。
7. 下钻跳转透传学期：`router.push({ path, query: sem ? { semester: sem } : {} })`。

---

## 4. 改菜单 / 角色 / 预警规则（系统元数据）

这些数据在 **两处** 定义，改时**两处都要同步**，否则重建会回退：

1. **代码源**：`code/backend/etl/seed.py`（`MENUS` / `ROLE_MENU` / `ROLES` / `ALERT_RULES`）——
   `run_etl` 重建时写入。
2. **运行库（LIVE DB）**：用幂等迁移脚本只改 `sys_*` 表，避免全量重 ETL：
   - `code/scripts/migrate_menu.py` —— 同步菜单与角色菜单绑定
   - `code/scripts/migrate_alert_rules.py` —— 同步预警规则

流程：先改 `seed.py`，再改对应 migrate 脚本（保持一致），跑 migrate 更新 LIVE DB，重启 uvicorn。
下次有人重跑 init 时 seed.py 保证重建结果一致。

> 预警规则的阈值改动若要**真正生效到预警结果**，需重跑 ETL（`alert_engine.py` 仅在 ETL 阶段消费阈值）。
> 系统设置页改阈值只写回 `sys_alert_rule.params`，UI 已明示「下次重算生效」。

---

## 5. 改数据 / 加业务域

**铁律：不在 API 层硬编码假数据。** 任何「造数」都要落到 ETL 合成真表并走 `run_etl`。

- **真实学业源已有的**（成绩/任务/异动/校外考试/调停课）：在 `transform.py` / `extract_ts.py` 加工。
- **真实源缺失、需要合成的业务域**（毕业/考纪/出勤/师资画像/学分要求）：在
  `code/backend/etl/synth_business.py` 仿现有范式新增——固定随机种子（`config.SEED`）保证可复现、
  标 `source='sim'`、前端不暴露 `source`。
- 在 `schema.sql` 加表，在 `run_etl.py` 的编排里接入新表，重跑 init。
- 源实体的真实属性（如职称分布、选课密度）应在**源数据生成器**层改，不在 ETL 改源库。
  （源生成器不随本包附带，见 `datasource/构造数据/README.md` 的说明。）

---

## 6. 鉴权机制（现状与扩展）

- 当前实现：**仅菜单级权限**。登录签发 JWT；`auth` router 按角色从 `sys_role_menu` 返回可见菜单；
  前端按返回菜单渲染侧边栏与路由守卫。
- **数据范围（data_scope）暂未实装**：`sys_role`/`sys_role_scope` 已建表并绑定演示范围
  （院长→某学院、系主任→某专业、辅导员→若干班级），但查询接口**未按 scope 过滤**，所有角色看全量。
- 扩展数据权限：在受保护接口里读当前用户角色的 `sys_role_scope`，对查询追加
  `WHERE college_id IN (...)` 等过滤。这是后续工作量集中点。

---

## 7. 测试 / 核对

- `code/scripts/e2e_check.py`：无依赖端到端核对，逐接口与库现算基线比对，动态基线（换库仍有效）。
  改接口后跑一遍确认零回归：
  ```bash
  cd code && PYTHONIOENCODING=utf-8 python -X utf8 scripts/e2e_check.py
  ```
- 改了维度/报表口径后，重点核对空参输出是否与改动前一致（基线对齐）。

---

## 8. 注意事项清单

- 终端 Python 一律 `PYTHONIOENCODING=utf-8 python -X utf8`。
- `major_id` 每次 ETL 重建可能重排，代码里**按专业名**解析真实方案（`安全工程`/`海洋油气工程`），
  勿写死 id。
- 错误包络 `code` 必须镜像 HTTP status。
- 改 `sys_*` 元数据走幂等迁移脚本 + 同步 seed.py。
- 分析库只读；唯一允许写 `sys_*` 的是迁移脚本。
- ETL 重建是 DROP+CREATE 幂等，安全可重复。
