# 54 · 产品范围与待决策事项

> 文档状态：生产系统立项前范围基线。  
> 维护原则：已确认、待确认、暂缓三种状态必须分开，不以原型页面存在作为生产立项依据。

## 1. 产品目标

面向学校、学院和授权教师，建立可解释、可追溯的学生学业分析能力，重点回答：

- 学生当前完成了什么、缺少什么、下一步应该修读什么。
- 成绩失败是历史经历还是当前仍未解决的问题。
- 哪些课程、年级、课程类别和时段存在资源或质量异常。
- 学生学业状态如何随学期变化，哪些低年级事件值得尽早关注。
- 培养方案、课程资源、教师团队和教室资源是否能够支持学生完成学业。

当前产品不是心理测评系统、教师绩效系统，也不自动替代学校作出学籍、毕业、学位或处分决定。

## 2. 原型与生产系统的关系

| 类型 | 定义 | 处理原则 |
|---|---|---|
| 原型已验证 | 已有页面、接口和可核对数据 | 生产开发可复用需求和交互，不默认复用实现 |
| 生产必做 | 已确认的生产业务能力 | 必须形成数据合同、权限、接口和验收标准 |
| 条件性能力 | 业务成立但依赖学校补数 | 数据未到位前不得用模拟结果替代 |
| 待决策 | 产品责任边界尚未确定 | 不进入承诺范围，不删除原型研究成果 |
| 暂缓 | 当前阶段明确不实施 | 记录触发重新立项的条件 |

## 3. 生产系统必做范围

### 3.1 成绩与课程结果

- 保留每次原始修读和考试尝试。
- 形成学校认可的当前有效课程结果。
- 区分正常、补考、重修、缓考、缺考、免修、作废和更正。
- 区分历史挂科、当前未通过和重修仍未通过。
- 支持课程替代、课程等价和学分认定。
- 所有挂科、学分和毕业相关指标使用统一版本化口径。

### 3.2 学生成长轨迹

- 按学期展示课程、成绩、学分、方案缺口和关键学业事件。
- 标记首次挂科、同课反复未通过、连续学期下降和后续改善。
- 支持从课程、教师、教学班、学院和课程类别追溯事件。
- 对大一首次挂科开展队列分析，但不直接作心理或因果判断。
- 数据按辅导员、任课教师、学院和学生本人实行最小必要访问。

### 3.3 培养方案与课程建议

- 按学生匹配正确的培养方案版本和个别例外。
- 计算已通过、在修、应选未选、未通过待重修和尚未到建议学期。
- 说明课程缺口对培养模块、毕业和学位要求的影响。
- 匹配可用的正常班、重修班、补修班或跟班资源。
- 输出可解释的选课/重修建议，保留人工核验提示。

### 3.4 课程开设与教学运行

- 建立课程—教学班—课程日历—教室—教师的标准关系。
- 支持单门课程历年开设、年级、类别、班额和时间分布。
- 支持体育课、思政课等课程类别的时段热力图。
- 支持教学任务、调停课和实际执行日历追溯。
- 教室利用率使用管理员维护或正式台账中的可用资源作为分母。

### 3.5 师资与课程团队

- 统计教师基本结构和课程承担情况。
- 仅根据真实历史排课结果推断时间、地点和集中度偏好。
- 对每门课程分析可授课教师、年龄段、职称段和梯队结构。
- 识别单一教师依赖、团队断层和重修资源覆盖不足。
- 结果用于课程资源规划，不直接作为教师个人绩效结论。

### 3.6 管理、权限与审计

- 统一身份认证和账号映射。
- 菜单、功能、数据范围和导出权限分开控制。
- 支持学校、学院、专业、班级、教学班和本人范围。
- 敏感字段按角色脱敏。
- 个人明细访问、导出和管理变更进入审计。
- 指标公式、数据批次和规则版本可追溯。

## 4. 原型已验证但生产需重构

| 能力 | 原型验证结果 | 生产重构要求 |
|---|---|---|
| 数据大屏与下钻 | 已完成核心指标和五级下钻 | 使用生产指标服务、缓存和正式数据权限 |
| 教学运行 | 已完成课程、教室、调停课、负荷等分析 | 接入真实课程日历和教室资源台账 |
| 师资结构 | 已完成结构、详情、团队和历史偏好原型 | 替换模拟画像，建立正式团队主数据 |
| 学生画像 | 已完成 GPA 迁移和挂科模式 | 升级为版本化成长事件模型 |
| 管理决策专题（原报表中心） | 已确认专题化方向，自定义报表和认证评估暂时移除 | 按 `70`、`71` 号规划分阶段建设五个管理专题 |
| 学业建议与关注要点 | 已完成产品与AI治理规划 | 先建设确定性模板和五类角色视角；学生端范围、模型部署及隐私边界待确认 |
| 规则发现 | 已完成确定性统计候选和治理链路 | 是否纳入生产需结合预警范围决定 |
| 系统安全 | 已验证 RBAC、限流、审计和 KPI 配置 | 接入 SSO、集中密钥、生产审计和安全基线 |

## 5. 条件性范围

以下能力业务上需要，但只有数据合同完成后才能进入生产开发验收：

- 全校培养方案和课程替代规则。
- 应选未选和选课失败原因。
- 真实重修班及剩余资源推荐。
- 星期、节次、周次级课程热力图。
- 教室真实可用数量和座位时段利用率。
- 教师年龄、职称梯队和课程资格。
- 真实毕业、学位、异动和调停课分析；考风考纪、出勤及校外考试因数据或价值未确认暂缓。

对应数据集见 `52-学校基础数据需求与缺口清单.md`。

## 7. 明确暂缓范围

- 预警后续处置闭环，除非 DEC-01 确认纳入。
- 多校多租户和跨校数据同步。
- 实践教学全域，等待实验、实习、论文和创新学分数据。
- LLM 自动生成学生干预结论。
- 依据课程或教师直接推断学生心理状态。
- 无人工复核的自动毕业、学位或学籍决定。

## 8. 关键产品约束

1. 生产页面不得把模拟数据显示为真实数据。
2. 推荐必须返回依据、数据时间和限制说明。
3. 学生风险结论不得使用未经学校确认的口径。
4. 教师分析不得越界为自动绩效评价。
5. 个人明细遵循最小必要原则并记录审计。
6. 学校业务规则必须版本化，不能只写在页面或代码中。
7. 数据缺失时显示不可计算或待补数，不生成貌似完整的结果。

## 9. 范围变更流程

新增或改变生产范围时，应记录：

- 决策编号、提出人和决策人。
- 业务目标和不做的后果。
- 所需数据和数据责任人。
- 涉及角色和权限。
- 指标、接口、页面和测试影响。
- 生效版本和迁移方式。

未经记录的口头需求不直接进入开发承诺。

## 10. 当前实施顺序

1. 学校数据缺口确认和样例取数。
2. 生产交接文档和需求追踪体系。
3. 最终有效成绩模型。
4. 学生成长轨迹。
5. 培养方案差异和课程建议。
6. 单门课程、课程日历和资源分析。
7. 师资团队和排课偏好。
8. 权限、性能、同步、部署和生产验收。
