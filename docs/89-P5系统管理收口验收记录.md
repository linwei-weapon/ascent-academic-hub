# P5 系统管理收口验收记录

日期：2026-07-19
分支：`产品终稿`

## 1. 验收结论

P5 已完成。系统管理当前统一为十个二级菜单：

1. 账号管理
2. 角色与功能权限
3. 菜单管理
4. 数据权限
5. 指标与口径管理
6. 分析方案管理
7. 审计日志
8. 系统参数
9. 决策配置
10. 数据采集监控

系统管理员默认具有全校业务数据范围和全部系统管理入口。二级学院等非管理员角色
既看不到系统管理菜单，也不能通过直接输入 URL 或调用 API 绕过限制。

## 2. 模块实现

### 2.1 账号管理

- 顶部五项治理状态区分有效账号、已映射、待映射、权限异常和已停用/归档，并可直接筛选名单。
- 账号列表使用服务端分页和组合筛选，同时显示账号来源、默认工作身份、权限准备度和统一身份映射状态。
- 账号核查抽屉展示全部认证来源、工作身份、教职工号、最近登录及账号治理记录。
- 认证接入检查抽屉提供稳定认证主体、教职工号、生命周期和密钥边界实施清单。
- 平台不保存统一身份认证密码、认证密钥或票据。
- 账号可直接定向进入本人的数据权限配置，保留目标账号查询条件并自动打开配置抽屉。
- 数据权限页提供返回账号管理入口，并恢复原查询条件。
- 停用和归档必须填写原因，保留历史身份、范围和审计证据。
- 账号新增、修改、归档、密码重置和认证映射变更均写入审计；详情不混入普通登录审计。

原型完成“学校认证主体—本地账号”映射治理；CAS、OAuth2/OIDC 或学校统一身份
认证网关的真实登录回调，在生产部署阶段按学校接口规范接入。

### 2.2 角色与功能权限

- 菜单权限与页面关键动作权限在同一抽屉分 Tab 配置并原子保存。
- 已登记 15 项动作权限，覆盖业务数据、学业预警、教学运行、培养质量、
  AI 管理决策和系统管理。
- 权限预览同时展示角色、数据范围类型、菜单入口和关键动作。
- 系统阻止当前管理员移除自身的 `system.manage` 权限或系统管理入口。
- 数据范围不在角色页配置，仍由账号工作身份、组织范围和人员关系计算。

### 2.3 数据权限

沿用并收口 P2 的统一数据权限工作台：

- 支持账号、教职工号、多工作身份和组织范围。
- 支持学院、专业、行政班、任课关系、辅导员/班主任带班和导师带生关系。
- 展示缺失映射、过期关系、重复关系和来源缺失。
- 支持按账号核验有效菜单、动作、范围和可见学生数量。

### 2.4 菜单管理

- `sys_menu` 是菜单真值源，保持三个一级分组和二级叶子菜单。
- 显示层级、父级、排序、路由、图标和授权角色数。
- 系统管理固定为十个二级入口，系统管理员拥有全部入口。

### 2.5 指标与口径管理

指标与口径管理已由“少量首页卡片配置”升级为统一指标目录：

- 客户确认材料中的 207 个稳定指标编号全部登记；
- 分析范围背景和历史兼容项单独登记 3 项，统一目录合计 210 项；
- 指标定义、页面引用、展示阈值分层治理，避免一处配置同时承担正式口径和页面样式；
- 当前挂科学生率（O-10）与历史挂科经历率（G-08）已统一分母和实现口径；
- 缺少可靠事实来源的毕业率、学位授予率旧展示项已停用并解除页面引用。

每项指标展示稳定编号、名称、管理用途、计算公式、统计边界、数据源、统计粒度、
更新周期、定义版本、实现状态和页面证据。目录支持服务端分页、筛选、页面一致性
核验、详情抽屉和客户确认清单导出；旧 `sys_kpi_config` 只保留兼容周期内的页面
展示配置，不再作为正式指标定义真值源。

### 2.6 分析方案管理

- 集中展示三个首批管理专家、产品版本、学校有效版本和适用角色。
- 分析方案支持草稿、兼容性测试、发布、角色覆盖和停用。
- 管理专家配置支持学校版本发布和回滚。
- 学校方案只覆盖白名单参数和适用角色，不复制页面、不改变指标公式，
  也不保存组织数据范围。
- 普通管理用户从“决策研判”保存方案，不需要理解 Prompt 或技术 Skill。

当前正式库尚未保存学校分析方案，因此方案列表显示空态；三个产品管理专家及其
有效版本已正常展示。

### 2.7 审计日志

审计范围包括：

- 登录、登出和工作身份切换。
- 学生名单、学生详情和数据导出。
- 账号、角色、菜单、数据权限和统一身份映射变更。
- 指标展示配置、预警规则、系统参数变更。
- AI 研判、模拟、分析方案测试/发布/停用和专家版本操作。

敏感读取审计不记录请求正文、Token 或查询参数，只记录操作人、当时的工作身份、
动作、业务对象、结果、客户端和时间。真实链路已验证学生名单与学生详情读取会生成
`data.student.list.read` 和 `data.student.detail.read` 记录。

### 2.8 系统参数

系统参数分为学校信息、学期与数据、大模型接入、性能与展示四组，共 14 项。

- 学校名称、学校代码、当前业务学期和教学任务学期。
- 数据更新时间策略。
- 模型启停、学校批准的接入方式、允许数据范围和生成模式。
- 管理要情/决策研判缓存、默认表格行数和数据来源显示。

参数变更必须填写原因并记录版本。模型密钥、统一身份认证密钥、数据库口令由部署
环境管理，不在页面保存或回显。学业预警规则仍在“学业预警监控”中治理，不进入
系统参数。

### 2.9 数据采集监控

- 18项应接入数据源形成统一目录，覆盖基础主数据、学籍与培养方案、成绩与课程结果、
  教学任务与师资、实际教室占用。
- 接入状态与校验状态分离，原17批`accepted`误报已修正。
- 采集待核验不再读取教学运行域32项问题；当前真实显示培养方案3项、教室楼宇10项、
  实际占用楼宇匹配389项。
- `etl_run_batch`支持一个任务关联多个输入批次；现有2次课程结果重建已形成6条关联。
- 页面提供四项管理状态、优先事项、数据源态势、运行与异常、交付清单和两类证据抽屉。
- 手动重跑移入受控运维抽屉，白名单、动作权限、并发保护和安全审计继续生效。
- 正式调度由学校数据交换平台负责，平台不维护源业务数据。

## 5. 生产交接边界

1. 统一身份认证的实际协议、回调地址、客户端标识和密钥由学校部署环境提供。
2. 教职工号、辅导员/班主任带班和导师带生关系继续以学校权威数据同步为准。
3. 新指标必须先在后端实现计算、权限过滤和测试，再登记到口径管理。
4. 分析方案不得改变事实指标公式；学校个性化仅覆盖管理专家白名单参数。
5. 系统参数页不承担教务主数据维护，也不承担预警规则管理。
