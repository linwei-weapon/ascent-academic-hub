# 06 · 数据库表结构

> 权威 DDL：`code/backend/etl/schema.sql` 与 `schema_v2.sql`。
> 表数量会随幂等迁移增加，不再使用“固定33张表”作为版本判断依据。

## 1. 双库定位

| 数据库 | 用途 | 生产含义 |
|---|---|---|
| `analytics.sqlite` | 现有可运行原型、历史分析和系统元数据 | 兼容层与演示库 |
| `analytics_v2.sqlite` | 新增真实数据、生产模型和接入验证 | 生产数据结构参考 |

两个库均只消费学校数据。系统管理写操作只修改平台配置、权限、审计和派生治理表。

## 2. 旧分析库核心表

### 维度

`dim_college`、`dim_major`、`dim_class`、`dim_course`、`dim_teacher`、`dim_semester`、
`dim_student`。

### 事实

`fact_grade`、`fact_lesson`、`fact_plan_course`、`fact_plan_meta`、`fact_alert`，
以及毕业、学籍异动、外语/证书、教师画像、调课和教室占用等事实表。

### 预聚合

`agg_college_term`、`agg_major_term`、`agg_course_term`、`agg_gpa_dist`、
`agg_teacher_load`、`agg_classroom_util`。

大表索引以学期＋学生/课程/教师/教学班复合键为主，避免页面扫描全表。

## 3. V2生产模型

V2按“批次—主数据—关系—事实—派生结果”组织：

- 批次与血缘：数据批次、源文件、同步时间和质量状态。
- 主数据：学生、组织、专业、课程、教师、楼宇和教室。
- 人员关系：辅导员/班主任带班、导师带生、任课教师和开课组织。
- 培养方案：方案版本、模块规则、课程要求、课程替代、学生方案绑定。
- 教学运行：教学任务、教学班、排课时段、实际教室占用和调课。
- 学业事实：成绩尝试、课程通过状态、预警事件和成长轨迹。

培养方案执行的关键派生表：

| 表 | 粒度 | 说明 |
|---|---|---|
| `student_plan_course_status` | 学生—方案—课程 | 通过、认定、明确未通过、无完成证据、是否到期及有效学分 |
| `student_plan_module_status` | 学生—方案—模块 | 采用的可信规则、目标值、完成值、模块是否达到和证据状态 |
| `student_plan_progress_summary` | 学生—方案 | 模块覆盖、已达到模块、明确问题、数据候选、绑定状态和计算版本 |

上述三表是版本化派生结果，不替代学校源数据。生产系统应按成绩、方案、绑定、课程替代和学籍异动增量重算，并保留数据批次、规则版本、计算时间与来源。

详细字段见 `docs/56-原型真实数据接入与生产数据模型.md` 和
`docs/63-V2后端查询接口说明.md`。

## 4. 统一权限表

| 表 | 说明 |
|---|---|
| `sys_user` | 本地账号 |
| `sys_auth_identity` | 学校认证主体与本地账号映射 |
| `sys_role` | 角色及范围类型 |
| `sys_user_role` | 账号工作身份 |
| `sys_user_staff` | 账号与教职工号 |
| `sys_user_scope` | 工作身份组织范围 |
| `sys_staff_student_relation` | 带班/带生人员关系 |
| `sys_menu`、`sys_role_menu` | 两级菜单与角色入口 |
| `sys_role_action` | 页面关键动作权限 |

权限查询以当前工作身份生成范围指纹。旧 `sys_role_scope` 仅作兼容，不再作为真实用户唯一范围。

## 5. 规则、指标与AI治理表

| 表 | 说明 |
|---|---|
| `sys_alert_rule` | 已发布预警规则 |
| `sys_kpi_config` | 指标登记与展示配置 |
| `sys_kpi_config_history` | 指标展示配置历史 |
| `sys_ai_expert_version` | 学校管理专家版本 |
| `sys_ai_analysis_scheme` | 分析方案 |
| `sys_ai_analysis_scheme_role` | 方案适用角色 |
| `sys_system_parameter` | 学校、学期、模型边界和展示参数 |
| `sys_system_parameter_history` | 系统参数历史 |

正式指标公式在代码注册，`sys_kpi_config` 不接受页面任意公式。

## 6. 安全与审计表

`sys_security_audit` 记录登录、身份切换、敏感读取、导出、权限、规则、指标、系统参数和
AI方案操作；登录失败、限流、令牌撤销等由安全治理表支持。

审计不保存密码、Token、模型密钥或请求正文。

## 7. 迁移规则

主要幂等迁移：

- `migrate_menu.py`
- `migrate_permission_context.py`
- `migrate_staff_relationships.py`
- `migrate_system_management.py`

迁移必须：

1. 可重复执行。
2. 先在副本库测试。
3. 不删除学校业务事实。
4. 同步更新初始化 DDL/seed。
5. 提供测试和验收记录。
