# 教学运行与师资生产数据契约

> 适用范围：课程开设、课程日历、教室资源、历史排课分布、课程团队分析。  
> 系统定位：本系统是数据消费和分析系统，不维护教室、课程、教师等源业务数据。

## 1. 数据责任边界

| 数据域 | 上游责任 | 本系统责任 | 本系统不负责 |
|---|---|---|---|
| 课程主数据 | 提供稳定代码、类别、性质、标签及有效期 | 关联、分类统计、质量提示 | 创建或修改课程 |
| 教学任务 | 提供教学班、教师、学生范围、容量和学时 | 开课聚合、课程团队分析 | 排课、调课审批 |
| 课程日历 | 提供周次、星期、节次、日期、地点及变更 | 时段热力图、历史行为分布 | 生成或维护课表 |
| 教室资源 | 提供楼宇、教室、容量、可用状态和有效期 | 计算可用基数、利用率和异常分布 | 维护教室可用数量 |
| 教师档案 | 提供组织、职称、年龄段、在职状态及有效期 | 团队结构和资源风险分析 | 人事档案管理 |

## 2. 通用传输契约

每批数据必须包含：

- `batch_id`：全局唯一批次号。
- `source_system`：来源系统代码。
- `generated_at`：上游生成时间。
- `data_from`、`data_to`：数据覆盖时间。
- `schema_version`：字段契约版本。
- `is_full`：全量或增量标志。
- 删除数据必须提供删除标志或失效时间，不得仅从增量文件中消失。

字符编码统一 UTF-8；时间使用带时区的 ISO 8601；业务代码按字符串传输，保留前导零。

## 3. 核心数据集

### 3.1 课程主数据 `course_master`

| 字段 | 必填 | 说明 |
|---|:---:|---|
| `course_id` | 是 | 稳定课程代码 |
| `course_name` | 是 | 正式名称 |
| `organization_id` | 是 | 开课单位 |
| `category_code` | 是 | 课程类别代码 |
| `nature_code` | 是 | 必修、限选、任选等性质代码 |
| `subject_tags` | 否 | 体育、思政、实践等标准标签列表 |
| `credits`、`total_hours` | 否 | 学分、总学时 |
| `valid_from`、`valid_to` | 是 | 版本有效期 |
| `status` | 是 | 启用、停用、合并等正式代码 |

生产系统识别体育、思政课程必须优先使用 `subject_tags`，不得长期依赖名称关键词。

### 3.2 教学任务 `teaching_lesson`

业务唯一键建议为 `semester_id + source_lesson_code`。必须提供课程、开课单位、容量、实际选课人数、总学时、面向年级/专业/班级及状态。教师关系使用独立的 `lesson_teacher` 数据集，支持主讲、辅讲、实验指导等角色和工作量。

### 3.3 课程日历 `course_meeting`

| 字段 | 必填 | 质量要求 |
|---|:---:|---|
| `meeting_id` | 是 | 全局唯一且可稳定重放 |
| `lesson_id` | 是 | 必须关联有效教学任务 |
| `week_no` 或周次规则 | 是 | 能展开为实际教学周 |
| `weekday` | 是 | 1～7 |
| `period_start/end` | 是 | 必须关联节次代码表 |
| `room_id` | 否 | 线上、室外等情况使用正式地点类型代码 |
| `meeting_date` | 建议 | 调停课后应提供实际日期 |
| `status` | 是 | 正常、取消、调出、调入等代码 |
| `supersedes_id` | 调课必填 | 关联被替代的原日历记录 |

### 3.4 教室资源 `room_master`

必须提供 `room_id`、`building_id`、教室类型、座位数、是否虚拟、是否可排、状态及有效期。可用教室分母由上游业务规则确定并提供；本系统只校验以下异常：

- 标记可用但座位数为空或不大于零。
- 教室关联不到楼宇。
- 同一教室存在重叠有效版本。
- 已停用教室仍出现在有效课程日历中。

### 3.5 教师档案与课程团队

最低必需字段为教师代码、显示名称、组织、在职状态、职称及有效期。年龄只接收年龄段或受控计算结果，前端不得展示不必要的出生日期。课程负责人和团队成员关系应包含课程、教师、角色、生效时间和失效时间。

## 4. 数据质量门禁

| 编号 | 规则 | 阻断级别 |
|---|---|:---:|
| `TQ-01` | 教学任务业务键重复 | 阻断入库 |
| `TQ-02` | 教学任务课程无法关联 | 阻断聚合 |
| `TQ-03` | 课程日历无法解析星期或节次 | 隔离并告警 |
| `TQ-04` | 日历关联不到教学任务 | 阻断入库 |
| `TQ-05` | 教师代码缺失或关系重复 | 隔离并告警 |
| `TQ-06` | 教室可用但容量无效 | 排除利用率分母并告警 |
| `TQ-07` | 课程标签缺失 | 允许入库，专项分析标记不完整 |
| `TQ-08` | 职称缺失 | 允许入库，不参与梯队结构结论 |
| `TQ-09` | 单教师单学期教学班数异常 | 隔离复核，不静默纳入偏好 |
| `TQ-10` | 同教室同时间存在冲突日历 | 告警并保留冲突证据 |

所有质量结果需保存批次、源记录标识、规则版本、发现时间和处置状态。分析页面只显示消费结果与质量边界，不承担源数据修订。

## 5. 增量、重算与血缘

- 课程、教室、教师主数据采用带有效期的版本化同步。
- 教学任务和课程日历按学期增量同步，调停课以新记录替代原记录，不物理覆盖历史。
- 任一课程标签、日历、教师关系或教室可用状态变化，应标记受影响学期、课程、教师和楼宇的聚合结果待重算。
- 每个聚合结果保存 `source_batch_ids`、算法版本和计算时间。
- 前端查询的学期列表只返回已完成装载且通过最低质量门禁的真实教学任务学期。

## 6. 权限与隐私

- 全校聚合对校级授权角色开放。
- 学院用户只能查看本学院开课、团队和资源汇总。
- 教师个人历史排课分布只能用于资源分析，不形成绩效结论。
- 教师年龄段、职称等人事字段按最小必要原则展示，导出权限单独控制。
- 学生范围文本不得在课程团队和教室分析接口中泄露个人名单。

## 7. 验收样例

生产开发至少准备以下契约样例：

1. 一门普通课程跨多个教学班、多个教师的正常样例。
2. 一门体育课和一门思政课，能够通过标准标签进入专项热力图。
3. 单双周、跨节次、室外和线上课程日历。
4. 一次调课替代原课表的完整关联。
5. 可用、停用、虚拟、容量缺失四类教室。
6. 教师职称完整和缺失的课程团队，验证缺失不被误判为人才风险。
7. 无真实教学任务学期，所有页面显示诚实空态。

## 8. 原型到生产的迁移说明

- 原型 SQLite 与固定批次 ETL 仅用于验证，不作为生产物理架构。
- 原型的体育/思政名称关键词识别必须由标准课程标签替代。
- 原型教师排课分布仅覆盖已接入学期；生产风险分析需要多学期样本量和稳定性阈值。
- 原型教室可用基数来自当前主数据字段；生产以学校确认的上游业务口径为准。
- 原型 V2 API 可作为响应语义基线，生产接口需补充分页、数据版本、刷新时间和质量摘要。
