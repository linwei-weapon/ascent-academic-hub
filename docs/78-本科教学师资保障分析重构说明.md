# 本科教学师资保障分析重构说明

## 1. 产品定位

原“师资结构分析”由传统教师画像统计调整为“本科教学师资保障分析”。页面面向教务处和二级学院回答：哪些课程存在当期师资单点承担、哪些课程影响范围较大、教学任务是否集中、教授是否实际参与本科教学，以及课程团队证据是否足够。

系统一级菜单同步调整为“师资保障分析”。存量原型数据库执行 `python -m backend.etl.migrate_faculty_menu` 更新菜单名称，新初始化数据库直接使用更新后的菜单种子。

本模块不评价教师个人教学质量，不以学生平均成绩对教师排名，不使用模拟年龄、学历、教龄或学缘形成管理结论。

## 2. 管理指标

- 本科教学活跃教师：当前学期至少承担一个本科教学班的去重教师。
- 单一教师覆盖课程：当前教学任务只关联一名实际授课教师的去重课程。
- 高影响单点课程：单一教师覆盖且选课人次不少于100的课程；100人为原型核查阈值。
- 教授本科教学参与率：职称含教授且承担本科教学任务的人数除以教授人数；因缺岗位状态，分母需要人工核验。
- 职称证据完整率：实际授课教师中职称非空人数占比。
- 前10%主讲教师任务占比：按主讲教师字段覆盖选课人次排序，取前10%教师的覆盖人次占比，只描述任务集中度；联合授课当前没有工作量分配比例，因此不拆分工作量。

## 3. 管理操作链

学院保障对比支持收敛到单一学院；课程团队风险表可以直接进入团队证据；教师任务集中表可以进入教师教学档案。课程团队工作台展示实际授课成员、职称证据、历史开课规模和核查建议。

页面取消“学院保障概览—风险课程核查—主讲任务核查”三个页签，改为全校概览常驻、宽抽屉局部核查。点击学院后仅抽屉加载学院指标、风险课程和主讲任务摘要，全校指标及学院列表不刷新；关闭抽屉不请求接口。学院结果按“学期+学院”缓存，课程团队证据在同一个抽屉内继续下钻，返回学院核查时复用已有数据。

联合授课教师从 `teacher_id` 和 `teacher_ids` 两个字段合并去重，避免只统计主教师造成虚假单点风险。学院角色继续执行数据范围校验。

## 4. 移除和降级

- 移除教师任课平均分排名，课程成绩结果归属课程质量专题。
- 移除模拟年龄、学历、教龄和学缘结构图。
- 将“未上课教授”改为教授本科教学参与率，并明确岗位状态缺口。
- 不使用“超负荷”结论，只展示教学班、课程和选课人次供人工核查。

## 5. 数据边界

当前真实证据包括教师身份、组织、部分职称、教学任务、教学班、课程、容量和选课人次。生产系统仍需补充完整岗位状态、真实年龄、学历学位、课程资格、课程负责人、未来教学任务和学校正式工作量标准。

## 6. 验证

- 管理总览接口完成全校和学院筛选验证，典型响应低于500毫秒。
- 风险课程可以直接打开团队核查工作台。
- 联合教师拆分、课程成员、教学班、选课人次和历史开课学期完成接口核对。
- 后端语法检查和前端生产构建通过。
