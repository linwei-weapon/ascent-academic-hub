# 学生画像模块审计与第一批修正

## 审计结论

学生学业分析和学生清单已有真实成绩、学籍和预警接口，但存在以下基础问题：

1. 学院、专业和班级受限角色的数据范围 SQL 使用了错误别名，可能导致受限角色请求失败。
2. 毕业率和学位授予率没有完整继承班级筛选及角色数据范围。
3. 毕业、学位和多数专业学分要求来自合成数据，页面没有充分披露。
4. 学生清单显示的“平均 GPA”只计算当前分页 20 人，不代表完整筛选群体。
5. 清单的重修、非重修、必修和选修筛选没有真正进入 GPA 与挂科指标口径。
6. GPA 排序使用逐学生相关子查询，性能较差，且排序口径与页面展示口径不一致。
7. 当前“学生群体聚类”实际只是固定 GPA 分档，尚未实现时间趋势聚类、挂科模式和画像迁移。

## 第一批修正

### 数据范围

- 学生分析和学生清单统一使用 `dim_student` 限定数据范围。
- 学院角色仅能统计本学院学生。
- 毕业率和学位授予率通过筛选后的学生集合计算，继承学院、专业、年级、班级和角色范围。

### 清单指标

- 后端返回完整筛选群体的 GPA 均值和有 GPA 学生数。
- 前端不再使用当前分页自行计算平均 GPA。
- 重修/非重修、必修/选修筛选进入 GPA 和挂科数计算。
- GPA 为 0 时不再被错误转换为空值。

### 排序性能

- 复用已经按筛选条件计算的学生 GPA 映射。
- 在 12,670 名学生候选集合上完成一次内存排序后分页。
- 避免逐学生执行成绩均值相关子查询。
- 排序、展示和摘要使用同一套筛选口径。

### 证据边界

页面新增证据提示：

- 学籍、成绩、GPA、挂科和当前有效预警来自真实数据。
- 毕业结果、学位授予结果及非真实培养方案专业的学分要求来自合成数据。

## 验证结果

- 后端编译通过。
- 前端生产构建通过。
- 学院角色学生分析范围正确。
- 清单平均 GPA 与完整筛选群体一致。
- 必修筛选正确进入 GPA 口径。
- 全量端到端回归：112 项通过，0 项失败。
