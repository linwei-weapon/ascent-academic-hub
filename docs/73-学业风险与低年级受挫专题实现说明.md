# 学业风险与低年级受挫专题实现说明

## 1. 管理目标

专题将关注点前移到大一首次学业受挫，并观察学生后续是否恢复。它用于发现需要人工核查的群体与学生，不自动生成预警处置任务，也不推断个人受挫原因。

## 2. 原型口径

- 有效观察学生：入学年有效，且入学学年第一或第二学期至少存在一条已发布、未作废、通过状态明确的成绩。
- 大一受挫：上述两个常规学期至少一条未通过成绩；暑期或小学期（第 3 学期）不计入。
- 后续未再出现未通过：后续常规学期已有成绩且无未通过记录。只表示近期结果改善，不表示原挂科课程已经通过。
- 后续仍需观察：后续仍有未通过记录，但累计门次未超过大一阶段。
- 后续持续出现未通过：后续未通过门次超过大一阶段，用于关注排序，不推断个人原因。
- 暂无后续成绩：尚无后续常规学期成绩，应在下一批成绩发布后复核。

“恢复”只描述成绩记录变化，不代表困难原因已经消失；“持续困难”也不能直接归因于学生、课程或教师。

## 2.1 指标单位与管理价值

- 纳入低年级观察、大一有未通过课程、后续状态均按去重学生人数统计。
- 大一未通过比例的分母是纳入观察的学生，不是全校在籍学生。
- 课程表“未通过学生数”为去重人数，“未通过成绩记录数”可包含同一学生多次记录。
- 人数用于估算需要配置的关注资源，比例用于识别群体集中度；课程集中提示基础课支持，专业持续人数提示学院优先核查。

## 3. 已实现范围

- 接口：`GET /api/v2/topics/early-setback`。
- 筛选：组织、专业、入学年级；接口继续执行 V2 角色数据范围控制。
- 指标：有效学生、大一受挫人数与比例、恢复状态分布。
- 分析：年级分布、专业集中度、大一受挫课程 TOP10。
- 下钻：重点学生证据清单、分页、学生档案跳转及原路返回。
- 页面：`/admin/reports/early-setback`。

2026-07-13 完成可理解性和性能整改：后端学生、年级、专业和分页复用一次聚合结果，默认查询由约 8 秒降至约 2.5 秒；页面取消整页遮罩和选择即刷新，改为骨架屏、局部加载、手动应用筛选和旧请求防覆盖。

## 4. 生产系统建议

生产实现应建立学期序号维表，不应长期依赖学期代码字符串换算；应将专题指标做成按数据批次可追溯的快照，并记录口径版本。建议增加：

1. 学生学制、休学复学、转专业对实际学习阶段的修正。
2. 课程最终认定、补考和替代关系对“挂科门次”的统一治理。
3. 同一学生跨学期恢复曲线及同专业基准线。
4. 课程类别、必选修性质和培养方案模块维度。
5. 数据访问审计与名单导出审批。

## 5. 当前边界

- 不输出个人原因、心理状态或教师归因。
- 不把群体相关性表述为因果关系。
- 不自动建立帮扶任务，不代表预警闭环已经确定。
- 当前学院字段来自组织机构代码；显示名称映射仍应在生产主数据中统一。
