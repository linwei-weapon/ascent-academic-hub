# 转专业接收条件核对

应用资源版本：2.0.0。来源为资源目录种子；实际发布状态、固定依赖和运行记录由系统管理。

## 适用任务

核对年度接收、开课容量与培养时间等证据，防止把课程相近当作接收可行。

## 执行说明

任务：核对年度接收、开课容量与培养时间等证据，防止把课程相近当作接收可行。
先核对当前身份、对象与可用证据。
1. 明确来源与目标、年度及实际或假设群体，并标明群体性质。
2. 核对申请/接收规则与批准版本，区分资格和教学承接条件。
3. 检查开课容量、正式先修、剩余培养时间及冲突资料。
4. 当前资料不具备时列出缺项和可先做的方案层对照；补齐后需实现规则适配并重新验收。
回答顺序：当前可确认的事实 → 对管理问题的含义 → 不能确认的内容 → 最小下一步。只引用本轮工具返回的证据，不补写学校政策或业务数据。

## 输入

输入契约见 [input.schema.json](input.schema.json)。对象ID从当前身份的选项取得，不能用专业名称或示例标记直接调用。

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `plan_id` | 是 | 从当前身份可用选项选择的培养方案ID；不是专业名称。 |
| `target_plan_id` | 是 | 明确选定的另一份培养方案ID；转专业场景中为目标方案。 |
| `college_id` | 否 | 当前身份授权范围内的学院ID；不传不代表获得全校权限。 |

## 工作步骤

1. 确认本轮要回答的问题与当前身份范围；需要对象时调用 list_analysis_options。
2. 校验所需对象和证据，范围冲突或关键资料缺失时停止相应计算并列出具体缺项。
3. 明确来源与目标、年度及实际或假设群体，并标明群体性质。
4. 核对申请/接收规则与批准版本，区分资格和教学承接条件。
5. 检查开课容量、正式先修、剩余培养时间及冲突资料。
6. 当前资料不具备时列出缺项和可先做的方案层对照；补齐后需实现规则适配并重新验收。
7. 按输出契约保存结果、来源、限制及待明确事项；发布版本与运行时实际版本分别记录。

## 计算与解释规则

- 每次调用使用服务端当前工作身份校验范围；参数不能扩大学院范围，不返回个人身份信息。
- 先读取可选对象，再使用真实ID查询；输入不完整时只追问影响本轮计算的关键项。
- 只消费学校数据，既不回写学校主数据，也不执行开班、录取、课程认定或资格审批。
- 正式事实、管理者补充和讨论假设分开表达；口头补充不能覆盖已保存的来源事实。
- 未知、未映射、零记录和数值0分别表达；缺失对象不得被静默排除以制造完整结果。
- 输出实际范围、来源和观察时间；只有同对象、同规则且可复核的数据才能比较。历史批次不稳定时不补造趋势。
- 工具运行完成仅说明执行状态；需经人工检查数字、范围、边界后才可确认业务结果。
- 方案建议学期不等于实际开课，不等于有剩余名额或课表无冲突。
- 历史异动规模不能当作本批申请/接收群体。
- 条件性分析需列清假设，不能对外称已经形成实际接收决定。

## 输出

输出契约见 [output.schema.json](output.schema.json)。status=blocked；列明接收规则、实际群体、课程容量与冲突资料缺项，不生成容量数字和接收结论。

用户阅读顺序：范围与本轮判断 → 实际数据与证据表 → 限制与待补资料 → 可以继续的问题。运行成功与人工确认分开。

## 已知边界

- T4 开课可行性和 T5 完整承接影响当前阻止执行。
- 不输出最大接收人数、保证名额、无冲突课表或按期毕业承诺。
- 课程结构差异可由 transfer-plan-gap 独立提供，但不解除本 Skill 的缺项。

## 所需证据

- 当年度转专业申请与接收规则、批准版本和适用对象
- 明确的申请/接收群体、预计规模和剩余培养时间
- 实际开课、班额、可用容量和占用情况
- 正式先修规则、排课冲突及课程认定关系

## 当前固定缺项

- 当年度转专业申请与接收规则、批准版本和适用对象
- 明确的申请/接收群体、预计规模和剩余培养时间
- 实际开课、班额、可用容量和占用情况
- 正式先修规则、排课冲突及课程认定关系

## 工具依赖
