# 毕业审核记录核对

应用资源版本：2.0.0。来源为资源目录种子；实际发布状态、固定依赖和运行记录由系统管理。

## 适用任务

查看既有毕业和学位审核状态，明确需要人工复核的记录范围。

## 执行说明

任务：查看既有毕业和学位审核状态，明确需要人工复核的记录范围。
先核对当前身份、对象与可用证据。
1. 核对现有审核记录实际标注的批次、群体及生成时间；未返回的规则版本保持未知。
2. 分别查看已返回的毕业状态、学位状态和源系统公布标记，保留原值。
3. 原始字典未确认时不解释状态是否通过；没有逐条件记录时不编条件清单。
4. 列出需要业务部门核对的资料，不把记录缺失当作课程未完成。
回答顺序：当前可确认的事实 → 对管理问题的含义 → 不能确认的内容 → 最小下一步。只引用本轮工具返回的证据，不补写学校政策或业务数据。

## 输入

输入契约见 [input.schema.json](input.schema.json)。对象ID从当前身份的选项取得，不能用专业名称或示例标记直接调用。

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `college_id` | 否 | 当前身份授权范围内的学院ID；不传不代表获得全校权限。 |
| `semester_id` | 否 | 从当前数据选项选择的学期ID；未指定时由返回结果明确实际范围。 |
| `limit` | 否 | 最多展示的课程或汇总记录条数；不改变分母，截断必须披露。 |

## 工作步骤

1. 确认本轮要回答的问题与当前身份范围；需要对象时调用 list_analysis_options。
2. 校验所需对象和证据，范围冲突或关键资料缺失时停止相应计算并列出具体缺项。
3. 核对现有审核记录实际标注的批次、群体及生成时间；未返回的规则版本保持未知。
4. 分别查看已返回的毕业状态、学位状态和源系统公布标记，保留原值。
5. 原始字典未确认时不解释状态是否通过；没有逐条件记录时不编条件清单。
6. 列出需要业务部门核对的资料，不把记录缺失当作课程未完成。
7. 按输出契约保存结果、来源、限制及待明确事项；发布版本与运行时实际版本分别记录。

## 计算与解释规则

- 每次调用使用服务端当前工作身份校验范围；参数不能扩大学院范围，不返回个人身份信息。
- 先读取可选对象，再使用真实ID查询；输入不完整时只追问影响本轮计算的关键项。
- 只消费学校数据，既不回写学校主数据，也不执行开班、录取、课程认定或资格审批。
- 正式事实、管理者补充和讨论假设分开表达；口头补充不能覆盖已保存的来源事实。
- 未知、未映射、零记录和数值0分别表达；缺失对象不得被静默排除以制造完整结果。
- 输出实际范围、来源和观察时间；只有同对象、同规则且可复核的数据才能比较。历史批次不稳定时不补造趋势。
- 工具运行完成仅说明执行状态；需经人工检查数字、范围、边界后才可确认业务结果。
- 既有审核记录是本轮读取的证据，不等于本 Skill 重新完成全套资格审核。
- 审核状态原值需用确认后的字典解释；不得把未知状态映射成通过。
- 毕业与学位条件分开，局部条件满足不能升级为总体资格通过。
- 记录缺失不是学生未达到要求；规则不足时保留待确认。

## 输出

输出契约见 [output.schema.json](output.schema.json)。既有审核记录状态分布、条件或记录问题及可查来源；保留未知状态，不含个人明细。

用户阅读顺序：范围与本轮判断 → 实际数据与证据表 → 限制与待补资料 → 可以继续的问题。运行成功与人工确认分开。

## 已知边界

- 不代替学校正式毕业/学位决定，不自动修改审核状态。
- 没有条件级来源时仅展示记录层汇总，不编造逐项条件。
- G4 不涉及开班、补考或安排教学；G5 无稳定历史时不补造变化。

## 所需证据

- 已授权的审核记录、原状态及实际标注的批次和时间
- 解释状态含义另需已确认字典；逐条件审核另需正式规则与条件级记录

## 当前固定缺项

没有统一阻止此方法的固定缺项；每次仍需检查所选对象的真实记录。
