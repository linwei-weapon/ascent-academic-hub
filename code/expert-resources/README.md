# 专家资源内容包

状态：应用资源草稿种子。版本：2.0.0。运行可用性与发布结果以系统中对应版本的真实测试记录为准。

本目录保留 5 个专家、9 个既有 Skill 和内部教学数据 MCP，新增任务候选包。专家承担管理问题的解释职责，Skill 固定输入、步骤、规则和输出，MCP 提供已登记、按当前身份授权的只读工具。新增包明确列出真实来源与规则缺口；候选登记不代表可执行或已发布。逐项边界见 [覆盖清单](coverage.md)。

## 入口

| 内容 | 位置 | 用途 |
| --- | --- | --- |
| 资源目录 | [catalog.json](catalog.json) | 应用导入的结构化草稿内容；不含密码和假数据 |
| 专家说明 | [experts](experts) | 5 位专家的职责、操作说明、提问及当前/候选能力 |
| Skill 包 | [skills](skills) | 每项包含 SKILL.md、输入/输出 schema、业务契约和样例 |
| MCP 工具 | [工具定义](mcps/education-data/tools.json) | 精确工具名、参数和输出契约 |
| MCP 说明 | [连接与使用](mcps/education-data/README.md) | 配置、权限、连接检查与业务检查的边界 |
| 覆盖关系 | [coverage.md](coverage.md) | 25 个业务编号的去向与未完成部分 |

这些是 HighEdu 应用管理的资源，不会安装到用户个人 Codex Skills。专家与 Skill 内容可以在系统中形成新草稿；运行记录和发布依赖由数据库保存。磁盘种子不代表已发布版本，也不应覆盖已有编辑、测试和发布历史。

## 当前方法与执行边界

- 专业建设：方案结构，以及两份已选方案按全部模块、课程编号去重的比较。
- 课程质量：指定学期、授权开课院系及可选单课的已有课程聚合表现；保留首修人次与失败次数口径。
- 转专业：方案课程集合衔接对照，以及贴源异动解析出的学院/专业路径和原状态汇总；不认定个人成果，不把所有状态视为已完成。
- 毕业准备：指定方案的已有进度汇总，以及既有毕业审核原状态分布。
- 推免年度规则、转专业容量条件：已完整定义所需材料、交互、输出和验收边界，但处理器为 `unavailable`。缺实际规则/数据时阻止计算，不能发布为可执行能力。

培养方案相关三个 Skill 统一分列“课程目录学分”“方案字段原值（待核对）”与核对状态。前者读取 `act_course.credits`，后者保留 `act_curriculum_plan_course.credits`，不因展示调整就宣称原字段已修复。模块“课程目录学分合计”只供结构查看，不能作为正式方案应修或毕业最低学分。方案比较和转专业目标覆盖仍按课程编号去重计数，不使用学分加权。

P-COMPARE 与 C-PERFORMANCE 使用独立登记的 processorId，复用已有只读工具的唯一计算。任务结果版本为 2.0，完整证据与 tables 预览分开；previewLimit 不改变集合、统计和比例分母。双方独有课程分别展示，未知编号只列入未知记录；未确认分类不能支持排除公共课。课程聚合重复粒度、缺字段和零分母分别标记，跨行 students 不相加为唯一人数。

后续目标、认定、排名、条件核验、保存结果比较、路径与方案调整按 TaskDefinition 提供输入和依赖规划。algorithmImplemented 表示确定性算法是否实现，realAdapterAvailable 表示可信真实来源适配器是否就绪。两者与学校规则确认、技术测试和正式发布分别记录；未就绪任务返回具体原因。正式政策输入只接受对象和规则引用，不接收客户端上传的成绩、通过状态或学习成果作为事实。

新版资源显式声明 fingerprintScheme=task-v2，指纹覆盖任务注册、工具实现及共享依赖。没有 scheme 的既有版本继续严格检查原 runtime 文件 hash；构建种子不改变历史发布 hash 或 SQLite 内容。

转专业专家的当前依赖只绑定已实现的两项方法；容量检查放在 `plannedSkillIds`，防止一个未就绪的扩展阻止已有方法使用。保研专家只有尚未具备条件的方法，因此保持草稿和待准备状态。此安排不把暂缓能力藏掉，也不把它们列作领导的可执行操作。

## 样例不是学校数据

样例中的 `${selected_plan_id}`、`${selected_target_plan_id}`、`${selected_semester_id}` 是绑定标记。运行前从真实授权选项选择并替换；不替换时不得查询。`expected.assertions` 写的是验收条件，没有编造学校数值、资格名单或历史快照。

输入和输出契约属于实际运行部分。缺固定证据的方法在执行前返回 `blocked` 与缺项清单，不产生业务结果。正常工具结果包含范围、数据、来源、限制和缺项；可选 `tables` 用于页面显示证据表。实际的执行成功、人工确认、发布是三个不同步骤。

## 维护和验证

种子的单一编写入口是 [scripts/build_catalog.py](scripts/build_catalog.py)。它生成 `catalog.json`、专家说明、Skill 包和 MCP 契约；覆盖清单单独维护，记录业务目标与当前实现之间的差异。应用运行只读取构建产物，不执行构建脚本。

在仓库根目录执行：

```powershell
& code/backend/.venv/Scripts/python.exe -X utf8 code/expert-resources/scripts/build_catalog.py
& code/backend/.venv/Scripts/python.exe -X utf8 code/expert-resources/scripts/validate_catalog.py
```

校验包含 JSON 结构、ID 唯一性、专家/Skill/工具引用、已登记处理器、schema、生成文件一致性、引用路径，以及 25 项业务编号覆盖。它不替代真实数据库调用、权限回归或业务确认。

## 发布核对

1. 先核对 MCP 的真实协议与数据库连接，确认工具清单与输入输出。
2. 对已实现 Skill 选择真实对象执行样例，核对数据范围、口径、记录数、证据、缺项和零分母。
3. 人工确认对应内容版本与测试结果后发布。修改内容或依赖后重新测试，不复用旧确认。
4. 专家只绑定满足条件的 Skill 固定版本，进行一次完整业务样例并确认后发布。
5. 领导使用时重新检查当时的身份、数据条件和依赖状态。旧研究保留当时结果和版本，不能承诺重建不可稳定获取的历史批次。

正式业务依据仍为现有 [专家职责与场景发布清单](../../文档/4-需求文档/4.7-AI管理决策/expert-design-v3-20260916/02-专家职责与场景发布清单.md)。本目录不另创学校规则，也不修改现有专家研究的历史数据。
