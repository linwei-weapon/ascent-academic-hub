# 专家业务场景与资源覆盖

状态：当前资源包 1.0.0 的实现边界。此表用于核对需求，不能作为已通过真实环境验收的证明。

需求依据：`文档/4-需求文档/4.7-AI管理决策/expert-design-v3-20260916/02-专家职责与场景发布清单.md`；旧入口映射依据：`code/backend/expert_research/catalog.py`。

## 阅读方式

- **基础事实可执行**：已登记确定性只读方法，但仍需当前对象有数据、通过权限和版本检查。
- **仅覆盖部分**：可查询相关事实，需求中的高级判断尚未实现，不应在界面标为完整场景通过。
- **暂缓**：核心规则、资料或处理器未具备；完整内容和准入条件已保存，不开放执行入口。

7 个业务可执行 Skill 共用 7 个 MCP 工具，其中 1 个工具是对象选项查询。另有 2 个缺证据的方法契约保持阻止状态。不是 9 个 Skill 都可以产生业务结果，也不是每个专家的所有目标同时可用。

## 辅助能力与旧入口

| 旧入口 | 去向 | 当前边界 |
| --- | --- | --- |
| transfer.history / aux-history | transfer-history | 从`edu_source.std_alteration`与类型表解析`FIELDS_TEXT`的学院/专业路径，按`STATUS`原状态分组；以生效日期和学期起止日期筛选。学院两端均须唯一名称精确命中授权范围；不把所有记录当已完成，不解释为本院全部流入/流出 |

| recommendation.targets / aux-targets | recommendation-policy 的接收规则缺项 | 校内推免和目标院校接收分别核对；当前不做院校匹配或录取概率 |

## 资源组织决定

专业建设的两个 Skill 复用方案事实，课程质量共用一个事实查询，转专业共用结构对照与历史事件查询，毕业准备共用进度与审核记录。25 个业务编号保留作为审计索引，不复制为 25 个空方法。

历史转专业查询明确使用贴源表补充事实层当前缺失的路径与日期，没有修复或回写 ACT 投影。它只使用 `std_alteration` 对应集合，不混入 `student_changes`。源状态始终随路径分组展示，INITIAL、UNDONE 等状态不能算作已完成转入。结果上限只限制展示分组，不是完整路径或人数总量。

`capacity-evidence` 是转专业专家的候选能力，不是其当前发布依赖，避免阻止可用的结构和历史查询。`recommendation-policy` 是保研专家的核心依赖，缺项时该专家整体待准备。候选能力要真正开放，必须补齐资料、实现受控处理器、使用真实样例并通过业务确认，再绑定新专家版本。

## 后续验收不能省略的检查

1. 对每个运行方法从真实授权选项选对象，复核记录数、汇总字段、来源、空值与截断。
2. 校级与学院身份分别测试；输入其他学院对象时拒绝，历史异动不能泄露越界另一端。
3. 同一工具被不同 Skill 复用时不混淆口径，尤其方案结构重合与转入目标覆盖。
4. 固定缺项、对象无记录、数据库失败分别显示；不能用发布状态替代当前数据可用性。
5. 内容或依赖变化使旧测试失效；旧研究保留实际结果和版本；历史批次不稳定时不承诺可重算。
