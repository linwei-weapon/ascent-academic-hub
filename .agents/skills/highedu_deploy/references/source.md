# 从仓库定位部署代码

## 默认用法：在自己的项目内调用

同事将完整 Skill 目录放在自己项目的 `.agents/skills/highedu_deploy/`，在该项目中输入 `$highedu_deploy backend` 即可。Agent 自行运行 `git rev-parse --show-toplevel`、`git branch --show-current`、`git rev-parse HEAD`、`git remote -v` 并查找构建清单，展示识别出的来源后按已授权范围继续，不逐项要求同事填写已能读取的信息。

默认发布当前分支已提交的本地 HEAD，不自动用远端较新或较旧提交替换；明确要求远端最新版本时再 fetch 并固定该提交。有影响构建的未提交改动时询问要发布已提交版本还是工作区内容。仅文档等不影响产物的改动可保留并说明，不必为此阻塞构建。detached HEAD 则记录实际提交，不伪造分支名。没有 remote 但有本地 Git 提交时仍可构建，来源如实记录为本地仓库。

当前项目未找到 Java 模块时，先说明检测结果，请使用者切到自己的 Java 仓库后调用，或可选指定另一个仓库地址；不要要求原作者知道同事的路径，也不要扫描电脑寻找旧项目替代。同一个工作区包含多个仓库或多个可部署 Java 模块且无法从上下文区分时，只询问具体候选。

## 来源约定

| 信息 | 规则 |
| --- | --- |
| 组件 | frontend、backend 或 database；每个组件可以属于不同仓库 |
| 仓库 | 默认当前 Git 项目，自动读取 remote；跨仓库时可指定 HTTPS/SSH 克隆地址，不含密码或 Token |
| 版本 | 默认当前分支本地 HEAD；用户可指定另一分支、标签或完整提交，不猜测 main/master 或另一个仓库的同名分支 |
| 模块 | 相对于目标仓库根目录，例如 `code/backend-java`、`backend` 或 `.`；实际存在才采用 |
| 部署记录 | 仓库地址、原始分支/标签、解析后的完整提交、模块目录及产物 SHA-256 |

同事可在 Codex 对话中输入；第一种无需填写其他参数，其余为可选用法（替换尖括号内容）：

```text
$highedu_deploy backend
$highedu_deploy backend 分支=<当前仓库内另一分支>
$highedu_deploy backend 仓库=<Java仓库克隆地址> 分支=<待发布分支> 模块=<Maven模块相对目录>
$highedu_deploy frontend 仓库=<前端仓库克隆地址> 分支=<待发布分支> 模块=<前端相对目录>
$highedu_deploy database preview 仓库=<迁移仓库克隆地址> 分支=<分支名> 文件=<SQL相对路径>
```

这些是给 Agent 的输入示例，不代表服务器新增了命令行参数。已确定的来源在同一任务中继续复用，只询问缺失或歧义部分。无 `.git` 的源码目录不能据目录名推断分支；只有用户明确选择该本地产物来源后才使用。

## 解析与获取

1. 当前工作区只是候选源码；Skill 所在目录只用于定位 Skill 资源。读取候选仓库的 `git remote -v`、分支和状态，核对项目身份及模块。前后端不同仓库时分别处理，不能用前端分支替代 Java 版本。
2. 当前项目部署从已确定的本地 HEAD 创建隔离的 detached worktree。明确指定远端版本时，先核对 remote 身份并 fetch 指定版本；不在同事工作区直接 pull、切分支或覆盖未提交内容。需要另一个仓库且找不到匹配克隆时，在本机可写临时目录克隆，不依赖固定盘符；嵌套工作目录必须已被忽略。
3. 指定当前仓库另一分支时优先解析明确的本地 `refs/heads/<分支>`；本地不存在时查询已核对 remote 中该分支。明确要求远端分支则查询远端 `refs/heads/<分支>`；标签用 `refs/tags/<标签>`，最终固定为完整 commit。不存在或权限不足时报告原因，不回退默认分支或旧缓存。分支与标签同名时按用户指定种类选择，必要时询问。
4. 命令通过参数数组或正确的 shell 引号传递仓库和版本名，校验分支名并使用明确 ref；不将用户输入拼成可执行 shell 片段。不要运行用户提供的任意 Git remote helper。私有仓库使用协作者现有 Git 凭据/SSH 授权；权限不足时由其自行登录或申请访问，不索取凭据到聊天。
5. 读取固定提交中的 AGENTS 与构建说明。模块路径必须相对目标 checkout，解析后仍在该目录内；不允许通过绝对路径、`..` 或符号链接跳出。未提供模块时查找构建清单：前端看 Vite/package.json，Java 看 pom.xml 及 Spring Boot 启动模块；唯一候选可自动采用，多个可部署模块时询问。聚合 Maven 项目按其 reactor 构建，不只构建任意子目录。
6. 依赖的 submodule/LFS 内容应与固定提交匹配。构建前核对目标内容，构建期间不再次跟随分支更新。原仓库的未提交改动不会混入基于远端分支的产物；用户明确要求部署工作区内容时另记 dirty 状态和变更摘要，不能标为纯提交构建。
7. 构建、运行日志及凭据处理沿用发布/数据库指南；隔离目录清理仅针对本次创建且已核对归属的目录，不清理同事现有工作区。

## 不同仓库如何使用同一 Skill

可留在一个包含本 Skill 的项目中，通过仓库地址发布另一个项目；也可把完整 `.agents/skills/highedu_deploy/` 目录同步到前端和 Java 仓库，分别在各自仓库内调用。Skill 本身不包含个人路径或登录秘密，服务器地址保持共享测试环境地址。

这不要求把 Java 代码合并到前端仓库，也不自动向同事的仓库提交 Skill。当前项目的信息由 Agent 读取；仅需要从其他仓库获取源码时，才补充该仓库及版本并核对访问权限。
