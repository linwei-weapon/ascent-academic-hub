# 高教项目部署方案

> 现行方案 · V3.0 · 2026-09-29 · 适用于 edu-integrationTest 的 Java/MySQL 版本，当前部署环境为 114 服务器。

## 一、部署选型

前后端分离，部署在同一台 ECS，数据库使用独立 RDS。

| 项目 | 选型 |
| --- | --- |
| 服务器 | 阿里云 ECS，Ubuntu 22.04，2 核 2 GiB、40 GB 系统盘 |
| 前端 | Vue 3 + Vite，构建后由 Nginx 提供静态页面 |
| 后端 | Java 17 + Spring Boot 3.3.5，由 systemd 管理，监听 `127.0.0.1:8080` |
| 数据库 | RDS MySQL 8.0：`edu_analytics_v3` 业务库、`edu_source` 源数据库 |
| 访问地址 | [http://114.215.189.215](http://114.215.189.215) |

Nginx 的 80 端口提供前端，`/api/` 转发到后端 8080。当前配置用于少量开发、测试和演示；定时调度、启动预热和启动重计算暂时关闭。

## 二、如何部署

1. **准备环境**：ECS 安装 Nginx、Java 17，创建 `highedu` 服务用户；允许 ECS 通过私网连接 RDS。
2. **首次准备数据库**：创建两个高教库，导入表结构和数据并核对。运行账号对业务库读写，对源数据库只读；后续更新沿用现有数据，结构变更单独执行迁移。
3. **构建产物**：在开发电脑或构建机分别打包 `code/frontend` 和 `code/backend-java`，得到前端 `dist` 和后端 JAR。前端 API 地址设置为 `/api`。
4. **上传版本**：更新前备份数据库和配置，保留上一版本。按下方目录放置新产物，`current` 指向本次发布版本。
5. **填写配置**：服务器上的 `highedu.env` 保存数据库连接、账号密码、JWT 密钥和访问地址；`application-114.yml` 保存端口、连接池等配置。密码不写进源码或前端。
6. **启动服务**：配置 `highedu-api.service` 加载外置配置并运行 JAR；配置 Nginx 的前端目录和 `/api/` 代理，再执行下方命令。

```text
/opt/highedu/
├─ releases/<版本>/
│  ├─ frontend/              ← dist 中的文件
│  └─ backend/edu-backend.jar
├─ current → releases/<版本>
└─ shared/config/
   ├─ highedu.env
   └─ application-114.yml
```

以下命令在服务器执行，需要管理员权限；配置文件和产物须先准备好。

```bash
sudo systemctl daemon-reload
sudo systemctl enable highedu-api
sudo systemctl restart highedu-api
sudo nginx -t && sudo systemctl reload nginx
```

## 三、部署后验证

检查首页、登录、角色权限、主要查询和导出；服务无异常重启。健康接口仅表示服务存活，不能代替业务检查。

```bash
systemctl status highedu-api --no-pager
curl -f http://127.0.0.1:8080/api/health
sudo journalctl -u highedu-api -n 100 --no-pager
```

当前环境已部署，登录和常用页面已验证可用。

## 四、出现问题时回退

- **程序或配置问题**：确认上一版本兼容当前数据库，将 `current` 指回上一版本，恢复对应配置并重启后端。
- **Nginx 配置问题**：恢复发布前配置，检查通过后重载。
- **数据库问题**：先停止高教写入并保存最新数据，将备份恢复到独立库，核对后再切换连接。

程序回退不会自动撤销数据库变更。发布时记录版本、备份位置和检查结果。
