# 5.2 测试环境部署方案

> 新增方案，2026-09-14。环境主机、访问地址、部署负责人及运行证据尚未确定。本文描述待落实方案，不代表测试环境已部署。
> 依据：[原部署手册](03-部署手册.md)、[生产容量与验收方案](69-生产部署容量与验收方案.md)及当前前后端入口。

## 一、目标与环境隔离

测试环境用于验证当前 Vue + FastAPI 的集成行为、数据口径、身份范围与发布过程。代码版本、数据库、学期源库、模型配置及审计记录应与开发和生产隔离；采用脱敏或合成数据，不直接连接学校生产主库进行写入。

SQLite 和本地账号可以用于当前原型的隔离验证；这不代表已完成生产数据库和学校认证接入。机器配置和并发目标按实际数据规模另行确定，不直接沿用 QuizTestDemo 的 ECS、RDS、PM2 参数。

## 二、部署形态

测试前端使用 code/frontend/dist，由受控 Web 服务提供。/api 反向代理到 FastAPI，服务端监听受控地址。前端路由直接访问和刷新需要 SPA 回退。

FastAPI 当前检测到 dist/index.html 后可挂载静态目录，但 StaticFiles 的 html 模式不能据此推定所有 Vue 深层路径都会回退到首页。测试部署需要实际验证深层路径，必要时由 Web 服务配置路由回退。

反向代理需保留认证头与当前工作身份头；AI 流式响应的缓冲与超时按实际 POST SSE 行为配置并验证，不能把一次性普通 JSON 代理验证当作流式问策已通过。

## 三、环境准备顺序

1. 固定分支、提交和依赖锁文件，记录将部署的应用版本。
2. 配置独立数据目录和数据来源，备份已有测试数据库、平台配置和必要源文件。
3. 按开发部署方案安装依赖与构建；按选定数据来源初始化或执行必要迁移，逐项记录结果。
4. 配置后端环境、服务管理、日志、静态入口与反向代理；服务端秘密不进入前端构建变量或文档。
5. 启动后核对健康端点，再确认登录、数据查询、报表导出、身份切换和使用中的模型状态。

初始化真实 ETL 可能重建库，迁移也可能修改平台控制数据；在已有环境中应先于副本验证。不要将 init 脚本无条件放进每次服务重启步骤。

## 四、部署可用性确认

首页和 health 可访问只是第一层确认。部署后还应核对登录返回、功能菜单、授权范围、统计周期、实际数据来源、页面与导出的一致性，以及详情直达和刷新。

模型关闭或失败时确认系统展示实际状态，不能把未配置模型解释成业务数据不存在。检查报表和分析查询涉及的旧库、V2 库及源文件，避免只验证一张首页卡片。

上述为部署后的可用性检查，不是已经生成或执行的测试用例。本轮测试目录仅预留，完整用例待用户要求时编写。

## 五、记录与恢复

执行后另建带“新增”的部署记录，写明环境、时间、版本、配置引用、数据批次、操作结果、证据和待处理项。当前不填写虚假的成功记录。

失败时按 [5.4 发布验证与回退](新增-5.4-发布验证与回退方案.md)恢复对应应用和数据。生产准入要求继续按 [5.3](新增-5.3-生产环境部署方案.md)及原生产方案确认。
