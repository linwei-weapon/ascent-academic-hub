# 5.1 开发环境部署方案

> 新增方案，2026-09-14。依据当前分支代码和原部署手册整理；本轮未安装项目依赖、初始化数据库或启动服务，以下为待执行步骤。
> 原始依据：[03-部署手册](03-部署手册.md)、[依赖锁文件](../../code/frontend/package-lock.json)、[初始化脚本](../../code/scripts/init.bat)。

## 一、运行组成与环境

本地运行 Vue 前端与 FastAPI 后端，数据使用项目目录内的 SQLite 分析库及所需学期源库。开发前端为 3006，后端为 8000；前端当前代理目标为 127.0.0.1:8000，Vite 内嵌 Mock 已停用。

Python 按后端依赖要求准备，原手册基线为 3.11 以上、推荐 3.13。Node 以当前锁文件中 Vite 的要求为准：20.19 以上的 20.x 或 22.12 以上。旧手册的 Node 18 要求不适用于当前 Vite 7。

克隆源码不会自动带入依赖、数据库或本机配置，也不会自动使用另一个工作区的数据库。

## 二、依赖与前端配置

以下准备在当前项目根目录执行；可先使用独立 Python 虚拟环境，并核对脚本使用的 python 来自该环境：

```powershell
python --version
node --version
python -m pip install -r code/backend/requirements.txt
Set-Location code/frontend
npm.cmd ci
```

项目同时留有 npm 和 pnpm 锁文件，本文选择 npm 与 package-lock 配套，不混用包管理器更新依赖。前端没有 .env 时从 .env.example 复制，已有配置先保留。VITE_PORT 控制端口，VITE_BASE_URL 是静态资源基础路径，不是后端 API 地址。前端可见的 VITE_ 变量不存服务端秘密。

## 三、初始化数据

先确定使用“独立演示数据”还是“已授权真实数据副本”，再检查 init 脚本及目标路径。当前 init.bat 检测到指定教务源库时执行正式 ETL，可能重建分析库；没有源库且没有分析库时创建演示数据；没有源库而已有分析库时保留分析库并运行控制数据迁移。

因此，init 不是日常启动命令。已有数据先备份，不能通过反复初始化排查普通启动错误。脚本中的迁移逐条检查退出码和结果，不以最后打印的 OK 替代每条迁移成功。

新建演示环境确认没有需要保留的数据后，在项目根目录运行 code/scripts/init.bat。核对 analytics.sqlite、analytics_v2.sqlite 及报表所需演示源库是否按实际功能准备齐全；不添加 --force 自动覆盖。

## 四、启动与访问

已有辅助入口为 [后端隐藏启动](../../code/scripts/start_backend_hidden.vbs)和[前端隐藏启动](../../code/scripts/start_frontend_hidden.vbs)。确认依赖、数据、配置和端口后，可从项目根目录调用：

```powershell
wscript.exe code/scripts/start_backend_hidden.vbs
wscript.exe code/scripts/start_frontend_hidden.vbs
```

辅助脚本采用当前 PATH 中的 python/npm，且没有完善的长期日志和进程管理；前端 dev 自带打开浏览器行为。启动前检查是否已有本项目服务，避免重复启动；停止时先确定属于本项目的进程，不批量结束全部 Python 或 Node。

后端访问 http://127.0.0.1:8000/api/health，前端访问 http://127.0.0.1:3006/。health 当前只返回进程存活状态，不能证明双库、权限和模型可用。还需要实际登录、读取数据和打开一条证据进行部署确认，不能沿用旧文档中的验收通过数字。

## 五、构建与边界

在 code/frontend 执行 npm.cmd run build，产物为该目录下 dist。当前 build 仅运行 vite build，不含完整类型检查，不能写成“构建通过即类型检查通过”。

本方案没有实际执行记录。测试环境见 [5.2](新增-5.2-测试环境部署方案.md)，生产改造边界见 [5.3](新增-5.3-生产环境部署方案.md)，数据和应用恢复见 [5.4](新增-5.4-发布验证与回退方案.md)。
