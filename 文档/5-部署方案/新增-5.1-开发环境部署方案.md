# 5.1 开发环境部署方案

> 现行开发方案，更新于 2026-09-29。支持 local（本地前后端及 SQLite）和 test（本地前端连接测试服务器）两种启动方式。
> 原始依据：[03-部署手册](03-部署手册.md)、[依赖锁文件](../../code/frontend/package-lock.json)、[初始化脚本](../../code/scripts/init.bat)。

## 一、运行组成与环境

### 团队启动 Skill

技能位于项目 [.agents/skills/highedu-start](../../.agents/skills/highedu-start/SKILL.md)，与源码一起共享，无需使用个人机器路径。协作者获取包含技能的代码后，在仓库内打开 Codex 并输入：

- `$highedu-start local`：启动本地前端、FastAPI 后端并使用本地 SQLite；已有库直接复用。
- `$highedu-start test`：启动本地前端，连接测试服务器上的 Java 后端及 MySQL。

Codex 支持从仓库 `.agents/skills` 发现技能，见 [OpenAI 官方技能说明](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。其他支持 `SKILL.md` 的协作工具也可读取该文件执行。技能尚未显示时，可直接指定文件路径；不依赖个人技能目录。

### test：本地前端连接测试后端

准备 Node.js 20.19 以上的 20.x，或 22.12 以上版本，在项目根目录执行：

```bash
cd code/frontend
npm ci
npm run dev:test
```

`npm ci` 只需首次安装或依赖锁文件更新后执行。打开 http://127.0.0.1:3007，使用测试环境的账号登录；修改前端代码后自动更新页面，按 Ctrl+C 停止服务。

- 公共配置统一在 `code/frontend/vite.config.ts` 的 `frontendConfig` 中；`test` 配置将 `/api` 请求转发到测试后端，包含登录、下载和流式接口。
- 普通业务页面不需要启动本地后端、初始化数据库或填写数据库密码；专家问策和指标核验另需下述本机服务。保存、修改等操作会影响 114 环境的数据。
- 114 当前是 Java 后端；本地新功能需要对应接口已经部署。出现 404 或字段不匹配时，应核对后端版本。
- 3007 被占用时启动会报错；可执行 `npm run dev:test -- --port 3008`。修改配置后需重启前端。
- 修改测试后端地址或默认端口时，调整 `frontendConfig.test` 后重启；前端不加载 `.env` 文件。
- `npm run dev` 与 `npm run dev:test` 均连接测试环境；本地 8000 后端使用 `npm run dev:local`。正式构建使用 `npm run build`，线上 `/api` 代理由 Nginx 管理。

代理配置依据 [Vite server.proxy](https://vite.dev/config/server-options#server-proxy)。该模式只监听本机；本地同源请求的 Origin 随代理目标转换，服务端仍校验登录和业务权限。

### 专家问策与指标核验的本机服务

当前专家团入口已并入“AI管理决策 → 专家问策”。在仓库根目录首次安装服务依赖；已有 `code/backend/.venv` 时复用，不重建环境：

```powershell
python -m venv code/backend/.venv
.\code\backend\.venv\Scripts\python.exe -m pip install -r code/backend/requirements-expert-resources.txt
```

该依赖文件同时包含指标核验服务所需依赖。首次将 `code/backend/.env.metric-verification.example` 复制为同目录的 `.env.metric-verification`，已有配置不得覆盖；按实际授权连接填写 `MV_SOURCE_*` 和 `MV_ANALYTICS_*`。模板默认库名为 `edu_source`、`edu_analytics_v3`，地址、端口和账号以实际数据库或隧道为准。模板的空值不构成可用连接；应用服务器地址不能直接当作数据库地址。真实配置与本地控制库不进入 Git。

```powershell
.\code\scripts\start-metric-verification.ps1
.\code\scripts\start-expert-resources.ps1
```

脚本使用 UTF-8 BOM 编码以兼容 Windows PowerShell，隐藏启动 8010、8011 服务，日志与 PID 位于 `work/runtime/highedu-start/`。服务已运行时先核对归属与健康状态，避免重复启动。启动后刷新 3007 页面或重新登录，选择已授权的系统管理员身份查看管理入口；菜单仍由服务按当前身份返回。

若提示“登录环境暂时无法校验身份”，检查服务进程继承的 HTTP 代理；代理无效时，在该进程的 `NO_PROXY` 中加入本机及 `frontendConfig.test.apiTarget` 的主机，再重启服务，不修改身份校验或扩大权限。健康检查成功只说明服务启动，真实分析还需通过数据库连接、资源依赖和发布校验。首次初始化的 `code/backend/db/expert_resources.sqlite` 只有资源草稿，不会自动发布专家，也不会恢复其他机器的研究历史。

### local：本地前后端同时运行

本地运行 Vue 前端与 FastAPI 后端，数据使用项目目录内的 SQLite 分析库及所需学期源库。开发前端为 3006，后端为 8000；前端当前代理目标为 127.0.0.1:8000，Vite 内嵌 Mock 已停用。

Python 按后端依赖要求准备，原手册基线为 3.11 以上、推荐 3.13。Node 以当前锁文件中 Vite 的要求为准：20.19 以上的 20.x 或 22.12 以上。旧手册的 Node 18 要求不适用于当前 Vite 7。

克隆源码不会自动带入依赖、数据库或本机配置，也不会自动使用另一个工作区的数据库。

## 二、依赖与前端配置

以下准备在当前项目根目录执行；可先使用独立 Python 虚拟环境，并核对脚本使用的 python 来自该环境：

```powershell
python --version
node --version
python -m pip install -r code/backend/requirements.txt
Set-Location code/frontend
npm.cmd ci
```

项目同时留有 npm 和 pnpm 锁文件，本文选择 npm 与 package-lock 配套，不混用包管理器更新依赖。前端无需准备环境文件：`vite.config.ts` 的 `frontendConfig` 统一维护版本号、静态资源基础路径，以及 local/test 各自的端口和后端地址。前端配置不存数据库密码或密钥。

## 三、初始化数据

先确定使用“独立演示数据”还是“已授权真实数据副本”，再检查 init 脚本及目标路径。当前 init.bat 检测到指定教务源库时执行正式 ETL，可能重建分析库；没有源库且没有分析库时创建演示数据；没有源库而已有分析库时保留分析库并运行控制数据迁移。

因此，init 不是日常启动命令。已有数据先备份，不能通过反复初始化排查普通启动错误。执行迁移时逐条检查退出码和结果，不以最后打印的 OK 替代每条迁移成功；启动 Skill 不自动对已有数据库运行这些迁移。

新建演示环境确认没有需要保留的数据后，在项目根目录运行 code/scripts/init.bat。核对 analytics.sqlite、analytics_v2.sqlite 及报表所需演示源库是否按实际功能准备齐全；不添加 --force 自动覆盖。

## 四、启动与访问

已有辅助入口为 [后端隐藏启动](../../code/scripts/start_backend_hidden.vbs)和[前端隐藏启动](../../code/scripts/start_frontend_hidden.vbs)。确认依赖、数据、配置和端口后，可从项目根目录调用：

```powershell
wscript.exe code/scripts/start_backend_hidden.vbs
wscript.exe code/scripts/start_frontend_hidden.vbs
```

辅助脚本采用当前 PATH 中的 python/npm，且没有完善的长期日志和进程管理；前端 dev 自带打开浏览器行为。启动前检查是否已有本项目服务，避免重复启动；停止时先确定属于本项目的进程，不批量结束全部 Python 或 Node。

后端访问 http://127.0.0.1:8000/api/health，前端访问 http://127.0.0.1:3006/。health 当前只返回进程存活状态，不能证明双库、权限和模型可用。还需要实际登录、读取数据和打开一条证据进行部署确认，不能沿用旧文档中的验收通过数字。

## 五、构建与边界

在 code/frontend 执行 npm.cmd run build，产物为该目录下 dist。当前 build 仅运行 vite build，不含完整类型检查，不能写成“构建通过即类型检查通过”。

本文保留本地原型开发说明。当前 114 服务器使用 Java/MySQL 版本，部署、验证和回退统一见[高教项目部署方案](新增-高教项目部署方案.md)。
