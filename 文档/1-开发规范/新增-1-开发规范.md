# 1-开发规范

> 新增规范正文，2026-09-14。参考 QuizTestDemo 的规范组织方式，适配当前 Vue + FastAPI + SQLite 项目。适用于新增代码和进入整理范围的模块；历史代码不因本文发布就被视为完成改造。

## 一、文件、函数与注释

页面按业务放在 views/admin 的现有模块中；复用组件放 components；跨页类型放 types。新业务请求集中到对应 API 模块，展示辅助仍放 utils。命名优先说明职责，不以 new、final、v3 等名称制造多份同时生效的实现。

组件或工具文件头简述用途和使用位置。路由注释放在定义上方，用页面名称说明入口，层级交给 children 表达。关键业务函数、computed、身份切换、缓存和导航说明数据来源、派生规则或保留条件，避免只翻译函数名称。

```ts
// 将已应用的筛选传入导出，保证文件与用户当前看到的结果一致。
async function exportCurrentReport() {
  // 实现以本模块现有快照协议为准。
}
```

简单 map/filter 回调不机械添加注释。遗留事项写明触发条件和关联任务；不得用无限期 TODO 替代本次必须完成的逻辑。

## 二、前端请求规范

### 2.1 业务 API 与公共传输

调用顺序为“页面 → 业务 API → 公共传输 → 后端”。页面负责界面状态与选择条件，业务 API 负责端点、参数与返回类型，公共传输负责认证、工作身份和错误处理。

现有底座为 `utils/http.ts`；现有 ai/decision helper 是迁移起点。新增 `src/api` 文件时按模块迁移，保留必要兼容导出，不把全部页面同时替换为新协议。

普通 JSON 继续使用 `{code,msg,data}`，成功 code 为 0。文件下载和 SSE 不进入 JSON 解包函数。请求使用现有 `/api` 前缀约定，避免重复拼接为 `/api/api`。

### 2.2 登录与身份

认证请求携带 Bearer token，有当前身份时携带 `X-Active-Identity`。不得在页面自行拼接一套不同身份逻辑。401 按公共流程回到登录；403 保留“身份存在但无权限”的语义，不能统一伪装成无数据。

身份或查询上下文改变后，旧请求不能覆盖新的页面结果。缓存应包含实际影响结果的用户、工作身份、范围、周期、参数和数据版本；不能只按角色名共用学生明细。

### 2.3 类型与序列化

JSON 对象和数组在业务层保持结构化，只有 HTTP、文件和 localStorage 边界进行序列化。TypeScript 类型断言不代表服务端数据通过验证；外部输入与可配置对象需要实际校验。

当前接口返回结构和分页命名按模块保留。不得为了套模板，将 data.rows、data.items、快照令牌等统一改名而遗漏消费者。新 DTO 同步核对 Python 请求模型、业务返回和前端使用位置。

## 三、列表、筛选和分页

用户正在修改的表单值与已经提交的查询条件分开。搜索、重置和修改每页数量后，按模块约定回到第一页；翻页沿用已提交条件。未点击查询的筛选值不能影响当前结果的导出或下钻。

复用现有 DataTable。内置分页只适用于已获取完整集合；服务端分页由页面传入当前页结果并发起翻页请求，不能再对该页数据二次切片。当前组件内置默认页长为 10，可选 10/20/50/100；模块可指定自己的默认值，不用脚手架的 20 覆盖全部旧页面。

列表加载、刷新、空集合、数据源缺失、请求失败和无权限分别呈现。数据缺失不能等同于人数为 0，过滤后无结果也不能显示成服务异常。保留可恢复输入，重试时使用用户最后提交的查询。

表格偏好按用户与页面区分，修改列字段或含义时核对 configVersion，避免旧 localStorage 偏好隐藏必要字段。

## 四、后端与数据开发

### 4.1 路由、服务与查询

Router 解析参数、通过依赖获得当前用户和连接、调用业务逻辑并返回统一响应。可复用的计算按需向 service 提取，参数化 SQL 按业务归集；service 不反向依赖 Router。

SQL 参数使用绑定参数，不拼接用户输入。查询所需权限范围必须显式传递或由统一权限工具产生，不能在提取函数后遗漏学院、班级、导师关系或有效日期过滤。

当前使用 sqlite3；不要照搬 QuizTestDemo 的 Prisma 开发命令。调用连接助手区分分析只读与平台管理写入，写入由调用方明确提交和处理回滚。

### 4.2 数据结构和加工

结构变化提供可重复执行的迁移，先在副本验证连续执行的行为。schema、迁移、代码消费者与技术说明需要一致，不能手动改唯一数据库作为交付。

原始输入、事实、聚合和学校配置分别维护。ETL 的输入批次、处理结果、错误和规则版本可追溯；不要在接口层用硬编码数值代替缺失的数据源。

### 4.3 指标规则

指标至少写清统计对象、时间范围、分子分母、去重方式、无效记录排除、空值、分母为零、来源和版本。已解决的历史挂科不能无条件计为当前风险，重复通过记录不能简单重复累计学分。

正式定义使用 sys_metric_definition，页面引用使用 sys_metric_page_binding。修改公式同时核对页面、导出、证据和 AI 消费者。跨模块引用同一计算结果，不维护平行公式。

## 五、权限与审计

功能权限决定能否执行操作，数据权限决定可访问对象。菜单隐藏只是展示，详情、导出、证据、AI、配置写入和直接 API 均须服务端校验。

学院明细范围与跨院比较范围分离；辅导员、班主任、导师依据有效人员关系，缺失关系不回退全校。前端的学院 ID、学生 ID 和会话 ID 都是待校验输入。

敏感读取、导出、AI 运行和管理配置变更按现有审计机制记录。日志不输出令牌、模型密钥、完整学生敏感正文。平台参数不能替代统一身份认证或学校源系统主数据。

## 六、导出与 AI 特殊请求

导出使用当前已应用条件和现有快照令牌，服务端再次鉴权。保留原文件格式和文件名，不能把错误 JSON 保存成成功文件；下载失败不清空页面结果。

问策采用 POST SSE 时，保留 meta、delta、done、error 的事件含义及会话上下文。网络中断与完整回答应明确区分，不能因收到了部分文字就标记生成成功。

Skill 产生正式数字与证据，模型解释不得扩展数据权限。模型关闭或失败时披露实际生成状态；不能把模板回答说成已使用模型，也不能自动执行管理动作。

## 七、样式与组件开发

遵循[2-样式规范](../2-样式规范/新增-2-样式规范.md)。先复用项目组件，再使用 Element Plus。页面 scoped 样式只处理局部布局，不能重定义全局主色或为每张表建立另一套分页。

公共组件调整核对其他使用页面。单位、百分比精度、空值和状态名称是业务契约的一部分，不能以视觉统一为由改变计算或筛选含义。

## 八、验证与交付

纯文档任务校验引用、内容和文件保护，不启动数据库。代码任务先记录已有类型检查和业务基线，再运行影响模块的测试、构建和核心交互；完整集成阶段遵循项目要求。

核心检查至少涵盖查询条件、身份切换、名单与指标一致、证据返回、导出一致和错误恢复。构建通过不等于类型检查通过，历史测试通过不等于当前版本已验证。

用户已要求原有文档不修改，因此本轮及后续未获覆盖授权前，说明和补充写入名称含“新增”的文件；不要为遵循旧的同步文档规则直接覆盖原文。本次未修改任何业务代码或运行配置。
