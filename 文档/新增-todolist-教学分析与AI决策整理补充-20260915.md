## P1 — 工作身份与数据范围兼容

### P1-2 筛选元数据缓存未按账号和工作身份隔离

- **位置**：[filterMeta.ts](../code/frontend/src/api/shared/filterMeta.ts)、[旧导入兼容入口](../code/frontend/src/utils/meta.ts)、[服务端筛选选项](../code/backend/api/routers/meta.py)。
- **问题**：现有 getFilterMeta 使用模块级 `_cache` 与 `_inflight`，请求只带 Bearer，未带 X-Active-Identity。后端会根据用户的 detailScope 过滤学院等选项。源码显示同一页面进程内切换账号或工作身份可能复用旧选项；本次三个单身份账号通过独立浏览器上下文检查，不等于覆盖了这个切换场景，未宣称已复现跨权限数据返回。
- **方案**：确认多工作身份验收账号与默认身份回退规则后，拟将请求头与缓存键绑定当前账号、工作身份，并处理切换时的在途请求；需同步检查所有元数据消费者。不能单靠修改下拉选项替代服务端鉴权。
- **验收标准**：两个不同范围身份切换及同一浏览器退出重登后，选项属于当前范围；旧请求不能覆盖新选项；同身份并发加载仍可复用，失败可重试。
- **状态 / 临时兼容**：待确认；本轮原样迁移实现，旧 utils 出口与新 API 共用一份缓存。承接[原多身份待办 P2-1](新增-todolist.md#p2-1-多工作身份完整操作链路缺少已确认的验收账号与场景)。

### P1-3 规则候选名单导出未携带当前工作身份头

- **位置**：[rules.ts](../code/frontend/src/api/teachingAnalysis/rules.ts) 的 exportRuleCandidates、[规则治理页面](../code/frontend/src/views/teaching-analysis/alert/RuleGovernance.vue)、[公共身份请求](../code/frontend/src/utils/http.ts)。
- **问题**：候选名单 CSV 的原 fetch 只发送 Authorization；同页面的普通 JSON 请求使用公共 HTTP，带有当前身份头。两条请求链的身份传递方式不同。本次请求头对照验证确认保持原状，但没有已确认的多身份账号验证默认身份回退结果，不能直接认定实际导出了错误数据。
- **方案**：与 P1-2 一并确认身份传递及旧会话兼容后，拟补齐当前身份头；导出仍需服务端校验候选变更单、动作权限与数据范围。保留 CSV、失败提示及文件名协议。
- **验收标准**：当前身份可查看的候选变更单可导出；其他身份的变更单被拒绝；有无有效身份、过期登录与无权限返回均正确，列表和导出范围一致。
- **状态 / 临时兼容**：待确认；本轮提取 API 时保留原 Bearer 请求头及 Response，未扩展导出权限。

### P1-4 体验账号仍返回旧 AI 菜单，当前 AI 页面被拒绝

- **位置**：[菜单路径映射](../code/frontend/src/utils/menu.ts)、[统一路由守卫](../code/frontend/src/router/index.ts)、[AI 路由](../code/frontend/src/router/modules/aiDecision.ts)、[认证与菜单响应](../code/backend/api/routers/auth.py)、[菜单治理接口](../code/backend/api/routers/admin_rbac.py)。
- **问题**：本次整理前后的浏览器检查均复现，dean、school_leader、college_dean 访问当前简报和专家库会进入无权限页。进一步核对 dean 的登录与 /auth/me，返回的是 `/admin/reports/management-briefing`、`/admin/reports/decision-simulation`，缺少守卫要求的 `/admin/reports/decision`。前端已将这些旧地址重定向到当前入口，但授权列表未匹配。这是当前环境的菜单/授权数据与前端版本不一致，不能据此认定三个角色本应被授予相同权限。
- **方案**：先确认三个角色对决策简报、专家问策的目标授权及旧菜单记录迁移方式，再核对菜单、角色关联与登录响应是否应同步迁移；或确认是否需要有期限的前端旧菜单兼容。不能自行新增权限、改数据库或放宽路由守卫。
- **验收标准**：经确认有权的角色从新旧入口均可进入同一目标页面；无权角色仍被拒绝；刷新、重新登录、菜单展示及实际接口权限一致，历史关联可追溯。
- **状态 / 临时兼容**：已复现，方案待确认；正式代码与数据未绕过权限。只在隔离测试浏览器中提供临时菜单响应验证 AI 组件，结果不能当成实际账号权限已修复。

## P3 — 流式会话兼容

### P3-2 问策流提前结束时没有明确的不完整回答事件

- **位置**：[advice API](../code/frontend/src/api/aiDecision/advice.ts) 的 streamAdviceAsk、[专家对话页面](../code/frontend/src/views/ai-decision/advice/Chat.vue) 的 send。
- **问题**：原解析器在 reader 返回 done 后直接结束，没有确认是否收到 SSE 的 done/error 事件；页面 finally 会解除 streaming。已用本地流输入验证：只有 delta 后直接 EOF 时，回调仅收到 delta，不会触发明确的不完整回答提示。这个验证不代表真实模型服务在本轮发生过中断。
- **方案**：确认正常 EOF、用户取消、网络中断与旧服务事件格式的兼容后，拟增加完成事件跟踪和中断反馈；保留已收到正文，不能把本地检测当成服务端生成成功。需同时验证专家切换与页面离开时的在途回答归属。
- **验收标准**：完整 done 正常完成，error 显示原失败信息；无 done 的提前结束明确显示不完整，已显示正文保留；重试与专家切换不串会话，不将取消记成成功回答。
- **状态 / 临时兼容**：待确认；本轮只拆分文件，原 SSE 字节处理及四种回调语义保持。
