# 3.2 数据库与指标

> 新增技术正文，2026-09-14。按本项目双库、ETL 和指标规范编写，不采用 QuizTestDemo 的 Prisma/MySQL 结构。实际表结构以 schema 与后续迁移共同核对，本文件不声称新副本已经初始化。

## 一、数据库职责

| 数据位置 | 职责 | 读写边界 |
| --- | --- | --- |
| analytics.sqlite | 既有分析事实、聚合和平台治理状态 | 分析只读，平台治理及加工受控写入 |
| analytics_v2.sqlite | 新事实模型、方案绑定、人员关系、成绩尝试及进度聚合 | 在线分析只读，loader/builder 写入 |
| 学期源库与文件 | 加工输入，部分累计报表的来源 | 不通过平台业务接口回写 |

两个学生维表或成绩集合不能直接相加。它们可能覆盖不同人群、时期和成绩粒度，所有指标必须确定实际数据源及有效记录集合。

## 二、来源、事实与聚合

数据源先登记文件或采集批次，再映射组织、学期、学生、课程和教职工等基础标识。保留来源、批次、源行、采集时间和质量结果，后续指标能够追溯到输入。

V2 重点事实包括成绩尝试 grade_attempt、课程结果 student_course_result、学籍事件、学生方案绑定、课程替代关系、教学任务与人员关系。成绩尝试与最终课程结果不是同一粒度，不能混为一个“成绩条数”。

课程通过、教学供给、团队结构、学生模块进度与成长轨迹由对应 builder 加工。聚合必须能够按当前规则重建并记录版本，而不是在接口代码中保存一份固定统计数字。

## 三、学生与课程结果

学生通过 student_plan_assignment 绑定适用方案，方案描述课程、模块及要求。课程状态需要结合有效成绩、课程替代、模块规则及已接入的认定证据。没有成绩记录不必然等于学生真实漏修；数据候选与明确未通过必须区分。

同课程多次尝试、补考和重修不能简单合并为同一分母。当前未解决问题与历史曾经未通过也不能混算。已获学分应按有效课程结果和认定规则去重，避免重复通过重复累计。

缺少正式绑定、完整认定或未来开课证据时，毕业准备提供核查清单和边界，不直接形成毕业审核结论。

## 四、组织与人员范围

组织授权与人员关系是数据权限的事实依据。人员关系包含对应人员、学生或班级、关系类型、状态和有效日期。过期或无效关系不能继续授予明细范围。

账号身份、角色菜单和动作权限属于平台治理；人员任职与学籍主数据属于学校业务来源。平台不能为了让页面显示数据而虚构全校范围或自动创建人员关系。

## 五、指标登记

正式指标至少包含名称、稳定编号、定义版本、管理目的、对象粒度、周期、公式、分子分母、有效记录过滤、去重方式、空值处理、来源、更新周期和适用边界。

`sys_metric_definition` 保存定义；`sys_metric_page_binding` 记录页面与实现引用。旧 `sys_kpi_config` 只承接历史展示兼容，新增指标不能只在那里填写阈值就宣称完成登记。

常见边界：

| 指标问题 | 处理要求 |
| --- | --- |
| “挂科率”名称含糊 | 说明是学生人数、课程人次还是成绩记录比例，并给出周期 |
| 分母为零 | 返回可识别的无法计算状态，不伪造 0% |
| 补考和重修 | 使用对应尝试/结果规则，不能改变分母后仍用同一名称 |
| 方案进度 | 复用统一课程与模块状态，不能各页独立相加 |
| 学院横向比较 | 样本、范围和时间可比，聚合权限不授权明细 |
| AI 引用数字 | 来自已计算事实，保留规则、范围与证据 |

正式公式调整必须升版本并核对所有页面、名单、导出和 Skill 消费者。当前仅整理文档，不改变任何公式。

## 六、学校方案和分析状态

学校方案由 sys_ai_skill_config 及角色关系保存，内容是允许覆盖的参数、版本、试算和发布信息，不保存正式指标 SQL 或数据范围。无匹配学校版本时可以使用产品默认，页面应识别当前生效来源。

AI 简报快照和会话是平台状态。它们需要与用户、范围、规则、方案及数据版本关联；不能把旧快照无条件当作当前学生事实，也不能让别人的会话内容通过 ID 被访问。

## 七、ETL 与迁移

ETL 记录批次、任务、开始结束、处理数量、质量结果与错误。多个输入通过运行与批次关系表达；手动触发只允许白名单任务并接受动作权限校验。同任务并发、失败与重试应按现有执行机制处理。

schema 文件记录基础结构，后续迁移增加平台治理和派生结构。任何表或字段变更要提供幂等脚本，在副本验证连续执行及数据完整性；不能直接手工修改唯一数据库。

本次文档不会重新初始化分析库，也不从原工作目录搬运真实数据。下一阶段运行检查先明确选择真实数据副本还是脱敏演示初始化，并分别披露来源。
