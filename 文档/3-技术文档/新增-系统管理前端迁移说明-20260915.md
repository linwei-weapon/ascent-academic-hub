## 1. 本次范围与完成条件

用户已确认 `views/admin` 专用于系统管理，原先位于其中的教学分析、AI 管理决策等业务目录同步移到 `views` 下。公共后台布局独立归入 `layouts`，系统管理按菜单设置子目录。

本次整理九个现行菜单：账号管理、角色与功能权限、数据权限、菜单管理、指标与口径管理、分析方案管理、审计日志、系统参数、数据采集监控。旧决策配置组件保留为兼容代码，原访问地址继续重定向到分析方案管理。

前端整理包含代码目录、路由模块、认证后业务请求的 API 归属、必要注释和 SCSS 层级。角色、菜单授权、请求字段、响应格式、统计口径、配置保存规则、文件导出和任务触发行为沿用原实现；不修改后端运行代码，不执行账号、权限、指标、分析方案和 ETL 数据变更；八份现有源码契约测试仅同步前端文件路径。

完成条件为：旧 URL 和重定向可用，系统管理九个页面可访问，模块请求保持契约，原功能代码语义不变，局部样式改为有层次的 SCSS，构建通过，类型检查与迁移前基线比较无新增问题，相关菜单和反向权限路径通过验证。

## 2. 目录与路由组织

系统管理每个菜单使用独立目录，例如 `views/admin/accounts/Accounts.vue`；其余业务目录移出 `admin` 后保留原目录名和组件文件名。公共布局使用 `layouts/AppLayout.vue`，无权限页使用 `views/Forbidden.vue`。

系统管理路由抽出到 `router/modules/system.ts`，以 `children` 表达分组，路由上方一行注释标明页面名称。原 `/admin/system/*`、`/admin/settings` 和其他业务 URL 保持一致，避免影响数据库菜单路径、角色授权和既有书签。

页面请求经 `api/admin` 中对应模块调用现有 HTTP 封装。既有公共分析方案请求继续共用原实现，以兼容导出衔接模块入口，避免为系统管理复制一套与 AI 页面不同的协议。

## 3. 注释与样式

组件顶部一行说明用途和所属模块；业务函数、计算属性、初始化及关键流程调用在上方说明职责、来源或保留条件。简单内联回调不机械补注释，注释不发明业务规则。

页面使用 `<style scoped lang="scss">`，每条声明独立成行，状态修饰、后代元素及响应式规则按所属区域组织，嵌套通常不超过三层。移除静态行内样式并使用有意义的类名；动态样式继续表达实际动态数据。

SCSS 整理保留原选择器和声明语义，防止抽屉、弹窗挂载到页面外后失去样式。已有全局主题变量在值和语义一致时复用，其他颜色保留，不移植 QuizTestDemo 的黑白灰配色或前台画布宽度。

## 5. 页面、API 和公共布局的职责

`router/index.ts` 保留全局登录恢复、菜单准入与业务路由，引用 `router/modules/system.ts` 的系统管理分组。`/admin` 仍挂公共布局 `layouts/AppLayout.vue`，系统管理的中间分组不增加页面容器，因此菜单、页面返回和原布局继续共用原实现。

系统管理页面负责表单草稿、筛选、分页、交互确认、错误状态和下载；`api/admin` 负责把这些参数传给原接口。49 个 JSON 请求函数承接原页面的 51 处调用，两个 CSV 函数保持原 Bearer 和工作身份请求头，文件名与下载反馈仍由页面控制。轮询使用原 `getSilent`，没有改变提示和重试节奏。分析方案通过 `api/admin/schemes.ts` 转导出现有 `utils/decision.ts`，公共 AI 页面继续使用原实现。

| 菜单 | 页面入口（相对 `code/frontend/src`） | API 入口 |
| --- | --- | --- |
| 账号管理 | `views/admin/accounts/Accounts.vue` | `api/admin/accounts.ts` |
| 角色与功能权限 | `views/admin/roles/Roles.vue` | `api/admin/roles.ts` |
| 数据权限 | `views/admin/permissions/Permissions.vue` | `api/admin/permissions.ts` |
| 菜单管理 | `views/admin/menus/Menus.vue` | `api/admin/menus.ts` |
| 指标与口径管理 | `views/admin/kpis/Kpis.vue` | `api/admin/kpis.ts` |

| 系统参数 | `views/admin/parameters/Parameters.vue` | `api/admin/parameters.ts` |

`DecisionConfig.vue` 作为原有兼容组件与分析方案同目录保留，不恢复旧菜单。原 `views/admin/settings/index.vue` 是另一份历史业务组件，迁到 `views/settings/index.vue` 后继续保留；现行“系统参数”入口仍是 `Parameters.vue`，二者没有合并或互相替换。

- **类型**：`vue-tsc --noEmit --pretty false` 迁移前后均为 294 条错误；按新旧路径映射并排除注释引起的行号变化后，错误集合和数量一致。类型检查整体仍未通过，沿用原待办 P4-1，不能用构建成功代替类型通过。
