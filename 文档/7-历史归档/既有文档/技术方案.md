## 1. 目标架构

```
┌─────────────────────────────────────────────┐
│  Vue3 前端（现代浅色 SaaS，沿用现有工程）        │
│  · request 封装(JWT/包络/401跳登录)            │
│  · 登录页 + RBAC 动态菜单/路由守卫             │
└───────────────┬─────────────────────────────┘
                │ HTTP  /api/auth/*  /api/admin/*
┌───────────────▼─────────────────────────────┐
│  FastAPI 接口层                               │
│  · 鉴权依赖(JWT) → 注入 user + dataScope      │
│  · 角色数据权限过滤(院长只见本院…)             │
│  · 统一响应包络 {code,msg,data}               │
└───────────────┬─────────────────────────────┘
                │ SQL（优先读预聚合表）
┌───────────────▼─────────────────────────────┐
│  分析库 SQLite（预留迁移 Postgres）            │
│  维表 + 事实表 + 预聚合表 + RBAC/规则元数据表   │
└───────────────▲─────────────────────────────┘
                │ 写入
┌───────────────┴─────────────────────────────┐
│  pandas ETL（可重跑）                          │
│  抽取 → 清洗关联 → 预聚合 → 入库                │
│  + 模拟新学期增量 + 预警规则引擎 + docx解析     │
└──────────────────────────────────────────────┘
   ▲ 脱敏真实 Excel（成绩186K/选课/教学任务/课程信息/2培养方案docx）
```

**核心原则**：①口径在 ETL 落地、接口直读预聚合（性能）；②前端契约 = `逐页规格书` 响应形状，不返工；③模拟数据走真实分布、不加标识、ETL 内部 `source` 字段可回溯。

## 4. 分析库表设计（建模 modeling）

> 命名：维表 `dim_`、事实表 `fact_`、预聚合 `agg_`、系统/RBAC `sys_`。所有表带 `source`（real/sim）便于回溯，前端不暴露。

### 4.1 维表
| 表 | 主键 | 关键列 | 来源 |
|---|---|---|---|
| `dim_college` | college_id | name, source_name(成绩表"管理部门"原值) | 成绩表去重，14 真实学院 |
| `dim_major` | major_id | college_id, name | 成绩表"专业" |
| `dim_class` | class_id | major_id, grade, name | 成绩表"行政班" |
| `dim_course` | course_id(课程代码) | name, credits, category课程类别, is_required, dept | **成绩+教学任务补全**（课程信息残缺） |
| `dim_teacher` | teacher_id(工号) | name(脱敏), dept, title职称 | 教学任务，解析`姓名(工号)` |
| `dim_semester` | semester_id | year, term, is_current | 成绩"学期"枚举 |
| `dim_student` | student_id(学号) | name(脱敏), college_id, major_id, class_id, grade, enroll_on, status | 成绩表去重 |

### 4.2 事实表
| 表 | 粒度 | 关键列 |
|---|---|---|
| `fact_grade` | 学生×课程×教学班×学期（186K行核心） | student_id, course_id, lesson_id, semester_id, score得分, level等级, gpa绩点, is_pass是否通过, is_required, is_retake, credits |
| `fact_lesson` | 教学班（教学任务1528行） | lesson_id, course_id, semester_id, teacher_id, capacity选课上限, enrolled已选, retake_count重修, total_hours/theory/exp/practice/lab学时, classroom, utilization教室利用率, campus |
| `fact_plan_course` | 专业×年级×课程（2专业docx） | major_id, grade, course_id, module课程模块, credits, term, is_core★ |
| `fact_alert` | 预警记录（引擎产出） | alert_id, student_id, rule_id, type, level, trigger_detail触发链, status处理状态[模拟], created_at, semester_id |

> 选课表(9999抽样)仅作关联校验，不建主事实表（成绩表才是全量主源）。

### 4.3 预聚合表（性能核心，ETL 算好直读）
| 表 | 维度 | 度量 |
|---|---|---|
| `agg_college_term` | college_id × semester_id | students, avg_score, fail_rate, gpa_avg, alert_rate, credit_done |
| `agg_major_term` | major_id × semester_id | 同上 + grade 维 |
| `agg_course_term` | course_id × semester_id | avg_score, fail_rate, total, excellent_rate, retake_rate |
| `agg_gpa_dist` | scope(全校/学院) × semester_id × bucket(5档) | count, percent |
| `agg_teacher_load` | teacher_id × semester_id | hours, courses, classes, title |
| `agg_classroom_util` | building/type × day × period | utilization（解析教室利用率文本） |

### 4.4 系统/RBAC/规则元数据表
| 表 | 列 | 用途 |
|---|---|---|
| `sys_user` | user_id, username, password_hash, name, role_id, status | 登录账号 |
| `sys_role` | role_id, name, data_scope_type(all/college/major/grade) | 10 角色 |
| `sys_role_scope` | role_id, scope_id | 角色具体数据范围（院长→本院 college_id） |
| `sys_menu` | menu_id, parent_id, title, path, icon, order | 菜单树（替换 MENU_ITEMS） |
| `sys_role_menu` | role_id, menu_id | 角色可见菜单（替换 ROLE_ROUTES） |
| `sys_alert_rule` | rule_id, name, level, trigger_type(threshold/ai), params(JSON), enabled | **驱动预警引擎**（settings 6 规则） |

### 4.5 索引
- `fact_grade`：`(student_id)`、`(course_id, semester_id)`、`(semester_id)`。
- `fact_alert`：`(student_id)`、`(level, status)`。
- 维表主键唯一索引。

## 5. ETL 流程（采集→加工→入库，阶段2 实现）

`run_etl.py` 编排，可重跑（幂等：先 drop 重建 or upsert）：

1. **extract**：openpyxl `read_only` 流式读成绩 236MB（已验证全量统计 39s）；xlrd 读 .xls 教学任务；docx 解析 2 培养方案。
2. **transform**：
   - 清洗：得分非数值(386个)归 NULL；等级制↔数字制兼容；教师列正则 `姓名(工号)`（多教师分号分隔）；教室利用率正则提 `(67%)`。
   - 关联：成绩 ⟕ 教学任务（教学班代码）补课程/师资/学时；选课表交叉校验。
   - 维表生成：14 学院 / 29 专业（成绩表为主，选课院系做映射对齐）。
   - 口径计算：挂科率(是否通过)、GPA(绩点)、平均分、优秀率、学分完成(∩培养方案，2专业)。
3. **simulate**（见 §6）：生成 2025-2026-2 新学期增量。
4. **alert_engine**（见 §7）：算预警写 `fact_alert`。
5. **load + 预聚合**：写维/事实表 → 计算所有 `agg_*` 表。
6. **校验**：行数对账、全校挂科率≈3.9%、无孤儿外键、GPA 分布合理 → 输出质量报告。

## 6. 模拟新学期增量算法（R2，阶段2 独立子任务）

**目标**：在真实历史（最新真实学期 2025-2026-1 有 3,156 行）之上，生成完整的 **2025-2026-2** 学期，使看板像"活系统"。**不加演示标识**，但 `source='sim'`。

**步骤**：
1. **学生群体**：沿用真实在籍学生（成绩表 DISTINCT 学号 + 年级推进）；可选注入一届新生（学号续号、脱敏姓名）。
2. **开课结构**：复用 `fact_lesson` 上学期排课（课程/教学班/教师/容量），仿造本学期开课。
3. **成绩生成**：对每个 (学生, 课程)，按该课程**历史分数分布**（均值/方差/挂科率）采样得分 → 映射等级/绩点/是否通过；学分取课程学分。
4. **植入异常**（供预警引擎触发**真实**预警）：按比例制造"挂科累积≥3 / GPA 连降>0.3 / 学分缺口>10 / 核心课挂科"学生，使其精确命中 `sys_alert_rule` 阈值。
5. **一致性约束**：生成数据口径与真实一致（绩点-得分映射、必修选修、重修标记），保证多页数字不互相矛盾、不穿帮。
6. **确定性**：固定随机种子，ETL 可复现。

**产物**：新学期 `fact_grade`(sim) + `fact_lesson`(sim) → 进入预聚合与预警，前端无缝呈现为"本学期"。

## 7. 预警规则引擎（缺口 G1：规则算真预警 + 模拟状态）

**输入**：`fact_grade` + `sys_alert_rule`(6 规则) + `fact_plan_course`(学分要求，2专业)。

| 规则 | 等级 | 类型 | 实现（threshold 精确可算） |
|---|---|---|---|
| 挂科累积 | 严重 | threshold | COUNT(is_pass=false, 含重修) ≥3 |
| GPA持续下降 | 严重 | ai→规则近似 | 连续2学期 GPA 降幅 >0.3 |
| 学分缺口过大 | 警告 | threshold | 培养方案要求 − 已修 >10（2专业精确，其余近似/跳过） |
| 核心课挂科 | 提醒 | threshold | 专业必修课挂科 ≥1 |
| 选课异常 | 提醒 | ai→规则近似 | 选课数连降（默认 enabled=false） |
| 退学风险 | 严重 | ai→规则近似 | GPA<1.8 + 连续挂科 综合判定 |

**输出 `fact_alert`**：student/type/level/触发链文本（真实，如"近2学期GPA 2.8→2.4"）。
**处理状态（模拟）**：初始"未处理"，按解决率分布（settings 示例 ~34%）模拟流转"已约谈/已解决"。
**出勤异常类**：无考勤数据 → 该规则砍掉或留空。
**规则改动**：settings 改 `sys_alert_rule` → 重跑 `alert_engine` 重算（阶段3 可手动触发）。

## 8. 鉴权与 RBAC 数据权限（替换写死的 10 角色映射）

**现状**：`permissions.ts` 写死 `ROLE_ROUTES`/`MENU_ITEMS`（10 角色→路由），前端硬判断。**改为后端 RBAC 可配置**。

**登录流程**：
1. `POST /api/auth/login {username,password}` → 校验 `sys_user.password_hash` → 签发 JWT（含 user_id/role_id）。
2. 返回 `{token, user, menus(来自sys_role_menu), dataScope(来自sys_role+role_scope)}`。
3. 前端存 token，路由守卫按 `menus` 动态生成可见菜单（不再用 ROLE_ROUTES）。

**数据权限（关键，非仅前端藏菜单）**：
- 每个 `/api/admin/*` 接口经依赖 `get_current_user` → 取 `dataScope`：
  - `all`（处长/质量办）：不加过滤。
  - `college`（院长/教秘）：`WHERE college_id IN (role_scope)`。
  - `major`（系主任）：`WHERE major_id IN(...)`。
  - `grade/class`（辅导员）：`WHERE class_id/grade IN(...)`，且预警/学生明细限分管范围。
- **服务层统一注入 WHERE**，越权返回空或 403。
- 校领导特例：全校汇总但**无个人明细**（接口屏蔽 student 明细字段）。

**API**：`POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout`。

## 9. API 层设计（契约对齐逐页规格书附录A）

- **统一包络**：`{code:0,msg:"ok",data:...}`；异常 `{code≠0,msg}`。
- **通用过滤**：query `college/major/grade/class/semester` + 角色 dataScope 叠加。
- **分页**：`page/pageSize` → `{list,total,page,pageSize}`（预警/报表/明细）。
- **路由模块**（对齐逐页规格书）：auth、dashboard(大屏+学院/专业/课程/学生)、alert、operation(4)、curriculum(plan/analysis/objectives/requirements)、faculty、students/analysis、practice、reports(reports/custom/accredit)、dims(维表下拉)、settings(rules CRUD + roles/semester/backup)、export。
- **维表接口**`GET /api/admin/dims/{colleges|majors|grades|semesters}`：替换前端硬编码 `collegeMap`/`allMajors`。
- **既有契约复用**：大屏组 5 接口 + alerts + curriculum/plan 的响应形状已在 mock 定形（见 vite.config.ts），后端按同形状用真实数据实现，前端零改动即可切换。

## 11. 性能策略（R7，倾向预聚合）

- **预聚合优先**：186K 行成绩的院/专业/课程/GPA 分布等在 ETL 算入 `agg_*`，接口直读（毫秒级），避免实时全表聚合。
- **明细实时**：学生成绩明细/预警抽屉按 `student_id` 索引实时查（数据量小）。
- **SQLite 调优**：WAL 模式、关键索引（§4.5）、连接池。
- **接口缓存**：维表/大屏 KPI 可加进程内 LRU（短 TTL）。
- 迁移 Postgres 时聚合表与索引策略不变。
