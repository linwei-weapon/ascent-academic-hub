# 规则治理职责分离与权限矩阵

## 权限模型

新增 `sys_rule_governance_permission`，规则治理权限独立于菜单权限和数据范围权限，由后端接口强制校验。

权限包括：

- `edit`：创建草稿、试算、提交、创建回滚单；
- `review`：审批或拒绝；
- `publish`：发布规则配置；
- `activate`：激活候选预警；
- `audit`：查看变更单和候选明细。

## 默认职责映射

| 角色 | 编辑 | 审核 | 发布 | 激活 | 审计 |
|---|---:|---:|---:|---:|---:|
| 教务处（dean） | 是 | 否 | 是 | 否 | 是 |
| 质量办（quality_office） | 否 | 是 | 否 | 否 | 是 |
| 校领导（school_leader） | 否 | 否 | 否 | 是 | 是 |
| 辅导员及院系角色 | 否 | 否 | 否 | 否 | 否 |

因此，任何单一角色都不能独立完成“创建—审核—发布—激活”全流程。

## 接口保护

- 创建、试算、提交、回滚：要求 `edit`；
- 审批、拒绝：要求 `review`；
- 发布配置：要求 `publish`；
- 激活预警：要求 `activate`；
- 查看变更和候选：要求 `audit`。

新增 `GET /api/admin/settings/rule-permissions/me`，向前端返回当前角色的治理权限。页面据此控制阈值编辑、启停、试算、审核、发布、激活和回滚按钮；服务端仍执行最终授权校验。
