## 1. 文档目标、范围与阅读方式

### 1.1 文档目标

本文档完整说明“学业预警监控”用户可以看到、查询、点击、下钻、核查、导出等相关业务功能，主要包括：

1. 页面展示哪些字段、指标、选项和状态；

2. 每个指标如何计算，分子、分母、去重对象和排除项是什么；

3. 查询条件、指标卡片、图表和名单之间如何联动；

4. 点击后下钻到哪里，下钻条件如何继承；



### 1.2 功能范围

本文档覆盖三个一级工作页及其全部下钻：

| 一级工作页 | 主要能力 | 最深下钻 |
|---|---|---|
| 预警监控 | 当前预警规模、优先核查、时间分布、组织比较、学生名单 | 学生核查 → 同类轨迹、AI 研判、完整学业档案 |
| 预警规则 | 生产规则、规则变更单、影响试算、审核发布、规则自发现 | 阈值编辑、候选明细、影响分析、候选采纳 |
| 低年级风险观察 | 大一未通过及后续变化、群体集中、课程集中、学生核查 | 低年级核查 → 完整学业档案 |



### 1.3 术语约定

| 术语 | 含义 |
|---|---|
| 当前预警 | `fact_alert.is_active=1` 的规则命中记录 |
| 规则触发记录 | 一条当前有效预警记录；同一学生可有多条 |
| 当前预警学生 | 至少命中一条当前有效规则的去重学生 |
| 风险状态 | 由当前规则命中及最高预警等级决定 |
| 核查状态 | 由人工核查工作流决定，与风险状态分开记录 |
| 在籍学生 | 学籍状态为“在籍”的去重学生，是预警学生率的分母 |
| 当前权限范围 | 当前人员身份的数据范围权限 |
| 当前查询范围 | 当前权限范围与用户查询的学院、专业、年级、班级条件的交集 |
| 当前风险池 | 当前仍命中至少一条规则的学生集合 |

## 3. 全模块公共规则

### 3.1 当前工作身份与数据权限

所有页面、详情、导出和 AI 接口都必须在服务端重新校验当前工作身份。前端隐藏菜单或按钮不是权限边界。

| 当前工作身份 | 明细数据范围 |
|---|---|
| 校领导、教务处、系统管理员 | 全校授权数据 |
| 学院 | 本学院学生明细 |
| 辅导员 | 有效“人员—行政班”关系覆盖的学生 |
| 班主任 | 有效“班主任—行政班/学生”关系覆盖的学生 |
| 导师 | 有效“导师—学生”关系覆盖的学生 |

一人多角色时，以“当前工作身份”为准。切换身份后必须重新加载选项、指标、名单、导出范围、AI 研判等。

### 3.2 条件联动

学院、专业、年级、班级选项都基于当前人员身份范围计算。

联动规则如下：

1. 选择学院后，专业只显示该学院内且当前用户有权查看的专业；

2. 选择学院后，年级只显示该学院范围内有在籍学生或有效观察学生的年级；

3. 选择专业后，班级只显示该专业内且当前用户有权查看的班级；

4. 同时选择专业和年级后，班级取“专业 ∩ 年级 ∩ 当前用户权限”的交集；

5. 同时选择学院、专业、年级时，班级取四者交集；

6. 清空上级条件后，下级选项重新扩大到当前其余条件允许的范围；

7. 修改学院时清空已选专业和班级；修改专业时清空班级；

8. 如果年级变化使已选班级不再合法，自动清空班级；

9. 当前维度已选择一个值时，再次展开该维度仍要保留其他合法选项，不能只剩已选项；



### 3.3 查询与重置

- “查询”按选定的条件执行查询操作，刷新受该条件影响的指标、图表、名单等；

- “重置”清空当前条件区域全部查询条件，回到当前身份可见的全部数据；

- 查询过程中可保留旧结果并显示加载反馈，完成后一次性替换，避免局部新旧数据混杂；



### 3.4 风险与核查双状态

风险状态与核查状态是分开的：

- 风险状态回答“当前规则是否仍命中、最高风险是什么”；
- 核查状态回答“人工核查进行到什么阶段”；
- 已经有核查记录不等于规则不再命中；
- 当前规则仍命中不等于从未核查；
- 解除或关闭人工事件后再次命中，形成新的风险预警。

## 4. 学业预警监控首页：预警监控

### 4.1 页面路径说明

**菜单路径：** 教学管理分析 → 学业预警监控 → 预警监控<br>



### 4.2 页面目标

在当前工作身份和查询范围内，统一回答：当前有多少学生仍处于预警、多少属于严重风险、多少尚待核查、应先核查谁、预警主要在何时生成、风险是否集中在特定组织，以及具体学生证据是什么。

### 4.3 页面标题与最新预警统计时间

页面标题为“学业预警监控”。标题旁显示：

`最新预警统计时间：YYYY-MM-dd`

计算逻辑：

```text
最新预警统计时间
= 当前权限范围 ∩ 查询条件查询结果 ∩ 当前有效预警记录中 最近的预警发生日期
```

- 没有任何符合条件的当前预警时显示“—”；



### 4.4 查询条件

| 条件 | 控件 | 选项内容 | 默认值 | 作用范围 |
|---|---|---|---|---|
| 学院 | 下拉框 | 当前权限和其他已选条件下的学院 | 全部 | 全页 |
| 专业 | 下拉框 | 学院及当前权限下的专业 | 全部 | 全页 |
| 年级 | 下拉框 | 当前条件下有在籍学生的年级 | 全部 | 全页 |
| 行政班 | 下拉框 | 学院、专业、年级、权限交集下的班级 | 全部 | 全页 |
| 预警类型 | 下拉框 | 当前有效预警类型 | 全部 | KPI统计指标和卡片分子、图表、优先核查队列、名单 |
| 风险等级 | 下拉框 | 严重、警告、提醒 | 全部 | KPI统计指标和卡片分子、图表、优先核查队列、名单 |

注意：预警类型和风险等级只约束预警分子，不缩小“当前预警学生率”的在籍学生分母。否则选择“严重”后分母也变成严重学生范围，比例将失去意义。

操作按钮：

- **查询：** 应用条件并刷新整页；

- **重置：** 清空所有查询条件、并查询当前身份全部授权数据。



### 4.5 指标卡片

#### 4.5.1 当前预警学生

```text
当前预警学生数
  1: 首先学生必须是在籍的
  2: 其次必须是当前用户数据权限内与查询条件内的名单；
  3: 至少命中1条有效规则
  4: 一名学生命中多条规则只计 1 人
```

- 辅助文案显示“X 次规则触发”，其中 X 是当前范围内规则触发记录数，不是人数；

- 点击后，自动定位到 “当前预警学生” 卡片，并且自动查询显示对应的统计学生名单



#### 4.5.2 当前严重学生

```text
当前严重学生数
  1: 首先学生必须是在籍的
  2: 其次必须是当前用户数据权限内与查询条件内的名单；
  3: 至少命中1条有效规则
  4: 命中有效规则中的最高风险等级 = 严重
  5: 一名学生命中多条规则只计 1 人
```

风险等级顺序：严重 = 3、警告 = 2、提醒 = 1。点击后，自动定位到 “当前预警学生” 卡片，并且自动查询显示对应的统计学生名单



#### 4.5.3 严重且待核查

```text
严重且待核查学生数
  1: 首先学生必须是在籍的
  2: 其次必须是当前用户数据权限内与查询条件内的名单；
  3: 至少命中1条有效规则
  4: 命中有效规则中的最高风险等级 = 严重
  5: 一名学生命中多条规则只计 1 人
  6: 至少一条当前规则事件核查状态=待核查 的

```

点击后，自动定位到 “当前预警学生” 卡片，并且自动查询显示对应的统计学生名单。



#### 4.5.4 待核查学生

```text
待核查学生数
  1: 首先学生必须是在籍的
  2: 其次必须是当前用户数据权限内与查询条件内的名单；
  3: 至少命中1条有效规则
  4: 一名学生命中多条规则只计 1 人
  5: 至少一条当前规则事件核查状态=待核查 的

```

点击后，自动定位到 “当前预警学生” 卡片，并且自动查询显示对应的统计学生名单。



#### 4.5.5 当前预警学生率

全校、学院、专业等非个人责任范围身份显示此卡。

```text
当前预警学生率
= 当前用户权限范围及查询结果范围内在籍学生的当前预警去重学生数
   ÷ 当前用户权限范围及查询结果范围内的在籍学生数
   × 100%
```

- 分子受预警类型、风险等级和组织条件影响；

- 分母只受权限及学院、专业、年级、班级影响；

- 结果保留 1 位小数；

- 分母为 0 时显示“—”；

- 辅助文案显示“分子/分母人”；

- Tooltip 固定显示“当前预警学生率 = 当前预警去重学生数 ÷ 当前用户权限范围及查询条件查询结果范围内在籍学生数”；



#### 4.5.6 我的待核查

辅导员/班主任/等班级范围或人员关系范围身份显示此卡，替代“当前预警学生率”。

```text
我的待核查学生数
  1: 当前用户为该生至少一条尚未关闭预警事件的责任人
  2: 一名学生命中多条规则只计 1 人

```

点击后，自动定位到 “当前预警学生” 卡片，并且自动查询显示对应的统计学生名单。



### 4.7 本轮优先核查队列

- 默认只从“待核查”或“核查中”的学生中形成队列，接口最多返回 10 人，首页展示前 4 人。


- 优先分公式：


```text
优先分 = 最高风险分 + 核查状态分 + 多规则分 + 持续时长分

风险分：严重 50分；警告 30分；提醒 15分
核查状态分：待核查 15分；核查中 8分
多规则分：每增加1条加5分，最高 15分
持续时长分：持续满 60 天加 10分；满 30 天不足 60 天加 5分；否则 0分
```

- 排序方式：优先分降序 → 最高风险降序 → 首次进入风险池时间升序 → 最近变化时间降序 → 学号升序。


- 卡片信息：

  - 主信息：学生姓名、优先分

  - 核查信息：最高风险等级+核查原因；如：“**严重风险；4条当前规则同时命中；仍有当前规则尚未核查；当前风险池已持续169天**”

  - 补充信息：学院/班级；如：“**国际教育学院 · 石工22-1留学生班**”

  - 点击学生进入[学生预警核查抽屉](#5-学生预警核查抽屉)。

- “**AI 管理研判**”  ，详见[教学运行分析相关需求](#7-ai-管理研判抽屉)。



### 4.7 当前预警时间分布

以柱状图的形式按月统计预警学生人数和命中规则数。纵轴人数、横轴月份

- 预警学生人数：
  - 一名学生命中多条规则只计 1 人
  - 同一个月学生多次被预警只计 1 人


- 命中规则数：一个月内预警命中学生触发的规则次数。

- 按月份降序取最近 10 个“有数据的月份”，再按时间正序展示；

- 柱高为当前仍命中学生数；

- 纵轴名称完整显示“学生数”；



### 4.8 各学院/专业/班级当前预警学生率

标题和统计维度按查询条件逐级变化：

| 已应用条件 | 标题 | 分组维度 |
|---|---|---|
| 学院为空 | 各学院当前预警学生率 | 学院 |
| 已选学院，专业为空 | 各专业当前预警学生率 | 专业 |
| 已选专业，班级为空 | 各班级当前预警学生率 | 班级 |
| 已选班级 | `{班级名称}-当前预警学生率` | 当前班级 |

- 统计数据：
  - 预警学生率：该组织当前预警去重学生数 ÷ 该组织在籍学生数 × 100%
  - 预警学生人数
  - 在籍学生人数
- 排序方式：按预警学生率降序 → 预警学生人数降序 → 组织名称升序；

- 图表展示前 10 个组织；

- Tooltip 显示组织名称、预警学生率、预警学生人数、在籍学生人数；

### 5.5 规则变更单

- 字段信息内容

| 字段 | 内容 |
|---|---|
| 编号 | 变更单唯一编号 |
| 规则 | 规则编号 |
| 变更原因 | 创建时填写，至少 5 个字符 |
| 状态 | 草稿、待审核、已通过、已拒绝、配置已发布、预警已激活 |
| 影响试算 | 当前、候选、保留、新增、退出、净变化、数据快照和有效性？ |
| 创建人 | 创建草稿的账号 |

- 状态机与操作

```text
草稿
├─ 试算脚本维护
├─ 影响试算（可重复，覆盖旧候选）
└─ 提交审核 → 待审核
                 ├─ 拒绝 → 已拒绝（终止）
                 └─ 通过 → 已通过
                            └─ 发布配置 → 配置已发布
                                           └─ 激活预警 → 预警已激活

配置已发布/预警已激活 ── 创建回滚单 → 新的草稿
```

提交、审核、发布和激活前都要求影响试算仍有效。回滚不直接覆盖生产规则，而是生成一个新的草稿，重新执行完整流程。

**审核流程建议能够灵活设置，能够增加审核节点/设置审核人员。**



#### <span style="color:red;font-weight:bold">5.5.1 试算脚本维护（新增功能）</span>

- 页面路径：教学管理分析 → 学业预警监控 → 预警规则 → 生产规则与变更 → 规则变更单 → 操作栏“试算脚本维护”。
- 入口范围：仅草稿状态且当前工作身份具有规则治理 `edit` 权限时显示；服务端再次校验权限和草稿状态。
- 页面形态：弹窗，标题“试算脚本维护”，展示变更单编号与规则编号。
- 脚本类型：支持“普通SQL”和“存储过程”两种配置，脚本正文不能为空，单次最多保存 50000 个字符。
- 操作按钮：
  - 保存：保存脚本类型、正文、最后维护人和维护时间；脚本有变化时，旧影响试算及旧候选结果失效，必须重新执行影响试算；
  - 取消：关闭弹窗，不保存本次编辑内容。
- 执行边界：本功能只维护脚本配置，保存时不直接执行用户编写的 SQL 或存储过程；当前影响试算继续使用生产规则引擎和拟议参数在内存中受控重算。若后续启用自定义脚本执行，必须另行落实只读事务、对象白名单、数据库方言适配、超时与资源限制及审计策略。



#### 5.5.2 影响试算

试算使用生产规则引擎和拟议参数在内存中重算。试算前必须首先保存试算脚本配置；未维护脚本时，前后端均不得执行影响试算。

```text
当前集合 C = 当前规则的有效预警学生集合
候选集合 P = 使用拟议参数重新计算的学生集合
保留 = C ∩ P
新增 = P - C
退出 = C - P
净变化 = |P| - |C|
全部候选影响集合 = C ∪ P
```

试算同时相关数据（如成绩、最大学期、学生数、培养方案课程数、学分等）进行校验，生成数据试算结果。如果基础数据变化后，旧试算标记为“已过期”，必须重新试算。



#### 5.5.3 候选学生明细

- 页面路径说明

​	**页面路径：** 教学管理分析 → 学业预警监控 → 预警规则 → 生产规则与变更 → 规则变更单 → 候选明细<br>	**页面形态：** 弹窗，标题“规则候选学生明细”

- 候选学生明细功能说明：展示当前变更单全部候选影响学生，即 `当前集合 ∪ 拟议集合`，
  - 暂不提供“全部、新增、保留、退出”分类切换，也不在页面列表展示内部变化类型数据。
- 主要信息内容
  - 字段：学号、姓名、学院、专业、候选命中说明。
  - 补充信息描述
    - 候选命中说明：
      - 新增和保留通常展示拟议规则的触发证据；
      - 退出记录可能没有新的触发证据；
      - 空证据显示“—”，不能编造原因。
  - 排序方式：按类型排序 新增 → 退出 → 保留 → 学号升序 ；但页面不展示变化类型

- 导出（**把 导出候选 CSV 改为 导出**）：导出字段有学号、姓名、学院、专业、班级、年级、**变化类型、预警等级、**候选命中说明



#### 5.5.4 影响分析

- 页面路径说明

​	**页面路径：** 教学管理分析 → 学业预警监控 → 预警规则 → 生产规则与变更 → 规则变更单 → 影响分析<br>	**页面形态：** 弹窗，标题“规则变更影响分析”

- 参数变更

  展示参数变更情况，包括参数、变更前（值）、变更后（值）、是否调整（未调整、已调整）；

- 学院专业年级分布：基于学院专业年级统计变更汇总信息。

  - 行结构：学院 → 专业 → 学院小计 → 全部合计。

  - 列结构：学院、专业、变更涉及的各年级动态列、小计

  - 学院、专业、年级缺失时分别归入“未知学院”“未知专业”“未知年级”，

  - 展示要求

    - 学院名称按学院下专业行合并；
    - 每个学院末尾有“小计”；
    - 表尾有“合计”；
    - 右上显示总影响人数；
    - 空数据文案为“暂无变更影响数据”；

    统计集合包含新增、保留、退出的并集。每个学生在变更单中只有一条候选记录



#### 5.5.5 提交审核

​	对规则变更单中的变更规则提交上级进行审核；提交后状态自动变为“待审核”

#### 5.5.6 审核操作

- 功能说明：对待审核的规则变更单进行审核
- 审核操作
  - 通过：对待审核的规则变更单给予通过操作，状态变为“已通过”
  - 拒绝：对待审核的规则变更单给予不通过操作，状态变为“已拒绝”

#### 5.5.7 发布配置

​	对规则变更单中“已通过”的变更规则进行发布，发布后，状态变为“配置已发布”

#### 5.5.8 激活预警

​	对规则变更单中“已通过”的变更规则进行激活，激活后，状态变为“预警已激活”

#### 5.5.9 创建回滚单

- 对状态变为“预警已激活”或者 状态变为“配置已发布” 的规则变更单 创建回滚单； 创建后，自动增加一条未完成变更单记录；
- 已有未完成变更单时禁止为同一规则再创建草稿

#### 5.5.10 发布与激活的区别

- **发布配置：** 把拟议参数和启用状态写入生产规则配置，并保存上一版本快照；不立即改变学生预警；

- **激活预警：** 按候选明细事务化更新当前预警事实和事件；

- **保留：** 更新仍活动的预警证据；若旧事件已结束，则关闭旧记录并创建新风险周期；

- **新增：** 创建当前预警和新的待核查事件，并按学生关系自动分派；

- **退出：** 关闭当前规则预警及其风险周期；

- 候选明细条数必须等于保留 + 新增 + 退出，否则拒绝激活；

- 同一变更单禁止重复激活。

## 6.  预警规则首页：规则自发现候选页面

### 6.1 页面路径说明

**菜单路径：** 教学管理分析 → 学业预警监控 → 预警规则 → 规则自发现候选<br>

### 6.2 主要功能

基于历史学生轨迹发现与严重学业结果相关的可执行特征组合，只形成候选建议供用户选择。

候选必须进入生产规则治理流程，经过流程处理和审核通过后发布，才能够生效，产生预警结果。

### 6.2 数据卡片看板

- 分析周期：默认为当前最近学期。
- 轨迹学生：当前学期在籍学生
- 待审核：处于待审核建议中的规则数量；
- 已采纳：已被采纳，纳入规则流转过程的规则数量。



### 6.2 运行新一轮分析

规则自发现以学校分析库中的历史学生轨迹为输入。启用学校批准的大模型接入时，模型只接收脱敏后的数值特征并参与模式复核；候选门槛、风险倍数、建议等级、最多保留数量和进入治理流程的边界仍由固定规则校验，模型不得临时发明正式指标。

- 用户点击“运行新一轮分析”后，系统先弹出执行确认框，内容包括：
  - 样本数据汇总：按本次实际连接且拟参与计算的库表动态统计库表数量、样本数据总量和样本学生数，不写死示例值；
  - 样本库表数据清单：显示库表中英文名称和各表拟参与计算的数据量；成绩、学籍异动等只统计规则实际使用的真实来源记录；
  - 数据脱敏说明：披露直接身份字段移除、任务内随机盐哈希、数值特征最小化、正负样本限量抽样和日志不保存样本正文等规则；
  - 免责说明协议：用户必须勾选同意数据脱敏方案，并同意在学校批准模型启用时推送本次脱敏样本特征；
  - 操作按钮：执行、拒绝。
- “执行”按钮：
  - 未勾选协议时保持禁用；服务端再次校验同意状态，直接 API 请求不得绕过；
  - 服务端校验确认框样本清单指纹，库表计数变化后必须重新确认；
  - 接入学校批准模型时，系统按脱敏规则推送限量特征样本进行模式复核；未配置模型时只运行现有本地受控分析引擎；
  - 任务进入后台运行，按钮显示加载动画和“新一轮分析运行中”，页面轮询任务状态，用户可继续查看或离开页面；
  - 启动任务时，本周期旧待审核建议标记为“已替代”，进入“已被新一轮分析替代”分区；
  - 运行完成后自动刷新“待审核建议”，候选仍须进入规则治理流程，不自动产生生产预警。
- “拒绝”按钮：关闭确认框，不登记运行任务，不推送数据，也不改变当前候选状态。

规则自发现的候选生成规则条件：

- 总可分析样本少于 100 人时不生成候选；
- 单特征或复合条件命中样本不少于 30 人；
- 命中正样本不少于 5 人；
- 风险倍数不少于 2.0；
- 最多保留风险倍数最高的 10 条；
- 计算逻辑
  - 命中风险率 = 命中条件且为正样本人数 ÷ 命中条件人数
  - 全体基线率 = 全部正样本人数 ÷ 全部分析样本人数
  - 风险倍数 = 命中风险率 ÷ 全体基线率

建议等级：风险倍数 `≥5` 为严重，`≥3 且 <5` 为警告，`≥2 且 <3` 为提醒。





### 6.3 待审核建议

- 信息内容包括：名称、建议等级、风险倍数、条件、命中人数、命中风险率及人数、全体基线率、算法版本。

- 相关操作

  - 采纳并创建变更草稿：创建一个默认禁用的自发现规则和一个规则变更草稿。

    - 采纳后仍需试算、提交、审核、发布和激活；
    - 已采纳或已启用的相同条件不重复建议；

  - 拒绝建议：状态改为已拒绝



### 6.4 历史状态分区

-  分为 已采纳建议、已拒绝建议、已被新一轮分析替代几个区域。

  - 已采纳建议：显示被采纳的规则建议。显示的信息包括：
    - 字段信息：规则建议、采纳时间、治理衔接、备注说明
    - 统计信息：已采纳建议数量

  - 已拒绝建议：显示被拒绝的规则建议。显示的信息包括：
    - 字段信息：规则建议、发现时间、风险倍数
    - 统计信息：已拒绝建议数量

  - 已被新一轮分析替代：运行新一轮分析时，当前周期旧待审核建议标记为“已替代”，显示的信息包括：

    - 字段信息：历史建议、发现时间、当时风险倍数

    - 统计信息：已被新一轮分析替代数量

| 当前预警时间分布 | 历史月度新增趋势 | 前者是当前风险池的生成月份结构 |
| 规则候选学生 | 新增预警学生 | 候选明细还包含保留和退出 |
| 风险倍数 | 个体发生概率 | 风险倍数是历史群体关联比值 |

### 8.4 跨页面对账

1. 点击指标卡后名单总数必须等于卡片人数；
2. 组织图各组分子合计应与同范围预警学生集合一致；
3. 规则影响交叉表总计、候选明细总数、保留+新增+退出必须一致；
4. 完整档案历史未通过课程数应等于按课程去重的历史未通过集合，不要求等于成绩记录数；
5. 页面、导出、AI 研判必须使用同一当前身份和同一查询范围；
6. 同名指标在监控页、AI 研判和确认书中不得出现不同公式。

## 9. 数据来源、版本和适用边界

### 9.1 主要数据来源

| 数据主题 | 主要数据表/对象 | 用途 |
|---|---|---|
| 学生与组织 | `dim_student`、`dim_college`、`dim_major`、`dim_class` | 权限、查询选项、组织维度、在籍分母 |
| 当前与历史预警 | `fact_alert` | 规则触发、风险等级、生成时间、版本、活动状态 |
| 核查事件 | `alert_event`、`alert_assignee`、`alert_followup`、`alert_status_history` | 核查状态、责任人、跟进和状态历史 |
| 成绩 | `fact_grade`、V2 `grade_attempt` | GPA、未通过、学分、低年级轨迹 |
| 课程与培养方案 | `dim_course`、`fact_plan_course`、`fact_major_req`、V2 方案状态表 | 课程名称、核心/必修、学分缺口、方案证据 |
| 学籍与毕业 | `fact_attrition`、V2 `graduation_outcome` | 自发现结果标签、同类轨迹毕业分布 |
| 人员关系 | 当前身份范围、行政班关系、导师学生关系 | 明细权限、责任范围、自动分派 |

### 9.2 版本信息

监控摘要至少返回：定义版本、当前学期、数据时点、规则编号与规则版本、历史比较能力、当前权限范围。当前实现版本包括：

- 预警监控定义：`alert-monitor-v2.0`；
- 优先队列：`alert-priority-v2.0`；
- 累计 GPA：`cumulative-gpa-v1`；
- 学生成长：`growth-v1`；
- 规则自发现：`association-v2`。

版本更新后，页面、导出、AI 研判和指标确认书必须同步。

### 9.3 数据边界

1. 平台只消费和分析教务数据，不维护学校业务主数据；
2. 真实、推导和合成数据必须保留来源标识；
3. 缺少批次或规则版本时不计算历史新增、升级、持续；
4. 缺少结构化培养方案时不输出正式方案完成结论；
5. 缺少人员关系时拒绝或返回空范围，不扩大权限；
6. 核查记录是平台管理证据，不代表源系统业务状态已经改变；
7. 所有学生级结论都需人工核验，不能据此自动处分、贴标签或推断原因。

## 10. 异常、空态和验收规则

### 10.1 通用异常

| 场景 | 期望表现 |
|---|---|
| 当前身份无有效范围 | 403 或明确空范围，不返回全校数据 |
| 查询条件越权 | 403，提示条件超出权限范围 |
| 接口失败 | 显示加载失败和重新加载，不显示 0 冒充结果 |
| 无符合条件数据 | 指标按合法空集合显示，列表/图表显示明确空态 |
| 比例分母为 0 | 显示“—”并保留公式说明 |
| 历史不可比 | 显示不可比较原因，不生成新增/升级结论 |
| 规则试算过期 | 标记已过期，禁止提交/审核/发布/激活 |
| 导出超过 5,000 人 | 拒绝并要求收窄条件 |
| 学生无权限 | 403；直接路由、抽屉、AI、导出均一致 |

### 10.2 预警监控验收

1. 最新预警统计时间等于当前筛选有效预警最晚生成日期；
2. 六类条件选项非空且按权限、关联条件联动；
3. 再次展开学院/专业下拉框仍有其他合法选项；
4. 前四张卡片点击后只更新名单，不改变其他卡片和图表；
5. 卡片人数与名单总数一致；
6. 时间图展示最近 10 个有数据月份，纵轴“学生数”完整；
7. 组织范围平均标签横向显示且不遮挡首条柱形；
8. 当前预警学生率按去重分子和在籍分母计算；
9. 查询后重置按钮后不出现“已查询”等重复文案；
10. 导出继承全部当前条件并执行权限校验。

### 10.3 规则治理验收

1. 教务处可创建、试算、提交和发布；质量办可审核；校领导可激活；
2. 创建人不能审核自己创建的变更；
3. 无有效试算或试算过期不能继续流转；
4. 候选弹窗始终展示全部候选，不显示分类切换和变化列；
5. 影响分析交叉表有数据，小计、合计和候选总数一致；
6. 发布不改变学生预警，只有激活才改变；
7. 回滚创建新草稿，不覆盖历史记录；
8. 新增、保留、退出激活过程保持事务一致性。

### 10.4 低年级风险观察验收

1. 学院、专业、年级、班级选项非空且联动；顺序正确；
2. 五张卡片点击后自动定位名单，人数与名单一致；
3. 各学院/专业/班级关注优先级有数据并按比例降序；
4. 学生名单含学院、专业、班级、年级且顺序正确；
5. 学号姓名支持模糊查询和回车查询，只影响名单；
6. 抽屉 GPA 横轴使用真实学期代码；
7. “大一未通过记录”只统计大一，下方“未通过课程记录”展示全部历史，两者无需相等；
8. 历史预警页签有数据时正常展示，无数据时使用明确空态；
9. 完整学业档案可返回来源页且服务端再次鉴权。

### 10.5 角色回归矩阵

至少使用以下身份执行浏览器和接口回归：校领导/教务处全校视角、二级学院本院视角、两个不同辅导员或班主任的班级隔离、两个不同导师的学生隔离、系统管理员全校业务与系统权限。必须覆盖直接 URL、接口、导出、AI 研判、学生详情和工作身份切换。
