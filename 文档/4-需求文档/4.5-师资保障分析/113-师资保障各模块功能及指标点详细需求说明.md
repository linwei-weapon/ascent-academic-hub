## 1. 文档目标、范围与阅读方式

### 1.1 文档目标

本文档完整说明“师资保障分析”中用户能够看到、筛选、比较、点击、下钻和核查的功能，重点回答以下问题：

1. 首页、KPI 下钻、课程师资情况、课程详情和教师教学经历分别展示哪些信息；
2. 每个字段、指标、状态、标签、筛选选项和提示语的业务含义是什么；
3. 每个指标如何计算，统计对象、分子、分母、去重键、排除项、阈值、精度和排序方式是什么；
4. 用户从哪个入口进入哪个抽屉，学期、学院、课程和教师上下文如何继承，在哪一层结束；
5. 哪些信息来自教学事实，哪些是规则推导，哪些是数据质量状态，哪些仍未接入；
6. 校级与学院级身份分别能看到什么，跨学院教师承担本院课程时如何限制明细；
7. 加载、空数据、证据不足、请求失败、无权限和快速切换时页面应如何表现；
8. 当前实现与正式需求存在何种差异，验收时如何复算和判断。

### 1.2 功能范围

“师资保障分析”以课程供给连续性和实际授课团队为主对象，不是教师评价系统。当前功能范围如下：

| 业务区域 | 主要管理问题 | 最深下钻 |
| --- | --- | --- |
| 师资保障分析首页 | 本学期实际授课师资规模、课程结构异常、连续单点、高职称和青年教师参与情况如何 | 首页 KPI → 指标明细 → 课程证据或教师教学经历 |
| 学院授课师资保障概览 | 哪些学院的优先核查、连续单点、结构核查或数据候选课程较集中 | 学院行 → 课程师资情况 → 课程详情 → 教师教学经历 |
| 全校/本院重点课程 | 哪些课程需要优先分配管理注意力，为什么 | 课程卡片 → 课程详情 → 教师教学经历 |
| 课程师资情况 | 当前范围内每门课程命中哪些核查类型，承担规模与原因是什么 | 课程行 → 课程详情 → 教师教学经历 |
| 课程详情 | 为什么进入队列、当前团队是谁、最近实际开课是否连续、历史供给如何 | 当前团队成员 → 教师教学经历 |
| 教师授课情况 | 教师在当前授权课程范围内承担了哪些课程、教学班、学生人次和学时 | 教师教学经历为终点，不再继续下钻 |

### 1.3 不在本模块范围内的能力

- 不评价教师个人教学质量、绩效、能力、责任心或奖惩；
- 不根据平均成绩、通过率、学生评价或调停课次数给教师排名；
- 不把“1 名教师授课”单独认定为风险；
- 不把学生人次平均分摊为联合授课教师的正式贡献或工作量；
- 不认定教师工作量达标、超负荷或不足；教师负荷归属“教学运行分析”；
- 不使用模拟年龄、学历、学位、毕业院校、教龄或学缘形成正式结论；
- 不把实际授课团队等同于学校正式任命的课程团队；
- 不根据历史开课自动认定教师具有未来授课资格或一定能够接续；
- 不自动换教师、停开课程、分配备份教师、调整人事或回写教务、人事源系统；
- 不展示学生名单、成绩明细或与课程保障无关的教师个人画像。

### 1.4 状态标记与阅读约定

本文使用以下标记：

- **现行实现：** 当前工作区前端和后端已经执行的行为；
- **正式要求：** 生产开发和验收必须满足的规范；
- **待修正：** 当前实现与正式要求不一致，不能把现状固化为产品规则；
- **待确认：** 需要学校确认阈值、字典、责任归属或业务合理性；
- **未接入：** 当前没有足够真实数据，页面应披露缺口而不是显示为 0；
- **历史行为：** 旧页面或历史文档曾经存在，但当前路由不可达，不属于现行功能。

页面功能优先关联公共指标确认书中的 `F` 编号；没有正式指标编号的筛选、列表、提示和中间计算标记为“页面功能”。

### 1.5 阅读顺序

建议按以下顺序阅读：

1. 先看[第 2 章](#chapter-2)，确认页面树和完整下钻终点；
2. 再看[第 3 章](#chapter-3)，理解学期、权限、数据质量、分页和空值公共规则；
3. 按实际操作顺序阅读[首页](#chapter-4)、[课程师资情况](#chapter-5)和[教师授课情况](#chapter-6)；
4. 开发、测试和数据人员使用[第 7 章](#chapter-7)复算指标，使用[第 8 章](#chapter-8)核对数据来源；
5. 交付前按[第 9 章](#chapter-9)完成异常、权限、下钻和一致性验收。

## 2. 页面树与完整下钻链路

### 2.1 模块入口与路由

- **菜单路径：** 教学管理分析 → 师资保障分析
- **当前主路由：** `/admin/faculty`
- **当前页面组件：** `code/frontend/src/views/teaching-analysis/faculty/Index.vue`
- **KPI 下钻组件：** `code/frontend/src/views/teaching-analysis/faculty/FacultyKpiDrilldown.vue`

当前实现不是“首页、课程师资、教师授课”3 个独立路由页面，而是同一个主路由内的多层抽屉。文档仍按业务页面拆分章节，便于用户定位和开发验收。

当前页面调用链如下：

| 页面/功能 | 接口 | 主要参数 |
| --- | --- | --- |
| 首页 | `GET /api/admin/faculty/management-overview` | `semester`、可选 `college` |
| KPI 下钻 | `GET /api/admin/faculty/management-kpis/{metric_key}/details` | `semester`、可选 `college/department/keyword`、`page/page_size` |
| 课程师资情况 | `GET /api/admin/faculty/management-courses` | `semester`、可选 `college/review_type/keyword`、`page/page_size` |
| 课程详情 | `GET /api/admin/faculty/management-course/{course_id}` | `semester` |
| 教师授课情况 | `GET /api/admin/faculty/management-teacher/{teacher_id}` | `semester`、可选 `course_id` |

以上接口统一在服务端读取当前工作身份并重新校验数据范围；前端路由参数不构成授权。

## 3. 全模块公共规则

### 3.1 当前工作身份、菜单准入与数据范围

| 身份或范围 | 首页范围 | 明细范围 |
| --- | --- | --- |
| 校领导、教务处及被明确授予全校范围的角色 | 全校 KPI、学院聚合、全校优先课程 | 可查看授权范围内学院、课程团队和必要教师教学经历 |
| 系统管理员 | 仅在被明确授予全校业务数据权限时查看全校 | 系统管理权限本身不作为师资数据授权 |
| 二级学院院长、教学秘书或其他学院范围角色 | 本学院 KPI 和本院责任课程工作区 | 仅查看本院责任课程；可查看承担本院课程的外院教师必要教学证据 |

公共规则：

1. 菜单是否显示由后台菜单与角色授权决定，但菜单隐藏不是安全边界；
2. 所有师资接口都要求登录，并读取当前工作身份；
3. 前端请求自动携带 Bearer Token 和 `X-Active-Identity`；
4. 后端使用统一 `college_data_scope` 重新计算范围；
5. 受限身份显式请求非授权学院时返回 403；没有任何可用学院范围时返回 403；
6. 课程详情以课程责任学院校验，不以教师人事归属替代；
7. 学院用户因本院课程查看外院教师时，必须携带课程 ID，接口只返回该授权课程；
8. 身份切换后必须清空旧首页、队列、课程、教师和 KPI 缓存。

### 3.2 学期选择

- 控件：单选下拉框，placeholder 为“选择学期”；
- 选项来源：`GET /api/admin/meta/filters` 的 `semesters`；
- 选项字段：`value`、`label`、`current`；
- 前端排序：元数据后端按学期代码升序返回，师资页面倒序展示，最新学期在前；
- 默认值：URL 中的 `semester` 存在且属于可用选项时使用该值，否则使用倒序后的第一项；
- 作用范围：首页 KPI、学院聚合、优先课程、课程队列、课程详情和教师当前学期任务；
- 历史连续性：只使用不晚于当前分析学期的最近实际开课记录；
- 正式要求：学期必须来自后端可用选项；直接 API 传入非法或不可用学期时应返回 400 或明确无覆盖状态，不能静默伪装为普通空数据。

### 3.3 课程责任学院与教师人事归属

本模块同时存在两种组织语义，不得混用：

| 组织语义 | 当前来源 | 用途 |
| --- | --- | --- |
| 课程责任学院 | `dim_course.dept` 清洗后与 `dim_college.name` 映射 | 首页学院聚合、课程队列归属、课程详情权限、课程核查责任 |
| 教师人事归属 | 人员快照、正式人员主数据或真实教师维表 | 教师名单展示、人员结构说明、教师筛选 |

正式要求：

- 课程由哪个学院负责，必须按课程责任组织判断；
- 外院教师承担本院课程，不改变课程责任学院；
- 教师所属学院不能反向开放外学院课程团队；
- 学院比较可以展示聚合，其他学院的教师和课程团队明细不得下钻；
- 当前高职称学院分布按人员解析后的 `dept` 组织，青年教师学院分布按教师承担的授权课程学院组织，两者组织语义不同，横向比较前必须完成学校确认，见[第 9.3 节](#current-gaps)。

学院选项均由当前数据和当前授权范围动态生成，不使用前端硬编码。2026 年 9 月 20 日工作库可见值为：人工智能、化学工程与环境、国际教育、地球物理、地球科学、外国语、安全与海洋工程、新能源与材料、未来能源、机械与储运工程、理、石油工程、经济管理、马克思主义学院。该清单只用于说明当前选项内容，数据更新后允许变化，不作为固定验收数量。

### 3.4 数据质量门禁

分析学期内，满足以下全部条件的教师 ID 进入异常排除集合：

```text
domain = operation
AND entity_type = teacher
AND semester_id = 当前学期
AND status IN (open, reviewing)
AND severity IN (high, critical)
```

应用规则：

1. 如果教学任务的主讲教师在异常集合中，整条教学任务从正式课程分析中排除；
2. 如果异常教师只出现在联合教师字段，保留教学任务，但从该任务成员集合中移除该教师；
3. 被排除教学任务不进入课程教学班数、学生人次、团队人数、优先级、首页 KPI 和课程聚合；
4. 历史连续性按每个历史学期的同类未关闭高/严重问题排除；
5. 课程只要存在被排除任务，即记录 `excluded_lesson_count` 并进入数据候选原因；
6. 教师教学经历抽屉用于核查原始任务，当前实现仍展示该教师任务并给出数据质量提醒，不应把明细合计误当作正式 KPI；
7. 数据问题关闭或修正后，应使缓存失效并重新计算，不保留旧排除结论。

### 3.5 去重键、人数与人次

| 对象 | 去重或累计规则 |
| --- | --- |
| 课程 | 以 `course_id` 去重 |
| 教学班 | 优先以 `lesson_id` 去重；缺少 ID 的 KPI 归集使用请求内占位键避免行丢失 |

        - 最近最多3次实际开课中，同一名教师至少2次作为唯一授课教师。

      - **规则二：重点高集中度：**

        - 属于重点保障课程；

        - 可比组至少有10门课程；

        - 有效教学班数不少于4个；

        - 学生人次不少于100人次；

        - 最大主讲教师教学班占比达到同类同规模课程的百分位九十阈值；

        - 最大主讲教师覆盖学生人次占比也达到百分位九十阈值。

    - **重点课程识别**：

      满足以下任一条件即识别为重点课程：

      - 课程主数据标记为必修；
      - 课程名称、课程性质或课程类别中包含规定的重点关键词，例如必修、主干、核心、基础、思想、政治、体育、数学、英语等。

  - **连续单点**：

    计算规则：对每门课程

    1. 以页面选择的统计学期为截止学期；
    2. 查找该课程最近最多3次实际开课；
    3. 不要求是自然连续学期；
    4. 如果同一教师至少2次作为该课程唯一授课教师，则命中连续单点。

    “连续单点”是可并存规则，不是互斥主分类：

    - 一门课程可能同时计入连续单点和结构核查；

  - **结构核查**

    课程必须具备可评估条件，并命中以下至少一项规则

    - 规则一：连续单点结构

      最近最多3次实际开课中，同一教师至少2次作为唯一授课教师

    - 规则二：年龄结构

      当前有效授课教师年龄证据完整，并且：

      - 所有教师均大于等于55岁；或者
      - 所有教师均小于等于55岁。

      恰好55岁的教师同时满足“大于等于55岁”和“小于等于55岁”的边界。

      年龄证据不完整时，不触发年龄结构规则

    - 规则三：职称结构

      当前有效授课教师职称证据完整，并且所有教师职称只包含：

      - 助教；
      - 讲师。

      只要存在未知职称，就不通过该项职称结构规则。

      计算规则：

      - 同一课程命中1项或多项结构规则，均只计1门；
      - 结构核查可以与连续单点、优先核查同时累计；
      - 结构核查字段统计命中结构规则的课程，不只统计主分类为“结构核查”的课程。

      例如，一门课程主分类为优先核查，但同时命中连续单点结构规则，它会同时计入：

      - 优先核查；
      - 连续单点；
      - 结构核查。

  - **数据候选**：触发条件

    课程命中以下任意一项，即成为数据候选：

    1. 课程责任组织无法映射到教学学院；
    2. 有效授课教师证据为空；
    3. 存在教学任务命中异常门禁并从正式指标中排除；
    4. 一名或多名实际授课教师缺少职称证据。

    数据候选具有最高主分类优先级。

    即使课程同时命中：

    - 重点单点；
    - 连续单点；
    - 高集中度；
    - 年龄结构；
    - 职称结构；

    只要存在数据候选原因，其主分类仍显示为“数据候选”，不会计入“优先核查”主分类数量。

- **排序方式：** 优先核查课程数降序 → 结构核查课程数降序 →数据候选课程数降序→ 学院名称升序 。
- **分页：**不分页，全部显示
- **操作功能：** 点击操作栏的 “核查学院”或点击“整行“或点击学院名称”，打开标题为“`{学院名称} · 课程师资情况`”的[课程师资情况](#overview-students)抽屉。**详见  6.1 章节**

- **字段补充说明**

  - **核查类型：**

    含义：

    - 显示课程命中的管理核查分类；
    - 一门课程可以同时显示多个标签。

    可能显示的标签：

    | 标签     | 含义                                                   | 颜色   |
    | -------- | ------------------------------------------------------ | ------ |
    | 优先核查 | 命中重点单点、重点连续单点或重点高集中度规则           | 红色   |
    | 连续单点 | 最近最多3次实际开课中，同一教师至少2次作为唯一授课教师 | 蓝色   |
    | 结构核查 | 命中连续单点、年龄结构或职称结构规则                   | 橙色   |
    | 数据候选 | 课程组织、教师、职称或异常任务证据不足                 | 灰蓝色 |
    | 一般观察 | 未命中上述分类                                         | 绿色   |

    计算规则：

    - 如果主分类是优先核查，显示“优先核查”；
    - 如果命中连续单点正式规则，同时增加“连续单点”；
    - 如果命中任一结构规则，同时增加“结构核查”；
    - 如果主分类是数据候选，显示“数据候选”；
    - 如果以上标签都没有，则显示“一般观察”。

    一门课程可能显示：

    > 优先核查、连续单点、结构核查

    这是因为连续单点既可能形成结构核查，又可能在重点课程和规模条件满足时形成优先核查。



  - **职称证据率：**分母是当前课程实际授课教师去重人数；分子是其中职称字段非空的教师人数

  - **核查原因：**

    含义：

    - 显示课程为什么进入当前核查分类；
    - 一门课程可以有多条原因。

    可能显示的内容包括：

    - “重点保障课程，本期由1名教师承担X个教学班、覆盖Y人次”；
    - “最近N次实际开课持续由同一教师单点承担”；
    - “重点课程最大主讲教师教学班占比X%、覆盖人次占比Y%，均达到可比组百分位九十阈值”；
    - “同一教师在最近3次实际开课中至少2次作为唯一授课教师”；
    - “授课教师年龄全部大于等于55岁或全部小于等于55岁”；
    - “授课教师职称仅包含助教或讲师”；
    - “课程责任组织未能映射到教学学院”；
    - “有效授课教师证据为空”；
    - “X条教学任务命中已登记异常并从正式指标排除”；
    - “X名实际授课教师职称证据缺失”。

    计算规则：

    - 系统逐项判断优先核查、结构核查和数据候选规则；

    - 所有命中的原因均加入该课程的原因列表；

    - 多个原因不会互相覆盖；

    - 如果没有原因，页面兜底显示“一般观察”。



    相关规则条件说明：

    - 可评估课程

      ```text
      可评估
      = 有效教学班数 > 0
        AND 实际授课教师数 > 0
        AND 课程责任学院映射成功
        AND 被异常门禁排除的教学任务数 = 0
      ```

    - 被异常门禁排除的教学任务

      同一教师在同一学期关联的教学任务数量超过200条

    - 重点保障课程：

      满足任一条件：

      - 必修课程；
      - 课程名称、课程性质或课程类别包含以下任一关键词：

      ```text
      必修、主干、核心、基础、思想、政治、形势与政策、
      体育、数学、英语
      ```

    - 规模门槛和规模档

      达到核查规模 = 教学班数 ≥ 4 OR 学生人次 ≥ 100

      | 规模档   | 学生人次范围                |
      | -------- | --------------------------- |
      | 小规模档 | 少于60人次                  |
      | 中规模档 | 大于等于60人次且少于200人次 |
      | 大规模档 | 大于等于200人次             |

    - 高影响单点

      高影响单点  = 重点保障课程   AND 达到核查规模  AND 实际授课教师数 = 1

    - 连续单点

      对不晚于当前分析学期的历史教学任务按学期倒序，取最近最多 3 次具有有效教师团队的实际开课：

      ```text
      连续单点
      = 存在同一 teacher_id，
        在最近最多 3 次实际开课中
        至少 2 次是该课程唯一授课教师
      ```



    - 当期主讲任务集中度

      高集中同时满足：

      - 课程可评估；

      - 可比组样本量≥10；

        所选统计学期内，全校符合相同“重点课程属性”和相同“学生规模档”，并且具备基本可比较条件的课程数量

      - 教学班数≥4；

      - 学生人次≥100；

      - 最大主讲教学班占比≥组内教学班占比 P90；

      - 最大主讲学生人次占比≥组内学生人次占比 P90。

    - 结构规则

      ```text
      结构核查
      = 课程可评估
        AND (
             连续单点
             OR 全体教师年龄同处 55 岁阈值一侧
             OR 全体教师职称已知且仅包含助教/讲师
        )
      ```

      结构核查可以与优先核查、连续单点和数据候选标签并存。



    - 数据候选原因

      命中任一项即记录数据候选原因：

      - 课程责任组织未能映射到教学学院；

      - 有效授课教师证据为空；

      - 有教学任务被异常门禁排除；

      - 存在实际授课教师职称证据缺失。



- **排序方式：** 主分类优先级（优先核查 → 结构核查 → 数据候选 → 一般观察） → 重点课程在前 →  学生人次降序→ 课程名称升序。

- **分页：**默认每页 20 条，显示查询记录总数，可切换为 10、20、50、100 条；

- **操作功能：**

  - 点击操作栏的 “详情”，打开标题为“`{课程名称} 详情`”的[课程详情](#overview-students)抽屉。**详见   6.2章节****

- **展示约束：**如果没有查询到数据，显示 ”当前条件下没有课程”。

### 6.2.1 为什么进入当前队列

展示内容包括：

- **核查类型标签：**分为 优先核查、结构核查、数据候选、一般观察

  - 分类标签和颜色

    | 分类     | 触发优先级 | 标签颜色 | 规则说明                                         |
    | -------- | ---------- | -------- | ------------------------------------------------ |
    | 数据候选 | 最高       | 蓝灰色   | 有数据候选问题，归为“数据候选”；                 |
    | 优先核查 | 次高       | 红色     | 命中重点单点、连续单点或高集中度，归为“优先核查” |
    | 结构核查 | 次之       | 橙色     | 命中结构异常规则，归为“结构核查”                 |
    | 一般观察 | 最低       | 绿色     | 其他情况归为“一般观察”。                         |

    **补充说明：**点击“教师结构异常课程数”进入课程详情后，课程虽然命中了结构规则，但最终分类可能仍显示为“优先核查”或“数据候选”，因为系统按主分类优先级进行显示：

  - **分类说明**

    - **数据候选：**“数据候选”不是单独的一条结构异常规则，而是“当前证据不足，暂不形成正式保障判断”的数据质量分类，课程满足以下任一条件时，标记为数据候选：

      1. **课程责任组织无法映射到教学学院；**

         1. 触发条件：

            - 课程所属部门或责任组织为空；
            - 或者课程所属部门无法在学院基础数据中找到对应学院。

         2. 显示原因：

            > 课程责任组织未能映射到教学学院

      2. **没有有效授课教师证据；**

         1. 触发条件：

            - 当前学期存在课程教学任务；
            - 但从主讲教师和联合授课教师字段中，无法识别出有效教师工号；
            - 去重后的实际授课教师数为 0。

         2. 显示原因：

            > 有效授课教师证据为空

      3. **存在被异常数据质量规则排除的教学任务；**

         1. 触发条件：

            - 当前学期该课程存在教学任务；
            - 教学任务的主讲教师命中已登记的数据质量问题；
            - 问题状态仍为“待处理”或“复核中”；
            - 问题严重度为高或严重；
            - 该教学任务因此被排除出正式课程分析。

         2. 显示原因：

            > X 条教学任务命中已登记异常并从正式指标排除

            其中“X”是被排除的教学任务数量。



      4. **存在实际授课教师职称证据缺失。**

         1. 触发条件：

            - 课程存在有效授课教师；
            - 其中至少一名教师的职称为空或无法识别。

         2. 显示原因：

            > X 名实际授课教师职称证据缺失

            其中“X”是缺少职称证据的教师人数。

      只要命中一项，课程就会标记为数据候选；命中多项时，所有原因会同时保留并显示。



    - **一般观察：**只有前面 3 类都没有命中时，才归为“一般观察”；具体包括以下情况：

      1. **普通可评估课程**

         同时满足：

         - 有有效教学任务；
         - 能识别实际授课教师；
         - 课程责任学院可以映射；
         - 没有异常教学任务被排除；
         - 未命中重点单教师、连续单点、高集中度或结构异常规则。

         这是最典型的一般观察课程。

      2. **单教师授课，但没有达到优先核查条件**

         课程只有 1 名授课教师，但至少有一项不满足：

         - 不是重点课程；
         - 教学班数少于 4 个且学生人次少于 100；
         - 未达到当前规模核查条件。

         也就是说，单教师事实本身不会自动成为优先核查课程。

      3. **存在连续单点事实，但没有达到优先核查条件**

         课程在最近最多 3 次实际开课中，确实存在同一教师至少 2 次作为唯一授课教师的情况，但：

         - 课程不是重点课程，或；
         - 教学班数少于 4 个且学生人次少于 100。

         此时只保留为一般观察，不进入优先核查。

      4. **主讲任务较集中，但没有达到高集中度核查条件**

         可能存在某名主讲教师承担较多教学班或覆盖较多学生，但未同时满足以下条件：

         - 课程是重点课程；
         - 达到教学班数不少于 4 个或学生人次不少于 100；
         - 可比课程组样本数不少于 10 门；
         - 教学班占比达到同组百分位九十阈值；
         - 学生人次占比也达到同组百分位九十阈值。

         这种情况不会归为优先核查。

      5. **教师年龄结构正常或未形成异常结论**

         包括：

         - 授课教师年龄分布没有全部处于 55 岁及以上；
         - 也没有全部处于 55 岁及以下；
         - 年龄证据不完整，无法形成年龄结构异常判断。

         年龄证据不足本身不会自动归为数据候选，也不会自动归为结构异常。

      6. **授课教师职称结构未命中异常规则**

         包括：

         - 授课教师职称不只是“助教”和“讲师”；
         - 教师职称结构中包含其他职称；
         - 职称部分缺失，但未因此形成可用的结构异常结论。

         如果存在职称缺失，可能同时触发“数据候选”；如果没有触发数据候选，才可能继续归入一般观察。

      7. **没有任何可显示的核查原因**

         当前实现中，如果课程不属于数据候选、优先核查或结构核查，系统将：

         - 分类标签显示为“一般观察”；
         - 原因列表为空；
         - 在课程队列中如果需要兜底，会显示“常规观察”；
         - 建议核实事项显示：

         > 保留常规观察，无需作为本期优先管理事项。



- **标题：“为什么进入当前队列”；**

- **全部核查原因：**具体原因模板与触发条件如下

  - **模板一：重点课程单教师承担**

    1. 显示模板：

       > 重点保障课程，本期由 1 名教师承担 X 个教学班、覆盖 Y 人次

    2. 触发条件：

       - 课程被识别为重点课程；
       - 当前课程达到规模条件：
         - 教学班数不少于 4 个，或
         - 学生人次不少于 100；
       - 当前有效授课教师数等于 1。

       “单教师授课”本身不单独触发该原因，必须同时满足重点课程和规模条件。

  - **模板二：连续单点承担**

    1. 显示模板：

       > 最近 N 次实际开课持续由同一教师单点承担

    2. 触发条件：

       - 最近最多 3 次有真实教学任务的开课记录中；
       - 同一教师至少 2 次作为该课程唯一授课教师；
       - 同时属于重点课程；
       - 同时达到教学班数不少于 4 个或学生人次不少于 100 的规模条件。

       这里的“最近 N 次”按实际存在教学任务的学期观察，不要求自然学期连续。

  - **模板三：重点课程高集中度**

    1. 显示模板：

       > 重点课程最大主讲教师教学班占比 A%、覆盖人次占比 B%，均达到可比组百分位九十阈值

    2. 触发条件：

       - 课程属于重点课程；
       - 达到规模条件；
       - 可评估；
       - 可比组样本不少于 10 门课程；
       - 最大主讲教师教学班占比达到同类课程、同规模组的百分位九十阈值；
       - 最大主讲教师覆盖学生人次占比也达到同一可比组的百分位九十阈值。

  - **模板四：连续单点结构原因**

    1. 显示模板：

       > 同一教师在最近 3 次实际开课中至少 2 次作为唯一授课教师

    2. 触发条件：

       - 课程满足结构核查的基本条件；
       - 最近最多 3 次实际开课中，同一教师至少 2 次为唯一授课教师。

  - **模板五：年龄结构原因**

    1. 显示模板：

       > 授课教师年龄全部大于等于 55 岁，或者全部小于等于 55 岁

    2. 触发条件：

       - 每名当前有效授课教师都有可用年龄证据；
       - 所有授课教师均处于 55 岁及以上，或均处于 55 岁及以下；
       - 年龄证据不完整时，不触发该条正式结构判断。

  - **模板六：初级职称结构原因**

    1. 显示模板：

       > 授课教师中，职称仅包含助教或讲师

    2. 触发条件：

       - 当前有效授课教师均有职称证据；
       - 所有已知职称只能归入“助教”或“讲师”；
       - 不能把职称缺失人员直接当作助教或讲师。

  - **模板七：数据候选原因**

    数据候选原因可能包括：

    - 课程责任组织未能映射到教学学院；
    - 有效授课教师证据为空；
    - X 条教学任务命中已登记异常并从正式指标排除；
    - X 名实际授课教师职称证据缺失。

    这些原因可以和结构原因同时出现，但课程最终分类优先显示“数据候选”。



- **“建议核实事项”：**

  - 显示在“为什么进入当前队列”区域右侧；
  - 标题固定为“建议核实事项”；
  - 每门课程只显示一条主分类建议；
  - 使用普通文字段落显示，根据核查类型标签显示对应内容

  | 核查类型标签 | 建议核实事项显示内容                                         |
  | ------------ | ------------------------------------------------------------ |
  | 优先核查     | 核实下期是否继续开设、是否已有共同授课或备份安排，以及教学任务拆分是否准确 |
  | 结构核查     | 核实正式课程团队、课程负责人及梯队安排；当前结果不评价现有教师能力 |
  | 数据候选     | 先核实课程责任组织、教师映射、职称或异常任务；数据确认前不形成保障结论 |
  | 一般观察     | 保留常规观察，无需作为本期优先管理事项                       |



### 6.2.2 KPI指标数据看板

- **数据看板KPI**

  | 卡片         | 值与公式                                               | 副文案                 | Tooltip                                 |
  | ------------ | ------------------------------------------------------ | ---------------------- | --------------------------------------- |
  | 实际授课教师 | 当前有效教学任务主讲+联合教师去重数；单位：人；如 30人 | 主讲与联合教师去重     | 来自当前学期有效教学任务                |
  | 教学班       | 当前有效教学任务条数；单位：个；如30个                 | 当前有效教学任务       | 被数据质量门禁排除的教学班不进入此数    |
  | 覆盖学生人次 | 有效教学任务选课人次合计；单位：人次；如300人次        | 各教学班选课人次之和   | 联合授课不拆分教师贡献比例              |
  | 职称证据     | `(教师数-未知职称人数)/教师数 人`                      | 仅用于课程团队结构核实 | 职称缺失时不形成正式结构结论            |
  | 异常任务排除 | 原始任务数-有效任务数；单位：条；如30条                | 不进入正式指标         | 命中已登记高/严重数据质量问题的教学任务 |

  异常任务排除数大于 0 时使用红色，否则使用普通色

- **KPI指标说明**

  - **实际授课教师**
    - 计算规则：
      - 统计当前学期该课程有效教学任务中的主讲教师和联合授课教师；
      - 合并两类教师工号后去重；
      - 被异常数据质量规则排除的教师不计入。
    - 条件范围：
      - 当前选择学期；
      - 当前身份可查看的课程；
      - 当前课程的有效教学任务；
      - 仅统计能从主讲或联合授课字段识别出的教师。

  - **教学班**

    - 计算规则：
      - 统计当前学期该课程的有效教学任务数量；
      - 主讲教师命中异常问题的任务会被排除；
      - 当前接口按有效教学任务记录数量统计。
    - 条件范围：
      - 当前选择学期；
      - 当前课程；
      - 当前身份授权范围；
      - 通过当前数据质量门禁的教学任务[有效教学任务]。

  - **覆盖学生人次**

    - 计算规则：
      - 将当前课程所有有效教学任务的选课人数直接相加；
      - 空值按 0 处理；
      - 同一学生修读多个教学班时可以重复计入；
      - 联合授课不按教师人数拆分或平均分配。
    - 条件范围：
      - 当前选择学期；
      - 当前课程；
      - 当前有效教学任务；
      - 已排除异常主讲教师任务。

  - **职称证据**
    - 计算规则：
      - 分子：当前实际授课教师中，职称字段非空的教师人数；
      - 分母：实际授课教师总人数；
      - 显示格式为“已知职称人数/实际授课教师人数”。
    - 条件范围：
      - 当前选择学期；
      - 当前课程有效授课教师集合；
      - 职称为空的教师进入分母，但不进入已知职称人数；
      - 职称证据缺失不自动推断为低职称。



  - **异常任务排除**

    - 计算规则：
      - 当前学期该课程原始教学任务数；
      - 减去因主讲教师命中已登记高严重度或严重度数据质量问题而排除的任务数；
      - 得到被排除的异常任务数量。
    - 颜色：排除数量大于 0 时使用红色；
    - 条件范围：
      - 当前选择学期；
      - 当前课程；
      - 已登记且状态仍为“待处理”或“复核中”的高严重度、严重度教师数据质量问题；
        - 同一教师在同一学期关联的教学任务数量超过200条
      - 被排除任务仍可能在教师教学经历页面中作为原始核查记录显示，但不进入正式课程指标。



### 6.2.3 跨学期供给连续性

- **“连续单点承担”判断**：

  - 在最近最多 3 次实际开课中；
  - 同一教师至少 2 次作为唯一授课教师；
  - 不要求是自然连续的 3 个学期；
  - 没有实际开课记录时，不形成连续性结论。

- **“摘要说明信息**：

  当课程满足连续单点条件时显示：

  > 最近 N 次实际开课持续呈现单点承担

  不满足时显示：

  > 最近 N 次实际开课未形成连续单点承担结论

  其中 N 为实际找到的最近开课次数，最多为 3 次。

- **最近学期开课卡片显示**

  每个最近学期开课单元显示：

  > 学期
  > X 名教师 / Y 个班

  例如：

  > 2025—2026—2
  > 2 名教师 / 4 个班

  显示规则：

  - 最多展示最近 3 次实际开课；
  - 按学期倒序；
  - 每个学期一个小卡片；
  - 学期名称加粗；
  - 区域整体使用浅蓝色背景、浅蓝色边框；
  - 最近学期小卡片使用白色背景。

| F-09 | `senior_title_teaching_rate` | 高职称教师授课占比（教授、副教授） | 3.2 | 教师 × 学期 × 授权范围 |
| F-19 | `young_teacher_teaching_rate` | 青年教师授课占比（35岁以下） | 3.4 | 教师 × 学期 × 授权教学范围 |
| F-01 | `active_teaching_teacher_count` | 实际授课教师数 | 3.0 | 教师 × 学期 × 授权范围 |
| F-20 | 页面功能 | 学院课程总数 | 现行页面口径 | 学院 × 学期 |

后端页面卡片规则版本：

- 课程核查分类：`FACULTY-ASSURANCE-2026.09.3`；
- 首页 KPI：`FACULTY-KPI-2026.09.16`。

### 7.2 支撑指标词典

| 名称 | 计算逻辑 | 管理用途 | 适用边界 |
| --- | --- | --- | --- |
| 实际授课教师数 | 有效教学任务主讲与联合教师去重 | 观察真实参与规模 | 不代表正式在职教师总数 |
| 可评估课程数 | 班数>0、教师数>0、责任学院可映射、无异常排除任务 | 明确基础事实可用范围 | 不表示保障正常 |
| 单一教师承担课程数 | 当前课程教师数=1 | 组合规则基础事实 | 不单独触发风险 |
| 当期任务集中度 | 最大主讲教师班次占比和学生人次占比 | 识别主讲任务集中 | 不等同工作量 |
| 优先核查课程数 | 数据候选之外，命中高影响单点、重点连续单点或重点高集中 | 形成本期核查队列 | 原型重点和规模阈值待学校确认 |
| 职称证据完整率 | 职称非空授课教师÷授课教师 | 判断结构结论可用性 | 缺失不等于低职称 |
| 数据候选课程数 | 组织、教师、职称或异常任务证据不足 | 分流数据治理 | 不形成正式风险 |
| 异常任务排除数 | 被质量门禁排除的教学任务数 | 解释统计差异 | 原始任务仍可在核查详情查看 |
| 连续单点承担课程数 | 最近最多 3 次实际开课中，同一教师至少 2 次唯一承担 | 识别供给依赖 | 不是自然连续 3 学期 |
| 学院课程总数 | 可评估课程数+数据候选课程数 | 展示进入分析或治理范围的规模 | 两类当前可能重叠，不是去重开课课程总数 |
| 教学班占比 | 教师相关教学班数÷课程有效教学班数 | 说明团队承担面 | 联合教师可能重复覆盖同一班 |
| 学院优先核查率 | 优先核查课程数÷可评估课程数×100% | 学院聚合参考 | 分母 0 应显示“—”，当前页面显示 0% |

### 7.3 跨页面同源要求

1. 首页、KPI 下钻、课程队列和课程详情必须复用同一 `_faculty_analysis` 课程事实；
2. 同一学期、学院、课程在各页面的责任学院、教师数、教学班数、人次、排除数和分类必须一致；
3. 首页连续单点教师数必须等于明细教师 ID 去重数；
4. 教师结构异常课程数必须等于结构明细课程 ID 去重数；
5. 高职称和青年比例分子、分母、覆盖率必须与下钻学院表和名单对账；
6. 课程详情实际团队人数必须等于成员去重数；
7. 课程历史摘要和历史开课表必须使用同一异常门禁；
8. 教师经历可以展示原始核查任务，但必须提示为什么它与正式 KPI 合计不同；
9. 页面、指标目录、公共确认书和接口返回的名称、公式、来源、边界和版本必须同步。

### 7.4 排序一致性

| 页面 | 默认排序 |
| --- | --- |
| 学院概览 | 优先核查数↓、结构核查数↓、数据候选数↓、学院名↑ |
| 课程队列 | 主分类优先级、重点课程在前、学生人次↓、课程名↑ |
| 授课教师名单 | 教学班数↓、授课课程数↓、姓名↑、工号↑ |
| 教师结构异常课程 | 教学班数↓、课程号↑ |
| 连续单点教师—课程 | 教学班数↓、部门↑、姓名↑、课程号↑ |
| 高职称学院分布 | 占比↓、学院名↑ |
| 青年教师学院分布 | 可计算值在前、占比↓、学院名↑ |
| 高职称/青年教师名单 | 部门↑、姓名↑、工号↑ |
| 课程历史 | 学期↓ |
| 教师当前任务 | 课程名↑、教学班 ID↑ |
| 教师历史 | 学期↓、课程名↑ |

同值必须有稳定末级键，分页请求重复执行时不得换序。

### 7.5 口径不得推出的结论

- 高职称比例高不等于教学质量高；
- 青年教师比例高或低不等于年龄结构合理或不合理；
- 结构异常课程不等于课程不合格；
- 连续单点教师不等于教师有风险；
- 单教师课程不等于课程一定断供；
- 历史承担不等于未来具备资格或已有备份；
- 学生人次和教学班数不等于正式教师工作量；
- 数据缺失不等于 0、正常或低风险。

### 8.2 人员字段来源优先级

| 字段 | 优先级 |
| --- | --- |
| 部门 | 人员学期快照 → 正式在职人员主数据 → `source=real` 教师维表 → 授权课程学院/“待映射部门” |
| 职称 | 人员学期快照 → 正式在职人员主数据 → `source=real` 教师维表 |
| 学历 | 人员学期快照或正式在职人员主数据；没有真实字段时为空 |
| 人员类别 | 人员学期快照 → 正式人员 `staff_type` |
| 青年标识 | 快照出生日期按当前日期计算 → 快照受控 `is_under_35` |
| 教师姓名 | 真实教师维表；缺失时显示教师 ID |

当前 schema/迁移对人员快照的 `education` 采用兼容读取，字段不存在时返回空值；不得从模拟画像补齐。

人员状态和人员类型必须使用以下现行受控值：

- 人员快照 `employment_status`：在岗、active、employed、正常；
- V2 人员后备 `status`：在职、在岗、employed、正常、active；
- V2 人员后备必须为 `source=real`，并排除 `staff_type` 为 `mentor`、`class_adviser`、`lesson_teacher` 的关系补录占位人员；

- 指标编号与技术主键；
- 规则版本；
- 请求学期和实际数据学期；
- 当前工作身份与范围指纹；

### 8.5 未接入或不充分的数据

| 数据 | 当前处理 | 正式要求 |
| --- | --- | --- |
| 正式课程团队和成员任命 | 当前用实际授课团队代理 | 接入课程—教师—角色—有效期关系后与实际任务并列展示 |
| 课程负责人 | 不输出覆盖率 | 未接入时显示“未接入”，不显示 0 |
| 备份教师资格 | 不作正式判断 | 需要资格、历史承担或学校认定证据 |
| 未来开课计划 | 历史记录不能替代 | 接入计划后才能判断未来供给 |

| 联合授课贡献比例 | 不拆分 | 接入正式分工或工作量数据前只展示覆盖事实 |

2026 年 9 月 20 日当前本地数据基线中，人员学期快照无可用记录，因此实际页面会出现人员覆盖部分就绪、青年年龄证据待接入等状态。该事实只描述当前开发数据，不代表生产系统永远未接入。

### 8.6 隐私与适用边界

- 人事敏感字段按最小必要原则展示；
- 不向前端返回出生日期或精确年龄；
- 不在课程团队页展示学生名单；
- 学院只能查看本院责任课程所需的外院教师证据；
- 导出当前未实现；后续开放时必须单独授权、记录审计并应用相同范围；
- 师资指标只能用于教学保障核查、课程团队建设和数据治理；
- 所有阈值属于当前原型核查规则，不替代学校制度、人事政策或正式评价办法。

## 9. 异常、空态和验收规则

### 9.1 加载、空态与错误态

接口成功响应统一为 `{code: 0, msg: "ok", data: {...}}`。权限、对象和参数错误必须保留明确 HTTP/业务状态，前端不得一律转换成普通空数组。

| 场景 | 页面要求 | 指标/证据要求 |
| --- | --- | --- |
| 首页首次加载 | 结构化骨架，不闪现 0 或上一身份数据 | 响应成功前不生成管理结论 |
| 首页首次失败 | “师资保障数据加载失败”+错误摘要+重试 | 不显示空 KPI 冒充 0 |
| 已有首页数据刷新失败 | 保留旧结果并明确“上次成功数据” | 标记旧学期/范围/时间，详情不得误绑定新条件 |
| KPI 下钻首次加载 | 骨架和“正在汇总指标、组织分布与明细证据…” | 不先显示旧指标 |
| KPI 下钻失败 | 错误摘要和重新加载 | 重试使用当前条件 |
| 课程队列无结果 | “当前条件下没有课程” | 区分无课程与筛选无命中 |
| 首页无优先课程 | “当前筛选下没有需优先核查的课程” | 不等于全校没有师资问题 |
| 学院无核查课程 | “当前筛选下，本院没有需核查课程” | 不等于数据完整或保障正常 |
| 课程详情失败 | “课程证据加载失败”+重试 | 保留课程 ID 和学期 |
| 教师当前无任务 | “当前学期暂无教学任务” | KPI 应为可解释 0 或空，不回退其他学期 |
| 教师无历史 | “暂无历史记录” | 不推定没有教学能力 |
| 人员快照未接入 | 显示“—/待接入/部分就绪” | 不读取模拟年龄、学历或当前人数回填历史 |
| 高职称覆盖不足 | 卡片“—”，下钻保留名单和治理证据 | 不输出正式比例 |
| 青年年龄证据全缺失 | 卡片“-”，学院表显示授课教师和 0%覆盖率 | 青年人数和占比显示“—” |
| 分母为 0 | 显示“—” | 不触发比例规则 |
| 无权限 | 403 或拒绝页 | 不以普通空态掩盖 |
| 对象不存在 | 404 | 不展示缓存对象 |
| 身份切换 | 清空首页、抽屉和缓存并重载 | 旧身份数据不得残留 |
| 快速连续切换 | 只接受最后一次请求 | 旧响应不得覆盖新学期/对象 |

现行服务端重点错误语义：

- 未知 KPI：404，“未知的师资保障指标”；
- 越权学院、课程或教师：403；没有任何可用学院范围时同样返回 403；
- 学院不存在：404；
- 课程存在但所选学期没有教学任务：404，“当前学期暂无该课程教学任务”；
- 首页或列表在授权范围内确实无业务数据：成功响应，计数为 0、数组为空；不能与 403/404 混为一类。

### 9.2 参数与数据校验

- `semester` 必须属于后端可用学期；
- `metric_key` 只接受 5 项白名单；
- `review_type` 只接受 5 项核查类型；
- `college` 必须存在且属于当前授权范围；
- `course_id`、`teacher_id` 必须使用稳定 ID；
- 页码≥1，页长仅允许 10、20、50、100，并受服务端 100 上限约束；
- 教学班数、学生人次、容量、学时、教师人数、分子和分母不得为负；
- 比例必须能由明细分子分母复算；
- 职称、人员状态、人员类型和数据问题状态使用受控字典；
- 未知课程组织、教师、职称或年龄进入数据候选/治理清单，保留原始值和来源；
- 联合教师必须拆分后精确匹配，禁止使用不带边界的字符串包含匹配。

### 9.7 权限与安全验收

至少使用校领导/教务处、两个不同学院、无范围身份和系统管理员进行以下回归：

1. 校级角色和系统管理员只有在明确全校业务授权时查看全校；
2. 两个学院分别只能查看本院责任课程队列和课程团队；
3. 学院 A 手工请求学院 B 的 `college` 返回 403；
4. 学院 A 手工请求学院 B 责任课程返回 403；
5. 外院教师承担学院 A 课程时，学院 A 携带该课程可查看必要经历，但不能查看该教师其他学院课程；
6. 修改 `teacherCourse` 为无授课关系课程不能放行；
7. 无范围身份不回退全校；
8. 切换身份后旧首页、KPI、课程、教师和表格偏好范围不泄露；
9. 旧 URL、直接 API、未来导出和缓存读取都执行相同服务端范围校验；
10. 审计记录用户、当前身份、范围、学期、对象、接口、结果、规则版本和数据批次。

### 9.8 性能与可用性验收

- 首页首屏不请求完整课程队列和所有 KPI 明细；
- 学院行 250 ms 预取失败不影响操作；
- 后端 180 秒缓存不会跨身份、批次或规则版本错误复用；
- 快速切换学期、学院、课程、教师、筛选和页码时只接受最后一次响应；
- 课程列表使用服务端分页；前端全量分页明确最大返回上限；
- 1366 × 768 及常用大屏下抽屉可滚动，关键按钮不被遮挡；
- 非模态抽屉不能造成焦点丢失，键盘可关闭并回到触发点；
- 长课程名、原因和证据有完整 Tooltip；
- 状态不能只靠颜色表达；
- 页面没有导出时不显示无效导出入口。
