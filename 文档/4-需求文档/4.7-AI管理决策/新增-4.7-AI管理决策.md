# 4.7 AI管理决策

状态：现行需求及实施边界。修订日期：2026-10-07。专家问策、AI简报和后台处理服务的V3.3前后端已实现；首期当前管理员试跑／正式／撤回／修正、指标登记及关闭浏览器后的真实周期已验证。模型未配置，全部岗位和故障场景仍未完整验收。契约、开发分解及证据见[专家方案导航](expert-design-v3-20260916/README.md)。

## 1. 重新定位与业务目标

**AI管理决策为已授权教务管理人员提供研究具体管理问题的工作区：明确问题和范围，读取真实数据，按适用规则核验，说明能够确定的结论及需要判断的部分，保留可复看的依据。**

AI管理决策保留两个业务入口：AI简报、专家问策。AI简报帮助用户先发现值得关注的问题；专家问策通过会话研究具体问题，保存原问题、实际范围、各轮结果、所用规则和依据。专家帮助用户分析；Skill定义可执行业务任务；MCP提供受控工具。问策页面统一使用“会话”，内部复用已有研究容器。

业务价值应落在三个方面：

1. 将分散在培养方案、成绩、认定或政策中的信息，组织成能回答具体问题的对照与核验。
2. 让用户知道判断依据哪些事实和规则，有哪些未知、冲突及适用限制。
3. 补充有效资料或改变范围后，能回到原问题重新核验，并保留前后结果。

AI的必要作用是理解问法、确定任务、做必要澄清、解释已核事实和讨论有条件的做法。数字、正式条件和权限由确定性程序控制。固定筛选和表格能够解决的查询直接提供；只有事实表格时标明“事实分析”。真实模型接入并通过解释验收后，才算完成相应AI专家能力。

## 2. 需求必要性与取舍

每个新任务先回答：谁在什么业务时点提出什么问题，现有教学页面为什么不能直接回答，需要什么数据或规则，输出如何帮助下一步工作。没有明确答案的任务保留为候选。

| 编号 | 需求 | 必要性与决定 | 验收结果 |
| --- | --- | --- | --- |
| N01 | 从会话进入问策 | 必要。＋选择专家、提出问题；模型未就绪时提供明确的固定分析入口 | 用户不用填写taskId、Skill名或MCP名，就能开始适用任务 |
| N02 | 必要范围和适用条件 | 必要。对象、学期、年度或学院按任务出现；展示条数是次级设置 | 输入与结果范围一致；改变下一轮输入不改变旧轮结果 |
| N03 | 真实数据与确定性核验 | 必要。复用可靠计算；缺来源或规则时限定结果 | 可独立复算；空值、分母为0、记录不完整不伪装为0或已满足 |
| N04 | 主要判断和解释 | 必要。先主要结果，再依据、未知和边界 | 用户能复述本次回答了什么、尚不能决定什么 |
| N05 | 来源和证据查看 | 必要。结果附近直接查看口径和实际保存明细 | 结果与依据对应；查询时间与源数据更新时间分别展示 |
| N06 | 保存、复看和续做 | 必要。自动保存已完成轮次；新分析独立成轮 | 返回后读到当时结果；失败、取消有真实状态，不覆盖旧结果 |
| N07 | 待明确事项与原问题重核 | 存在影响结果的缺项时必要 | 保存引用只表示资料已提供；重核满足对应条件后才明确该事项 |
| N08 | 当前数据或已有结果比较 | 有明确目的才提供。先检查群体、规则和口径 | 有两份实际可比结果才算变化；不承诺历史批次重建 |
| N09 | 条件性建议 | 对管理研究必要；须有事实、规则和约束 | 说明解决什么、必要条件与仍需核查内容；低通过率不直接推导责任或因果 |
| N10 | AI简报 | 必要独立入口。专家预设任务按业务周期和数据准备度执行，简报汇总保存结果并支持进入问策 | 每项可查看来源、时间、口径及未知；执行失败与无命中分别显示；进入问策保留原问题与结果引用 |
| N11 | 专家、技能、MCP维护 | 必要后台能力；沿用系统管理三个并列菜单 | 配置、依赖、执行器、测试和发布对应；上传或连接成功不等于业务可用 |
| N12 | 跨专家联合研究 | 具体问题确需多个职责时再增加；当前先单专家复用多技能 | 贡献与上下文明确；不以专家数量代替分析质量 |

### 本轮精简

- 教学总览已能显示的常规数字继续在教学管理分析中阅读，不另建全校指标看板。
- “专家问策”与新版专家团合并，仅保留一个专家业务入口“专家问策”，以会话为主流程。
- AI管理决策同时保留独立“AI简报”菜单，承接现有决策简报；它汇总当前范围的管理关注事项，并与专家问策共用计算和证据。简报可在用户尚未创建会话时使用；会话成果也可按需整理为简报。
- 暂不建设任意SQL或脚本执行、通用流程拖拽、多专家辩论、外部MCP市场、全量自动重算和办理督办。
- 不要求每次研究都加意见、补齐所有资料或生成材料。用户读完有效结果后可以结束使用。
- 保留25个历史场景编码作为索引，按必要性和数据条件选择开发范围。19个Skill种子和70张任务卡是已有资产及分解，不是必须全部发布的数量目标。

### 实际走查发现的定位偏差

2026-10-06，旧简报实际显示“今日需处置”“本周内”“3个工作日内”和建议责任单位，并披露部分Skill使用快照；它与新版五专家研究使用不同职责目录和结果链。旧问策仍围绕四类专题。这构成三套入口和解释并存的问题。

期限、责任单位和优先程度有明确校历、规则或安排来源时可以作参考；仅由模板生成的不得表达成正式处置安排。混合时间的事实分别标明时间和可比性。分组为空、能力未接入或计算失败不能统一写成“无异常”。本次读到了这些输出，没有独立核验旧四类信号的公式与业务批准状态；它们须单独盘点，不能直接继承成五专家结论。

## 3. 五位专家如何支撑业务

稳定编码沿用program、course、transfer、recommendation、graduation。名称和职责可维护；能力准入落实到任务。

| 专家 | 优先回答的必要问题 | 用户应得到什么 | 关键依赖与边界 | 当前能力判断 |
| --- | --- | --- | --- | --- |
| 专业建设 | 两份培养方案有哪些共同基础和差异，哪些值得继续了解？ | 共同课程、双方差异、学分与要求对照、未知及来源 | 真实适用方案；目标支撑、先修和投入须有额外资料 | 支持两份指定方案事实比较；相似度不能推出撤并、保证共开或培养质量 |
| 课程质量建设 | 本学期哪些课程表现值得了解，某门课首修表现如何？ | 分布、首修人次与通过率、未通过次数、未知原因及单课查看 | 学期和开课院系明确；人次与去重人数区分；原因和措施须有材料 | 支持真实聚合和单课事实；未通过次数排序是浏览线索，不能作为教学质量排名 |
| 转专业 | 转入目标方案的要求差异是什么，真实已修成果可认定什么，还需什么？ | 方向明确的要求对照、已确认认定、补修和未知；有依据时展示安排约束 | 目标要求、已修成果、正式认定规则；接收、容量和未来开课分别核实 | 方案集合与历史异动可辅助；完整认定和承接能力仍有资料缺口 |
| 保研／推免 | 当年适用哪些条件，材料已具备哪些，哪些条件待确认？ | 适用条款、条件核验和未知；完整群体和规则具备后才输出相应排名 | 当年校院细则、对象全集、精确成绩及必要非成绩资料 | 当前缺正式规则和材料；不使用通用或上一年度规则生成当年资格结论 |
| 毕业资格审核 | 学生或本届群体有哪些已核条件差额，哪些只是记录或规则未明确？ | 逐条件满足／不满足／未知／不适用、差额与共性问题、来源和规则 | 学生方案绑定、要求、成绩与认定、适用规则及来源覆盖 | 已核到真实绑定；限定条件核验仍须规则和完整性依据。旧进度或状态不能替代核验 |

### 对现有建设的独立判断

1. 专业、课程两个事实任务有真实输入和明确结果，可作第一批研究能力；有数据仍不等于完整管理建议成立。
2. 毕业方向下一步价值较明确。测试库已核到30,992条主方案绑定，涉及897份方案，不能继续以没有绑定作为整体阻塞理由。绑定只解决用哪个方案，要求、成绩覆盖和规则仍分别准入。
3. 转专业与毕业复用要求、认定和学分分配计算；转入方向、目标方案、接收与安排是独立条件，不能复用毕业结论代替。
4. 推免的年度适用性与对象完整性门槛较高。保留职责入口并解释缺口，不开放看似可执行的空任务。
5. 历史预警、师资需求不因五位新专家就直接删除。常规事实留在教学页面；具体跨数据研究问题再决定任务或职责，当前不据此扩建两位专家。

场景、Skill和工具依赖见[02任务与资源组织](expert-design-v3-20260916/02-专家职责与场景发布清单.md#十二修订后的任务与资源组织)。本文调整定位及优先顺序，不另复制资源目录。

## 4. 专家、Skill、MCP和业务数据的分工

| 对象 | 负责 | 用户看见什么 |
| --- | --- | --- |
| 专家 | 已发布职责、人设、适用任务、必要澄清和解释；受模型与能力清单限制 | 名称、能研究什么、支持与缺项、实际分析方式 |
| Skill | 单项任务的输入、前提、步骤、规则依赖、输出和验收 | 业务任务、必要输入和结果；技术依赖在后台维护 |
| MCP工具 | 受控查询、文档读取或计算；权限、契约、超时受服务校验 | 来源、时间和口径；不用手工选工具拼流程 |
| 数据与正式资料 | 真实记录、适用范围、时间、政策与认定依据 | 实际使用资料及版本；缺项靠近受影响结论 |
| 执行服务 | 固定版本、授权、处理器、调用校验、状态和证据保存；后台周期运行由服务配置控制 | 真实执行状态；管理员可检查服务、授权和失败 |
| 业务确认 | 公式含义、规则适用、争议和可发布范围 | 可定位确认依据；模型或职责文字不能批准政策 |

同一计算维护一个权威实现。年度规则符合契约时复用技能；只有独立输入、输出和验收责任时拆新Skill。内部工具可同服务部署，无业务需要不额外部署MCP服务。

指标核验服务于产品、交付和用户对应用指标与三层数据、SQL、结果的验收；AI管理决策消费已明确指标和事实，回答具体问题。两者以指标、口径和证据引用衔接，不合并页面或重复公式。尚无正式指标映射的专家计算标为该任务事实口径，经核验后关联，不能按名称猜测106指标编号。

## 5. 唯一专家入口：专家问策

用户已明确：专家团与专家问策只保留一个业务菜单，名称为“专家问策”。主流程是连续对话；从输入框旁的“＋”选择专家，左侧新建和打开历史会话，右侧阅读本轮输出及数据。专家管理、技能管理、MCP管理继续位于系统管理。

该合并只涉及两个专家入口。AI管理决策的目标二级菜单为“AI简报”和“专家问策”；AI简报继续独立保留。

### 5.1 工作区职责

| 位置 | 呈现及操作 | 交互原则 |
| --- | --- | --- |
| 左侧会话栏 | 新建会话、搜索、按最近活动排列的历史会话；会话名称与最近使用专家 | 点击恢复原消息和保存结果；会话名称来自首个有效问题，可重命名；首期不建设文件夹、标签体系或共享权限平台 |
| 中间对话区 | 用户问题、专家回复、必要条件确认、真实执行状态；底部输入框、＋、当前专家和发送／停止 | 专家名称在每条回复中明确；主要回答直接可读；用户在同一会话追问，无须切换任务页面 |
| 右侧结果区 | 当前所选轮次的结果、数据、依据；专家、实际对象／时间范围和状态 | 摘要与明细引用同一保存结果；点击消息的“查看结果”切换右侧，始终标明正在看哪一轮 |

界面使用熟悉的会话、消息和结果操作方式；业务数据、规则与权限要求由本平台落实。默认不再先进入全屏专家卡片或长期范围表单。专家职责目录放在＋选择面板，职责维护仍在后台。

桌面宽度足够时显示三栏；结果区可收起和调整宽度。进入本工作区时原系统导航可折叠，避免导航与会话栏占满左侧。窄窗口优先保留对话，历史和结果通过按钮切换为面板；不能强行压缩三栏表格。选择旧消息的结果后保留消息阅读位置与未发送输入。

### 5.2 ＋选择专家

点击＋ → 选择专家 → 面板显示五位业务专家的名称、简短职责、可用或缺项状态 → 选择后在输入框上方显示当前专家。

- 选专家仅设置下一次发送的处理者，不调用Skill、不取数，也不创建结果。
- 一次发送由一位专家处理。可在同一会话切换专家，首期不提供多选专家、联合编排或并行辩论。
- 没有选择专家时仍可写问题，但发送前须选择；首期不默认以通用专家接收，也不自动猜选专家。
- 专家不可用时在选择面板说明原因；选择职责介绍可以查看，未准入能力不执行。
- 同一专家的可用事项以问题示例或轻量任务卡呈现。用户不选择Skill或MCP。
- 切换专家只影响后续消息。原消息、结果、规则版本和证据不改变。
- 切换后清除不适用于新专家的任务和对象条件；不静默把课程筛选当学生归属学院、把基线方案当转入目标。必要共同范围是否沿用在发送前明示。
- 本轮执行中锁定该轮专家和范围。停止或结束后才可以在该会话发送下一轮；用户可切其他会话阅读，原执行仍属于原会话。

### 5.3 历史会话与新建

新建先打开空白会话，显示简短引导与输入框；选择专家后展示其适用问题。未发送前不创建一条空历史。首个有效请求被服务端接受后生成会话，消息和实际状态保存。

历史列表优先显示名称、最近活动时间和必要状态，专家名称作为辅助信息。同名会话能由时间区分。超过近期列表的会话须可分页及搜索，不以当前100条列表作为全部历史。

打开会话恢复已保存消息和相应结果，不重新查询学校库来填充旧数字。默认选中最近有效结果；如果最后一轮失败或需要补条件，说明右侧仍是第几轮已保存结果。点击任一有结果消息可查看当时的数据；回到最新结果有明确入口。

重命名与归档可作为会话维护；归档可恢复，不代表问题已经解决。首期不提供永久删除、复杂分类、共享会话或审批流。新建会话不自动带入其他会话的学生、规则、附件或结果；引用其他结果须有明确目的并重新鉴权。

### 5.4 AI简报：发现问题与进入问策

AI简报帮助教务处、学院先发现有依据、值得进一步了解的教学事项，再进入专家问策。来源是专家预设任务的实际保存结果。学校采集与ETL沿用既有流程；本模块只消费数据。普通阅读和刷新不触发重算，授权管理员可以手动生成或补跑。首期不增加督办、审批或消息推送。

业务闭环：明确管理问题 → 固定业务期间及授权范围 → 检查数据 → 执行已发布任务 → 保存可核事实 → 呈现观察事项及选入理由 → 查看依据或继续问策 → 必要时主动更新。这个闭环以帮助用户了解问题为终点，不把形成简报等同于学校问题已经解决。

| 内容 | 必要信息与操作 |
| --- | --- |
| 头部 | 学期、开课院系范围、最近结果时间、正常／更新失败／待生成状态；数据日期未知就说明；历史和刷新显示 |
| 观察事项 | 课程、为什么被选入、首修通过率与参照水平、首修人次、首修未通过人次；数字和单位就近显示 |
| 核对提示 | 可核记录数、具体缺项／重复／冲突，影响哪些判断；来源整体覆盖未知时始终说明已接入记录范围 |
| 条目操作 | 查看依据、继续问策；有权管理员另有重新生成入口，普通用户不维护后台参数 |
| 详情 | 原字段、口径、结果引用、查询／数据／生成时间、版本和实际证据；技术信息按需展开 |

个人会话不自动成为公共简报来源。旧四类信号逐项核准后决定保留，不直接当成新版五专家结果。模型只解释保存且获准的事实，数字、观察条件、排序由确定性程序控制。未配置模型或解释失败时显示真实事实摘要及解释缺口，不能伪造专家研判。

#### 5.4.1 首个业务问题及指标口径

首期C-BRIEF-01定为“所选学期、本开课院系范围内，哪些已接入课程的首修表现值得进一步了解，涉及多大首修人次规模，还有哪些数据无法核实？”归课程专家，复用C-PERFORMANCE、course-performance Skill及education-data的read_course_performance工具，补充任务观察输出并发布验证后的新版本；当前处理器已实现下面的观察计算；真实范围及发布证据见05第8.1节。

| 项目 | 首期明确决定 |
| --- | --- |
| 输入和范围 | 从真实选项选择固定semester_id及全校或一个授权开课院系；不按日期猜学期。course_id留空，展示数量不限制计算或保存证据全集 |
| 原始来源 | edu_analytics_v3.agg_course_pass_stat关联act_course；贴源和加工关系引用已核文档，不按表名猜映射，不伪造106指标编号 |
| 有效集合 | 课程×学期唯一、first_attempts为正整数、first_pass为非负整数且不大于first_attempts，且实际加工依据证明可采用同一首修口径。缺项、零分母、重复和冲突保留核对提示，排除于参照计算 |
| 课程事实 | 首修人次N=first_attempts；首修通过人次P=first_pass；首修通过率=P/N；首修未通过人次U=N−P。U是同口径推导的人次，不能替代原库failures或解释为唯一学生人数 |
| 本范围参照 | 同一保存结果、同学期及授权开课院系有效集合的R=ΣP/ΣN。名称为“已接入可核记录的首修通过率参照”，同时显示集合及分母；不宣称全校完整通过率 |
| 观察条件 | U>0且P/N<R；用未四舍五入数值比较。它是本任务的观察方法，不是学校质量标准或106正式预警阈值，不临时发明80%、30人等政策门槛 |
| 呈现顺序 | 满足条件的课程按U降序、实际通过率升序、课程编号排序，首页前5条，可查看全部。名称为“观察事项”，不用教学质量排名或正式处置优先级 |
| 管理用途 | 同时看相对表现与涉及人次，形成向学院进一步了解首修情况的具体问题；仅有这些数据不能判断教学原因、教师责任或建设投入 |
| 例外 | 仅一门有效课程、没有有效分母或未触发条件时分别说明。小样本仍显示实际N，不隐藏分母；未知记录不能写成零，未触发不能写成没有教学问题 |

原库failures可在依据详情保留原值、原口径，不参与上述首修观察排序。跨课程ΣN和ΣU仅为累计人次，不作唯一学生数。学院参照须独立读取本学院范围，不能裁剪全校简报后沿用全校分母。

参照集合还须核对实际rule_version及加工依据。不同版本只有经证据证明首修集合及通过含义一致才可合并；缺版本号不直接判错，但需其他真实加工依据。无法证明一致时保留已支持原字段和待核项，不合并跨口径参照，不自动选择某一组冒充整个范围。

该参照只是同范围观察线索。课程性质、考核方式等可比条件未核实时不作质量评价；来源整体覆盖仍为unknown。低于同范围参照是一项观察条件，不等于新发生异常，也不保证跨课程可比；事实简报的用途是了解和核查，不能按周生成同样内容后声称风险变化。没有权威当前学期标识时只写所选学期。

首修未通过人次U的正式展示还需确认：N/P来自同一首修有效集合、通过状态完整且二元、P为N的子集。仅凭两个整数不能证明N−P均为未通过；实际114加工依据未核实前，差额只能标为待核口径，不进入正式观察排序。旧SQLite聚合脚本可提供核对线索，不能代替114的真实依据。

新推导项归属AI简报指标目录，独立于106教学总览；复用已核指标时保存其真实指标及口径版本引用，不向106目录插入新观察指标。先核现有登记与页面绑定，再使用既有映射Skill产出结构化关系、SQL和验证结果。当前映射服务固定模块的限制须先补齐受控模块选择；未核定的三层关系标为待核，不伪造对应表或通过结论。

#### 5.4.2 预设任务及首次发布

预设任务放在系统管理“专家管理”的专家详情。保存及人工试跑必填名称、稳定编号、业务问题、已发布任务、真实学期与组织范围；服务可带入内置登记，周期、时区及生效窗口先选填。草稿默认不自动运行；只有启用定期执行时，这些运行字段与有效服务授权才必填。Skill、MCP、处理器和版本由任务带出；正式计算在技能中维护，计划不另存一套公式。自动周期可建议每周一08:00、Asia/Shanghai，但维护者须结合实际数据更新情况确认；窗口结束停跑，更换学期须验证新分析条件。

1. 新增／修改后保存草稿，不执行。学期、范围、方法／口径或数据源变化形成新分析条件，必须重试跑；名称、展示数量、周期或预算调整保留相同分析条件的既有结果，只重新检查对应运行条件。旧结果不改。
2. 用当前操作者真实授权试运行，展示候选预览、指标、选入依据及缺项；候选仅供有权维护者查看，不进入组织简报。
3. “启用并生成首期”检查当前分析条件有效试跑、资源、服务状态、后台授权和窗口，登记首次正式后台运行，随后按周期自动运行。提交未成功不得显示已启用；首次取数失败显示真实失败及是否仍在等待下一次执行，不能把候选当正式首期。
4. 当前授权管理员也可“手动生成正式简报”，使用当前分析条件的有效试跑、当次身份与发布范围，重新执行并按5.4.5校验发布；不要求填写自动周期、窗口或取得服务委托授权。内置执行服务仍须实际就绪，不能据手动通过宣称定时执行通过。
5. 正式执行先校验事实，在同一控制库事务中保存结果和发布引用，再独立执行可选AI解释；不要求每个周期人工审批。解释必须引用已保存事实并追加版本，失败不丢失事实、不把事实运行改为失败；全项取数／事实校验失败不发布成功结果。
6. 停用阻止新自动提交，不删除历史；有历史任务仅停用／归档，无历史且未启用任务可删除。改业务范围、方法版本或学期后无适用正式结果时显示待生成，不套用旧范围结果；只改运行周期不清空相同条件的已有事实。

更改运行服务授权不改变计划业务范围。实际可执行范围必须同时满足服务授权和计划范围；配置权不自动带来全校数据权。

#### 5.4.3 运行、更新和故障

后台复用现有专家资源服务，首期单实例串行检查到期任务，调度不依赖浏览器。每次真实执行都重新读取并保存当前结果；暂不建设内容指纹缓存、历史批次重建或多任务批次汇编。学校缺稳定批次标记时保留限定覆盖，有明确加工未完成信号时等待；单表最大更新时间不当成ETL完成证明。

同一次触发去重，同一计划最多一个活动执行；重复点击返回原运行，明确补跑形成新尝试。瞬时连接错误在预算内重试一次；参数、权限、资源失效及缺资料直接报告。事实保存与工作进程结束分开判断；解释尚在运行时仍占原执行名额，事实和解释合用本次时间预算。服务取得独占运行资格后才处理自己遗留的不确定运行；确认旧工作进程已终结才释放活动名额。恢复检查有期限，超时显示恢复受阻及处理入口，阻止新执行，保留可读历史和诊断，不能永久显示正在恢复。重启仅对未保存事实的当前有效任务补一次；已保存事实而解释中断，只标解释中断，不重复取数。正常刷新只读保存结果。

最近尝试和最近成功分别记录。更新失败可显示同问题、同期间、同范围、同适用版本的旧成功结果及日期；首次无结果显示待生成。无可信数据日期显示未知，不能拿查询／完成时间填充。业务窗口到期、服务离线、授权失效都有具体状态和维护入口。

#### 5.4.4 组织结果与问策衔接

保存计划版本、原问题、输入和组织含义、运行目的、触发及周期、授权版本、冻结依赖、状态和时间、完整事实与未知、记录数及证据引用。结果只保留一个权威；简报引用该结果，不另算数字。旧简报读取原保存内容，不能从当前库重建过去。

后台结果不进入个人会话历史。组织读取仅开放已正式发布、范围明确且属于发布引用的结果；摘要、明细、依据、下载和问策引用都按读者当前114身份重新授权。私人结果继续owner／identity／scope隔离，不能放开原有所有权检查来实现共享。

- “查看依据”读取原结果，直接说明首修口径、参照集合、触发条件和未知，不重取学校数据。
- “继续问策”打开新会话草稿，预选课程专家，带入该课程、原学期／范围、当时结果和时间。默认问题为“这门课程为什么进入本次观察，哪些数字可以核实，还缺什么判断依据？”不自动发送，不重复整份简报问题。
- 用户发送上述解释任务时使用已保存结果，明确“依据本次简报”，不冒充当前数据。模型未配置时仍可给确定性条件说明；自由原因分析须真实模型及相应资料，不能编造原因。
- “更新当前数据”是单独明确动作，按当前权限取数并新建个人轮次。返回恢复原简报及阅读位置，新轮次不覆盖旧简报。

先走通一个问题、一个学期、一个授权范围。其他专家按培养方案发布、毕业／推免窗口、真实转专业申请等业务条件扩展，不按专家数量每天凑五份简报。

#### 5.4.5 发布、变更与核验边界

试跑、正式事实、解释状态分别显示，不共用一个“成功”。全无记录或事实口径不成立时不发布观察结论；存在有效事实但部分数据未知时可发布限定事实及核对提示。没有可观察课程时说明原因，不能把空清单当全面正常。

发布门槛由服务端统一执行，不能靠页面绿色状态或人工勾选代替证据：

| 实际依据和本次验证 | 发布行为 |
| --- | --- |
| 实际首修语义及参照集合成立、使用指标已登记、本次冻结输入独立复算通过 | 允许正式观察；来源整体覆盖未知仍披露，合法部分事实标limited |
| 上述条件成立，三层核验仅缺同口径对象的可比数据时点 | 允许限定观察，三层状态保留待核／不可比较，不能声称三层一致 |
| U含义、参照可比口径或新指标登记未成立 | 只可呈现已支持的原字段事实及具体缺项，禁止对应新推导及观察排序；没有可支持事实则不发布 |
| 本次计算不一致、关键依据已确认错误，或层间发现影响该结论的实质矛盾 | 阻止受影响结论，保留诊断；其他有独立依据的原字段可作限定事实 |

口径依据、登记引用、计算结果与三层结论分别绑定来源、方法、映射修订和实际核验时点，条件变化后重验证；不把上次三层核验通过自动写成每次运行通过。缺可比时点下的数值差异只标待核，不直接认定加工错误；实质矛盾必须有同口径可比证据或明确字段／规则冲突依据。执行契约见[04第14.5.11节](expert-design-v3-20260916/04-数据与运行技术规格.md#14511-发布准入撤回与阶段终结契约)。

运行保存原计划、分析条件及时间。业务条件已改变时，合法旧运行可按原条件留存历史，但不能推进新条件的当前结果；晚到结果和旧解释不能覆盖更新的当前记录。只改周期、名称或展示条数时沿用相同分析条件的正式事实，详情保留其原生成版本。

核验分两项记录：一是用保存的最小原始聚合输入独立复算N/P/U、参照及选入；二是用三层SQL核对贴源、事实、应用加工关系。第二项没有同口径、同对象和可比较数据时点依据时标为待核／不可比较，不能用第一项通过替代三层正确，也不能从当前库重建过去。源数据更新后，原结果仍应能复算当时实际支持的数字。

已发布结果发现错误时，有当前管理、分析及该发布范围权限的维护者可撤回，原因必填。撤回保留原事实、版本、操作者及时间，并移出当前适用结果；历史可按原权限复看且醒目标明撤回原因，不能作为有效观察继续问策。修正后按新有效依据重新执行和发布，关联被更正的发布编号，不覆盖旧数字。已确认错误的依据影响其他发布时，相应引用立即标失效并阻止消费；正常版本升级不自动判旧事实错误。无仍适用成功结果时显示待重新生成，不回退到同一错误依据的旧结果。停用自动任务与撤回发布是不同操作，不增加逐期审批。

## 6. 对话式主流程

### 6.1 正常问策

新建会话 → ＋选择专家 → 写问题或点击该专家的业务示例 → 确认必要对象与范围 → 发送 → 专家在对话中回复主要结论 → 右侧呈现对应结果／数据／依据 → 同一会话追问或切换专家继续研究。

必要条件在对话内用明确问题和名称选择卡补充，例如两份方案、学期、课程、年度。输入卡只收当前任务必需条件；可点击已确认范围调整下一轮。展示条数位于右侧数据设置，不进入主要提问流程。

发送前显示当前专家和影响计算的关键范围。没有资料或规则时说明影响，可以回答的独立部分继续；不把未知当成学生不满足。专家理解自由文本后仍须在其已发布任务和当前授权范围内执行。

### 6.2 当前模型缺口的处理

现有真实模型未配置。对话式布局可以承载已发布的数据分析任务，但自由提问、自动澄清与解释仍须真实模型接入并验收。

模型未配置时，在输入区明确说明当前支持的业务事项，用户通过该专家的任务卡和对话内条件卡执行。可选备注标明只作背景，不把任意文字伪装成已识别的筛选。任意自由问答的发送不能假成功或静默执行默认任务。

模型具备后，问题可直接发送；仅在必要时询问条件。技术能力缺口有真实状态，页面布局完成不等于AI能力完成。

### 6.3 右侧结果与对话的对应

| 情况 | 对话区 | 右侧 |
| --- | --- | --- |
| 空白会话 | 选择专家和问题引导 | 收起或简短说明分析后可看结果，不平铺空表格 |
| 正在执行 | 真实阶段和停止操作 | 说明本轮执行中；已有结果可保留阅读，标明旧轮次 |
| 正常结果 | 主要判断、关键未知与“查看结果” | 当前轮次的结果、表格、来源和保存时间 |
| 需要条件 | 必要问题和回答卡 | 保留原结果，并说明本轮尚无新结果 |
| 部分结果 | 明确已完成部分及缺口 | 有效数据与未知分开，不能显示完整资格结论 |
| 失败或取消 | 真实原因、原输入和重试入口 | 保留原已保存结果；失败或取消不生成成功结果 |
| 查看旧消息 | 高亮所选消息，保留阅读位置 | 固定到该轮专家、范围、版本及证据，不换成最新数字 |
| 切换会话 | 恢复该会话消息与草稿状态 | 恢复该会话所选结果，不接收其他会话迟到内容 |

新结果只更新所属会话。用户正在读旧消息或编辑输入时不强制抢滚动和焦点；显示新结果提示，用户可打开。右侧“结果”读主要分析，“数据”看实际表格及记录数，“依据”看口径、规则、来源与保存明细；内容不足时不制造空标签或演示结果。

输入支持Enter发送、Shift＋Enter换行；中文输入法组词确认不触发发送。专家选择面板能用键盘打开、选择和退出，退出回到输入框；未选专家、缺必要条件或正在执行时发送状态和原因明确。

### 6.4 补充依据与原问题重核

用户从对应回复或结果进入待明确事项，查看缺什么、影响什么，补充可定位依据后回到同一会话。重新核验引用原问题、原专家及原范围，先显示这些条件再发送；不能因当前已切换专家而用另一专家关闭原事项。

资料已提供与问题已明确分开。引用保存、审批或用户说已处理均不直接改变条件结果；可暂缓，未知仍保留。新轮次确实回答受影响条件后才更新相应事项，旧消息和证据保持不变。

### 6.5 实现衔接与精简

业务界面统一使用“会话”。现有研究容器、执行、结果和证据存储继续复用，不另建同义聊天结果库。当前服务把专家及依赖固定在整项研究，新增会话内换专家需要将执行所用专家、版本和依赖落实到每轮；执行、保存及历史读取不能使用后来选中的专家解释旧结果。

原专家团地址转入专家问策，保留可定位的会话链接；旧专家问策会话保留真实消息和来源，不伪造新结果编号或缺失证据。旧四专题会话与五专家职责映射先核对，不因菜单合并把旧信号当成新任务正式结果。现有决策简报承接为独立AI简报，保留旧地址和真实历史；其职责及与问策的衔接按5.4落实。

本节页面、路由和控制库迁移已实施；实际验收范围见05第8.1节。具体开发衔接见[04第14节](expert-design-v3-20260916/04-数据与运行技术规格.md#14-统一专家问策的对话工作区开发计划)。
## 7. 最小输入和输出

输入：身份由系统验证；业务任务和必要对象、时间使用名称选择器。规则年度、目标方案、来源覆盖或保存结果引用按任务必填。背景、展示条数及引用说明可选。专家／Skill／工具／处理器和实际规则版本由系统固定，用户不填技术标识。

| 输出 | 最低要求 |
| --- | --- |
| 问题和范围 | 原问题、实际对象、学期／年度、学院含义和轮次 |
| 主要结果 | 直接结论与必要表格；事实、规则核验、假设和建议性质明确 |
| 覆盖和未知 | 可核范围、具体未知或冲突、是否足以支持结论；留存完整与业务覆盖完整分开 |
| 依据 | 来源、数据和查询时间、口径、规则版本、实际保存明细 |
| 下一步 | 能继续看什么、缺什么、还需核实什么；无依据不自动派人和期限 |
| 留存 | 保存结果、执行状态、输入和版本；从我的研究恢复原轮次 |

默认突出业务含义。原始字段、执行步骤和技术编号按需查看。数字旁保留单位、分母和影响理解的关键限制。

## 8. 数据、规则与能力准入

原型业务数据默认来自114测试环境。普通接口使用114服务；专家和指标核验侧车读取同一RDS的edu_source、edu_analytics_v3。专家配置、版本和研究证据存原型控制库；学校贴源、事实及应用业务表只读。现有指标映射在应用库SYS元数据表中的维护写入沿用既有授权接口，与业务数据查询分开；不改学校主数据或事实加工结果，不以SYS表名推断指标已确认。

代码实现、真实数据核对、业务规则确认和允许发布范围分开记录。连通、测试、资源发布和业务闭环不能互相代替。

- 无合法分母时比例未知；无成绩完整性依据时，缺记录不能直接解释为未完成。
- 既有审核状态是记录，不能反推规则或个人条件明细。
- 方案学期不自动作为正式先修、未来实际开课或名额保证。
- 无两份实际可比结果时不生成历史变化。复看保存证据可实现，不承诺从当前库重建历史批次。
- 配置权与数据权分开；历史、来源和下载仍检查当前权限。
- 当前真实模型未配置；外部MCP、通用沙箱和多专家编排无完整运行验证，不计已交付。

### 8.1 后台处理服务管理

在系统管理新增“后台处理服务”配置入口，三个资源菜单继续各负其责。首期登记一个实际运行的expert-resources内置服务，复用当前8011服务及项目后台启动机制；不新增独立MCP部署或通用调度平台。配置页面管理服务级运行条件，专家详情管理业务问题、学期、范围和周期。

| 管理内容 | 具体决定 |
| --- | --- |
| 服务识别 | 名称可修改；固定编号、内置类型、部署环境、实际地址及版本只读；首期保留一个内置登记，不让用户创建任意进程或执行地址 |
| 数据与模型 | 选择服务端已登记的数据连接引用，显示所属库及脱敏连接状态；首期仅114测试连接。模型使用现有受保护配置引用，未配置就显示事实模式，连接账号不代表业务授权 |
| 自动运行授权 | 有权管理者依据当前114身份授予本系统专用服务主体明确的任务清单、组织范围和有效期；首期只授予C-PERFORMANCE及试点范围。授权登记、续期、缩小及撤销留痕，不保存用户Bearer |
| 运行参数 | 自动任务开关、执行超时、瞬时错误重试0／1次；首期后台并发固定1，不能覆盖已发布任务的限制，周期和学期不在此重复配置 |
| 检查及应用 | 保存草稿、检查连接／权限／发布依赖、应用配置；检查必须真的请求服务并做受控只读检查，配置存在不算连接成功。应用失败保留原有效版本 |
| 状态和故障 | 实际心跳、调度状态、最近执行、队列／在途、最近故障、受限日志；恢复超时显示受阻原因、诊断与重新检查入口；浏览器不能连接时显示无法访问，最后心跳不能冒充当前正常 |
| 停用和撤销 | 停用自动任务阻止新后台提交，已合法在途任务可完成，交互问策继续；撤销或缩小授权在关键阶段阻止不再合法的运行及发布。停用历史保留，不提供网页任意启动／终止系统进程 |

服务授权是原型自身的明确委托机制，由统一权限层校验、存入服务端控制库；它不冒充114服务账号，也不依赖未证实存在的114任务授权API。读者仍按当前114权限读取组织结果。授权变更立即生效，普通预算配置仅影响后续任务；越权或不明范围拒绝。

运行闭环由Codex实施并验收：启动机制 → 实际服务心跳／数据连接 → 配置检查并应用 → 后台授权 → 首次正式运行 → 至少一次浏览器关闭后的实际定时运行 → 保存、读取、故障和重启恢复。首期运行于当前原型主机，主机或服务停机期间自动任务不可用；页面准确呈现，不把本地主机包装成持续在线生产服务。持续部署迁移另以实际主机登记验收。

本节及5.4已完成首期实现。服务配置、后台委托和真实自动简报的验收结果见05第8.1节；学校业务数据仍只读。

## 9. 业务验收

| 编号 | 操作 | 合格标准 |
| --- | --- | --- |
| A01 | 新建会话、＋选择专家、开始问策 | 选择不触发执行，必要条件在对话内确认，不需要技术ID |
| A02 | 两份真实方案比较 | 共同、方向差异、分母与未知清楚，来源可读 |
| A03 | 学期分析后打开单课 | 沿用原学期和真实课程，数字一致，旧结果不变 |
| A04 | 切会话、点击旧消息、编辑下一轮 | 右侧摘要、数据和依据属于所选会话／轮次；旧结果不被当前库或其他会话替换 |
| A05 | 缺项、分母0、冲突或不适用 | 具体原因及影响；不生成假数字、完整资格或全局排名 |
| A06 | 补依据并重核 | 恢复原问题和范围，新建一轮；只明确实际满足条件的事项 |
| A07 | 失败、取消、权限变化 | 真实状态与原输入、旧结果可理解，不假成功、不扩权 |
| A08 | 打开／生成AI简报、复看历史、进入问策 | 实际范围、时间、选入依据和未知清楚；每项可看数据；问策带入原问题与引用，确认后执行；旧简报不被新结果覆盖 |
| A09 | 真实模型任务 | 同义、澄清、追问、否定修正通过；事实不漂移，不补造政策 |
| A10 | 实际岗位走查 | 能复述结论、未知和下一步；记录误解与放弃点，Codex走查与岗位验收分开 |
| A11 | 同会话切换专家后发送 | 每轮专家／范围／版本清楚；旧结果不改，新专家不沿用不适用条件；原事项重核绑定原轮 |
| A12 | 分析中切会话、窄窗及恢复 | 迟到结果只归原会话；消息、输入和右侧选择不串；历史及结果面板能返回 |
| A13 | 简报模型缺失、来源混期、失败或越权 | 事实与AI解释状态分别明确；不造正式优先级、期限或“无异常”；不可比不计算趋势；引用和进入问策不扩大权限 |
| A14 | 维护预设计划并定期执行 | 问题、范围、实际参数和版本固定；选择或保存草稿不执行；真实后台授权、窗口和数据准入通过后才启用 |
| A15 | 重复触发、计划变更、重启及组织读取 | 同计划不并发重复运行；历史不改；跨院、私人结果和撤销授权拒绝；机器任务不混入个人历史 |
| A16 | 首修观察的独立核对 | 有效集合、同范围参照、U及条件一致；可说明选入理由、样本及未知，不能误读为质量评价或唯一学生数 |
| A17 | 配置后台处理服务并启用首期 | 真实检查、应用、授权、首次正式发布、浏览器关闭后实际到期运行及故障恢复走通；未执行项不能标通过 |
| A18 | 撤回错误简报并发布修正结果 | 原结果和原因保留，当前及问策引用拒绝失效依据，新结果关联更正，不覆盖历史 |
| A19 | 解释占用与恢复受阻 | 事实保存后解释仍守原名额／总预算；恢复超时有出口，真实旧进程结束后才重新接受执行 |

本次管理员实操已验证课程分析、单课、来源、证据分页、历史轮次和原问题重核，见[05实际记录](expert-design-v3-20260916/05-验收与审计整改对照.md#78-本轮实施与验证记录)。证明限定事实流程可用，正式规则、模型解释、旧链路迁移和实际岗位用户试用分别验收。

## 10. 后续顺序

1. 对话工作区：按统一专家问策完成会话栏、输入框＋选择专家、必要条件卡、右侧结果以及每轮专家绑定；复用已核的P/C计算和保存证据。
2. 兼容与菜单：盘点旧问策／专家团的历史、权限和链接，迁入唯一专家问策入口；同时保留独立AI简报，旧地址兼容。
3. 补有价值闭环：基于真实方案绑定，先支持一个规则和覆盖有依据的限定毕业条件任务；转专业复用计算并补自身规则。
4. 模型与解释：接通获准真实模型，先验证P/C路由、澄清和解释，再扩展规则任务。事实任务可先独立使用。
5. AI简报闭环：先核114首修语义、参照可比集合及真实SQL，再扩展映射登记和实现C-BRIEF-01；走通无自动配置的人工试跑、正式发布、撤回及修正，再接专用授权、真实周期、服务配置与问策。首修依据暂缺只阻塞对应观察，Q工作区和服务基础可继续。旧信号逐项核准，历史比较仅用实际保存结果。
6. 逐任务扩展：材料支撑、接收安排、当年推免按必要性和准入推进；跨专家、外部MCP和额外成果模块有具体需要再建。导出、用户意见按实际用途增加。

这是需求优先级。Codex后续继续回填[04开发计划](expert-design-v3-20260916/04-数据与运行技术规格.md#13-修订方案的技术契约与可执行开发计划)和[05验收](expert-design-v3-20260916/05-验收与审计整改对照.md)，不另建按日期重复方案。
