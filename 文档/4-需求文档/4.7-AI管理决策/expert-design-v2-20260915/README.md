## 推荐的整体框架

**一事一研究，一项研究一条主对话；专家按需加入，相关资料按需打开，领导自己的意见独立保存。**

- 左栏以“我的研究”为主、以“本次参与专家”为辅，可收起；不是固定五专家菜单，也不做复杂任务树。
- 中间优先给判断、业务讨论和方案比较。数字跟随当前问题，不常驻一面与讨论争空间的指标墙。
- 添加专家只建立参与关系；发送问题才分析。已加入专家不必每轮都回答，结果只列实际参与者。
- 查看资料、质疑补充、比较做法可以来回进行，不强制按固定步骤。系统判断、正式来源与领导个人意见分开。
- 研究能离开、恢复和归档；个人意见不因新分析被改写；需要时先预览再整理讨论材料。
- 保留原决策简报、现有专家分析和原问策；不回写教务源库，不自动执行管理决定。

## 如何使用这份设计包

总体框架看01；专家职责与实际回答是否有管理价值看02，尤其第7.4节；页面每一步如何操作看03和06；研发与验收使用04和05。

本次完成的是设计规格及两张静态视觉示意，不是正式系统改造，也不是18状态的可点击原型。下一阶段应先按规格制作独立可点击原型，确认完整操作过程，再进入系统实施。该顺序保留“先看视觉、确认后修改”的边界。

现有资料和规则可以支持哪些判断、哪里需要整理或补充，已列在总设计第8.1节及各场景的资料不足处理。缺少的年度规则、业务认定、大纲或获批模型条件，不能由设计文档替代，也不能用示意数字补齐。
