# 交互与资料闭环规格 V3

2026-09-16。本文为待实现、待操作验证的行为契约。与01的岗位框架、02发布范围共同生效，不以可点击外观替代业务能力。

## 1. 固定布局与内容身份

全局菜单不变。局部左栏：新建研究、搜索、近期研究、归档；下方“本次专家”可折叠。默认左栏展开、右面板关闭。左栏收起后标题旁保留切换研究及专家入口，不让用户丢失导航。

主区标题旁显示当前工作身份、对象、适用年级/业务年度、数据时间；详情可展开，不把技术版本堆在标题上。“本题进展”默认显示不超过三项短内容：目前判断、尚需明确、上次以来的变化。首轮无历史变化时不显示空栏目，不复制整段回答。

连续对话保存研究过程；“本题进展”是当前有效轮次的索引，不替代原始资料；“我的意见”是领导自己的文字。旧判断被修正后标明变化并可回到原文，不静默删除。

正文建议16px，阅读宽度以640—820px为起点；具体尺寸由原型测量。输入默认四行，最多八行后内部滚动。比较表放主区，资料/意见使用一个辅助面板；正文无法保留约600px时面板覆盖显示。窄窗左栏改抽屉，不叠第二层侧栏。

## 2. 逐操作规则

### O01 新建研究与岗位入口

首页提供直接输入和少量按岗位组织的业务问题。处长示例强调全校比较与协调；院长示例强调本院培养、课程和保障。点示例先准备问题，不自动选学生、不自动把年度改成本届。

第一次发送才建立正式研究；同身份保留一个新研究草稿。已有研究各自有草稿。研究建议标题可改，改标题不改变范围和计算。只有身份及已确认组织范围可默认继承，不继承上一项专业、学生和意见。

### O02 澄清研究目的与范围

只补问真正影响对象、计算或授权的条件。“两个专业相似吗”若目的会决定采用结构相近或转入覆盖，提供业务选择说明，而不问技术算法名。已知条件不重复问。

正式计算所需的培养方案版本、业务年度不清楚时先明确。只有2022级资料不能当作本届；可以说明现有资料允许研究哪一届。范围修改在提交前为草稿，提交后新建范围快照和分析轮次；历史保留原范围。

### O03 提问、业务动作与专家自动参与

点击发送或明确“比较/继续分析”业务动作表示提交本轮。系统可选用当前身份已获准、当前对象已达到资料条件且未被本研究排除的专家，不以已加入名单为调用前置。开始时明示实际分工，随后把参与专家保留到本研究。

查看资料、展开表格等只读动作不启动新模型分析。按钮的动作类型在返回契约中固定，不能显示“查看”却暗中启动完整任务。需要扩大范围或使用未批准服务时停止并说明，不自动取得新权限。

回车换行，Ctrl+Enter及发送按钮提交；中文输入法组合状态不得误发。双击和网络不确定重试沿用请求标识，不生成重复轮次。问题确认收到前不清空用户输入；成功后保留下一轮正在编辑的草稿。

### O04 手动添加与指定专家

添加使用居中窗，含职责、适合问题、当前对象可分析子能力和资料待准备状态。按工作问题检索，不展示模型参数。暂缓且无可用子能力的专家不能假装可执行；只提供资料要求说明。

手动加入仅把专家保留在本研究，便于以后指定；不自动开始分析，也不要求每轮发言。指定某专家补充时可直接输入问题；从职责说明进入则预填问题，用户发送后执行，定向仅本轮有效。

已有未发送文字时，预填不得覆盖：允许追加或暂不使用；不会因专家弹窗抢走意见编辑。关闭回到原焦点与阅读位置。

### O05 移出、排除与版本停用

主动移出影响后续并加入本研究排除名单；普通自动选择不能立即加回。点击明确的重新加入解除排除。历史贡献、引用、个人意见都保留。

排队时移出对尚未开始的本轮生效；进入分析中后，参与偏好已冻结，移出提示“本轮已开始，后续不再参与”，不暗中取消。紧急停用版本不同于主动移出：服务端阻止该版本发布新结果，已受影响结果显示说明；不能让另一位专家冒名补足。

### O06 分析中、切换与停止

同研究一次一轮。忙时可编辑下一轮问题、读已有资料和意见、切换研究；不隐式排队新的问题。需要修改本轮条件时可准备草稿，并明确选择停止后重新发送或等待完成。

停止先显示请求已收到，服务端裁定后显示已停止或已经完成。不得只停动画。成功的独立事实可以保留，未完成内容不得成为完整管理建议。A研究结束时只在A留下结果和轻提示，不抢B焦点。

### O07 阅读结果与本题进展

先显示与当前问题直接相关的判断、决定它的事实和条件；后续动作不超过两个主要选项。不能每轮要求形成意见或材料。缺少关键资料时说明现有事实允许判断到哪一步，不编造建设优先级。

系统解释尚未通过校验时不以正式结论样式展示；解释失败可显示已验证事实与未完成说明。本题进展只引用有效结果，标明范围、待明确事项和已发生变化。用户读旧内容时不强制滚到底部，提供“有新内容”入口。

### O08 资料定位与意见对照

从具体判断、数字或课程进入使用的原文段落、规则条款或计算记录；默认打开实际采用版本。没有授权的底层资料不做伪入口，可展示已批准的摘要与计算说明。版本缺失、无权限、加载失败分别反馈。

资料/意见共用面板；编辑意见时可固定一段来源摘录，正文保持可读。展开完整资料保留意见草稿、选区和滚动，返回原处。不将暂未保存文字误标已保存。

### O09 比较做法与本级管理用途

以现状为基线，在主区域比较两到三种有实际针对性的做法。按问题呈现能解决什么、影响对象、必要条件、本级可研究事项、需其他单位说明或协调的条件，以及观察变化的方法。

只有已确认规则和数据才能算学分、人数或资源影响；未知字段不评分、不填0。没有资源资料就不展示假成本。比较结果是一轮研究内容，不自动新建任务或发起安排。

### O10 质疑、补充和有限修正

领导可直接说与实际不符，或在某段点补充情况。将原资料、补充说明和受影响判断分开；不盲从，也不固执重复旧话。明确只改变受到该事实影响的判断。

“已经共同开课”只影响开课组织前提，不自动证明培养任务一致或没有重复投入。用户文字作为研究补充，可在明确假设下继续；只有经获授权渠道发布的数据或规则才能进入正式计算。修正保留前后关系与原因，不用重新生成遮盖历史。

### O11 建立待明确事项

在结果或用户补充中识别具体事项：缺什么、影响哪个判断、已有何种来源、补齐后能判断什么。用户可新增、编辑描述、暂缓或重新打开；不产生自动派单和截止日期。

区分资料/规则缺项与管理取舍。资料缺项按第3节状态解决；管理取舍由用户留下当前想法或暂缓，不被系统标为正式决定。讨论无需留下事项也可以结束。

### O12 通过已有渠道补充资料

领导可导出待明确事项清单供既有业务渠道使用，不自动发给其他人。首期不提供未经治理的任意文件上传分析按钮。可以引用已发布资料或录入文字补充。

数据人员收取文件、解析和校验；获授权业务人员确认规则适用，按现有治理流程发布。领导不需要学习数据清洗或规则配置。提交、退回、已发布的关联状态可回显研究，但不自动生成分析或关闭问题。

### O13 新资料后的继续研究与事项关闭

相关资料发布后显示“有已确认资料，可以继续分析”，说明影响的事项；不自动替换旧轮次或意见。用户点击继续分析形成新轮次。

对资料缺项，只有新有效分析确实使用确认资料并回答原缺项，才可标“已明确”；仅上传、解析或发布不能标解决。来源发布状态、必要字段覆盖和解决轮次由服务端按事项规则校验，不能只因模型文字说已解决而关闭。解释争议须有相应人工确认记录。条件仍不完整继续保留。管理取舍类事项只能由用户标记已有当前想法或暂缓，所有状态可追溯、可重开。

### O14 我的意见、采纳与保存

用户可以直接写，或选取分析内容加入意见。选择部分内容默认追加；改写/替换先预览并明确采纳。保留所据轮次与必要引用，新分析不自动覆盖。采纳一段不表示接受整轮建议。

短延迟自动保存，以服务端确认显示已保存；失焦和切换尝试立即保存。正常面板关闭及研究切换保留内存草稿；失败明确提示暂未保存并可重试或复制。故障恢复只保证到最后服务端确认版本；退出身份或设备崩溃不能保证恢复未保存文字。首期不使用未经批准的本地持久恢复副本。

### O15 多窗口冲突与恢复

冲突时保留双方内容，可比较、手动合并或另存为当前意见的新版本，不自动最后写入覆盖。恢复旧版本作为新版本保存。聊天、改标题和专家列表变化不造成无关的意见冲突。

服务端状态未知时先查询原操作结果，不能换新请求标识反复提交。身份变化立即隔离旧缓存；重新进入原身份并鉴权后只恢复合法、已保存内容，不让其他身份先看到草稿。

### O16 搜索、复看与长期研究

搜索所有授权研究及轮次，不止近期列表；命中定位原内容，提供查看最新进展。分页使用稳定阅读锚点，加载更早内容不改变当前段落。去掉产品层80条强制另题，但不把全历史无差别塞给模型。

同一管理问题保持研究；改变完全不同问题时建议新建，不自动迁移敏感对象。带入相关问题摘要和引用须由用户明确选择并重新鉴权。总结不是正式数据来源，正式数字从原计算结果或重算获取。

### O17 归档与恢复

归档只移出近期，不删除记录或代表已作决定；可以恢复，恢复时重新鉴权。分析中提示返回或停止并归档，不静默取消。暂停研究不需要填写意见、完成日期或原因表。

### O18 整理讨论材料与再次使用

首期提供网页预览和DOCX讨论稿；选择具体分析轮次、已保存意见版本及待明确事项，先预览再保存/下载。无个人意见则不出现“领导认为”；存在失败贡献不得写成全体一致。

服务器固定材料版本，后续分析不回写。再次打开旧稿提示数据日期、相对当前研究的已知变化，允许查看原稿或重新整理。原文及资料权限变化时重新鉴权，不能靠旧下载地址绕过。

首期不做在线共享审批或复杂报告排版编辑器；导出后用户自行修改不影响平台原版，已下载文件不能承诺被平台撤回。成品结构、表格和来源规则见06。

## 3. 待明确事项与资料状态

| 事项状态 | 进入条件 | 允许动作 | 不可混淆的含义 |
|---|---|---|---|
| 待补充 | 缺资料、规则冲突或来源不明确 | 查看需求、导出清单、补充文字/引用、暂缓 | 不是学生不符合，也不是已派给某人 |
| 已提交待确认 | 获得资料接收记录 | 查看提交信息、退回说明、继续讨论已知部分 | 提交或解析成功不等于正式事实 |
| 退回补充 | 确认流程发现版本、对象或内容问题 | 看原因、补交，保留原提交历史 | 不悄悄选用更方便的版本 |
| 已有确认资料 | 相关版本已获授权发布 | 查看变更、继续分析 | 仅表示可以重算，不表示原疑问已经解决 |
| 已明确 | 有效新轮次使用确认来源并解决该资料问题 | 回看判断变化、重新打开 | 不表示领导作出正式管理决定 |
| 暂缓 | 用户决定目前不继续 | 恢复、补充当前想法 | 不替代事实确认，仍保留未明确内容 |

每次状态变化记录事项ID、来源/轮次、操作者类型、时间、前后状态和说明。规则冲突由获授权业务流程解释，不按模型偏好择一。源版本被撤回时相关事项重新提示需明确，旧记录保留。

## 4. 运行与保存状态的用户反馈

| 情况 | 用户看到及可以做什么 |
|---|---|
| 条件不明 | 一个必要业务问题，可选可答，不自动计算错误届次 |
| 已收到/等待处理 | 真实等待，允许切研究、改下轮草稿、停止 |
| 分析中 | 真实阶段，不造百分比；来源与已存意见仍可读 |
| 已完成 | 本轮业务结果与适用条件，不自动归档研究 |
| 部分完成 | 明确成功范围、未完成部分及是否可重试，不伪装完整结论 |
| 超时或失败 | 保留问题和已确认结果，提供在当前范围重试或调整问题 |
| 已停止 | 本轮不会再发布新正式结果，已保留片段标状态 |
| 资料暂不支持 | 当前可做与不能做分别说明，不显示技术失败重试诱导 |
| 资料/规则更新 | 旧结果仍属旧版本，可查看变更后主动重算 |
| 专家版本紧急停用 | 明确受影响部分，新结果受阻，不冒名换专家 |
| 保存中/失败/冲突 | 未确认不称成功，文字在当前页面保留，恢复边界明确 |
| 权限变化 | 先鉴权后呈现，合法已保存内容可在原身份恢复 |

## 5. 输入、焦点与无障碍验证

中文组合输入期间不发送；文字超限保留并说明，不自动截断。重要操作均有文字、键盘可达，不只靠颜色或悬停。Tab顺序符合阅读顺序，关闭弹窗和面板返回原焦点；Esc先处理未保存风险，不清空文字。

新结果不抢编辑焦点，不在读旧内容时强制滚动。状态通知不逐字朗读整篇流式内容。1280/1440/1920窗口、125%缩放、长标题、宽表、长意见及专家目录扩展必须实际试用；本文不宣称符合完整无障碍标准。
