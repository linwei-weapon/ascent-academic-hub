# 交互与资料闭环规格 V3

状态：交互规格。当前增量版本：V3.3，代码与首期管理员主流程已实操，未验证范围见05第8.1节。核对日期：2026-10-07。原O01—O18保留历史连续研究目标；实施与验收分别见04第14.5.10节及05第8.1节。

## 1. 固定布局与内容身份

阅读顺序：第1—5节保留旧连续研究设计，第6节说明V3.2执行与资料机制；统一专家问策的V3.3入口和每轮专家规则以第7节及现行模块需求为准。旧设计中的自动组织专家、添加多位专家和研究目录不作为本次增量要求。

全局菜单不变。局部左栏：新建研究、搜索、近期研究、归档；下方“本次专家”可折叠。默认左栏展开、右面板关闭。左栏收起后标题旁保留切换研究及专家入口，不让用户丢失导航。

主区标题旁显示当前工作身份、对象、适用年级/业务年度、数据时间；详情可展开，不把技术版本堆在标题上。“本题进展”默认显示不超过三项短内容：目前判断、尚需明确、上次以来的变化。首轮无历史变化时不显示空栏目，不复制整段回答。

连续对话保存研究过程；“本题进展”是当前有效轮次的索引，不替代原始资料；“我的意见”是领导自己的文字。旧判断被修正后标明变化并可回到原文，不静默删除。

正文建议16px，阅读宽度以640—820px为起点；具体尺寸由原型测量。输入默认四行，最多八行后内部滚动。比较表放主区，资料/意见使用一个辅助面板；正文无法保留约600px时面板覆盖显示。窄窗左栏改抽屉，不叠第二层侧栏。

## 2. 逐操作规则

### O01 新建研究与岗位入口

首页提供直接输入和少量按岗位组织的业务问题。处长示例强调全校比较与协调；院长示例强调本院培养、课程和保障。点示例先准备问题，不自动选学生、不自动把年度改成本届。

第一次发送才建立正式研究；同身份保留一个新研究草稿。已有研究各自有草稿。研究建议标题可改，改标题不改变范围和计算。只有身份及已确认组织范围可默认继承，不继承上一项专业、学生和意见。

### O02 澄清研究目的与范围

只补问真正影响对象、计算或授权的条件。“两个专业相似吗”若目的会决定采用结构相近或转入覆盖，提供业务选择说明，而不问技术算法名。已知条件不重复问。

正式计算所需的培养方案版本、业务年度不清楚时先明确。只有2022级资料不能当作本届；可以说明现有资料允许研究哪一届。范围修改在提交前为草稿，提交后新建范围快照和分析轮次；历史保留原范围。

### O03 提问、业务动作与专家自动参与

点击发送或明确“比较/继续分析”业务动作表示提交本轮。系统可选用当前身份已获准、当前对象已达到资料条件且未被本研究排除的专家，不以已加入名单为调用前置。开始时明示实际分工，随后把参与专家保留到本研究。

查看资料、展开表格等只读动作不启动新模型分析。按钮的动作类型在返回契约中固定，不能显示“查看”却暗中启动完整任务。需要扩大范围或使用未批准服务时停止并说明，不自动取得新权限。

回车换行，Ctrl+Enter及发送按钮提交；中文输入法组合状态不得误发。双击和网络不确定重试沿用请求标识，不生成重复轮次。问题确认收到前不清空用户输入；成功后保留下一轮正在编辑的草稿。

### O04 手动添加与指定专家

添加使用居中窗，含职责、适合问题、当前对象可分析子能力和资料待准备状态。按工作问题检索，不展示模型参数。暂缓且无可用子能力的专家不能假装可执行；只提供资料要求说明。

手动加入仅把专家保留在本研究，便于以后指定；不自动开始分析，也不要求每轮发言。指定某专家补充时可直接输入问题；从职责说明进入则预填问题，用户发送后执行，定向仅本轮有效。

已有未发送文字时，预填不得覆盖：允许追加或暂不使用；不会因专家弹窗抢走意见编辑。关闭回到原焦点与阅读位置。

### O05 移出、排除与版本停用

主动移出影响后续并加入本研究排除名单；普通自动选择不能立即加回。点击明确的重新加入解除排除。历史贡献、引用、个人意见都保留。

排队时移出对尚未开始的本轮生效；进入分析中后，参与偏好已冻结，移出提示“本轮已开始，后续不再参与”，不暗中取消。紧急停用版本不同于主动移出：服务端阻止该版本发布新结果，已受影响结果显示说明；不能让另一位专家冒名补足。

### O06 分析中、切换与停止

同研究一次一轮。忙时可编辑下一轮问题、读已有资料和意见、切换研究；不隐式排队新的问题。需要修改本轮条件时可准备草稿，并明确选择停止后重新发送或等待完成。

停止先显示请求已收到，服务端裁定后显示已停止或已经完成。不得只停动画。成功的独立事实可以保留，未完成内容不得成为完整管理建议。A研究结束时只在A留下结果和轻提示，不抢B焦点。

### O07 阅读结果与本题进展

先显示与当前问题直接相关的判断、决定它的事实和条件；后续动作不超过两个主要选项。不能每轮要求形成意见或材料。缺少关键资料时说明现有事实允许判断到哪一步，不编造建设优先级。

系统解释尚未通过校验时不以正式结论样式展示；解释失败可显示已验证事实与未完成说明。本题进展只引用有效结果，标明范围、待明确事项和已发生变化。用户读旧内容时不强制滚到底部，提供“有新内容”入口。

### O08 资料定位与意见对照

从具体判断、数字或课程进入使用的原文段落、规则条款或计算记录；默认打开实际采用版本。没有授权的底层资料不做伪入口，可展示已批准的摘要与计算说明。版本缺失、无权限、加载失败分别反馈。

资料/意见共用面板；编辑意见时可固定一段来源摘录，正文保持可读。展开完整资料保留意见草稿、选区和滚动，返回原处。不将暂未保存文字误标已保存。

### O09 比较做法与本级管理用途

以现状为基线，在主区域比较两到三种有实际针对性的做法。按问题呈现能解决什么、影响对象、必要条件、本级可研究事项、需其他单位说明或协调的条件，以及观察变化的方法。

只有已确认规则和数据才能算学分、人数或资源影响；未知字段不评分、不填0。没有资源资料就不展示假成本。比较结果是一轮研究内容，不自动新建任务或发起安排。

### O10 质疑、补充和有限修正

领导可直接说与实际不符，或在某段点补充情况。将原资料、补充说明和受影响判断分开；不盲从，也不固执重复旧话。明确只改变受到该事实影响的判断。

“已经共同开课”只影响开课组织前提，不自动证明培养任务一致或没有重复投入。用户文字作为研究补充，可在明确假设下继续；只有经获授权渠道发布的数据或规则才能进入正式计算。修正保留前后关系与原因，不用重新生成遮盖历史。

### O11 建立待明确事项

在结果或用户补充中识别具体事项：缺什么、影响哪个判断、已有何种来源、补齐后能判断什么。用户可新增、编辑描述、暂缓或重新打开；不产生自动派单和截止日期。

区分资料/规则缺项与管理取舍。资料缺项按第3节状态解决；管理取舍由用户留下当前想法或暂缓，不被系统标为正式决定。讨论无需留下事项也可以结束。

### O12 通过已有渠道补充资料

领导可导出待明确事项清单供既有业务渠道使用，不自动发给其他人。首期不提供未经治理的任意文件上传分析按钮。可以引用已发布资料或录入文字补充。

数据人员收取文件、解析和校验；获授权业务人员确认规则适用，按现有治理流程发布。领导不需要学习数据清洗或规则配置。提交、退回、已发布的关联状态可回显研究，但不自动生成分析或关闭问题。

### O13 新资料后的继续研究与事项关闭

相关资料发布后显示“有已确认资料，可以继续分析”，说明影响的事项；不自动替换旧轮次或意见。用户点击继续分析形成新轮次。

对资料缺项，只有新有效分析确实使用确认资料并回答原缺项，才可标“已明确”；仅上传、解析或发布不能标解决。来源发布状态、必要字段覆盖和解决轮次由服务端按事项规则校验，不能只因模型文字说已解决而关闭。解释争议须有相应人工确认记录。条件仍不完整继续保留。管理取舍类事项只能由用户标记已有当前想法或暂缓，所有状态可追溯、可重开。

### O14 我的意见、采纳与保存

用户可以直接写，或选取分析内容加入意见。选择部分内容默认追加；改写/替换先预览并明确采纳。保留所据轮次与必要引用，新分析不自动覆盖。采纳一段不表示接受整轮建议。

短延迟自动保存，以服务端确认显示已保存；失焦和切换尝试立即保存。正常面板关闭及研究切换保留内存草稿；失败明确提示暂未保存并可重试或复制。故障恢复只保证到最后服务端确认版本；退出身份或设备崩溃不能保证恢复未保存文字。首期不使用未经批准的本地持久恢复副本。

### O15 多窗口冲突与恢复

冲突时保留双方内容，可比较、手动合并或另存为当前意见的新版本，不自动最后写入覆盖。恢复旧版本作为新版本保存。聊天、改标题和专家列表变化不造成无关的意见冲突。

服务端状态未知时先查询原操作结果，不能换新请求标识反复提交。身份变化立即隔离旧缓存；重新进入原身份并鉴权后只恢复合法、已保存内容，不让其他身份先看到草稿。

### O16 搜索、复看与长期研究

搜索所有授权研究及轮次，不止近期列表；命中定位原内容，提供查看最新进展。分页使用稳定阅读锚点，加载更早内容不改变当前段落。去掉产品层80条强制另题，但不把全历史无差别塞给模型。

同一管理问题保持研究；改变完全不同问题时建议新建，不自动迁移敏感对象。带入相关问题摘要和引用须由用户明确选择并重新鉴权。总结不是正式数据来源，正式数字从原计算结果或重算获取。

### O17 归档与恢复

归档只移出近期，不删除记录或代表已作决定；可以恢复，恢复时重新鉴权。分析中提示返回或停止并归档，不静默取消。暂停研究不需要填写意见、完成日期或原因表。

### O18 整理讨论材料与再次使用

首期提供网页预览和DOCX讨论稿；选择具体分析轮次、已保存意见版本及待明确事项，先预览再保存/下载。无个人意见则不出现“领导认为”；存在失败贡献不得写成全体一致。

服务器固定材料版本，后续分析不回写。再次打开旧稿提示数据日期、相对当前研究的已知变化，允许查看原稿或重新整理。原文及资料权限变化时重新鉴权，不能靠旧下载地址绕过。

首期不做在线共享审批或复杂报告排版编辑器；导出后用户自行修改不影响平台原版，已下载文件不能承诺被平台撤回。成品结构、表格和来源规则见06。

## 3. 待明确事项与资料状态

| 事项状态 | 进入条件 | 允许动作 | 不可混淆的含义 |
|---|---|---|---|
| 待补充 | 缺资料、规则冲突或来源不明确 | 查看需求、导出清单、补充文字/引用、暂缓 | 不是学生不符合，也不是已派给某人 |
| 已提交待确认 | 获得资料接收记录 | 查看提交信息、退回说明、继续讨论已知部分 | 提交或解析成功不等于正式事实 |
| 退回补充 | 确认流程发现版本、对象或内容问题 | 看原因、补交，保留原提交历史 | 不悄悄选用更方便的版本 |
| 已有确认资料 | 相关版本已获授权发布 | 查看变更、继续分析 | 仅表示可以重算，不表示原疑问已经解决 |
| 已明确 | 有效新轮次使用确认来源并解决该资料问题 | 回看判断变化、重新打开 | 不表示领导作出正式管理决定 |
| 暂缓 | 用户决定目前不继续 | 恢复、补充当前想法 | 不替代事实确认，仍保留未明确内容 |

每次状态变化记录事项ID、来源/轮次、操作者类型、时间、前后状态和说明。规则冲突由获授权业务流程解释，不按模型偏好择一。源版本被撤回时相关事项重新提示需明确，旧记录保留。

## 4. 运行与保存状态的用户反馈

| 情况 | 用户看到及可以做什么 |
|---|---|
| 条件不明 | 一个必要业务问题，可选可答，不自动计算错误届次 |
| 已收到/等待处理 | 真实等待，允许切研究、改下轮草稿、停止 |
| 分析中 | 真实阶段，不造百分比；来源与已存意见仍可读 |
| 已完成 | 本轮业务结果与适用条件，不自动归档研究 |
| 部分完成 | 明确成功范围、未完成部分及是否可重试，不伪装完整结论 |
| 超时或失败 | 保留问题和已确认结果，提供在当前范围重试或调整问题 |
| 已停止 | 本轮不会再发布新正式结果，已保留片段标状态 |
| 资料暂不支持 | 当前可做与不能做分别说明，不显示技术失败重试诱导 |
| 资料/规则更新 | 旧结果仍属旧版本，可查看变更后主动重算 |
| 专家版本紧急停用 | 明确受影响部分，新结果受阻，不冒名换专家 |
| 保存中/失败/冲突 | 未确认不称成功，文字在当前页面保留，恢复边界明确 |
| 权限变化 | 先鉴权后呈现，合法已保存内容可在原身份恢复 |

## 5. 输入、焦点与无障碍验证

中文组合输入期间不发送；文字超限保留并说明，不自动截断。重要操作均有文字、键盘可达，不只靠颜色或悬停。Tab顺序符合阅读顺序，关闭弹窗和面板返回原焦点；Esc先处理未保存风险，不清空文字。

新结果不抢编辑焦点，不在读旧内容时强制滚动。状态通知不逐字朗读整篇流式内容。1280/1440/1920窗口、125%缩放、长标题、宽表、长意见及专家目录扩展必须实际试用；本文不宣称符合完整无障碍标准。

## 6. 修订后的任务与资料闭环

核对日期：2026-10-06。适用于114侧车后续实现；前文旧研究的意见、材料及专家参与规格继续保留，但不作为本轮新增执行器、多专家编排或材料功能的完成依据。

### 6.1 从业务问题到执行

1. 用户选择专家后可以选择业务任务；模型具备时也可直接提问，无需知道或填写taskId。服务端先在本专家已发布绑定内识别，再检查任务特定输入。
2. 使用页面明确选中的对象及当前身份；范围发送前可见。历史仅引用必要的已保存结果和待回答澄清，带当时时间；本轮变更和清空字段明确显示，不自动继承上轮全部input。缺年份、对象或目的且会影响计算时，一次询问最关键条件。
3. 检查任务依赖、当前对象与规则。权限不足拒绝；规则或数据缺少时列出影响；允许独立部分执行时先说明范围。
4. 发送后显示实际执行阶段；问题、范围、版本、执行状态及结果保留。切换页面不创建第二次任务。
5. 结果按“本次范围—主要结果—关键依据—缺失及下一步”组织。完整明细和技术过程按需展开，不要求用户先理解Skill或MCP。

用户无需进入资源管理才能分析。模型尚未接入时只开放选择任务及明确参数的入口，文字备注只保存，并在发送前显示实际执行范围；不能暗示已理解自由文本筛选。模型入口的不支持条件明确指出，不能静默回退到另一口径。

澄清是有原问题引用的一轮回复；对应执行以needs_input终结，工作进程不等人。用户回答后建立新execution，引用原turn/clarification，重新鉴权和校验后执行。原问题、答案与所选范围可复看，不要求用户新建研究或重新粘贴全部问题。

### 6.2 四种状态分别呈现

| 状态类别 | 值与含义 |
| --- | --- |
| 资源 | 草稿、已发布、停用；只表示资源生命周期 |
| 任务 | 排队、执行中、需输入、完成、部分完成、阻塞、失败、取消 |
| 业务条件 | 满足、不满足、未知、不适用；不能由任务状态自动转换 |
| 结果性质 | 事实、规则核验、假设分析、建议 |

技术测试passed不得展示为“毕业通过”或“业务验收通过”。执行完成但部分条件未知时，保留未知计数；规则覆盖不完整时不显示完整毕业、学位或推免资格结论。

来源覆盖与留存完整分别说明。没有成绩记录但来源覆盖未知，呈现“无法确定是否完成”；已确认完整范围中没有有效成果，才呈现相应已核条件“未完成”。用户看到的是业务原因，明细中可检查完整性依据。

### 6.3 缺失、冲突与范围纠正

事项分别保存材料准备状态和原问题解决状态，避免一个复杂状态混合两种含义。

| 情况 | 准备状态 | 用户动作与后续 |
| --- | --- | --- |
| 缺数据或规则 | missing | 查看需要什么、影响哪个判断；提供已有确认来源或交由既有渠道补充 |
| 已交资料，尚未确认 | awaiting_confirmation | 查看接收与确认记录，暂不用于正式判断 |
| 年份、对象不符或材料被否决 | rejected | 显示理由，补交或修正范围，保留旧提交 |
| 两条适用规则冲突 | conflict | 展示冲突位置，由责任人解释；不按模型偏好择一 |
| 条件已经满足可执行 | ready | 提示“资料已准备，可以重新核验原问题” |
| 经确认对本范围无适用性 | not_applicable | 记录适用性依据；不将任意缺项标为不适用 |

原问题状态使用open/resolved/deferred。只有关联的新执行实际回答了受影响问题，或经授权确认该问题不适用，才能resolved。材料发布、解析完成、接口成功均不能直接关闭原问题。规则撤回后可重新打开。业务取舍问题可暂缓，不伪装成事实已经确认。

重新核验保留originalTurnId、issueId、依据版本和新executionId。修改范围后标明回答对象发生变化；旧结果与旧问题保留，不覆盖、不自动关闭其他范围的事项。

事项动态与研究对话分开保存，不改变轮次序号或把资料提交显示为专家分析；最新对话、最近有效结果各有明确引用。查看资料仍按当前权限，不由事项链接扩大权限。

### 6.4 旧结果使用

复看旧结果先重新鉴权，并显示当时范围、时间及已知版本变化。相同对象和规则的实际保存结果可检查可比性；群体、口径、规则或证据不足时只能并列查看，不能生成改善趋势。

新数据不自动改写旧结论、个人意见或历史材料。重新执行使用明确选择的可用版本，形成新轮次。执行失败时问题和已保存内容保留；未知网络结果先查原executionId，不换请求编号盲目重发。

新正式resultId等于executionId，来源证据按该结果读取保留内容，不能点击后自动取当前库填入旧结果。无证据只显示实际保存内容及不足。保存失败不出现已保存结果编号。

旧依赖代码已不可用时，保留旧结果阅读，提供“使用新版本重新分析”并显示变更；不会静默升级。排队/取数中授权失效时停止，服务重启失去短期授权时旧执行有明确失败原因。用户重新登录后可用原请求开始新执行，提示数据时间可能变化。

### 6.5 专家上下文的用户可理解边界

专家人设决定表达重点与职责，所绑定Skill决定可执行方法，正式规则决定条件。用户当前观点、补充和假设保留其身份，不因专家认可而变成学校政策。用户无需配置上下文；详情可看本轮任务、采用资料/结果、明确假设及版本。

专家只使用本题有关、当前获准的历史引用。换对象或年度时提示范围变化；跨专家问题涉及本专家没有的能力时说明可用入口，不暗中调用其他专家工具。多专家联合和自由规划仍不在本批实现范围。

本轮实施状态：任务执行、保存证据、失败恢复和原问题事项已经接入当前侧车；事项补充引用不等于解决，只有服务端重新核验可改变解决投影。真实模型未配置；多专家编排、旧版完整材料生成及扩展任务不据此标为完成。实际检查点见04第13.12节、05第7.8节。

## 7. 统一专家问策的会话与轮次规则

状态：V3.3首期已实施，实际验证范围见05第8.1节。完整用户流程以[现行需求第5—6节](../新增-4.7-AI管理决策.md#5-唯一专家入口专家问策)为准；本节补充需要落实的状态规则。第6节仍描述当前V3.2入口和单专家绑定，不作为会话切换专家已完成的证明。

1. **空会话**：新建只进入空白编辑状态，首次有效发送被服务端接受才进入历史；不创建假专家或空结果来填容器。
2. **选择**：＋面板设置下一轮专家，选择、取消和移除不执行；每次发送前当前专家及必要范围可见，执行中的本轮不能改专家。
3. **轮次**：每轮保存实际专家、依赖版本、输入、执行与结果引用。更换专家是同会话的下一轮，不重写之前消息，不等同多专家联合执行。
4. **历史**：点击会话恢复该会话；点击消息选择该轮右侧结果，与下一轮草稿及专家分离。未完成回复不冒充有新结果，最近有效结果有轮次提示。
5. **上下文**：新专家可按明确问题引用当前获准的已保存结果，保留时间、来源及性质；只传必要相关内容，不能将旧成绩当实时数据或以用户观点批准规则。不适用的输入清空，必要范围重新确认。
6. **在途**：同会话最多一个执行中任务；可切别的会话阅读，执行仍归原会话。返回后查询真实状态；迟到结果不更新别的会话右侧，不清空其草稿。
7. **原问题**：澄清回复、失败重试、原问题重核都绑定原请求／轮次的专家和范围；当前输入框另选专家时先说明原专家再提交，不能跨专家静默解决旧事项。
8. **恢复**：未发送文字切面板时保留；刷新故障只保证恢复服务端确认内容。会话重命名／归档与分析状态分离，归档可恢复。身份切换隔离消息、草稿和结果，重新鉴权后再显示。

没有新建会话文件夹、专家小组、通用任务编排、独立结果库或全历史自动重算需求。模型未配置的任务卡模式与真实自由提问是不同执行能力，均用同一对话工作区，分别说明并验收。

AI简报预设任务按[现行需求第5.4节](../新增-4.7-AI管理决策.md#54-ai简报发现问题与进入问策)先走业务草稿、真实试跑及人工正式生成；周期／窗口／服务委托授权在启用定期执行时补全。候选预览不开放组织读取，首次失败不能假发布；人工正式生成独立校验当前分析条件试跑、当次权限及统一发布门槛。服务授权与运行配置见[06第1.3节](06-界面结构与材料样例.md#13-后台处理服务配置)，与专家业务周期分工明确。

组织后台结果不插入个人历史，公共简报不消费私人假设。继续问策携带具体事项、原范围／时间和结果引用，预选专家并打开草稿，用户发送后解释当时保存结果；更新当前数据另由明确动作提交。原结果、当前事实及新轮次区分，引用重新校验当前114权限；返回保留原简报及阅读位置。

服务配置草稿与有效版本分开。检查、应用、停用自动、授权到期／撤销及运行失败都必须实际反馈；服务离线不显示正常，参数保存不算运行成功。由Codex走维护、读取、问策与恢复全流程；真实周期及新业务理解检查对应[05第8节](05-验收与审计整改对照.md#8-统一专家问策的增量验收)，目前均待执行。

### 7.1 本轮审计后的结果与修改规则

简报按统一准入保存事实与正式发布，可选解释独立追加版本；事实保存后解释仍占原工作名额及剩余预算，实际结束才释放，失败不清空数字，不显示成取数失败。详情区分别显示事实、解释及数据覆盖状态，原时间保留。UI合并接口回复以当前会话／计划、publicationSequence及解释版本为准，迟到回复不倒退结果，也不覆盖另一个会话草稿。

计划修改时说明影响：学期／对象／业务范围／数据源／方法变化暂停并重试跑；周期、名称、展示数量、预算只重查运行条件，同条件旧事实继续可读。新分析条件尚无正式结果时待生成，旧条件结果仅历史；启用、运行成功、解释成功分别显示。

指标核验的新观察项归AI简报，106目录保持既有需求范围。程序复算保存输入与三层加工核验分别显示结果；没有稳定历史／可比时点就待核，不将前者通过当三层均正确。具体执行子步骤见[04第14.5.9节](04-数据与运行技术规格.md#1459-二十个执行子步骤)。

发布发现错误时在有权维护者的正式结果详情撤回，原因必填，取消保持原状态。撤回后历史带原因可复看，观察卡和问策引用提示失效；修正后重新生成并关联原发布，不改旧轮次。已有合法事实但解释中断只标解释失败，不能自动重取一份事实。

恢复超时显示受阻、最后检查与处理入口；重新检查只核归属及退出证据，不忽略占用。处理完成前新执行不可提交，获准历史与诊断可读。具体准入、撤回和阶段规则见[04第14.5.11节](04-数据与运行技术规格.md#14511-发布准入撤回与阶段终结契约)。
