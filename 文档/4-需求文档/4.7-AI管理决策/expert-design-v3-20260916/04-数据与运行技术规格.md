# 数据、权限、运行与迁移技术规格 V3

2026-09-16。目标设计，尚未实施。范围仅为独立专家团；不修改业务主数据、不替换原决策简报或专家问策。

## 1. 已知基线与实施边界

现有expert_team接口仍声明structured，analyze在请求内计算后创建会话；重算更新最新request/result并保留前后标题摘要，80条限制仍在。独立team_document按plan_id存储，team_session只有当前完整结果，不应假定历史每轮资料均存在。前端有草稿与版本保护，但仍包含按expertId组织的缓存。以上是已有代码基线，不代表本轮重新测试服务或盘点数据库。

优先复用已确认的课程比较、有效成绩、培养进度、权限和源资料提取。新增研究容器及可靠执行不等于引入另一个业务事实库；正式计算不得转交模型临时生成SQL或脚本。

## 3. 正式资料准入与留存

### 3.1 从原文件到可用资料

接收→解析→字段与对象映射检查→业务规则/适用范围确认→数据校验→发布不可变版本。每一步保留操作者权限和结果。原文、人工录入和OCR都是输入，不因解析成功自动成为正式计算依据；模型生成的关联标为推议，不能直接发布为学校规则。

首期领导不直接上传任意文件供模型分析。文件通过既有获授权人员渠道进入；研究可以引用已发布资料和记录文字补充。治理入口可以复用既有流程或受控导入清单，不在领导页建设新经办平台。若现有流程缺少确认角色或记录，列为发布前依赖，不绕过。

批次发布记录字段覆盖、主键映射、适用年级/年度、来源日期、冲突和准入结果。方案中的目标、课程模块与实际开课、建设项目、学生完成情况分别建来源类型，不互相替代。规则冲突由获授权业务人员说明，发布新版本而不是直接覆盖。

### 3.2 新轮次的可追溯实现选择

原文采用内容寻址的不可变文件/文本版本，另保留页段定位及提取器版本；结构化计算保存参与计算的最小必要数据切片和规范化schema，或使用已确认可长期读取的上游不可变版本。首期默认选择本地受控的原文版本＋必要数据切片，不仅记哈希。

切片保留复算需要的字段、关联键、有效成绩选择结果、分子分母对象与排除理由；不无差别复制整个教务库。学生标识属于敏感内容，不写普通日志或未经批准的提示词；存储、备份和访问按学校批准的数据保护要求执行。

SourceBundle固定本轮采用的来源版本清单、各自截止时间、规则版本和一致性检查结果。源库不能提供同批次视图时，先从只读来源提取到隔离分析切片，再在该固定切片计算；一致性不足时停止受影响指标或只做明确标注的局部分析，不能把不同时间拼成同一时点。

新数据发布不改变旧来源包。资料撤回则保留审计元信息并重新鉴权，受影响历史可能被限制访问；不能承诺历史内容永远可见，也不能用新版假装旧依据。

留存、受控存储/备份及清理政策须以retention_policy_id绑定学校批准规则，生产发布前必须确认；本轮不擅自设置删除期限，也不执行删除。未知策略不得以无限收集敏感切片方式上线。测试资料使用明确的非正式或获授权范围。

## 4. 权限矩阵与来源访问

| 能力 | 教务处授权身份 | 学院授权身份 | 首期状态与返回边界 |
|---|---|---|---|
| 本权限范围方案详细比较 | 全校授权方案 | 本院授权方案 | 沿用现有授权；返回课程及已准入原文，不自动扩展其他数据权限 |
| 跨院方案摘要比较 | 授权全校范围 | 须单独获准 | 默认学院不开；获准后仅返回专业/版本、课程数量与类别汇总、共同/独有数量及计算说明等批准字段 |
| 跨院课程逐条/原文内容 | 按授权 | 不随聚合比较自动开放 | 若学校另有明确授权再增加能力；没有入口时解释聚合来源，不提供假的全文链接 |
| 学生群体统计 | 授权全校对象 | 本院授权对象 | 交叉小群体泄露风险按既有披露规则处理，不临时指定阈值 |
| 学生明细与成绩 | 实际授权内 | 本院且岗位允许 | 二次服务端检查；可比较不等于可下钻 |
| 研究、事件、标题、小结、意见、资料和下载 | 本人及当前合法身份/数据依赖 | 同左 | 当前权限重新校验；生成时授权和归属都不是永久通行证 |

学院未获得跨院比较权限时，候选只称“本院可比较范围”，不足2—3个不凑数。跨院摘要、课程原文和学生明细使用不同capability，不复制角色白名单。系统管理员及其他身份依既有专家团明确授权，不因其他AI菜单自动开放。

来源拒绝访问时，不先传到前端再隐藏。涉及不可访问依赖的整体结论不得通过保留原数字、删除候选来继续呈现；可返回合法的受限状态，并由用户在当前范围重新分析。更换身份立即隔离旧缓存，事件发布及下载前再次校验。

## 5. 问题处理与结果契约

入口先验身份及功能，再记录请求和运行。解析问题只允许映射已注册场景及白名单工具；模型本身及提交文本的发送范围也必须属于批准服务。未接获批模型时只开放明确支持的结构化问题，不把所有自然语言输入标为可用。

明确对象由服务端解析为合法引用，不能相信客户端给出的学生/方案ID。必须澄清时，运行以needs_input结束，不产生正式分析结果；新答复形成新轮次。明确范围在正式读取与计算前冻结。范围激活须检查提交时context_epoch，已有其他有效更改则先提示冲突，不覆盖。

普通提问自动选择可用且未排除的专家，实际参与才加入研究；不以成员列表作为能力授权。相关贡献共用SourceBundle，但每个metric_ref保留自己的计算定义。最多一主答两补充，依赖结果的串行、无依赖的在容量内并行，不暴露技术编排。

返回至少包含：问题类型、对象/范围、来源清单、可复算事实、管理判断及其支持关系、重要条件、可比较做法（需要时）、待明确事项、下一步动作及实际参与者。动作使用固定kind（view_source/read_table/submit_analysis/edit_opinion等），不能让模型生成任意执行命令。

正式数字由受控结果填入，文字解释不能改数、改分母或把资料缺项变为负面资格。结构校验和来源存在检查之外，须校验来源是否支持判断。资料/规则不一致阻止相应确定性判断；价值取舍不同则保留做法与条件，不以专家多数制造共识。

只需要读来源或整理已保存意见的操作不重跑全套分析。修改假设须新轮次，不能只改文字沿用旧数字。记录模型标识、方法/提示词版本、工具及业务规则版本，不能因文字不同就假定事实不同。

## 6. 有界运行契约

### 6.1 标识、占用与事务

用户操作的client_request_id识别同一逻辑提交；run_id识别轮次的运行；attempt_id与lease_generation识别执行尝试。同身份、研究、操作及请求标识幂等：同键同内容返回原结果/运行，同键不同内容返回冲突。首次提问创建研究、轮次、运行与待处理事件需一个原子事务，避免有研究没任务或重复空任务。

数据库原子保证同研究最多一个active运行（queued/running/cancel_requested）。领取任务同时更新租约代次；写入贡献、终态与当前指针时必须检查代次和取消状态，过期执行者不能发布。重要运行不依赖浏览器或一次HTTP连接。

耗时分析使用本模块可隔离的工作进程，监督与状态裁定不放在可能被计算或网络调用阻塞的同一执行循环。调用模型和耗时计算前释放数据库写事务，锁等待计入剩余预算。硬超时可中断或回收本模块工作进程并确认执行槽释放，不终止其他应用或无关服务；外部服务是否真正停止仍按实际返回与请求超时确认。该隔离、回收和重启行为必须通过E19—E20测试，不能只实现一个超时提示框。

### 6.2 工程起始配置（待目标环境验证，不是性能承诺）

| 参数 | 首期设计起始值 | 执行规则 |
|---|---|---|
| 同研究active运行 | 1 | 忙时仅保存下轮草稿，不隐式队列多个问题 |
| 全局执行/同用户active | 2 / 2 | 同用户active包含排队与执行；不同研究结果不能串用 |
| 全局等待队列 | 最多20项 | 容量满时不接受新运行，返回容量提示，保留输入，不建重复空研究 |
| 队列等待上限 | 60秒 | 到期failed(queue_timeout)，可主动重试，不无限等待 |
| 单轮运行预算 | 180秒 | 从领取起包含解析、读取、计算、模型、验证与自动重试；澄清为终态，不占等待用户时间 |
| 单次模型调用 | 最长45秒且不超过剩余预算 | 超时后只对可恢复错误按策略重试；实际服务上限更短时取更短 |
| 单轮模型调用次数 | 最多6次，含重试 | 超额停止扩展，返回已验证部分或失败，不无限追加专家 |
| 自动重试 | 同失败步骤最多1次，且总预算内 | 仅瞬时网络/执行中断；规则缺失、权限失败和无效输入不重试 |
| 工作租约/心跳 | 30秒 / 10秒 | 心跳必须小于租约；失效后原执行者失去发布权 |
| 取消逻辑裁定 | 正常服务下5秒内 | 返回已取消或已完成；不代表外部提供方已物理停止计费 |

全部预算同时生效，不将每步上限相加作为用户耗时承诺。这些参数用于首轮故障验证，测量后按版本调整并复验；未通过目标环境验证不得标为运行门禁通过。超时参数由服务端配置，客户端或自然语言不能覆盖。

取消后已失去发布权的外部调用仍占用对应资源计数，直到实际结束或请求超时，避免连续取消耗尽资源。服务整体停机期间不能更新终态；前端显示连接中断，服务恢复后依据截止时间和租约恢复或终止，不假装已经成功。

### 6.3 状态×事件×裁定

| 当前状态/事件 | 服务端处理与新状态 | 用户恢复方式 |
|---|---|---|
| queued/可执行 | 原子领取并锁定请求上下文及最新参与偏好→running | 可切换研究，读取既有内容；排队期偏好改变纳入本轮 |
| queued/等待到期 | failed(queue_timeout)，释放active占用 | 明确重新提交重试，不自动无限排队 |
| running/需澄清 | needs_input，保留问题及必要条件，不生成正式结论 | 用户回答后新轮次 |
| running/完整且验证通过 | completed，事务写结果及符合条件的当前指针 | 继续研究或离开 |
| running/只有独立部分有效 | partial，列明成功及失败依赖 | 可查看有效部分或明确重试失败部分 |
| running/无有效结果或预算耗尽 | failed，保留问题和安全诊断 | 同范围重试或修改问题 |
| queued/running/取消先获准 | cancel_requested→cancelled，代次失效，拒收迟到发布 | 重新发送新问题 |
| 已完成/收到取消 | 保持原终态，返回已经完成 | 用户决定继续使用或另开新轮次 |
| running/租约失效 | 有预算且属可恢复错误则新代次接管，否则failed | 显示正在恢复或失败，不重复发布 |
| 任意执行/权限撤回或版本紧急停用 | 阻止后续访问/发布，取消或受限失败 | 合法身份/能力恢复后再明确提交 |
| 任意终态/重复事件或旧执行者返回 | 不改变已裁定结果；记录安全诊断 | 不在页面出现重复结果 |

部分重试是显式新run并关联retry_of，使用相同范围/SourceBundle和成功贡献引用；冻结原失败部分，最终形成新不可变结果。来源、规则或范围已改变则不得拼接，必须新分析。用户不需要学习标识，但系统须区分重传、失败重试和新问题。

## 7. 当前判断、事件与材料的一致性

任何运行完成都可以在本研究所属轮次保存合法结果；只有context_epoch、scope、来源有效性及发布条件满足时，才能更新current_summary_id。旧范围结果不得改成当前判断。研究的后续来源更新先置stale提示，不自动触发模型调用。

状态事件带research_id、run_id、event_id、单调序号、安全上下文引用。客户端按研究归属路由、去重并检查身份代次；服务器先鉴权再发布，不依赖前端过滤。事件不是唯一存储，断线重连读取规范状态并按序号补取；不能凭没收到完成事件就再创建任务。

材料创建一次提交精确的result/progress/opinion/issue版本清单；服务端在同一事务验证引用、当前授权、保存状态及范围一致性后创建快照。不同来源时间可以被明确列出，但不能伪装同一时点；不同范围的结果只有用户明确选择、材料明确分栏时才能合并，不默认混用。

## 8. 草稿、意见与故障恢复

输入草稿与意见各用独立revision及幂等保存标识；成功应返回实际保存版本与时间。改变标题、聊天或参与者不能造成无关意见冲突。自动保存可合并细碎中间版本，但明确采纳、恢复及材料引用版本不可丢失。

冲突保留双方内容，比较后新版本提交；恢复也是新版本，不覆盖历史。网络结果未知先查操作结果。首期保存保证为最后一次服务端确认版本；内存中未保存文字不能保证刷新、崩溃或断电恢复，UI如实提示并提供重试/复制。未经学校批准不新增本地敏感持久副本；身份切换和退出隔离旧内容。

## 9. API实施约定

建议独立版本路径/api/admin/expert-research/v3；名称在实现时遵循项目规范，不能覆盖旧接口含义。

| 操作 | 目标接口与关键约定 |
|---|---|
| 目录可用性 | GET /catalog?scope_id=...，返回专家/场景的对象级状态及允许结果范围 |
| 首次提交 | POST /researches，含first_message、client_request_id及已知范围，原子建研究/轮次/运行 |
| 已有研究与历史 | GET/PATCH /researches/{id}；GET /researches/{id}/turns?before=cursor；改名/归档带metadata_revision |
| 新问题/明确业务动作 | POST /researches/{id}/turns，含expected_context_epoch、scope、kind及指定专家（可选） |
| 专家偏好 | GET/PATCH /researches/{id}/participants，独立participants_revision，支持加入和排除 |
| 草稿/意见 | GET/PATCH /drafts/new；/researches/{id}/draft；/opinion；/opinion/versions及restore，独立版本 |
| 待明确事项 | GET/POST/PATCH /researches/{id}/questions，状态变更校验来源发布与解决轮次，不允许客户端自行声称已确认 |
| 资料接收/发布查询 | 复用治理接口或/source-submissions、/source-publications，写入受专门权限控制，领导页不因可读自动可发布 |
| 来源定位 | GET /source-references/{id}，固定版本、允许字段及可用定位 |
| 运行/取消/重试 | GET /runs/{id}；POST /runs/{id}/cancel；POST /runs/{id}/retry，区分重传与新尝试 |
| 搜索与事件 | GET /researches/search；GET /researches/{id}/events?after=...，所有条目在返回前鉴权 |
| 材料 | POST /researches/{id}/materials；GET /materials/{id}；POST /materials/{id}/exports及受控下载 |

409须区分版本冲突、当前运行占用、请求标识内容不一致；422说明条件无效/待明确；429用于用户或队列容量限制，拒收不生成重复运行；权限错误不泄露被拒对象信息。规范响应包含request_id与可恢复动作，不记录完整敏感提示词。HTTP状态不直接当用户文案。

## 10. 旧场景映射与迁移切换

仅迁移现有独立expert_team会话，绝不把原决策简报或旧专家问策历史混入。以下映射说明新主线归属，不自动启用02中暂缓能力。

| program/similarity | P1 | 保留现存结果及新范围适配 |

| course/alignment | C3 | 旧记录可读，新执行受资料准入限制 |
| course/options | C4 | 保留做法与条件 |
| course/outcomes | C5 | 保留可比学期变化 |
| transfer/paths | T1 | 保留方案层衔接 |
| transfer/conditions | T5的准入规则子项 | 旧记录保留，正式规则未齐不启用资格计算 |

唯一映射键为旧库命名空间＋legacy_session_id。迁移保存原始记录、最新完整分析、当前已保存意见与时间；旧消息保留原文，只有摘要的旧轮次明确标记。最新完整分析作为新研究可继续起点，不猜测历史参数或恢复不存在的依据。

重跑遇到已有映射不覆盖新写入；源revision与切换点不一致须停止该条并处理冲突。校验数量、JSON/文本校验和、顺序、作者与权限，不按同专业或标题合并。

回退关闭新写入，但保留新库与合法只读访问。随版本提供只读兼容读取组件并纳入回退包；不能假定未经适配的旧二进制认识新数据。先加表与兼容接口，不删除旧数据；迁移和回退脚本要求可重复执行，实际编写及演练属于后续实现。

## 11. 专家发布、模型评测与运行维护

首期用研发维护的受控目录即可，不另建领导配置平台。新增专家必须有业务负责人、资料/权限要求、工具白名单、输出契约、固定测试、批准版本和停用方式。方法/提示词、模型、规则或输出schema变化均形成新版本并复验。

固定测试分别验证：确定性数字与集合；对象和意图；来源支持；管理推理；中文表达。相同事实下允许文字变化，不允许关键数字、范围、资格边界或受同一事实影响的判断无故漂移。用户强硬否定、已共开但有重复项目、基础课才是主要问题等反例必须纳入。文字检查失败可保留已验证事实，不能冒充完整专家意见。

运行维护记录失败类型、耗时、等待、取消、恢复、使用版本和资源计数，不默认保存敏感全文。备份/恢复、任务执行器及只读回退组件纳入现有隐藏后台服务机制，不打开可见终端作为长期服务。未演练前不宣称高可用或永久恢复。
