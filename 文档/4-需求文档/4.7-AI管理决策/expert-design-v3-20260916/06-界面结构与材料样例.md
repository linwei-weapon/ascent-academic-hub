# V3界面结构与讨论材料规格

本文件维护专家问策及资源管理的界面规格。当前V3.3前后端已实现，实际操作验收见05第8.1节。核对日期：2026-10-07。第6—6.1节保留此前资源管理记录；不将历史操作算为新增界面的验收。

## 1. 目标工作区：统一专家问策

本节是V3.3交互规格，依据[现行需求第5—6节](../新增-4.7-AI管理决策.md#5-唯一专家入口专家问策)。代码已将两个专家入口合并；左侧会话、中间对话、右侧结果，保留独立AI简报。当前管理员首期主流程已实操，具体截图和未验收范围见05第8.1节；第6节旧操作不能替代本次证据。

| 左侧：会话 | 中间：问策 | 右侧：结果 |
| --- | --- | --- |
| 新建会话、搜索 | 当前会话标题 | 所选第N轮／专家／时间 |
| 最近会话及必要状态 | 用户问题与专家主要回复 | 结果：判断、关键未知和下一步 |
| 点击恢复消息及结果 | 必要对象、学期、方案或年度的确认卡 | 数据：指标、图表／表格及记录数 |
| 名称、最近活动时间、专家辅助信息 | 消息旁查看结果；真实执行状态 | 依据：来源、口径、规则与保存证据 |
| 按需重命名、可恢复归档 | 底部固定输入框、＋选择专家、专家标记、发送／停止 | 可收起／展开，内容与所选消息一致 |

专家目录在＋面板中呈现名称、简短职责与可用性，不另设业务专家库首页；后台仍维护专家、技能和MCP三个模块。选择专家只改变后续发送者，不自动执行。

每轮只有一位专家；会话内可以更换。每条回复标明实际专家，右侧旧结果不会随当前输入框专家改变。点击旧消息不改变下一轮专家。重新核验原问题使用原轮次专家和范围，先明示再发送。

输入卡在必要时出现，展示条数移到数据区，专家／Skill／MCP配置和原始技术过程均按需查看。模型未接通时显示当前支持的任务卡，任意文字不能静默变成默认任务；真实自然语言模式独立验收。

桌面宽度足够时三栏，原系统导航可折叠；窄窗保留对话，历史和结果以可返回面板打开。没有结果时右侧收起或简短空态，不常驻空表格。新结果不抢正在阅读旧消息或编辑输入的焦点，右侧始终显示轮次、范围和数据时间。

具体状态和保存规则见[03第7节](03-交互与资料闭环规格.md#7-统一专家问策的会话与轮次规则)，开发拆解见[04第14节](04-数据与运行技术规格.md#14-统一专家问策的对话工作区开发计划)。本次只有文档修订，没有替换运行中的页面。

### 1.1 AI简报与问策衔接

AI简报读取[需求5.4](../新增-4.7-AI管理决策.md#54-ai简报发现问题与进入问策)的正式保存结果。头部只突出学期、开课院系、最近结果时间及更新状态；数据日期及覆盖边界就近说明，技术时间、版本和运行编号放详情。普通用户阅读、查看历史和刷新显示，不提交任务。

首期内容结构：

```text
AI简报  〔真实学期〕  〔授权开课院系〕     最近结果〔时间〕 〔更新状态〕
仅已接入记录 · 可核〔数量〕 · 尚需核对〔数量〕              [历史]

首修表现观察
〔课程名称〕 首修〔N〕人次，未通过〔U〕人次
通过率〔P/N〕；本范围可核记录参照〔ΣP/ΣN〕
选入理由：首修通过率低于本范围参照，存在首修未通过人次
[查看依据] [继续问策]

[查看全部观察课程]  〔重复／缺字段等数据核对提示〕
```

以上是字段线框，不是学校数据。首页前5条来自完整保存集合，不把前5条作为计算全集。未触发条件、无有效记录、仅一条可核记录和更新失败分别说明；未知不显示0，不展示全校健康状态。原failures不替代首修未通过人次。

查看依据打开原结果，包含有效集合、分母、同范围参照、实际条件及未知。已撤回或依据失效的结果显示原因及已有修正结果链接，不能继续作为有效观察问策。有管理、分析和发布范围权限的维护者可从正式结果详情撤回，填写原因、确认或取消；历史保留，修正另执行。

继续问策打开新草稿，预选课程专家，带具体课程、原范围、时间、获准引用及默认问题“为什么进入本次观察，哪些数字可以核实，还缺什么判断依据？”用户发送后先解释保存结果；不点击即执行，也不自动重跑全部课程。单独“更新当前数据”才新取数。返回恢复原简报与阅读位置，新结果不覆盖原卡。未接模型时提供确定性事实／条件说明，任意自由原因问题不假成功。

### 1.2 预设任务维护

专家管理详情内增加“预设任务”页签，资源维护仍为专家、技能、MCP三个模块。后台运行配置另在1.3的后台处理服务维护，不把业务周期重复写入该服务。

| 字段／操作 | 必填、默认与行为 |
| --- | --- |
| 名称、稳定编号、业务问题 | 必填；所属专家从详情带入。编号建立后不改，名称可改 |
| 已发布业务任务 | 必填，从该专家有效任务选择；Skill／MCP／处理器版本自动带出，新版需重新验证 |
| 学期及业务范围 | 必填，真实名称选择器；首期范围为全校或一个授权开课院系，明确组织含义，不提供任意技术ID |
| 后台处理服务 | 草稿可带入内置登记；人工试跑／正式生成只检查实际执行服务就绪与当前身份。启用自动时必填并展示任务／范围委托授权、有效期及可用性，缺授权不可自动运行 |
| 周期、时区、生效窗口 | 保存／人工试跑／人工正式生成选填，启用定期执行时必填；默认不自动运行。可建议每周一08:00、Asia/Shanghai，按实际数据更新确认；窗口结束停跑。测试验证计划可选5分钟及短窗口，验后停用并恢复正式计划 |
| 观察方法 | 只读展示绑定技能的口径和选入说明；不在计划表单重定义公式、正式阈值或排序 |
| 保存／取消／试运行 | 保存不执行，取消保留原有效版本。试跑使用当前真实身份，候选预览标识醒目；改变业务条件／计算依赖后旧试跑不满足启用条件，名称／周期／预算调整可保留相同分析条件试跑 |
| 启用并生成首期 | 通过当前分析条件有效试跑及实际服务、授权、依赖、窗口检查才可提交；显示首期运行进度。提交失败不显示启用成功，运行失败显示具体原因，不把候选发布 |
| 手动生成正式简报 | 单独操作，以本分析条件有效试跑、当前身份／发布范围及统一准入真实执行发布；不要求周期／窗口或服务委托授权，明确不代表定时通过 |
| 停用／删除／记录 | 停用只阻止新自动；无历史未启用任务可删除，有历史保留。手动计划下次计划显示未启用定期执行，记录含真实触发／成功／失败 |
| 正式结果撤回／修正 | 有权维护者在正式结果详情填写原因并撤回；取消不变，有冲突刷新后重新确认。历史显示原因，新生成可关联被更正发布，不直接编辑原数字 |

预设已启用、事实运行状态和AI解释状态分别显示，不能共用绿色“正常”。事实先保存，模型失败保留数字及明确解释失败；观察口径未核定时显示具体缺项，不给首修未通过或质量结论。数据或模型失败就近显示；权限错误只对有权维护者展示必要原因。改范围后的最新页面等待新范围正式结果，不沿用旧卡；只改周期／名称／预算保留同分析条件事实，详情仍显示原生成版本。

### 1.3 后台处理服务配置

系统管理增加“后台处理服务”；具体契约见[需求8.1](../新增-4.7-AI管理决策.md#81-后台处理服务管理)和[04第14.5节](04-数据与运行技术规格.md#145-ai简报的预设任务与周期执行)。管理员用此页判断是否能跑、修改服务参数和授权、处理故障；普通用户仅看业务结果，不进入该页。

```text
后台处理服务  〔实际服务及调度状态〕
名称〔专家分析处理服务〕  环境〔当前原型主机／测试〕  实际地址〔只读〕
[配置] [授权] [运行记录]

配置：数据连接〔已登记114引用〕  〔真实检查状态〕
      模型连接〔受保护引用或未配置〕 〔事实模式／已验证解释能力〕
      允许自动任务〔开关〕  超时〔180秒〕  网络重试〔0或1〕
      后台并发〔固定1，事实及解释合用名额〕
[保存草稿] [检查配置] [应用配置]       〔有效版／草稿版，实际检查时间〕

授权：允许任务〔已发布任务选择〕  组织范围〔授权选项〕
      生效时间〔日期时间〕  到期时间〔日期时间〕
      授予者〔只读〕  有效／到期／已撤销
[保存授权] [续期] [撤销授权]

运行记录：触发方式  预设问题  范围  开始时间  实际阶段  结果／原因
恢复受阻时：〔原因／最后检查〕 [只读诊断] [重新检查恢复]
```

| 字段及操作 | 校验和反馈 |
| --- | --- |
| 名称 | 必填可编辑；固定编码、内置类型、部署环境、地址和版本只读，首期不新增任意服务或删除内置登记 |
| 数据连接引用 | 必填，仅选择服务端登记的114连接；所属edu_source／edu_analytics_v3可读，凭据不回显；读取失败显示真实原因摘要 |
| 模型引用 | 事实模式可空；真实解释须有效配置及实际检查。填写模型名称不能变成“AI可用”，保留当前实际未配置状态 |
| 自动任务开关 | 影响新后台提交，默认关闭；打开需要有效授权和服务检查，不能覆盖计划未启用／窗口到期；交互问策独立 |
| 超时／重试 | 必填，180秒默认、20—300秒服务上限及任务更严上限；重试0／1，限定瞬时错误。并发1只读，不开放任意队列策略 |
| 授权任务／范围／有效期 | 全部必填，服务端验证授予者当前114权限上限。首期C-PERFORMANCE及一个试点范围；不把数据库连接当全校数据权 |
| 保存草稿／检查／应用 | 草稿不影响运行；检查调用真实服务、只读数据、授权及依赖，分项展示通过／失败／未知；应用做冲突校验，失败保留旧版，成功显示生效版本 |
| 停用自动任务／撤销授权 | 文案分别说明新任务停止与不合法在途阻断；取消确认保持原状态。授权变化即时校验，一般预算影响后续任务；保留记录 |
| 心跳与日志 | 心跳、调度及最近错误来自实际观测，日志脱敏且按管理权限读取。失联显示无法访问和最后可知时间，不声称缓存状态仍健康 |
| 运行及恢复 | 从失败进入原运行／计划；恢复超时显示受阻，新执行不可提交，历史可读；诊断和重新检查不接受命令／PID，实际旧进程结束才恢复。仅解释中断不重取事实；物理清理由既有启动／诊断机制处理 |

数据源变化要重试跑、授权变化立即校验；模型引用变化只重验解释能力，失败继续显示事实模式，不清空事实。预算／名称／周期调整不改变业务分析条件。业务问题、学期和周期只在专家预设任务维护，工具接入参数只在MCP维护；本页不复制它们。

首期服务授权独立于授予者浏览器会话，到期及撤销是真实控制；不承诺114人员角色变化自动撤销登记授权。状态详情明确有效期和授予者，续期再次检验当前身份范围。操作闭环包含必填、取消、草稿、检查、应用、启停、续期、撤销、保存冲突和故障复看，不以几个静态开关算实现。

### 1.4 指标核验与结果状态衔接

指标核验目录区分教学总览／106与AI简报；新首修观察项只能出现在AI简报，引用既有指标显示其真实名称及版本。模块切换清空不适用结果、保留各自筛选，不把AI包回退为106内容；未登记显示未登记。

依据详情提供“程序复算”及“三层数据核验”的独立状态和SQL／记录数／比较时点。缺可比依据时显示待核或不可比较，不把保存输入复算成功写成贴源、事实和应用均一致。不新增独立核验页面，复用既有模块和该项详情链接。正式观察还须实际语义及参照可比、指标登记、本次复算成立；三层只缺可比时点可限定呈现，已确认实质矛盾阻止受影响结论，具体见[14.5.11](04-数据与运行技术规格.md#14511-发布准入撤回与阶段终结契约)。

撤回及明确错误依据导致的失效在列表、详情、依据和问策入口一致显示；有修正结果提供链接，无有效结果则待重新生成。停止自动任务不能代替撤回错误结果。

历史默认固定实际事实及解释版本；新解释可选择新版本，旧版本内容不覆写。服务页和专家详情的运行记录打开同一执行详情，分别保留返回过滤和位置。晚到状态按publicationSequence／解释版本校验，不能覆盖当前结果。

## 2. 四个关键交互结构

### 2.1 岗位不同，起始问题不同

处长首页可见少量问题示例：专业培养差异是否需要论证、跨院共同课程有哪些值得了解的问题、本届毕业准备有哪些共性堵点。院长示例：本院哪些关键课值得先了解、本院专业培养差异体现在哪里、哪些共同补修条件需要学校支持。

这些是业务入口，不预先给定结论，也不自动使用不清楚的届次。用户可直接写自己的问题，场景分类不成为必经表单。

### 2.2 待明确事项不是待办看板

```text
尚需明确 · 课程K101的开课与建设情况              [暂缓]
影响：目前不能判断是否应提出共同开课或资源建设建议
已有：培养方案课程表、领导补充“已经共开”
还需：该期教学任务记录；若讨论投入，再补建设项目资料
状态：已提交待确认
[查看关联资料] [导出需明确事项]

资料发布后：有已确认资料，可以继续分析           [继续分析]
新分析后：开课方式已明确；建设投入问题仍待明确     [查看变化]
```

事项必须具体到影响的判断，不显示含混的“证据不充分”。资料发布不自动关闭事项或运行新模型。暂缓只表示用户现在不继续，不等于事实成立或管理决定完成。

### 2.3 我的意见与依据对照

```text
主讨论与比较表                         │ 我的意见                [关闭]
保持原阅读位置                         │ 已保存于…… / 暂未保存
                                       │ 用户可直接写下当前想法
                                       │ 系统整理先预览，采纳才写入
                                       │
                                       │ 固定参考摘录（最多一段）
                                       │ 资料名称 · 实际使用版本
                                       │ 简短原文或计算说明
                                       │ [查看完整资料] [移除摘录]
```

完整资料打开前保留文字、选区和阅读位置，返回不丢当前编辑。窄窗口采用覆盖式面板，提供清楚的返回，不把正文压成窄条。单段摘录供对照，长表和多文件比较仍在主区或完整资料视图。

### 2.4 添加、排除与资料条件

专家选择窗按业务问题检索，专家条目包含职责、当前可支持的子能力、已保留/实际参与记录。资料不足只提供具体缺项说明，不让用户误以为点加入即可生成正式结果。

加入按钮文案为“加入本研究”，注明不会立即分析。已经明确发送的业务问题不额外弹这个窗。主动移出明确后续排除，紧急停用则提示该方法版本不能继续发布新结果；两种状态不能只用同一个灰色图标。

## 3. 管理内容样例：有用，但不超出依据

以下专业、课程、数字、资料状态全部为设计假设，不是学校数据，不能直接用于正式报告或证明系统已具备对应能力。

### 3.1 首轮：已知课程结构，建设资料不足

研究问题：两个专业的课程是否有必要调整？

目前判断：现有课程结构不足以支持直接减课或提出共建安排，但已经可以明确需要进一步说明哪些培养任务与现有安排。

关键事实示例：同版本、排除公共课后的逐门必修范围中，双方各52门，共同24门、合并去重80门，结构重合30.0%，各自共同部分占46.2%。其中18门基础、4门主干、2门实践只作分类；不由此认定前18门合理、后6门应调整。

处长看到的管理含义：本轮可形成向相关学院了解培养分工的具体问题；现阶段不宜仅凭该比例提出整合任务。院长看到的管理含义：先对照本院目标与共同课程承担的训练任务，挑出已有明确疑点的课程进一步研究，没有理由时不强行排重点。

下一步：“对照共同课程的培养任务”“列出需明确的开课与建设情况”。已有确认资料时直接给出具体条款和差异，不继续用“建议查看”替代内容。

### 3.2 领导补充：这些课程已经共同开设

回应：这项补充影响我们对开课组织方式的了解。可以先按已经共开的情况讨论，原课程结构数字不变；培养任务差异及建设投入是否重复仍需分别看资料，不能因此直接认定不存在问题。

页面只更新开课组织对应的条件说明，保留文字补充的来源类别。正式教学任务记录发布并经新分析使用后，该开课方式缺项标为已明确；其他缺项保留。不能把一次领导补充自动当成所有资料问题都解决。

### 3.3 规则齐备时不回避明确计算

在规则已确认、必要记录完整且该能力通过准入时，结果可以写：“按本年度已确认规则，该项课程条件满足；另有一项业务认定尚待确认。”同时显示规则、对象与具体结果。

这不同于“已经获得推免资格”或“正式审核通过”。不能把未确认写为不符合，也不能因为正式决定不由本系统作出，就只反复显示数据不足而回避可计算条件。

## 4. 讨论稿的成品要求

### 4.1 首期明确交付

网页内容预览＋可编辑DOCX文件。首期不交付复杂在线排版编辑器、协作审批或自动发送；PDF可在后续单独增加。预览只承诺内容对应，正式分页须在生成DOCX后实际渲染检查，不能把网页截图当Word排版验收。

讨论稿默认结构：

```text
关于〔研究事项〕的讨论稿
范围：……  适用年度/年级：……  数据截至：……

一、目前可以明确的情况
直接判断＋必要事实，不大段复制聊天

二、可供讨论的做法（有必要才出现）
现状 / 做法甲 / 做法乙
解决问题、影响对象、必要条件、需说明或协调事项

三、当前想法（用户已保存且选择加入时才出现）
保留用户原意；没有意见不编造“领导认为”

四、尚需明确的事项（存在时出现）
具体问题、影响、已有资料、尚缺内容

附：计算口径、来源与实际使用版本
研究编号、形成时间、材料版本
```

不默认出现会议人员、决议、责任单位、完成期限或批准状态。可明确业务环节与已有时间窗口，但须有实际校历、规则或安排来源，不能自动派出任务。

### 4.2 阅读与排版约定

默认A4纵向、约24毫米页边距，中文正文建议12磅、1.5倍行距，标题约18磅；使用部署环境可用的规范中文字体，不以罕见字体影响打开。这是排版起点，实际生成后按内容验证。

正文优先一至两页管理摘要，课程明细与来源移至附表；不为限制页数删除重要边界。表格有列标题、重复表头、清楚单位，长表分页；宽表拆为概要比较和详细附表，不把字缩小到难读。无数据用准确文字说明，不留看似为0的空格。

来源附录使用可定位的资料名称、使用版本、数据时间、条款/页段或计算说明，不把内部数据库路径和技术日志塞给领导。必要条件靠近对应结论，不在最后一页用大段免责文字兜底。

### 4.3 旧材料、修改与权限

服务器保存精确版本快照。重新整理生成新稿，旧稿不随聊天或资料变化被替换；再次使用旧稿时提示它的数据日期以及此后研究中的已知变化，用户可查看原稿或生成新版。

下载再次校验当前权限。导出后用户自行修改不改变平台原版，也不能保证平台识别所有离线修改；材料标明平台原版版本便于区分。已经下载的文件不能承诺随权限撤回自动消失。

## 5. 原型评审范围

- 专家库按专业建设、课程质量、转专业、推免准备、毕业准备五类展示职责、支持事项、实际发布版本及缺项。选择方法和数据范围后运行；自然语言问题作为研究背景，不声称任意提问都能自动路由或调用大模型。
- 三个模块分别提供分类筛选、卡片／列表视图、新增、复制、修改配置、引用查看、删除和恢复。删除为可恢复删除，当前草稿或发布版本仍引用的资源禁止删除，并列出关联对象。专家编辑依次为基本与职责、能力与依赖、测试与发布。Skill列明输入、输出、处理步骤、计算规则、证据要求、工具依赖及样例；MCP列明只读工具及参数、返回结构和真实连接检查。专家选择可复用技能，MCP依赖从Skill推导；技能绑定已发布的内部MCP工具，MCP可从受控模板建立独立工具组合。尚未实现处理器的空白技能明确显示待接入。
- 第一版提供五专家、九个方法包、一个教学数据MCP及七个只读工具。25个原研究场景在资源目录的coverage.md说明覆盖或缺项；没有年度政策、容量证据、已确认的课程目标资料时，不能生成对应正式判断。
- 专家及Skill初始为草稿。真实技术测试、业务复核、发布分开记录；编辑使草稿测试与复核失效；发布固定依赖版本。旧研究保留使用版本与结果，新研究使用当前发布版；停用立即阻止新调用。
- 测试及研究读取配置中的114测试库；资源定义、发布版本和研究记录存入本地原型SQLite控制库。两者在页面与部署说明中区分。学校业务表仅只读，不写回源数据，不用本地样例替代查询。
- 当前数据快照保留本次实际返回结果与时间，不承诺按历史批次重建数据库。学院范围需在服务器校验；未知范围拒绝，课程学院筛选明确为开课院系口径。

### 6.1 截图字段与当前维护流程

专家管理提供必填名称、固定应用编码、图标、共享分类、描述、运行方式、模型标识、迭代上限、沙箱要求、专家类型、子专家、已发布技能绑定、人设及欢迎语。确定性专家无需模型；模型专家须填写模型标识，但当前没有接入模型执行器。编排专家至少关联一个子专家，禁止自引用及循环。MCP由技能自动带出，只读展示。分类可选择或输入；运行配置保存为草稿，不自动改变已发布计算。

技能管理新增采用“技能包→基本信息”两步：ZIP解析仅检查不写数据库，确认后保存。包须有根目录或唯一子目录根的SKILL.md、非空name/version/description。路径归一化后须为ASCII相对路径，禁止上级路径、重复、加密、符号链接及非UTF8文本。支持文本技能包，拒绝二进制而不丢弃内容；界面展示完整文本文件。压缩包最多2MB，最多100文件，单文件120KB，保存的预览结构最多150KB。更新包保持name并提升语义版本，记录revision防止并发覆盖；新包不继承旧执行处理器或测试资格。包解析仅识别必需元数据和多行描述，其他front matter保留原文，不自动建立运行依赖。

MCP管理区分内部工具、原生MCP和HTTP接口转MCP。维护稳定编码、描述、服务地址、连接方式和请求头；请求头值不返回浏览器，同名留空保留，移除行删除配置。外部连接参数可保存，未接协议执行器前不能测试成功或发布。内部服务继续使用真实只读工具及工具契约。

专家卡片提供独立测试对话入口，左侧历史、主区实际结果和范围输入、历史产出回看。当前确定性专家执行已发布业务技能并保存研究，问题作为背景；草稿测试仍在配置页。模型对话、语音、文件解析、沙箱及编排没有执行器时明确显示不可用，不生成模拟回复。测试对话路由继承专家管理准入，接口再次校验身份与数据范围。

操作核查：新建／复制→保存→测试→业务核对→发布→专家团使用；修改建立新草稿，停用阻止新执行，引用阻止删除，软删除可恢复且恢复后停用。管理配置闭环与执行能力分开验收：七个登记技能使用114真实库；新上传包、模型、编排及外部服务目前止于“已保存、待接入”，不能标为运行闭环已完成。Nacos和Loom不是本原型基础设施，不显示虚假同步成功。

#### 配置与发布

新建/导入 → 确认基本信息 → 绑定实际执行与依赖 → 候选测试 → 核对业务 → 发布。测试固定草稿revision及代码指纹，不要求先发布；修改候选内容后重新测试。候选返回testRunId并明确开发用途，不能给正式研究当上游结果。候选能力不作为已发布专家的必需依赖。

编辑形成新草稿，旧发布内容保持。代码变更导致旧执行指纹不兼容时，旧版不可新执行且显示理由；候选回归后重新发布并更新专家绑定。旧研究显示“查看原结果/使用新版本重新分析”，不静默改版本，也不保证旧代码永久可运行。

规则维护显示来源、年份、对象、候选条款、结构化条件及确认记录。无确认权时只能提交或导入外部确认依据，不显示可自行批准的按钮。冲突位置、否决理由和重新提交入口可见。

删除前显示当前引用；软删除可恢复，恢复保持停用；重新启用前检查依赖。旧版本和研究不因删除资源被物理清空。

#### 用户分析

默认页面展示专家的业务任务、真实可用范围和必要对象。选任务和直接提问是两种入口；直接提问在模型可用时启用，不要求填写技术taskId。确定性入口按明示参数执行，文字备注仅保存；发送前展示实际范围。只补充影响结果的条件；澄清答案关联原问题，执行无需一直等待用户。Skill、MCP、版本及过程放入详情，用户无需配置才能分析。

结果主要区域显示：本轮范围、执行状态、事实/规则核验/假设标签、主要结果、条件未知、重要依据和下一步。方案比较默认可查看双方差异；课程分析默认呈现统计粒度；毕业核验默认呈现所核条件范围，不能将局部全满足显示为整体毕业通过。

来源和完整证据按权限展开；技术查询预览不抢占阅读主区。预览条数调整只改变表格，不改变统计和留存证据。遇到缺项，显示“需要什么、影响什么、补齐后继续原问题”，不要求用户新建研究或进入资源配置。

来源覆盖未知与证据留存完整分别提示；缺成绩记录不自动显示未完成。证据默认显示来源时间、源查询/保留条数及影响范围，展开读取原resultId保留内容，不能取当前库冒充历史。资料动态不增加研究对话轮次；最新回复和最近有效分析分开显示。

测试对话按实际执行方式标识：确定性模式显示真实技能结果；模型模式显示实际模型和调用阶段，模型尚未接通时保持不可用。语音、上传资料、多专家和沙箱均按真实处理能力启用，测试页不会生成模拟回复。

旧结果保留时间和版本，出现已知变化时提示查看原结果或新执行。身份变化立即隔离缓存，旧请求不得回填新身份。执行失败、保存失败、部分结果与业务未知分别提示，保留问题并给出明确恢复动作。

未知网络结果先查原请求；明确失败后用新编号重试。授权失效显示重新登录入口，服务重启失授权说明旧任务已经终止；恢复为关联的新执行，不称继续旧授权。保存失败没有正式结果编号。下游选择器只选当前获准、用途及证据满足任务的实际保存结果，候选测试结果不可选。

专家：新增 → 编辑字段 → 绑定技能 → 测试 → 发布 → 分析 → 停用 → 引用检查 → 删除/恢复。
