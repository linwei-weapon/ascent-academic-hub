# V3界面结构与讨论材料规格

2026-09-16。本文件是修订后的页面结构稿与内容样例，不是已实现页面、可点击原型或渲染通过的DOCX。V2两张静态图保留为历史探索，不再作为V3交互定稿。

## 1. 默认工作区：问题与进展居中，专家操作次级

```text
原系统导航 │ 我的研究                  │ 两个专业的培养安排是否需要进一步论证
           │ ＋ 新建研究    搜索        │ 工作身份 · 对象/适用年级 · 数据截至时间
           │                           │
           │ ● 当前研究                │ 本题进展
           │   本院关键课程问题        │ 目前判断：一句话说明当前能判断到哪里
           │   本届毕业准备            │ 尚需明确：具体事项1、事项2       查看
           │   查看归档                │ 上次变化：有变化才显示，不堆空栏目
           │                           │
           │                           │ 连续讨论：提问、具体事实、判断和条件
           │                           │ 宽表及做法比较留在这里
           │                           │ 来源入口就近；不设常驻数字墙
           │                           │
           │ 本次专家 ▾                │ [对照培养任务] [列出需明确的情况]
           │ 专业建设（已参与）        │
           │ 课程质量（本轮未参与）    │ 写下问题或补充情况……
           │ ＋ 添加专家               │ 默认四行，最多八行    回车换行 [发送]
           │ 收起研究栏                │ [查看资料] [我的意见] [整理讨论材料]
```

图中的状态文字描述实际参与情况，不把左栏所有专家当成本轮发言者。自动分析可以使用符合权限、资料和排除偏好的相关能力；不要求用户先打开专家选择窗。手动添加仍保留，满足用户主动组织分析视角的需要。

“本题进展”提供恢复研究所需的最少信息，不是一张重复整篇回答的结论卡。首轮无变化时仅显示当前判断与必要缺项；离开后回来才更突出变化。没有缺项时不保留空框，也不强迫领导写意见。

视觉沿用白底、浅灰分区及克制紫色。重要操作有文字，紫色不同时承担普通、警告和完成三种含义。弱化重复头像、装饰卡片和多余留白；不依靠“专家正在思考”等拟人化演出来提供状态反馈。

## 2. 四个关键交互结构

### 2.1 岗位不同，起始问题不同

处长首页可见少量问题示例：专业培养差异是否需要论证、跨院共同课程有哪些值得了解的问题、本届毕业准备有哪些共性堵点。院长示例：本院哪些关键课值得先了解、本院专业培养差异体现在哪里、哪些共同补修条件需要学校支持。

这些是业务入口，不预先给定结论，也不自动使用不清楚的届次。用户可直接写自己的问题，场景分类不成为必经表单。

### 2.2 待明确事项不是待办看板

```text
尚需明确 · 课程K101的开课与建设情况              [暂缓]
影响：目前不能判断是否应提出共同开课或资源建设建议
已有：培养方案课程表、领导补充“已经共开”
还需：该期教学任务记录；若讨论投入，再补建设项目资料
状态：已提交待确认
[查看关联资料] [导出需明确事项]

资料发布后：有已确认资料，可以继续分析           [继续分析]
新分析后：开课方式已明确；建设投入问题仍待明确     [查看变化]
```

事项必须具体到影响的判断，不显示含混的“证据不充分”。资料发布不自动关闭事项或运行新模型。暂缓只表示用户现在不继续，不等于事实成立或管理决定完成。

### 2.3 我的意见与依据对照

```text
主讨论与比较表                         │ 我的意见                [关闭]
保持原阅读位置                         │ 已保存于…… / 暂未保存
                                       │ 用户可直接写下当前想法
                                       │ 系统整理先预览，采纳才写入
                                       │
                                       │ 固定参考摘录（最多一段）
                                       │ 资料名称 · 实际使用版本
                                       │ 简短原文或计算说明
                                       │ [查看完整资料] [移除摘录]
```

完整资料打开前保留文字、选区和阅读位置，返回不丢当前编辑。窄窗口采用覆盖式面板，提供清楚的返回，不把正文压成窄条。单段摘录供对照，长表和多文件比较仍在主区或完整资料视图。

### 2.4 添加、排除与资料条件

专家选择窗按业务问题检索，专家条目包含职责、当前可支持的子能力、已保留/实际参与记录。资料不足只提供具体缺项说明，不让用户误以为点加入即可生成正式结果。

加入按钮文案为“加入本研究”，注明不会立即分析。已经明确发送的业务问题不额外弹这个窗。主动移出明确后续排除，紧急停用则提示该方法版本不能继续发布新结果；两种状态不能只用同一个灰色图标。

## 3. 管理内容样例：有用，但不超出依据

以下专业、课程、数字、资料状态全部为设计假设，不是学校数据，不能直接用于正式报告或证明系统已具备对应能力。

### 3.1 首轮：已知课程结构，建设资料不足

研究问题：两个专业的课程是否有必要调整？

目前判断：现有课程结构不足以支持直接减课或提出共建安排，但已经可以明确需要进一步说明哪些培养任务与现有安排。

关键事实示例：同版本、排除公共课后的逐门必修范围中，双方各52门，共同24门、合并去重80门，结构重合30.0%，各自共同部分占46.2%。其中18门基础、4门主干、2门实践只作分类；不由此认定前18门合理、后6门应调整。

处长看到的管理含义：本轮可形成向相关学院了解培养分工的具体问题；现阶段不宜仅凭该比例提出整合任务。院长看到的管理含义：先对照本院目标与共同课程承担的训练任务，挑出已有明确疑点的课程进一步研究，没有理由时不强行排重点。

下一步：“对照共同课程的培养任务”“列出需明确的开课与建设情况”。已有确认资料时直接给出具体条款和差异，不继续用“建议查看”替代内容。

### 3.2 领导补充：这些课程已经共同开设

回应：这项补充影响我们对开课组织方式的了解。可以先按已经共开的情况讨论，原课程结构数字不变；培养任务差异及建设投入是否重复仍需分别看资料，不能因此直接认定不存在问题。

页面只更新开课组织对应的条件说明，保留文字补充的来源类别。正式教学任务记录发布并经新分析使用后，该开课方式缺项标为已明确；其他缺项保留。不能把一次领导补充自动当成所有资料问题都解决。

### 3.3 规则齐备时不回避明确计算

在规则已确认、必要记录完整且该能力通过准入时，结果可以写：“按本年度已确认规则，该项课程条件满足；另有一项业务认定尚待确认。”同时显示规则、对象与具体结果。

这不同于“已经获得推免资格”或“正式审核通过”。不能把未确认写为不符合，也不能因为正式决定不由本系统作出，就只反复显示数据不足而回避可计算条件。

## 4. 讨论稿的成品要求

### 4.1 首期明确交付

网页内容预览＋可编辑DOCX文件。首期不交付复杂在线排版编辑器、协作审批或自动发送；PDF可在后续单独增加。预览只承诺内容对应，正式分页须在生成DOCX后实际渲染检查，不能把网页截图当Word排版验收。

讨论稿默认结构：

```text
关于〔研究事项〕的讨论稿
范围：……  适用年度/年级：……  数据截至：……

一、目前可以明确的情况
直接判断＋必要事实，不大段复制聊天

二、可供讨论的做法（有必要才出现）
现状 / 做法甲 / 做法乙
解决问题、影响对象、必要条件、需说明或协调事项

三、当前想法（用户已保存且选择加入时才出现）
保留用户原意；没有意见不编造“领导认为”

四、尚需明确的事项（存在时出现）
具体问题、影响、已有资料、尚缺内容

附：计算口径、来源与实际使用版本
研究编号、形成时间、材料版本
```

不默认出现会议人员、决议、责任单位、完成期限或批准状态。可明确业务环节与已有时间窗口，但须有实际校历、规则或安排来源，不能自动派出任务。

### 4.2 阅读与排版约定

默认A4纵向、约24毫米页边距，中文正文建议12磅、1.5倍行距，标题约18磅；使用部署环境可用的规范中文字体，不以罕见字体影响打开。这是排版起点，实际生成后按内容验证。

正文优先一至两页管理摘要，课程明细与来源移至附表；不为限制页数删除重要边界。表格有列标题、重复表头、清楚单位，长表分页；宽表拆为概要比较和详细附表，不把字缩小到难读。无数据用准确文字说明，不留看似为0的空格。

来源附录使用可定位的资料名称、使用版本、数据时间、条款/页段或计算说明，不把内部数据库路径和技术日志塞给领导。必要条件靠近对应结论，不在最后一页用大段免责文字兜底。

### 4.3 旧材料、修改与权限

服务器保存精确版本快照。重新整理生成新稿，旧稿不随聊天或资料变化被替换；再次使用旧稿时提示它的数据日期以及此后研究中的已知变化，用户可查看原稿或生成新版。

下载再次校验当前权限。导出后用户自行修改不改变平台原版，也不能保证平台识别所有离线修改；材料标明平台原版版本便于区分。已经下载的文件不能承诺随权限撤回自动消失。

## 5. 原型评审范围

至少连续走通：岗位提问→明确范围→查看有效判断→业务动作自动补充→有限修正→建立待明确→资料发布后主动分析→更新相关事项→保存想法→切换返回→预览讨论稿。

另外验证失败、取消、断网、保存冲突、跨院无权限、资料版本撤回、专家排除和紧急停用。完整状态与通过标准见05。V3本轮交付结构规格，不把上述状态标成已经实现或操作通过。
