# 专家卡片调整与真实任务体验审查

2026-09-16｜EXP-V3-UI-02 / EXP-V3-USE-01

## 结论

**卡片入口和新建操作的本次专项检查通过；专业建设真实研究任务未通过，不能评价为已适合领导日常独立使用。**

这次不只检查按钮、页面尺寸和接口。以教务处处长身份，在运行中的页面亲自选择两个专业，提出管理问题、阅读结果、纠正分析范围、保存自己的意见、整理材料、查看来源并归档。真实操作暴露出：系统能保存研究，却还不能可靠接住领导的追问；材料有内容，但没有按管理讨论组织。

图形只在帮助理解具体问题时采用，不启动全校三维关系图开发。当前优先级是业务对话、重要资料问题的处理和讨论材料，而不是增加视觉复杂度。

## 二、实际操作的研究任务

身份：教务处处长。问题：人工智能与计算机科学与技术是否需要进一步论证培养分工和课程安排。

资料：2022级人工智能专业培养方案、2022级计算机科学与技术专业培养方案。只分析当前真实导入资料，不代表学校已发布认定。

首轮实际输入：

> 【体验走查】人工智能与计算机科学与技术这两个专业，是否存在课程重复、培养特色不够清晰的问题？请先给出目前能成立的判断，再说明共同课程是否合理，以及学院应优先论证什么。

纠正范围的实际追问：

> 先不判断专业特色。请把公共课程排除，只列双方已经明确属于专业基础和专业主干的共同课程；分类不清楚的单列。告诉我这次可以请学院核对的具体课程和培养目标材料是什么。

| 步骤 | 页面实际表现 | 使用感受与判定 |
|---|---|---|
| 选择专家和两份方案 | 卡片详情和准备问题可操作；培养方案选择成功 | 可完成；首次分析仍显示“补充”，概念不一致 |
| 提出问题 | 首轮长问题直接变成页面大标题 | 在实际侧栏浏览器中占据多行，挤压结果阅读；不通过 |
| 阅读初步判断 | 首屏强调273门共同课程、365门并集、74.8%重合 | 所有课程的代码对照不等于专业课程相似；注意力被总体数字吸引，不通过 |
| 查看课程分层 | 双方公共课程共有250门；基础共有1门、主干共有0门 | 公共课程决定整体数值观感；应先说明与管理问题相关的范围，不应要求领导自行拆解 |
| 查看培养定位 | 人工智能原文培养目标实际为石油工程表述；系统已识别不一致 | 关键问题藏在折叠说明中，主结果仍继续组织特色讨论；不通过 |
| 自然语言纠正范围 | 明确要求排除公共课程、分类不清单列后，仍返回全部课程的273门与74.8% | 没有明确说明请求未执行，也未按要求给出可用部分；不通过 |
| 保存个人意见 | 填写意见、保存版本、查看历史成功 | 基础操作通过；时间仍为技术格式，阅读不友好 |
| 整理讨论材料 | 默认不选入个人意见，确认后生成独立材料成功 | 选择与保存通过；几百行课程表先于个人意见，不适合会前快速阅读，不通过 |
| 查看资料来源 | 有冻结资料和版本；首先展示大段计算规则，原文位置靠后 | 想确认培养目标归属时，需要额外翻找；来源存在不等于查阅顺手 |
| 归档并新建 | 本条体验研究成功归档，内容仍保留；新建回到空问题、展开范围并聚焦输入 | 通过；未删除任何已有研究 |

注意：不同层次的共同课程数不能未经确认直接相加或用“273−250”冒充正式专业共同课程数，双方课程可能存在跨类别对应。上述分层数字只复述实际表格，不推导新的正式指标。

## 三、关键发现及根因

### P1-01：看似在对话，实际没有接住纠正

观察：追问明确改变范围，回复仍沿用全部课程，且未明确承认未执行。

代码对应：`expert_research/service.py`的`resolve`和`expert_team/conversation.py`主要支持固定范围短语与关键词。组合请求、否定要求和多个约束未被可靠识别；“先不判断专业特色”仍含关键词，不能视为用户要求分析特色。目前未配置开放模型服务。

影响：领导会以为系统已按新要求计算，从而误读后续结论。这比按钮失效更危险。

整改要求：识别当前对象、排除条件、希望回答的问题及暂不讨论的内容；提交前后均展示实际采用范围。请求无法执行或资料不支持时，明确指出哪部分未执行，提供可完成的下一步，不得悄悄沿用旧范围。仅增加一个精确短语不能算完成。

### P1-02：重要资料问题没有改变回答顺序

观察：人工智能方案名称与培养目标原文不一致，仍先展示整体重合率及特色相关材料。

影响：领导先受到数字和错误原文的影响，再在下方读到限制；免责声明没有阻止不可靠判断进入讨论。

整改要求：先说明“这份培养目标暂不能用于判断专业定位”及具体来源；隔离受影响结论，保留仍可靠的结构对照，不把所有研究一并封锁。不能让冲突内容作为“目前可以明确的情况”进入材料正文。

### P1-03：数字组织与管理问题不匹配

观察：公共课程占据共同课程主体，“相近”对象也受全部课程池影响；建议逐项说明273门共同课程的培养任务，工作量缺乏现实性。

影响：处长需要决定先讨论什么、请哪个学院说明什么，不需要收到未经筛选的大清单。

整改要求：按管理问题给出能够成立的判断、影响判断的缺项、少量具体讨论事项及对应课程/材料。公共课程是合理共同基础的可能来源，不自动算重复建设，也不能一律视为无管理价值。分类不明的课程另列，不能凑成专业排名。

### P1-04：讨论材料是结果集合，不是讨论稿

观察：范围、概览及多张长表在前，个人意见在后；培养目标冲突内容仍出现在主材料中。

整改要求：正文按“研究事项—目前看法—需讨论的分歧与做法—需补充的情况”组织，领导意见明确标为个人意见；关键依据就近简列。完整课程清单与计算说明放附录。没有可比做法时，直说条件不足，不生成虚假的方案比较。Word分页仍需另外验收。

### P2：阅读与操作细节

- 短标题与原始问题分开：标题可编辑，完整问题留在对话中；窄窗和长文本不得使阅读区只剩极小高度。
- 首次“请他分析”、已有研究“请他补充”在入口、提示和参与状态中一致。
- 来源入口直接定位本条结论所依赖的课程或原文章节；计算规则次级展开。
- 时间用正常中文日期和本地时区展示，技术时间仍留后台。
- 先承接一句用户最新问题，再给针对性回答，避免每轮重复全量报告。

## 四、下一轮修正及验收顺序

1. **先修范围承接和资料异常处理。** 用本次两条原话及同义、否定、混合条件表达复测；实际范围发生改变，或明确拒绝未支持部分，不能静默回退。存在资料冲突时不产生对应定位判断。
2. **再修回答内容组织。** 处长能看出此刻可以判断什么、不能判断什么、先请学院说明哪几件具体事情；每件事可打开对应课程或原文。没有正式分层依据就不输出专业相似度排名。
3. **再修讨论稿。** 不浏览长附录也能理解研究议题、当前意见和待讨论事项；个人意见保留独立版本，关键资料缺项在正文中可见。
4. **同步修标题、用词、时间和来源定位。** 在1280/1440/1920及125%下，用真实长问题而非短测试标题复测。
5. **扩展到其他专家和院长任务。** 按转专业、课程质量、毕业准备各选一个真实管理任务；推免条件不具备时验证拒绝及下一步说明。不把专业建设单例的结论冒充全部专家验收。

本轮未实施以上业务整改。上述顺序是基于实操发现的实施建议，不改变原有正式数据、权限和生产批准门槛。
