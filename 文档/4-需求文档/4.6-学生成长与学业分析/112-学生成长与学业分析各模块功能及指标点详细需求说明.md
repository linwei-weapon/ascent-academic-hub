## 1. 文档目标、范围与阅读方式

### 1.1 文档目标

本文档完整说明“教学管理分析 / 学生成长与学业分析”当前可运行原型中的页面、功能、指标、字段、计算公式、业务规则、权限边界、交互事件和全部下钻终点，供以下工作共同使用：

1. 产品经理确认页面范围、文案和下钻链路；
2. 教务业务人员确认指标含义、统计对象和管理用途；
3. 前后端开发人员统一字段、接口、排序、空值和异常处理；
4. 数据治理人员确认源表、聚合表、规则版本和数据边界；
5. 测试人员设计功能、口径、权限和回归测试；
6. AI 研判能力建设人员确认确定性证据与解释性结论之间的边界。

本模块不只是一个固定的统计首页。同一菜单和同一路由会根据“当前工作身份”展示两种工作台：

- 校领导、教务处、二级学院、专业负责人和系统管理员进入“管理比较工作台”；
- 辅导员、班主任和导师进入“本人关系范围工作台”。

两类工作台最终都可以进入学生证据抽屉、完整学生学业档案和学生学业研判，但其初始统计范围、可见组织层级和学生集合不同。

### 1.2 功能范围

本文档覆盖以下功能：

- 角色自适应的学生成长与学业分析首页；
- 两学期比较范围、可比较学生口径和在籍学生并集口径；
- 明确改善、明确恶化、连续受挫、低年级首次受挫、重复未解决等指标；
- 学院、专业、行政班动态组织比较；
- 优先关注学生证据名单、搜索、分页和列设置；
- 辅导员/班主任的“我的班级学业关注”；
- 导师的“我的学生学业关注”；
- 学生学业证据抽屉；
- 完整学生学业档案，包括 GPA 趋势、成长时间线、课程证据、培养方案进度、确定性建议等；
- 学生学业研判抽屉；
- 全部页面的权限、缓存、来源、异常、空态和验收规则。

### 1.3 不在本模块范围内的能力

以下能力不属于本模块的直接职责：

- 不维护学生、课程、成绩、培养方案、行政班或导师关系等业务主数据；
- 不向教务源库回写数据；
- 不自动认定退学、留级、毕业、学位授予或课程替代关系；
- 不自动发起预警处置、约谈、重修报名、开班或排课；
- 不把“需要关注”直接解释为学生能力评价、教师教学质量评价或责任认定；
- 不用 AI 临时发明正式指标、阈值或未经验证的事实；
- 不把历史曾经不及格直接等同于当前未解决；
- 不把培养方案中的“未完成”直接等同于“未选课”“无法毕业”或“必须重修”。

### 1.4 状态标记与阅读约定

本文档按以下三类状态描述功能：

| 标记 | 含义 | 使用方式 |
|---|---|---|
| 当前实现 | 已在现行前端、接口和数据逻辑中实现 | 可直接作为当前版本验收对象 |
| 正式需求 | 为保证业务正确性必须满足的稳定规则 | 当前实现不一致时，应以正式需求作为整改目标 |
| 适用边界 | 当前数据不足或业务能力未接入时的限制 | 页面必须披露，不得以默认值伪装结论 |

公式中的符号约定如下：

| 符号 | 含义 |
|---|---|
| `S0` | 起始学期 |
| `S1` | 目标学期，且必须满足 `S0 < S1` |
| `R0`、`R1` | 起始学期、目标学期在籍学生去重集合 |
| `U` | 在籍学生并集，`R0 ∪ R1` |
| `C` | 可比较学生交集，`R0 ∩ R1` |
| `GPA0`、`GPA1` | 学生在起始学期、目标学期的学分加权 GPA |
| `F0`、`F1` | 学生在起始学期、目标学期的未通过课程去重门数 |
| `ΔGPA` | `GPA1 - GPA0` |
| `ΔF` | `F1 - F0` |

### 1.5 核对依据与冲突处理

本文档依据现行页面、路由、后端计算、V2 数据结构、历史在籍名册读取逻辑、阶段记录和指标口径确认书交叉核对形成，并参考《109-教学运行分析各模块功能及指标点详细需求说明.md》的组织方式。

发生冲突时按以下顺序处理：

1. 已确认的产品决策、数据权限和数据真实性原则；
2. 指标口径确认书中已确认的正式定义；
3. 后端实际计算和接口契约；
4. 前端展示、文案和交互；
5. 历史设计方案和阶段记录。

如果前端文案与后端计算不一致，本文档会同时记录“当前表现”和“正式要求”，并在[第 7.5 节](#consistency-gaps)列入一致性问题，而不是选择其中一方掩盖差异。

### 2.4 条件继承与返回规则

1. 管理首页采用“草稿条件”和“已应用条件”分离。用户修改下拉框但未单击“查询”时，现有结果仍属于上一次已应用条件。
2. 单击指标卡或可比较学生数后，只改变同页名单分组，并将页码重置为第 1 页；学院、专业、班级、起止学期保持不变。
3. 搜索仅作用于名单，输入关键词并按 Enter 或单击查询后，页码重置为第 1 页。
4. 管理首页把已应用的起止学期、组织条件、名单分组、关键词、页码和页大小写入 URL，刷新和返回时应恢复。
5. 打开学生证据抽屉不改变 URL；快速切换学生时应以最后一次请求为准，旧请求不得覆盖新学生。
6. 从证据抽屉进入完整学生档案时，应携带 `returnTo`、`returnLabel` 和滚动位置；返回后恢复原查询上下文。
7. 学生档案中的面包屑可以离开本模块，但不属于本模块的内部下钻链路。

### 2.5 下钻终点

以下位置没有继续的本模块业务下钻：

- 动态组织比较表的组织行；
- 学生学业证据抽屉内的课程行、预警行和时间线行；
- 学生学业档案内的 GPA 图、时间线事件、方案课程行、成绩行和挂科行；
- 学生学业研判抽屉。

学生学业研判中的证据卡是解释性信息，不应默认为可点击链接。若未来新增证据回跳，必须明确目标页面、继承条件和权限检查，不能仅依赖前端已有数据。



## 3. 全模块公共规则

### 3.1 当前工作身份与数据权限

| 当前身份 | 默认范围 | 可比较范围 | 学生明细范围 |
|---|---|---|---|
| 校领导、教务处 | 全校 | 全校学院、专业或班级聚合 | 全校已授权学生 |
| 二级学院 | 本学院 | 本学院内专业、班级；指定场景可看其他学院聚合 | 仅本学院学生 |
| 专业身份 | 本专业 | 本专业内行政班 | 仅本专业学生 |
| 辅导员、班主任 | 有效关系覆盖的班级/学生 | 不展示全校组织比较 | 仅有效关系覆盖学生 |
| 导师 | 有效导师—学生关系 | 不展示全校组织比较 | 仅所带学生 |
| 系统管理员 | 明确授权的全校范围 | 全校 | 全校 |

公共安全规则：

- 范围缺失时默认拒绝或返回空集合，不得回退成全校；
- 组织下拉框只能缩小当前授权范围，不能扩大范围；
- 学生详情、名单、AI 接口、直接 URL 均应按当前身份重复鉴权；
- 当前身份切换后，应清理上一个身份的页面缓存、表格偏好上下文和未完成请求；
- 能查看其他学院聚合比较，不代表能查看其他学院学生名单；
- AI 研判不得突破确定性接口的数据权限。

### 3.2 学期、在籍名册与统计集合

管理比较工作台必须选择两个真实学期，且起始学期早于目标学期。两个学期的学生集合来自各学期历史源数据库中的 `students` 名册，先按在校/在籍状态筛选，再与当前身份授权学生集合求交。

```text
R0 = distinct(起始学期源名册中状态为“在校”或“在籍”的授权学生)
R1 = distinct(目标学期源名册中状态为“在校”或“在籍”的授权学生)
U  = R0 ∪ R1
C  = R0 ∩ R1
可比较学生占比 = |C| ÷ |U| × 100%
```

业务含义：

- `U` 用于说明两个学期参与范围内出现过的学生总规模；
- `C` 用于说明两个学期都在籍、具备身份连续性的学生规模；
- “两个学期都有成绩证据”是成绩口径，不等于“两个学期都在籍”；
- 历史源名册无法读取或缺少必要字段时，不允许用当前学生维表近似替代，应返回数据不可用状态。

### 3.3 成绩有效性、学期 GPA 与有效课程结果

学期 GPA 使用真实来源、学分大于 0 且 GPA 非空的成绩记录：

```text
学生学期 GPA = Σ(课程 GPA × 课程学分) ÷ Σ课程学分
```

若分母为 0，则显示 `—`，不得显示 `0.00`。同一学生、同一课程存在多次成绩时，不同指标按下列两种粒度处理：

- 学期变化：统计指定学期内的真实成绩事实；未通过门数按课程去重；
- 当前累计结果：每名学生、每门课程取最新有效结果，最新通过则当前已解决，最新未通过则当前未解决。

累计总 GPA 的正式口径为：对每门课程取最新真实有效结果，再按学分加权。已获学分的正式口径为：对每门课程取真实通过记录中的可认定学分一次，避免重修多次重复累计。

### 3.4 变化量、阈值和分类规则

```text
ΔGPA = GPA1 - GPA0
ΔF   = F1 - F0
GPA 明显上升：ΔGPA ≥ 0.30
GPA 明显下降：ΔGPA ≤ -0.30
未通过减少：ΔF ≤ -1
未通过增加：ΔF ≥ 1
```

阈值 `0.30` 属于 `student-growth-v2` 规则的一部分。规则版本改变时，接口、Tooltip、文档和指标确认书必须同步更新。

正式分类条件：

```text
明确改善 = (ΔGPA ≥ 0.30 且 ΔF ≤ 0)
        或 (ΔF ≤ -1 且 ΔGPA > -0.30)

明确恶化 = (ΔGPA ≤ -0.30 且 ΔF ≥ 0)
        或 (ΔF ≥ 1 且 ΔGPA < 0.30)
```

只有起止两个学期都有有效成绩证据时，才进入明确改善、明确恶化或稳定分类。缺少任一学期成绩证据时为“证据不足”。

### 3.5 当前未解决、重复未解决与历史已解决

对同一学生、同一课程按学期和记录顺序取最新有效结果：

| 状态 | 规则 |
|---|---|
| 当前未解决 | 历史上至少有一次未通过，且最新有效结果仍未通过 |
| 重复未解决 | 同一课程累计未通过次数 `≥ 2`，且最新有效结果仍未通过 |
| 历史已解决 | 历史上曾未通过，但最新有效结果已通过 |

重复未解决学生数按学生去重，不按课程门数累加。一个学生有多门重复未解决课程，在人数指标中仍计为 1 人，在学生详情中展示课程门数和课程明细。

### 3.6 当前有效预警与预警状态

正式需求统一定义如下：

```text
当前有效预警 = 尚未失效，且业务流程状态不属于“已解决/已关闭”的预警事件
```

页面必须同时区分：

- 风险状态：规则或模型识别出的风险事实；
- 人工流程状态：是否已核查、处理中、已解决或已关闭。

人工流程已结束不等于历史风险从未发生；风险仍活跃也不等于尚未开展人工处置。当前实现同时存在 `alert_event.workflow_status` 和 `fact_alert.is_active` 两套判定，统一要求见[第 7.5 节](#consistency-gaps)。

### 3.7 公共表格、列设置、分页和排序

公共数据表支持以下能力：

- 列显示/隐藏；必显列不可隐藏；
- 列顺序调整；
- 紧凑、默认、宽松三种密度；
- 每页 `10`、`20`、`50`、`100` 条；
- 表格偏好按“用户 + 当前工作身份 + 表格标识 + 配置版本”保存在本地；
- 浏览器存储不可用时使用默认配置，不影响业务数据加载。

页面没有声明可排序列时，不得显示虚假的排序交互。主证据名单由服务端按业务优先级排序；班级展开表和导师学生表保持接口返回顺序。

### 3.8 数字、单位、舍入和空值

| 类型 | 显示规则 |
|---|---|
| GPA | 保留 2 位小数；无有效证据显示 `—` |
| GPA 变化 | 保留 2 位小数，正数显示 `+`；`≤ -0.30` 为负向色，`≥ 0.30` 为正向色 |
| 比例 | 保留 1 位小数，并同时显示分子/分母 |
| 学分 | 一般保留 1 位小数；无要求或无证据显示 `—` |
| 人数 | 非负整数，单位“人” |
| 课程数 | 非负整数，单位“门” |
| 预警数 | 非负整数，单位“条” |
| 未计算 | 使用 `—` 或“暂不可计算”，不得用 0 代替 |

所有比例必须允许用户看到分子和分母。零分母时显示“暂不可计算”，不得展示 `0%`。

### 3.9 加载、缓存和并发

- 重新查询失败时保留上一次成功结果，不先清空页面；

- 缓存键必须至少包含当前身份权限指纹、起止学期和组织条件；正式要求还应纳入数据批次或聚合刷新版本，防止源数据刷新后继续命中旧结果。

      - 任一学期 GPA 无法计算：变化值显示“—”，不标红或标绿

    - 字段说明：显示2个比较学期的未通过课程数和变化信息。
    - 显示格式：`${起点学期未通过门数}→${终点学期未通过门数}门 ${± 变化值}` 如 2 → 1门-1
    - 颜色说明：

      - 当差值为正：  ± 和  变化值为绿色，加粗显示；
      - 当差值为 0： 正常颜色，无± 号，变化值为0。如　“3 → 3门0”
      - 如果某个学期没有成绩数据：起点学期或终点学期的未通过课程数会显示为 `0`；变化值显示为“—”；不标红或标绿，按正常颜色显示；

    - 补充说明：同一学生、同一学期、同一课程即使存在多条未通过记录，也只计算1门。

  - **触发原因**

    - 原因&颜色

      一名学生可以同时命中多个原因：

      1. 明确恶化
      2. 连续受挫
      3. 低年级首次受挫
      4. 重复未解决

      如果学生没有上述四类关注原因：

      - 属于明确改善：显示“明确改善”。
      - 不是明确改善，但两个学期均在籍：显示“两个学期均在籍”。

      | -------------- | ---------------- |
      | 明确改善       | 绿色             |
      | 明确恶化       | 橙色             |
      | 连续受挫       | 橙色             |
      | 低年级首次受挫 | 红色             |
      | 重复未解决     | 红色             |
      | 两个学期均在籍 | 灰色/中性色      |

    - 显示顺序

      明确恶化→ 连续受挫→ 低年级首次受挫→ 重复未解决

  - **当前未通过课程**

    - 规则说明：
      - 以前未通过、后来已经通过：不计入。
      - 以前通过、最新一次未通过：计入。
      - 同一课程多次未通过：课程总数仍只计1门。
      - 不受页面所选两个学期限制，判断的是当前最新有效结果。

    - 显示格式
      - 没有当前未通过课程：无
      - 有当前未通过课程、没有重复未解决：3门
      - 有当前未通过课程、有重复未解决的：3门 · 重复1门

    - 颜色说明
      - “3门”等当前未通过课程总数：普通正文颜色。
      - “· 重复1门”：红色加粗。
      - “无”：灰色

  - **当前有效预警**

    - 字段说明：显示当前学生触发的未解决、未关闭预警事件条数。

      例如：

      - 2条待处理、1条已解决：显示“2条”。
      - 1条待复核、1条已关闭：显示“1条”。
      - 全部已解决或已关闭：显示“0条”。

    - 显示规则

      - 大于0：显示为红色加粗。
      - 等于0：显示“0条”，普通文字颜色。
      - 单位统一为“条”。

    - 当前预警规则

      | 规则 | 名称            | 主要条件                                                 | 等级 |
      | ---- | --------------- | -------------------------------------------------------- | ---- |
      | R1   | GPA持续下降     | 近2～3个有成绩学期GPA连续下降，累计降幅大于0.3           | 严重 |
      | R2   | 未解决挂科累积  | 近2学期不同且尚未通过的课程至少3门                       | 严重 |
      | R2W  | 未解决挂科关注  | 近2学期不同且尚未通过的课程为2门                         | 警告 |
      | R3   | 学分缺口过大    | 已修学分较期望进度缺口大于10学分                         | 警告 |
      | R4   | 核心/必修课风险 | 有培养方案时核心课、无方案时必修课，近2学期未解决至少2门 | 提醒 |
      | R6   | 退学风险        | 本学期GPA低于1.8，且近2学期未解决课程至少2门             | 严重 |

### 4.10.4 变化与方案进度

内容包括：相邻学期学业变化 和 培养方案进度证据

- **相邻学期学业变化**

  - **功能说明：**提供相邻学期学业变化，显示 GPA 和未通过课程变化；


  - **呈现方式：**表格


  - **表格字段：**

    | 字段           | 含义                                  |
    | -------------- | ------------------------------------- |
    | 学期           | 学期编号/名称，按时间倒序             |
    | 学分加权 GPA   | 该学期有效课程的加权 GPA              |
    | 较前一学期     | 当前行相对前一自然记录学期的 GPA 变化 |
    | 未通过课程     | 当学期未通过课程去重门数              |
    | 较前一学期     | 未通过门数变化                        |
    | 本学期获得学分 | 当学期通过课程按课程去重后的获得学分  |


- **培养方案进度证据**

  - **信息内容**：绑定状态、方案名称、完成模块、规则证据覆盖、明确缺口模块和待核验候选模块。

  - **绑定状态：**

    - 已绑定 显示 “**${培养方案名称}**” 如: “**2022级材料科学与工程专业培养方案**”；

    - 未绑定 显示 **“未绑定培养方案”**

  - **完成模块：**每个模块有学分或者课程门数要求，满足这个要求，说明这个模块完成（模块下课程有成绩并通过）；

    - 数据呈现分数：“**已完成模块数 / 可评价模块总数**” ； 如 6 / 8

    - **可评价模块**系统按以下优先顺序选择模块评价规则：
      - 有可信的最低学分要求：模块已获得学分 ≥ 模块最低学分。

      - 没有最低学分规则，但有最低课程门数或“N选M”规则：完成课程数 ≥ 要求门数。

      - 上述规则都没有，但模块包含必修课：模块内要求的必修课均已通过或已完成课程认定。

      - 三类规则都没有：该模块属于“不可评价模块”，不进入完成模块的分母。

  - **规则证据覆盖**：

    - 计算规则：`规则证据覆盖率 = 可评价模块数 ÷ 培养方案模块总数 × 100%`

      例如培养方案有9个模块，其中8个模块有可用规则：

      > 规则证据覆盖：88.9%

    - 这个指标衡量的是：“系统能不能根据结构化规则判断模块完成情况”，不是学生的学业完成率。

      一个模块至少满足以下一种情况，才算有规则证据：

      - 配置了可信的最低学分；

      - 配置了最低完成门数；

      - 能识别“N选M”等课程选择规则；

      - 有明确的逐门必修课程清单，可以逐门核查。

    - **明确缺口模块**：

      - 一个模块被统计为“明确缺口模块”，需要同时满足：

        1. 模块具备可执行的评价规则；
        2. 模块当前尚未达到完成要求；
        3. 模块内至少存在一门必修课程具有明确的未通过成绩证据。

        这里的“明确”是指系统已经获得有效成绩，且成绩结论为未通过，不是因为没查到成绩而推测学生挂科。

        例如：

        - 专业核心模块要求完成30学分；
        - 学生当前只完成26学分；
        - 其中一门必修课已有有效成绩，结论为未通过；
        - 该专业核心模块计入1个“明确缺口模块”。

      - 注意事项

        - 一个模块即使包含3门未通过必修课，也只统计为1个明确缺口模块。

        - 底层还会记录“明确未通过必修课程数”，但页面这项指标展示的是模块数。

        - 如果未通过课程后来重修通过，或者完成了有效的课程替代认定，重新计算后可以不再形成明确缺口。

        - 当前判断顺序中，如果一个模块按照模块规则已经达到完成要求，会优先认定为“完成模块”，不会再计入明确缺口。这对于按学分或选课数量完成的模块尤其重要。

    - **待核验候选模块：**

      - 一个模块成为候选模块，一般需要满足如下条件：
        1. 模块可以评价；
        2. 模块尚未达到完成要求；
        3. 模块中没有已经确认的必修课未通过证据；
        4. 至少有一门必修课已经超过培养方案建议修读学期；
        5. 该课程仍然是“未完成”或“完成状态未知”。

      - “超过建议修读学期”的判断是：

      > 课程建议修读学期 < 学生当前修读学期

      ​	当前学期应修的课程不会因为尚无成绩立即算作逾期。

      - 之所以叫“候选”，是因为系统只能确认“目前没有找到有效完成证据”，但不能直接确认学生确实缺修。可能原因包括：

        - 学生确实没有修读；
        - 已修读但成绩尚未同步；
        - 转专业、转学或课程替代认定尚未处理；
        - 培养方案绑定存在差异；
        - 课程计划学期与实际修读安排不同；
        - 成绩数据存在缺失。

        因此，候选模块只能进入人工核验范围，不能直接表述为“学生挂科”“确定缺修”或“不能毕业”。

      - 一个候选模块即使包含多门待核验课程，也只计为1个候选模块；

    - **模块四个指标之间的关系说明**

      | 模块状态   | 判断条件                                                | 影响的指标         |
      | ---------- | ------------------------------------------------------- | ------------------ |
      | 不可评价   | 没有可执行的学分、门数或逐门必修规则                    | 降低规则证据覆盖率 |
      | 已完成     | 已达到选定的模块规则要求                                | 计入完成模块       |
      | 明确缺口   | 未完成，并存在明确未通过的必修课                        | 计入明确缺口模块   |
      | 待核验候选 | 未完成，无明确挂科，但存在逾期且状态未知/未完成的必修课 | 计入待核验候选模块 |
      | 尚未到期   | 未完成，但不存在明确挂科或逾期候选课程                  | 不计入缺口或候选   |

      因此：

      - “明确缺口模块”和“待核验候选模块”互斥；同一模块不会同时计入两项。
      - 如果一个未完成模块同时存在明确未通过课程和待核验课程，会优先计入“明确缺口模块”。
      - `完成模块 + 明确缺口模块 + 待核验候选模块`不一定等于可评价模块数，因为还可能存在“尚未到期”的未完成模块。
      - 规则证据覆盖的分母是全部培养方案模块；完成模块的分母是可评价模块，两者口径不同。

  | 核心课挂科     | 展示尚未通过的核心课或必修课名称，通常最多先列出主要课程。   |
  | 退学风险       | 同时展示本学期GPA、GPA阈值以及最近窗口内挂科或未解决课程数量。 |
  | 挂科累积       | 展示历史规则统计出的最近窗口累计挂科门数。                   |

​      触发证据数值因学生而异：GPA、下降幅度、课程门数、学分缺口和课程名称都不是固定值。

## 5. 学生学业档案及其子功能

### 5.1 页面路径说明

**页面路径：** 教学管理分析 → 学生成长与学业分析 → 学生证据名单/班级学生/导师学生 → 学生学业证据 → 打开完整学生档案
**页面标题：** `{学生姓名} · 学生学业档案`
**访问前提：** 当前工作身份对该学生具有有效数据权限；服务端必须按学生编号再次鉴权。

本页是学生层面的完整确定性证据页，集中呈现学生基本信息、累计指标、学期变化、预警历史、培养方案完成情况、课程结果和确定性学业建议。页面不承担业务主数据修改和预警处置。

### 5.2 页面导航、返回和基本信息

#### 5.2.1 返回规则

从本模块证据抽屉进入时，页面顶部显示带来源语义的返回按钮。返回目标由 `returnTo` 决定，并应恢复来源页面查询参数和滚动位置；缺少合法返回参数时，回到学生成长与学业分析首页。

面包屑显示管理端入口、学院和学生姓名。面包屑可能离开本模块，不属于本模块的继续下钻。

#### 5.2.2 学生基本信息

| 字段 | 含义 | 展示规则 |
|---|---|---|
| 姓名 | 学生姓名 | 页面标题主信息 |
| 学号 | 学生唯一业务编号 | 不可编辑 |
| 学院 | 当前所属学院 | 无值为 `—` |
| 专业 | 当前所属专业 | 无值为 `—` |
| 行政班 | 当前所属行政班 | 无值为 `—` |
| 入学信息 | 实际入学日期或入学年级 | 有真实日期时显示日期；仅有 V2 入学年级时显示“YYYY 年”，不得伪造月日 |
| 预计毕业 | 预计毕业日期/年份 | 仅源数据有值时显示 |
| 当前年级 | 当前年级 | 作为核心指标之一展示 |

学生不存在时显示对象不存在空态并提供返回学生成长分析的入口；无权限时返回 403，不得用“学生不存在”掩盖权限逻辑，也不得泄露对象详情。

### 5.3 核心指标卡

**页面路径：** 学生学业档案 → 核心指标

页面展示 6 张指标卡：

| 指标 | 计算逻辑 | 辅助信息/Tooltip | 空值规则 |
|---|---|---|---|
| 总 GPA | 每门课程取最新真实有效结果后，`Σ(GPA×学分) ÷ Σ学分` | 说明为累计有效课程学分加权 GPA | 分母 0 显示 `—` |
| 已获学分 | 每门课程真实通过记录可认定学分去重汇总 | 说明已避免重修重复累计 | 无证据显示 `—` |
| 已修学时 | 当前原型按 `已获学分 × 16` 推算 | Tooltip 明确 `credits × 16` | 仅是推导值，不能代替真实教学计划学时 |
| 通过门数 | 最新有效结果为通过的课程去重数 | 副文本显示培养方案完成率或“学分要求待绑定” | 无有效课程为 0 |
| 预警状态 | 当前有效预警中的最高等级 | 副文本显示当前有效预警数量 | 无有效预警显示正常/无有效预警 |
| 年级 | 当前学生年级 | 来源于学生维表/V2 学籍 | 缺失显示 `—` |

培养方案完成率：

```text
培养方案完成率 = 已获学分 ÷ 正确绑定培养方案的要求总学分 × 100%
```

只有方案绑定可靠、要求学分为正数时才计算。正式规则应明确是否允许超过 100%；同一指标跨页面必须一致，见[第 7.5 节](#consistency-gaps)。

### 5.4 GPA 趋势

**页面路径：** 学生学业档案 → GPA 趋势

图表展示最近最多 6 个有有效 GPA 的学期：

- 横轴：学期；
- 纵轴：GPA，当前图表范围为 0～5；
- 折线值：学生学期学分加权 GPA；
- 参考线：GPA 2.0；
- Tooltip：必须展示真实学期、GPA 和必要的数据说明。

正式要求使用真实学期名称/编号作为横轴或 Tooltip 的首要标识。当前页面把横轴简化为 `S1～S6`，只能表示顺序，不能支持用户确认具体学期，应列为待统一项。

### 5.5 预警历史与变化摘要

**页面路径：** 学生学业档案 → 预警历史与变化

摘要信息包括：

| 信息 | 含义 |
|---|---|
| 历史预警总数 | 该学生全部历史预警记录数 |
| 当前有效预警数 | 当前仍有效的预警记录数 |
| 人工干预数 | 跟进、核查或状态流转记录数 |
| 最新变化 | 最新一条预警相对上一条预警的变化类型 |

变化类型按时间正序比较后产生：首次出现、持续、风险上升、风险下降或类型变化。风险等级比较必须使用固定等级序列，不能按中文字符串排序。

此区域用于解释风险演变，不等于人工处置结论。历史预警即使已关闭仍应保留在历史数量和时间线中。

### 5.6 成长时间线

**页面路径：** 学生学业档案 → 成长时间线

筛选选项：

| 选项 | 包含事件 |
|---|---|
| 全部 | 所有时间线事件 |
| 学业 | 学期表现、课程未通过/通过和学分变化 |
| 预警 | 预警产生、等级或类型变化 |
| 干预 | 人工跟进和流程状态变更 |
| 学籍 | 学籍状态和毕业相关事件 |

页面同时显示各类事件数量：学期表现、挂科事件、预警记录、人工干预、学籍/毕业事件。

时间线合并以下来源并按时间倒序：

1. 学期 GPA、学分和未通过课程摘要；
2. 每门课程的未通过历史；
3. 预警事件；
4. 跟进和状态变更；
5. V2 学籍状态与毕业事件。

每条事件至少包含时间、事件类型、标题、事实摘要和来源标识。相同时间应使用稳定的次级排序，避免刷新后顺序变化。时间线行当前为展示终点，不继续下钻。

### 5.7 确定性学业建议

**页面路径：** 学生学业档案 → 确定性学业建议

该区域由固定规则生成，不依赖生成式模型。页面明确标注“确定性证据模板”，避免用户把规则卡片误认为 AI 个性化结论。

#### 5.7.1 受众选项

| 选项值 | 页面名称 | 文案侧重点 |
|---|---|---|
| `student` | 学生本人 | 学习安排、课程核查和可执行提醒 |
| `counselor` | 辅导员 | 学生沟通、持续关注和事实核查 |
| `class_adviser` | 班主任 | 专业基础、课程衔接和学习指导 |
| `college` | 学院 | 共性课程、资源保障和同类学生规模 |
| `academic_affairs` | 教务处 | 跨学院资源、规则和正式教务安排边界 |

切换受众只改变建议表达，不改变证据、优先级和事实结论。

#### 5.7.2 建议卡字段

| 字段 | 含义 |
|---|---|
| 优先级 | `high`、`medium` 或 `positive`，分别对应高优先、一般关注和积极进展 |
| 主题 | 课程进度、成绩趋势、积极进展或困难课程等 |
| 标题 | 当前证据触发的简要判断 |
| 受众文案 | 当前选择受众对应的建议表达 |
| 证据 | 触发建议的确定性事实 |
| 核查说明 | 使用前需要人工确认的数据或边界 |
| 证据标识 | 课程、学期等可追溯标识；当前页面仅展示，不下钻 |

卡片最多返回 12 条，先按高优先级、一般关注、积极进展排序，再保持稳定顺序。

#### 5.7.3 当前建议规则

1. **必修课程未完成提醒：** 从可行动培养方案课程中取最多 5 门，提示核对下次开课、重修/补修安排和后续课程衔接；当前数据不包含完整重修班容量与报名条件。
2. **近期 GPA 变化：** 最近两个有 GPA 的学期平均绩点差绝对值 `≥ 0.30` 时，生成“明显改善”或“出现下降”建议；只解释结果，不推断具体原因。
3. **历史高难度课程提醒：** 课程历史样本量 `≥ 30` 且历史未通过率 `≥ 15%`，并且学生在最近学期修读该课程时，可生成课程核查建议，最多 5 门。

正式要求：建议规则中的 GPA 必须与本模块正式学期加权 GPA 同源同口径；历史课程难度必须披露样本量、统计范围和时间边界。

### 5.8 V2 学生成长事实

**页面路径：** 学生学业档案 → 学生成长事实

该区域补充 V2 结构化数据，字段包括：

| 字段 | 含义 |
|---|---|
| 已通过课程 | V2 有效课程结果中当前为通过的课程数 |
| 当前未通过课程 | V2 有效课程结果中当前仍未通过的课程数 |
| 已获学分 | V2 有效通过课程的学分汇总 |
| 平均 GPA | V2 成绩尝试中的 GPA 汇总值 |
| 重修尝试 | `attempt_type=retake` 的尝试次数 |
| 学籍事件 | 学籍状态事件数量 |

困难标识包括：

- 当前未通过课程达到 2 门及以上；达到 3 门及以上时提高严重度；
- 同一课程未通过次数达到 2 次及以上；
- 可行动的必修课程缺口；缺口达到 5 门及以上时提高严重度。

正式要求：该区域的平均 GPA、已获学分、重复未通过和当前未通过必须复用第 3 章公共口径，不能因 V2 表结构不同而展示第二套结果。

### 5.9 培养方案课程

**页面路径：** 学生学业档案 → 培养方案课程

页面分为两个页签：

#### 5.9.1 当前可行动课程

请求条件为 `actionable=true`，最多展示 200 条。字段包括：课程代码、课程名称、方案模块、建议修读学期、当前有效成绩、建议优先级和“重修/补修”建议。

#### 5.9.2 未完成候选课程

请求条件为 `status=not_completed`，最多展示前 100 条。字段包括：课程代码、课程名称、方案模块、课程性质、建议修读学期和状态。

页面显示候选总数并提示“当前展示前 100 条”。“未完成候选”不得改写为“未选课”或“毕业缺口”，因为当前数据未必覆盖选课、认定、免修和课程替代信息。

### 5.10 历史挂科与解决状态

研判入口只负责解释和组织已有证据，不修改档案数据。接口必须再次验证当前身份对学生的访问权限。

### 5.13 学生学业档案的空态和局部失败

- 学生主详情失败：页面整体错误，不继续请求或展示来自旧学生的内容；
- GPA 无数据：图表显示“暂无有效 GPA 数据”；
- 无预警：显示“暂无预警记录”，不能显示风险异常；
- 无时间线：显示“暂无成长事件”；
- 方案未绑定：显示方案边界，不计算精确完成率；
- V2 补充接口失败：正式要求显示局部不可用提示，主档案仍可使用；
- 建议无触发规则：显示“当前没有基于确定性规则生成的建议”；
- 成绩或挂科列表为空：分别说明“暂无有效成绩记录”或“暂无历史未通过课程证据”。

## 6. 学生学业研判及其子功能

### 6.1 页面路径说明

**页面路径：** 教学管理分析 → 学生成长与学业分析 → 学生学业证据 → 完整学生档案 → 学业研判

**页面形态：** 管理研判抽屉

### 6.2 研判对象、对象范围、生成时间

- 研判对象：学生姓名；
- 对象范围：`学院 · 专业 · 班级`。若都为空，则显示为 “`当前分析范围`”
- 生成时间：格式为`YYYY-MM-DD HH:mm`，前缀为“数据时点”
- 如 "**新能源与材料学院 · 材料科学与工程 · 材料25-3班 · 数据时点 2026-09-15 14:25**"
- 研判数据：继承当前查询条件范围。

### 6.3 管理结论

- 管理结论：当前模板为：

  ```
  {学生姓名}当前研判为{风险标签}，主要依据为有效预警、未通过课程、GPA趋势和历史课程难度。
  ```

  字段信息说明：

  | 字段         | 说明                                               |
  | ------------ | -------------------------------------------------- |
  | 学生姓名     | 学生姓名                                           |
  | 风险标签     | 高风险、中风险、关注、低风险                       |
  | 有效预警     | 用于计算风险等级                                   |
  | 未通过课程   | 按不同课程去重统计                                 |
  | GPA趋势      | 相邻学期平均GPA，用于识别下降趋势                  |
  | 历史课程难度 | 同课程历史未通过率，辅助识别是否涉及高未通过率课程 |

  - **卡片颜色**

    | 风险结果 | 中文触发规则                                                 | 结论卡背景色                               | 左侧强调色 |
    | -------- | ------------------------------------------------------------ | ------------------------------------------ | ---------- |
    | 高风险   | 存在“严重”级有效预警；或必修未通过课程≥2门；或累计未通过课程≥3门 | 淡红色                                     | 红色       |
    | 中风险   | 未达到高风险，且存在“警告”级有效预警；或至少有1门未通过课程；或相邻学期GPA下降超过0.30 | 淡橙黄色                                   | 橙色       |
    | 关注     | 未达到高/中风险，但仍存在其他有效预警，例如“提醒”级预警      | 淡青绿色                                   | 青绿色     |

### 6.4 为什么现在看、影响范围和比较基准

- 为什么现在看：最多显示3条。但有比较数据时，比较结果优先，会覆盖普通原因列表

  - 有至少两个学期GPA时，当前学生场景只生成1条比较信息：

    ```
    相邻学期GPA由 {上一学期GPA} 变为 {当前学期GPA}，{上升/下降/持平} {变化绝对值，保留两位小数}。
    ```

    示例：

    ```
    相邻学期GPA由 2.88 变为 2.38，下降 0.50。
    ```

    此时即使预警、必修未通过、高难度课程等原因同时存在，仍只显示这1条GPA比较信息。

  - 没有两个可比较学期时，按以下顺序生成，最后只取前3条

    | 顺序 | 触发条件                               | 内容模板                                                     |
    | ---- | -------------------------------------- | ------------------------------------------------------------ |
    | 1    | 存在任意历史预警记录                   | `最近一次预警为“{等级} / {类型}”，触发依据是：{触发详情或“规则命中”}。` |
    | 2    | 必修未通过>0                           | `该生仍有{数量}门必修课程未通过，毕业准备和后续选课需要优先核查。` |
    | 3    | 无必修未通过，但累计未通过>0           | `该生存在{数量}门课程未通过，建议区分必修、选修和重修资源后处理。` |

### 7.3 同名和近似指标不得混用

| 容易混淆的指标 | 必须区分的含义 |
|---|---|
| 在籍学生总数 vs 当前学生维表人数 | 前者是两个历史学期在籍名册并集；后者是当前静态学生维表记录 |
| 可比较学生 vs 两期有成绩学生 | 前者是两期在籍交集；后者是两个学期都有有效成绩事实 |
| 学期未通过 vs 当前未解决 | 前者描述某学期结果；后者取每门课程最新有效结果 |
| 历史未通过课程 vs 当前未解决课程 | 前者曾经发生即可；后者要求最新结果仍未通过 |
| 重复未解决学生数 vs 重复未解决课程数 | 前者按学生去重；后者按学生—课程统计 |
| 当前有效预警学生数 vs 当前有效预警事件数 | 一名学生可有多条事件 |
| 总 GPA vs 学期 GPA | 总 GPA 为当前有效课程累计加权；学期 GPA 只统计指定学期 |
| GPA 平均值 vs 平均 GPA | 班级“平均 GPA”应先算个人学期加权 GPA 再按学生平均；不得把所有课程记录直接平均 |
| 已获学分 vs 已修学时 | 已获学分来自课程结果；当前已修学时仅按 `学分 × 16` 推导 |
| 方案未完成 vs 未选课 | 前者是方案和结果的差集，后者需要选课事实 |
| 关注优先级 vs 风险等级 | 前者决定名单排序，后者说明研判风险严重程度 |

### 7.4 去重键、统计粒度和顺序

| 业务对象 | 去重键/粒度 | 顺序要求 |
|---|---|---|
| 学生人数 | `student_id` | 不因多课程、多预警重复计数 |
| 学期名册 | `semester_id + student_id` | 同一源名册重复行去重 |
| 学期未通过课程 | `student_id + semester_id + course_id` | 同学期同课程多记录只计 1 门 |
| 当前课程结果 | `student_id + course_id` | 按学期降序、记录顺序降序取最新有效记录 |
| 预警事件 | 预警事件唯一编号 | 同一学生多事件保留 |
| 人员关系 | `staff_id + student_id/行政班 + relation_type + 有效期` | 仅当前有效关系 |
| 组织比较 | 当前层级组织编号 | 先业务优先级，后名称稳定排序 |
| 时间线事件 | 来源事件编号 | 时间倒序，同时间使用稳定次级键 |

### 7.5 跨页面一致性硬约束

1. 首页、证据名单、学生证据抽屉、完整档案和 AI 研判必须使用同一学生身份和同一数据权限解析结果。
2. 同一学生、同一学期的 GPA 在所有页面必须一致，均采用真实有效成绩和学分加权。
3. 同一学生的当前未解决课程清单、数量和重复未解决数量必须可逐项对账。
4. 当前有效预警在首页、关系工作台、证据抽屉、档案和研判中必须使用同一事件集合。
5. 可比较学生、范围学生和两期有成绩学生是三个不同集合，接口字段和页面标签不得互换。
6. 组织比较的合计不能简单相加后当作全校人数，尤其在组织映射缺失或学生跨组织时，应按学生去重重算。
7. 培养方案进度只有在方案绑定可靠时才显示精确比例；不可靠时所有页面统一显示边界。
8. 确定性建议和 AI 研判只能引用已存在的指标，不能重新从原始表计算另一套 GPA、学分或未通过数量。
9. 页面 Tooltip、公开排序说明和后端实现必须同步；规则版本变更时应进行契约测试。
10. 数据来源为演示、模拟或推导时，所有消费页面都必须保留来源标识。

| SG-GAP-10 | 学生档案 V2 补充接口失败时相关区域可能静默隐藏 | 用户无法判断“无数据”还是“加载失败” | 展示局部失败、来源和重试，不影响主档案 |
| SG-GAP-11 | 主证据名单公开排序文案把第四优先级概括为“GPA 明显下降”，实际是“其他明确恶化” | 用户理解与实际排序不一致 | 使用第 4.7.4 节完整排序文案 |
| SG-GAP-12 | 概览缓存键包含权限和筛选，但未包含源文件修改时间或聚合刷新版本 | 数据刷新后最长约 900 秒仍可能返回旧值 | 把数据批次/聚合版本纳入缓存键或刷新时主动失效 |
| SG-GAP-13 | 组织比较“有效预警”字段、首页名单预警数和档案最高预警等级来自不同数据路径 | 汇总与明细难以对账 | 统一预警指标服务并增加汇总—明细契约测试 |
| SG-GAP-14 | 筛选元数据首次加载失败时缺少稳定的局部错误处理 | 页面可能停留在无可选项/加载状态 | 为学期和组织元数据提供明确错误、重试和上次成功缓存 |

上述问题应进入整改清单；在整改完成前，涉及指标的页面和 AI 结论必须披露适用边界。

| 学籍/毕业事件 | 学生成长时间线中的状态变化 | V2 事件事实；可能含模拟数据 |

### 8.3 规则和聚合版本

| 版本项 | 当前值/要求 | 说明 |
|---|---|---|
| 学生成长规则 | `student-growth-v2` | 含 `0.30` 阈值、比较名册和关注分组 |
| 累计 GPA | `cumulative-gpa-v1` | 每门课程最新真实有效结果、学分加权 |
| V2 课程结果 | `grade-effective-v1` | V2 有效课程结果规则 |
| AI 规则默认版本 | `AI-RULE-2026.07-v1` | 研判必须返回实际使用版本 |
| 聚合元数据 | 当前部分仍标记 `student-growth-v1` | 应与实际分类规则建立清晰映射或升级 |

版本披露至少包括：规则版本、数据批次/生成时间、参与学期、当前权限范围、真实/推导/模拟来源和已知限制。前端不能只显示人性化名称而丢失可追溯版本。

### 8.4 历史名册读取规则

历史名册读取必须满足：

- 对学期源数据库只读访问；
- `students` 表至少包含学生编号、学院、专业、年级、行政班和状态字段；
- 仅纳入状态为“在校”或“在籍”的学生；
- 再与当前身份授权学生编号求交；
- 同学期同学生去重；
- 缓存键包含源路径、源文件修改时间、学期、授权范围和组织条件；
- 源文件不存在、表缺失或字段不足时，返回明确不可用原因。

不允许用目标学期当前维表反推起始学期名册，这会造成毕业、转专业、转班或休学学生的样本偏差。

### 8.5 真实、推导和模拟数据边界

| 数据类型 | 可用于正式指标 | 页面要求 |
|---|---|---|
| 真实成绩、真实在籍名册 | 可以 | 展示学期、来源和有效性规则 |
| 聚合/推导指标 | 可以，前提是可追溯 | 展示公式、规则版本和生成时间 |
| 真实培养方案及正确绑定结果 | 可以 | 展示方案标识和覆盖边界 |
| 非真实方案要求 | 不可用于精确个人完成率 | 显示待绑定/模拟边界 |
| 模拟毕业或学位结果 | 不可作为正式结论 | 仅可用于演示并明确标识 |
| 离线 AI 策展样例 | 不可冒充实时模型结论 | 仅证据指纹完全匹配时使用并披露来源 |

### 8.6 当前可用能力

当前数据可以支持：

- 两个真实学期在籍名册的并集、交集和覆盖率；
- 真实成绩的学期 GPA、未通过课程和跨学期变化；
- 明确改善、明确恶化、连续受挫和首次受挫；
- 当前未解决、重复未解决和历史已解决课程；
- 当前关系范围内的班级/导师学生学业概览；
- 学生预警历史、核查过程和时间线；
- 正确绑定方案范围内的课程进度与确定性建议；
- 基于已有证据的规则/AI 辅助解释。

### 8.7 当前不可直接得出的结论

当前数据不足以可靠支持：

- 学生未选课、漏选课的正式认定；
- 某门重修课程是否一定开设、是否有余量、学生是否满足报名条件；
- 学生一定能或不能毕业、一定获得或不能获得学位；
- GPA 变化的具体原因，例如学习态度、教师质量、心理或家庭因素；
- 学生能力高低、教师责任或学院绩效的直接评价；
- 未完整接入课程替代、免修、认定规则时的最终毕业缺口；
- 仅凭连续两个学期未通过就认定长期持续风险。

### 8.8 性能和刷新边界

- 成长概览使用 900 秒缓存，适合分析读取，不适合作为源系统刚更新后的即时确认；
- 历史名册使用约 120 秒缓存，并通过源文件修改时间识别变化；
- 聚合表应在成绩或学生范围数据更新后重新生成；
- 页面应显示数据时间或最近加载时间；
- 需要即时核查时，应提供主动刷新或批次失效机制；
- 大范围名单分页必须在服务端完成，不能一次返回全校学生到浏览器。

### 8.9 AI 适用边界

AI 只能解释已授权事实、给出核查路径和角色化建议。重要结论必须包含或可追溯到：分析范围、数据时间、事实来源、规则/模型版本、证据入口和适用边界。

当确定性事实之间存在冲突时，AI 应停止生成肯定结论，提示“指标口径待核对”，并列出冲突字段；不得自行选择更有戏剧性的数字。

## 9. 异常、空态和验收规则

### 9.1 参数、权限和对象异常

| 场景 | 系统行为 | 提示/状态 |
|---|---|---|
| 起始学期不早于目标学期 | 不发起业务查询，保留上次结果 | “起始学期必须早于目标学期，当前条件尚未查询” |
| 学期不足 2 个 | 不构造比较 | “至少需要两个真实学期才能进行变化分析” |
| 历史名册源不可用 | 不用当前维表替代 | 返回 422，并说明缺失学期/表/字段 |
| 非法名单分组 | 拒绝请求 | 400 参数错误 |
| 页码小于 1、页大小非法或超过 100 | 拒绝或按契约校正 | 不得产生服务器异常 |
| 组织条件超出当前授权范围 | 拒绝或返回空范围 | 不得扩大权限 |
| 后端组织层级与筛选不一致 | 清空组织表，保留其他区域 | 指定层级不一致提示并允许重试 |
| 当前身份无有效关系 | 返回空范围 | 关系核对提示，不回退全校 |
| 学生不存在 | 不展示旧数据 | 404 对象不存在 |
| 学生存在但无权访问 | 不泄露学生信息 | 403 无权访问 |
| AI 场景非法 | 拒绝请求 | 400，不回退默认场景 |

### 9.2 加载、失败和保留策略

| 页面/区域 | 加载状态 | 失败策略 |
|---|---|---|
| 管理首页首次加载 | 全页加载提示 | 展示错误与重试 |
| 管理首页重新查询 | 保留旧数据并显示局部加载 | 失败后继续保留上次成功结果 |
| 组织比较 | 表格加载 | 局部错误，不清空概览和名单 |
| 学生证据名单 | 表格加载 | 保留概览和上次名单，允许重试 |
| 我的班级/我的学生 | 页面加载 | 错误说明 + 重试 |
| 学生证据抽屉 | 骨架屏 | 当前对象错误 + 重试，不能显示上一学生 |
| 完整学生档案主接口 | 页面骨架 | 页面级错误，不混用旧对象数据 |
| 档案 V2 补充区域 | 局部加载 | 局部错误 + 重试，主档案继续可用 |
| 学生学业研判 | 研判加载 | 错误 + 重试，清理旧研判 |

### 9.4 功能验收清单

#### 9.4.1 首页和筛选

- [ ] 非关系型身份进入 `/admin/students/analysis` 时显示管理比较工作台；
- [ ] 页面标题随全校、学院、专业权限范围正确变化；
- [ ] 默认选择最近两个真实学期，起始早于目标；
- [ ] 专业必须在选择学院后可用，行政班必须在选择专业后可用；
- [ ] 学院/专业固定身份的对应筛选不可扩大范围；
- [ ] 学院变化清空专业和班级，专业变化清空班级；
- [ ] 修改草稿但未查询时，结果和 URL 仍代表上次已应用条件；
- [ ] 无效学期组合不发请求并显示准确提示；
- [ ] 重置恢复身份默认范围并立即查询；
- [ ] 刷新页面可恢复起止学期、组织、分组、关键词、页码和 `10/20/50/100` 页大小。

#### 9.4.2 可比较看板和指标卡

- [ ] 可比较学生数等于两学期授权在籍名册交集去重数；
- [ ] 在籍学生总数等于两学期授权在籍名册并集去重数；
- [ ] 可比较占比的分子/分母和 1 位小数正确；
- [ ] 单击可比较学生数后加载 `comparable` 名单并滚动定位；
- [ ] 首页仅展示 5 张成长关注指标，不重复展示可比较 KPI；
- [ ] 明确改善/恶化按 `0.30` 和未通过变化组合规则计算；
- [ ] 连续受挫同时满足两期在籍和两期有未通过证据；
- [ ] 首次受挫排除目标学期以前已有真实未通过记录的学生；
- [ ] 重复未解决要求同一课程至少 2 次未通过且最新仍未通过；
- [ ] 每张 Tooltip 都包含指标说明、时间范围、公式和中文说明；
- [ ] 零分母显示“暂不可计算”，不显示 0%。

#### 9.4.3 组织比较和证据名单

- [ ] 未选学院返回学院，选学院返回专业，选专业返回行政班；
- [ ] 组织标题、首列名称、组织编号和响应粒度一致；
- [ ] 组织表按重复未解决、连续受挫、明确恶化和名称顺序排序；
- [ ] 组织表当前没有误导性的行级下钻；
- [ ] `all` 名单只含四类优先关注学生，不含仅改善学生；
- [ ] 7 个名单分组选项均返回正确集合，非法分组返回 400；
- [ ] 学号/姓名搜索、Enter、按钮和清空搜索行为一致；
- [ ] 分页总数、页码和页大小由服务端控制；
- [ ] 证据名单排序与公开文案一致；
- [ ] 姓名、详情均打开正确学生的证据抽屉；
- [ ] 当前未通过课程数、重复门数和有效预警数可与学生明细对账。

#### 9.4.4 关系工作台

- [ ] 辅导员、班主任进入同一路由时显示“我的班级学业关注”；
- [ ] 导师显示“我的学生学业关注”；
- [ ] 当前学期、来源和加载时间显示正确；
- [ ] 无有效关系时返回空范围，不出现学院或全校学生；
- [ ] 覆盖学生仅包含当前有效关系且符合正式学籍状态的学生；
- [ ] 平均 GPA 先按学生计算加权 GPA，再按学生平均；
- [ ] 有未通过学生占比分母只含有有效成绩学生；
- [ ] 学分完成率中位数排除无真实方案要求的学生；
- [ ] 预警学生数和事件数分开显示；
- [ ] 班级卡片可展开/收起，学生行打开正确证据抽屉；
- [ ] 班级本地分页的 `10/20/50/100` 条均可用。

#### 9.4.5 学生学业证据抽屉

- [ ] 从不同名单打开时均重新校验学生权限；
- [ ] 快速切换学生不会出现旧响应覆盖新学生；
- [ ] 从管理首页打开时显示触发原因和比较周期；
- [ ] 总 GPA、当前未解决、重复未解决和当前有效预警与档案一致；
- [ ] 学期变化表的 GPA、未通过门数、变化和获得学分正确；
- [ ] 方案未正确绑定时不展示虚假完成率；
- [ ] 当前未解决、重复未解决、历史已解决三个切换项数量和明细一致；
- [ ] 风险状态和人工流程状态分别表达；
- [ ] “打开完整学生档案”携带返回地址、查询条件和滚动位置；
- [ ] 关闭抽屉恢复原名单位置。

#### 9.4.6 学生学业档案

- [ ] 学生基本信息、真实入学日期或入学年份不被伪造；
- [ ] 累计 GPA、已获学分和通过门数基于每门课程最新有效结果；
- [ ] 已修学时明确为 `已获学分 × 16` 推导值；
- [ ] GPA 图显示真实学期并保留 2.0 参考线；
- [ ] 历史预警、当前预警、干预和最新变化可与时间线对账；
- [ ] 时间线 5 个筛选项和分类数量正确；
- [ ] 确定性建议的 5 个受众选项只改变文案，不改变事实；
- [ ] 建议卡最多 12 条，优先级排序稳定；
- [ ] V2 指标与公共 GPA、学分和课程结果口径一致；
- [ ] 可行动课程与未完成候选课程边界文案正确；
- [ ] 未完成候选超过 100 条时显示总数和截断提示；
- [ ] 成绩 `is_pass` 未知时显示 `—`，不显示未通过；
- [ ] V2 局部失败有可见提示和重试，不影响主档案；
- [ ] 学业研判按钮打开当前学生的研判抽屉。

#### 9.4.7 学生学业研判

- [ ] AI 接口按当前身份重新校验学生访问权限；
- [ ] 顶部信息图标可查看范围、来源、规则版本、数据时间和边界；
- [ ] 当前判断中的所有数字均能在学生档案复核；
- [ ] GPA、学分、当前未解决和当前有效预警不另算第二套；
- [ ] 主建议按当前角色选择，其他建议最多 2 条；
- [ ] 证据不足时说明缺口，不生成确定性结论；
- [ ] 规则兜底、在线模型和离线策展样例来源标识准确；
- [ ] 离线样例仅在证据指纹完全匹配时出现；
- [ ] 研判失败显示错误和重试，不保留上一学生内容；
- [ ] 研判抽屉没有未经定义的继续下钻或自动业务操作。

### 9.5 权限回归矩阵

| 用例 | 预期结果 |
|---|---|
| 校领导/教务处查看全校 | 可看全校比较、组织聚合和授权学生详情 |
| 学院身份查看本学院 | 组织筛选固定本学院，可看本院明细 |
| 学院身份请求其他学院学生接口 | 403 或空范围，不泄露详情 |
| 专业身份查看本专业 | 仅见本专业及其行政班 |
| 两名不同辅导员 | 只能看到各自有效关系班级/学生 |
| 两名不同班主任 | 班级范围相互隔离 |
| 两名不同导师 | 所带学生范围相互隔离 |
| 系统管理员 | 按明确授权查看全校业务数据和系统管理能力 |
| 当前身份切换 | 页面类型、数据、缓存和表格偏好上下文同步切换 |
| 直接访问他人学生 URL | 后端拒绝，不能依赖菜单隐藏 |
| 直接调用名单、详情、AI 接口 | 每个接口独立校验当前身份和数据范围 |

### 9.6 口径对账测试

至少准备以下可人工复核的固定样本：

1. 两期均在籍、GPA 上升 `0.30` 且未通过不增加；
2. GPA 下降 `0.30` 且未通过不减少；
3. 未通过减少 1 门、GPA 小幅下降但不足 `0.30`；
4. 未通过增加 1 门、GPA 小幅上升但不足 `0.30`；
5. 两期均有未通过且两期均在籍；
6. 目标学期首次未通过、此前从无真实未通过；
7. 同课程两次未通过且最新仍未通过；
8. 同课程曾未通过但最新已通过；
9. 两期均在籍但其中一期无有效成绩；
10. 仅一期在籍但两期意外都有成绩记录；
11. 一名学生多条有效预警；
12. 方案未绑定、方案正确绑定、学分超过要求三类学生；
13. 成绩通过状态为空、来源为模拟和记录作废的边界样本。

每个样本应对账：首页指标 → 证据名单 → 证据抽屉 → 完整档案 → AI 研判，验证学生集合、GPA、课程状态和预警数量一致。

### 9.7 性能、可用性和审计验收

- [ ] 首页三个业务接口可以独立失败和重试，不互相清空成功区域；
- [ ] 大范围名单使用服务端分页，页大小最大 100；
- [ ] 超过 2 秒显示长计算提示；
- [ ] 同条件缓存不突破当前身份权限指纹；
- [ ] 数据刷新后缓存按批次失效或在约定时限内更新；
- [ ] 表格偏好存储失败不影响业务数据；
- [ ] 浏览器后退/刷新能够恢复已应用查询，而非草稿查询；
- [ ] 学生详情和 AI 快速切换无串数据；
- [ ] 学生名单查询、学生详情访问、AI 研判和身份切换产生必要审计记录；
- [ ] 日志不输出完整敏感学生数据和未经脱敏的研判正文。
