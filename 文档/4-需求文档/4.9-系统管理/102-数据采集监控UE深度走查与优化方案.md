# 数据采集监控UE深度走查与优化方案

> 日期：2026-07-25
> 分支：`产品终稿`
> 范围：系统管理 / 数据采集监控

## 1. 产品定位

本模块定位为“数据接入可信度与运行保障工作台”，主要回答：

1. 平台需要的业务数据是否已经接入；
2. 数据是否在约定周期内更新；
3. 最近一次处理是否成功；
4. 哪些校验或映射问题会影响业务页面；
5. 实施人员应核查哪个源系统、批次或运行证据。

平台只消费和分析学校数据。本模块不编辑教务主数据、不在平台内处理学校业务流程，
也不替代学校数据交换平台的正式调度。

## 2. 走查发现

### 2.1 状态误报

原页面仅把`passed/ok`视为正常，而现有17个V2批次全部使用`accepted`表示接入成功，
导致全部被统计为“质检未通过”。本次将接入状态与校验状态拆分：

- 接入状态：已接入、尚未接入、超过更新周期、正在更新、最近处理失败；
- 校验状态：基础校验通过、有待核验项、校验失败、尚无校验。

`accepted`表示“已接入并通过loader基础校验”，不再被视为失败。

### 2.2 跨域问题混用

原“待处理数据质量问题”读取的是教学运行域32项`operation`问题，并非采集问题。
本次不再复用教学运行问题，采集待核验只来自：

- 数据源批次拒绝记录；
- V2代码映射待核验；
- 实际教室占用的楼宇匹配和无效源记录；
- 数据源缺失、超过更新周期或最近运行失败。

### 2.3 运行证据断链

原库17个批次均未关联`etl_run`；一项任务读取多个文件时，单个
`etl_run.batch_id`也不能表达真实关系。本次新增`etl_run_batch`，支持运行和批次
多对多关联。历史2次课程结果重建已回填成绩、历史成绩和课程替代共6条关联证据。

### 2.4 数据源覆盖不完整

实际教室占用原来只存在于V1专用批次表，没有进入采集监控。本次通过幂等迁移镜像
批次证据，不复制业务事实，将其纳入统一18项数据源目录。

### 2.5 计数含义冲突

部分loader会把一行源记录展开为多条人员关系或事实记录，因此“写入数”可能大于
“源行数”；课程替代只写入审核通过记录，写入数也可能小于源行数。页面不再用
`源行数-写入数`推算拒绝数，三类数分别解释：

- 源文件行数；
- 写入关系/事实记录数；
- 明确拒绝或无效源记录数。

## 3. 统一数据源目录

目录版本为`2026.07-v1`，共18项，分为：

| 数据域 | 数据源 |
|---|---|
| 基础主数据 | 组织机构、学年学期、楼宇、教室、课表时间、课程 |
| 学籍与培养方案 | 当前学籍与方案绑定、培养方案课程、历史学籍与毕业结果、学籍异动 |
| 成绩与课程结果 | 成绩明细、历史成绩桥接、课程替代 |
| 教学任务与师资 | 教师、班主任关系、导师关系、教学任务与排课 |
| 教室占用 | 实际教室占用 |

每项登记来源系统、交付方式、关键字段、更新周期、时效边界、管理用途和下游模块。
原型目录由版本化代码清单生成；生产系统可映射学校数据中台的数据源注册接口。

## 4. 页面结构

### 4.1 管理状态卡

1. 数据源接入：已接入数÷应接入数；
2. 超过更新周期：超过目录时效边界的数据源数；
3. 失败或执行中：最近处理失败或仍在执行的数据源数；
4. 待核验记录：映射、匹配和明确拒绝记录数。

卡片可以筛选下方数据源表，并提供清除筛选入口。

### 4.2 优先处理事项

只显示缺失、失败、超期和真实校验问题，明确问题对象、原因、影响模块、建议核查
动作和数据源详情入口。当前真实证据为：

- 培养方案课程：3项学生方案名称待核验；
- 教室信息：10项楼宇代码映射待核验；
- 实际教室占用：389条楼宇匹配待核验。

### 4.3 三个工作区

- 数据源接入态势：服务端分页、数据域/状态/关键词组合筛选和证据核查；
- 运行与异常：运行状态、输入数据源、耗时、生成记录和详情；
- 交付接入清单：学校接口准备所需来源、关键字段、周期和影响模块。

所有正式表接入公共`DataTable`，支持列显隐、列顺序、密度、分页行数、显示上限和
工作身份偏好隔离。

### 4.4 两类证据抽屉

数据源抽屉包含当前状态、最近批次、校验与映射、关联运行。源文件只显示文件名，
不在主表暴露服务器绝对路径或文件哈希。运行抽屉把`checks_json`转换为管理可读
校验项；原始字段和值只保留在受限“技术证据”页。

## 5. 受控运维

- 手动重跑移入“运维操作”抽屉，不占据管理首屏；
- 只允许`TRIGGER_TASKS`白名单任务；
- 后端继续校验`etl.trigger`，菜单可见不等于有操作权限；
- 页面最多等待350毫秒，未完成则返回运行编号并轮询；
- 用户可以关闭抽屉或离开页面，不需要在按钮上等待120秒；
- 同任务运行中由数据库唯一索引和API双重拒绝重复触发；
- 每次触发写入安全审计。

生产系统应由学校任务调度或数据交换平台返回正式作业编号；原型线程池只用于展示
异步受理交互，不作为生产调度器。

## 6. 数据结构与接口

新增：

- `data_source_definition`：数据源目录及交付元数据；
- `etl_run_batch`：运行与输入批次多对多证据；
- `idx_data_batch_source_ingested`：数据源最近批次查询；
- `idx_data_batch_quality`：批次质量状态查询；
- `idx_etl_run_batch_batch`：批次反查运行。

主要接口：

| 接口 | 用途 |
|---|---|
| `GET /overview` | 管理状态卡、优先事项、目录和动作能力 |
| `GET /sources` | 服务端分页和组合筛选 |
| `GET /sources/{source_code}` | 数据源批次、映射、运行和边界证据 |
| `GET /runs` | 运行历史分页筛选 |
| `GET /runs/{run_id}` | 管理校验、输入批次和技术证据 |
| `GET /checklist.csv` | 导出学校接入核验清单 |
| `POST /trigger` | 受控白名单异步重跑 |

旧`/batches`接口保留并改为服务端分页，供兼容调用和技术核查使用。

## 7. 快速实施能力

学校个性化主要通过数据源目录调整，而不是复制页面：修改来源系统、交付方式和更新
周期，映射学校接口字段，声明数据源影响的业务模块，即可由相同页面生成接入态势和
交付清单，不需要为每所学校重新开发一套监控页面。

- `accepted`不再被统计为失败；
- 教学运行域32项问题不再混入采集待核验；
- 现有2次运行形成6条批次关联；
- 组合筛选、服务端分页、详情抽屉、列设置和CSV导出可用；
- 无`etl.trigger`不能调用重跑接口；
- 非白名单任务返回400，同任务并发返回409；
- 数据采集模块15项迁移、接口、分页、权限、详情和导出测试通过；
- 完整后端测试310/310通过；
- 前端2548个模块生产构建通过；
- 概览、20行数据源列表和20行运行列表组合调用30次，平均11.99毫秒，
  P95 13.50毫秒，最大16.27毫秒。
