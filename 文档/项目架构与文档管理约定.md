## 1. 目标与本次规格

本仓库是本科教学分析与学业决策支持平台，服务校领导、教务处、学院、辅导员、班主任、导师和系统管理员。架构整理的目标是让模块、接口、类型、业务计算和文档各有明确归属，使后续需求可以按模块增量修改。

本约定依据 prototype-builder Skill 的 SKILL.md，以及 project-spec、conventions、modify 参考约定。Skill 区分新建模板与已有项目：本项目沿用 Vue + FastAPI + SQLite，适配其分层和文档原则，不使用生成器覆盖工程。项目运行和交接不依赖本机 Skill 路径。

本次精简规格如下，后续步骤只更新受影响部分：

| --- | --- |

模块索引下一步采用以下约定：稳定模块 ID；`current` 登记已存在的页面、路由、API/helper、类型、后端、数据来源和文档；`target` 登记待实施结构；`sharedDependencies` 引用共享能力。路径相对于仓库根目录。索引只用于定位和协作，不生成菜单、不参与运行时权限。

`reports/GraduationReadiness.vue` 应归培养质量，`reports/EarlySetback.vue` 应归预警。`routers/v2.py` 是多个业务共用的实现容器，不作为永久独立产品模块。

## 5. API、类型与后端边界

### 5.1 前端请求

新增或进入整理范围的页面使用“页面 → 命名业务 API → 公共 HTTP → FastAPI”。例如基础报表后续建立 `api/basicReports.ts`，页面调用查询、选项和导出函数，不自行拼接后端地址。

保留 `{code,msg,data}`，不机械改成模板的 `{success,code,errMsg,data}`。现有分页、列表字段、空值及快照令牌保持含义。公共请求负责 JWT、`X-Active-Identity` 和错误边界；传输层不反向依赖页面或业务 Store。

普通 JSON、文件下载和 POST SSE 是三种传输方式：认证可复用，响应不能强制统一解包。下载保留文件名和服务端快照校验，问策保留 meta/delta/done/error 事件及错误状态。身份切换、取消和在途请求行为在实际迁移时专项验证。

已有页面直接请求不要求在本次规则建立后立即全部重写；逐模块迁移并核对消费者，必要时保留旧导出路径作为兼容层。

### 5.2 类型与计算

前端按模块维护必要 DTO，避免全项目单一巨型 contracts 文件。Python 请求模型和实际响应与 TypeScript 类型共同核对；类型断言不等于运行时校验。只有实际需求明确后再引入 OpenAPI 类型生成，不手工维护两套独立“权威契约”。

业务计算、权限和状态转换保留在后端；Router 提取服务或 SQL 时保留已校验的范围上下文，service 不反向导入 Router。Skill 使用同一事实和正式指标，不通过前端计算或模型临时发明数字。

普通分析查询只读，平台治理受控写入，ETL 写入派生分析数据；不回写学校主数据。双库整合和指标公式调整必须另列任务，不作为目录整理的附带变更。

### 6.2 状态与更新

进入维护范围的规范文档标注状态、版本、核对日期及适用范围；状态使用“现行规范”“实施计划”“历史记录”或“待核对”。日期只表示核对时间，不表示比所有旧需求更有权威。

新需求先更新对应规格；改变接口同时更新 API、类型、后端及模块索引；改变目录同步索引、架构和引用；改变启动同步 README 与部署指南。每次只更新受影响部分，不自动生成新的同题 PRD。

冲突处理：用户已确认的决定优先；工程约定以本轮 AGENTS 和本文为入口；业务按对应模块的已确认需求与指标确认书核对。源码用于说明实际行为，但不能自动替代产品决策。无法确认的冲突登记为待核对，不悄悄修改业务。

## 7. 增量修改与验证

每个后续任务写清任务编号、所属模块、目标行为、允许文件、契约影响和完成条件。先读相关规格与模块索引，再改代码，最后同步文档并核对实际验证结果。

- 文档任务检查路径、链接、现状与目标标识、差异及 JSON（涉及时），不要求启动应用。
- 前端代码任务先确认类型检查基线，再运行构建和本模块核心流程；构建通过不代表类型检查通过。
- 接口、权限、导出、指标等变更运行相关既有测试和反向范围验证，集成阶段遵循 AGENTS 的完整要求。
- 数据库结构变化沿用幂等迁移规则；目录整理默认不改数据库结构。
- 未运行或受环境影响的检查要说明，历史结果不作为本次结果。
- 保留用户工作和旧地址，提交、推送及部署按实际任务范围执行，不因完成文档就自动执行。
